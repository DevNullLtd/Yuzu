rpm fixtures: REAL databases, trimmed by real rpm
  Recipe (the same for every rpm capture; run inside the same image with --network none):
    1. mount the captured database directory read-only, copy it to a scratch dbpath;
    2. rpm --dbpath <scratch> -e --justdb --nodeps --noscripts --notriggers --allmatches <every
       package not on the keep-list>  (in batches of 40);
    3. rpm --dbpath <scratch> --rebuilddb  (real rpm rewrites the container compactly);
    4. rpm --dbpath <scratch> -qa --queryformat of the exact old formats below, into inventory.tsv
       and list.txt; copy only the database file (rpmdb.sqlite, Packages.db or Packages) out.
  inventory.tsv:  rpm --queryformat '%{NAME}\t%{EPOCH}\t%{VERSION}\t%{RELEASE}\t%{ARCH}\t
                  %{INSTALLTIME:date}\t%{SIGPGP}\t%{RSAHEADER}\t%{VENDOR}\t%{PACKAGER}\n'
                  (the plugin's old list_inventory format, kRpmInvQueryFormat).
  list.txt:       rpm --queryformat '%{NAME}|%{VERSION}-%{RELEASE}|%{VENDOR}|%{INSTALLTIME:date}\n'
                  (the plugin's old `list` format).
  Both ran in a container with no TZ and no locale, so the dates are UTC and C-locale.
  Keep-lists (every gpg-pubkey is kept; each capture keeps an epoch package where the capture has one
  and at least one header over 8 KB; tzdata and any package whose changelog names a consumer-mailbox
  address were avoided, because rpm headers carry changelog author addresses and the personal-data
  guard scans binary files):
    fedora41     gpg-pubkey basesystem gmp libssh-config
    alma9        gpg-pubkey basesystem dbus gmp libgomp
    alma8        gpg-pubkey basesystem findutils libverto            (findutils: epoch 1, a 31 KB header)
    alma8-s390x  gpg-pubkey basesystem findutils libverto
    leap156      gpg-pubkey system-user-root fillup libffi7 libnsl2 libverto1 diffutils libcrypt1
    tumbleweed   gpg-pubkey system-user-root fillup openssl libnss_usrfiles2 lsb-release libjitterentropy3
  The rpm sqlite files are about 240 KB each, above the ~200 KB target: rpm creates an empty table and
  index for every tag (about 40 pages) whatever the package count, so that is the floor for a real
  rpm sqlite database. Index.db (ndb) was not committed: the reader never opens it.
  rpmdb.sqlite is WAL-mode (header bytes 18 and 19 are 2) and is committed WITHOUT its -wal and -shm
  sidecars (rpm removed them when it closed the database). The sqlite cases copy it into a yuzu_test_
  temporary directory before opening it, so no sidecar is ever created in this tree.
