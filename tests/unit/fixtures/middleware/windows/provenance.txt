No Windows capture of an IBM MQ installation exists yet.

The Windows leg of the middleware plugin reads, under HKEY_LOCAL_MACHINE in both registry views,
every subkey of SOFTWARE\IBM\WebSphere MQ\Installation, and from each subkey the values FilePath
(install path) and VRMF (version). Those key and value names come from IBM's documentation of the
Windows installation registry, not from a capture of a real install, so:

  - the leg is declared CONSTRAINED, not SUPPORTED, until a real install confirms the names;
  - every Windows case in tests/unit/test_middleware_parsers.cpp and
    tests/unit/test_middleware_win_parsers.cpp uses inline SYNTHETIC values and says so;
  - nothing under this directory is read by a test as a capture, and no plugin sample
    (agents/plugins/middleware/docs/samples/windows.txt) exists.

When a real capture is taken (reg query on a host with an IBM MQ install), commit it here with its
host, date and sha256, add the sample, and re-rule the leg's support level.
