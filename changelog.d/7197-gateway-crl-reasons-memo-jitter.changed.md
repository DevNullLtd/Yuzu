- **Gateway CRL watcher: two new rejection reasons, refused bytes counted once, and jittered refresh (#7070, #7067).** `yuzu_gw_mgmt_crl_rejected_total{reason}` is now a closed set of fourteen: `unsupported` (a well-formed CRL the gateway refuses by policy: a delta, scoped or indirect CRL, a `removeFromCRL` entry, an unprocessable critical extension) and `validity_too_long` join the set, and `malformed` is kept for input that does not decode; a corrupt file and a policy refusal were both `malformed` before. **Counter semantics change:** a CRL refused because of its bytes alone (`malformed`, `unsupported`, `unverified`, `issuer_mismatch`, `validity_too_long`) is remembered by hash (with the `mgmt_crl_max_validity_s` in force) for one hour and is no longer decoded and verified again on every refresh, so the counter moves once per distinct rejection in a row, repeated hourly while it persists, rather than once per tick (the body is still downloaded every refresh); `future_dated`, `replay` and the fetch failures are still decided afresh and counted every time. The state gauges report a remembered refusal exactly as a fresh one (`last_success` does not advance), so `YuzuGatewayMgmtCrlRefreshStalled` and `YuzuGatewayMgmtCrlNotLoaded` are unaffected; no shipped alert rates on this counter, but a rule of your own that does will see a lower rate. Each refresh wait is also shortened by a random 0 to 10 percent (never lengthened), so a fleet restarted together does not poll the server in one burst.
