- **The engine principal read routes no longer show an empty list or a credential count they could not read.** `GET /api/v1/engine-principals`, `GET /api/v1/engine-principals/{id}`, the MCP tools `list_engine_principals` and `get_engine_principal`, and the Settings Engine Principals panel read the principal list through the checked read and each principal's credentials through the checked token-store read. The two stores share one connection pool, so pool exhaustion used to answer `200` with no principals; now, when either read cannot answer, REST returns `503` with `Retry-After: 2` and `retry_after_ms: 2000`, MCP returns a retryable internal error with `retry_after_ms`, and each writes a `failure` audit row (`engine_principal.list`, `engine_principal.get`, `mcp.list_engine_principals`, `mcp.get_engine_principal`) instead of reporting no principals, `0` credentials or an empty `active_credentials` list for a principal that holds a live one. The Settings panel shows an "unavailable" notice when the list cannot be read, and "unavailable" in the Active Creds cell (offering neither Mint nor Rotate) from the first credential read that fails; it stops reading after that failure. The recovery wording that called these reads fail-soft is corrected in the manuals, the recovery runbook and the OpenAPI document, and the audit-log catalogue now lists the `failure` result for both verbs.
