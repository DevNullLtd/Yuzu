- **The engine principal read routes no longer show a credential count they could not read.** `GET /api/v1/engine-principals`, `GET /api/v1/engine-principals/{id}`, the MCP tools `list_engine_principals` and `get_engine_principal`, and the Settings Engine Principals panel read the token store through the checked read. When it cannot answer, REST returns `503` with `Retry-After: 2` and `retry_after_ms: 2000`, MCP returns a retryable internal error with `retry_after_ms`, and each writes a `failure` audit row (`engine_principal.list`, `engine_principal.get`, `mcp.list_engine_principals`, `mcp.get_engine_principal`), instead of reporting `0` credentials or an empty `active_credentials` list for a principal that holds a live one. The Settings panel shows "unavailable" in the Active Creds cell and offers neither Mint nor Rotate for that row. The engine-principal list itself is unchanged and still returns an empty list when the engine-principal store read fails.
