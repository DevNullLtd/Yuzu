- **Cookie-session writes require a same-site `Origin` or `Referer`.** One pre-routing check refuses any request other than `GET`, `HEAD` or `OPTIONS` that is authorised by the session cookie and carries neither header, or one naming another site (an entry from `--csrf-trusted-origin` is accepted), with `403` `cross-site request refused` and a `csrf.denied` audit row, after authentication and before authorization, step-up and the route handler, and before the body is read. A request that presents a valid session cookie is treated as a cookie-session request even if it also carries a token; requests authenticated only by a token are not gated. Existing per-route checks stay as defence in depth. This is a behaviour change for scripts that reuse a login cookie without the header: send `Origin` (or `Referer` where the endpoint validates `Origin` against its own allowlist), or use an API token. Behind a reverse proxy that rewrites `Host`, declare the public origin with `--csrf-trusted-origin`; the boot log and the first refusal name the flag. New metric `yuzu_server_csrf_denied_total{path_class,reason}`.
