- **A second core replica now resolves more of an agent's state correctly (HA WS-5; a second replica is still NOT supported, the safe-to-scale gate is not lifted).** A `NotifyStreamStatus` CONNECTED received while the route directory cannot be read is now always refused (`connected_unverified`), where it used to be accepted for a session the replica held locally; a gateway that includes #5695 resends it and it is accepted once the directory reads, and an older gateway leaves the agent undispatchable until its next reconnect (#5685). A replica holding an agent's session but not its gateway placement now sends through the route directory instead of failing the send (#5685 hp-1), and takes the fleet snapshot's `os` from the presence row (#5685 hp-2, snapshot half; the guardian heartbeat reconcile on a non-owning replica is not covered). A session id that this replica's session map and the route directory attribute to different agents is refused and listed for replay (new `yuzu_server_gateway_route_desync_total{op="session_lookup",outcome="agent_mismatch"}`, no alert; #6339). A dispatch to a plugin an agent lacks now reports `plugin_not_found` on a replica that does not hold that agent's session: the presence store (`endpoint_state`, migration v5) gains a small `endpoint_plugins` table, written once per session by the replica that owns it, and a failed read leaves the dispatch unwithheld. **Upgrade:** the migration is a plain `CREATE TABLE IF NOT EXISTS`, safe to roll back from; an agent registered before the upgrade stays "unknown" for this check until it re-registers.
