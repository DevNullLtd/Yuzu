- **`GET /api/v1/rbac/roles` and `GET /api/v1/rbac/roles/{role}/permissions` no longer answer an empty `200` when the RBAC store is degraded.** A closed store, a pool timeout or a failed query is now a retryable `503` (`retry_after_ms` 5000, fixed message, no database text), and a role name the roles table does not hold is `404` instead of `200 {"data":[]}`. New `RbacStore::list_roles_checked()` backs both; `list_roles()` delegates to it and now counts degrades in `yuzu_server_rbac_read_degrade_total`. The remaining fail-soft `list_roles()` callers (the no-admin auditors and the `discover_permissions` catalog) are unchanged.
