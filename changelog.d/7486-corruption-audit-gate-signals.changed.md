- **The server's Echo corruption audit gate is now bounded and observable, and the corruption alert counts new quarantines.** At most 4 agents hold a lookup or write slot at once (it used to be as many as the 65,536-entry map allowed, each holding a PostgreSQL pool connection), the per-agent map evicts an entry whose rate-limit window has elapsed before one still inside it, a reservation completed twice is a no-op, and a lookup that throws now opens the 60 s degraded window (dated from the failure, and only ever extended) instead of being retried on every heartbeat. A heartbeat whose audit step throws no longer fails the whole heartbeat: the health-store upsert is guarded like the other reconcile hooks. New metrics: `yuzu_server_echo_db_quarantines_total` (one per audit row written), `yuzu_server_echo_corruption_audit_degraded_total{reason}`, `yuzu_server_health_upsert_exceptions_total` and `yuzu_fleet_retired_tar_plugin_agents`. `YuzuEchoDbCorruptionDetected` now fires on any increase of the quarantine counter in an hour (a starting default, not sized from fleet data) instead of a rise in the `yuzu_fleet_echo_db_corruption_agents` population gauge, which kept firing when agents with an old quarantine reconnected; the gauge stays published and no rule reads it.
