- Integrations page, webhooks, offload targets and directory sync (System pages): three panels for the Settings > Integrations page, backed by six admin-only read fragments (`/fragments/settings/webhooks`, `.../offload-targets`, `.../directory-sync` and their delivery and user sub-fragments). Webhooks and offload targets list by destination host with the full URL on demand, show the newest delivery, open a delivery history, and can be created or deleted; creating one asks for a confirmation that names the destination host and the data the chosen events carry, and says it is not an approval. Directory sync shows Entra ID status from checked reads (a failed read, a never-synced directory and a failed run are three different states), a sync form whose tenant, client and secret are used for that request only, a group-to-role mapping editor that flags a mapping the server did not store, and a lazy, audited user list. Every write calls the existing JSON route; no new write route and no new MCP tool. Hardening that rides along: webhook and offload target creation refuses a URL with embedded `user:password@` and control bytes in the URL or event types; the `webhook.created` analytics event carries scheme and host only; the offload create audit row records the URL; the directory sync 400 and 500 outcomes and the group-mapping pairs are now audited. New `get_deliveries_checked` and `get_status_checked`/`get_synced_users_checked`/`get_synced_groups_checked` store reads distinguish a failed read from an empty one; the existing reads are unchanged for current callers. The parity ledger gains six rows and `BASELINE_UNTWINNED` moves 199 to 201 for the two webhook fragments.
