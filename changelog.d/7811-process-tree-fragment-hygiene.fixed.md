- **Device-id routes refuse an over-long or control-byte device id, and a failed Echo read shows the device's own error.** A device id over 256 bytes or carrying a byte below 0x20 now answers `400` (MCP `-32602`) through one shared id rule, before any check that names the device and before any audit row that carries the id, on: the Echo process-tree, DNS/ARP and capture-source routes and the two retention-paused re-enable and purge dashboard posts; the DEX per-device fragments and `/api/v1/dex/devices/{id}` routes; the device-page, hardware and fleet-visualization routes; `POST /api/v1/echo/retention-paused/purge`; the per-device app-usage read, SLE read and decommission, quarantine create and release, bundle dispatch, upload-grant mint, device-token create, tag and custom-property routes; the Pending enrolments approve, deny and remove routes; and the MCP tools `get_dex_device_score`, `get_dex_device_app_perf`, `get_dex_device_history`, `get_dex_observation`, `get_guardian_device_guards`, `get_guardian_agent_status`, `get_agent_app_usage`, `get_agent_inventory`, `query_software_licenses`, `get_software_host_collection_settings`, `get_tags`, `set_tag`, `delete_tag`, `quarantine_device`, `execute_bundle` and `mint_upload_grant`, plus the approval mint of every approval-gated tool. The tag routes and the MCP tools `set_tag` and `delete_tag` also refuse a tag key over 64 bytes or with a byte below 0x20, before the service-tag guard and any audit row that names the key; this is a size and control-byte check only. `POST /api/v1/upload-grants`, `POST /api/v1/device-tokens` and `GET /api/v1/hardware/{id}` read the id only after a global permission or fleet-read check that never sees it, and every MCP tool runs its tier check first. The hardware JSON routes answer `invalid device id`, the fleet-visualization host topology keeps its own message, and `get_hardware_ci`, `get_software_host_collection_settings` and the two Guardian drills keep their own answer. A route or tool that already refused such an id through its own route pattern, store check, control-byte check or visibility lookup is unchanged, and `GET /api/v1/devices/{id}`, the software-host reads and the MCP tools `get_agent_details`, `get_software_host`, `query_inventory` and `query_responses` have no id check. The Echo panels no longer tell the operator to upgrade the agent for a missing roll-up table; they show "The device reported an error: ..." with the device's text.
