- **Behaviour change: `yuzu_fleet_plugin_init_failed{plugin}` names only plugins in the server's catalogue, and `plugin="other"` is gone.** The server now labels a reported plugin name only when its own capability catalogue knows it (about 73 names). A failing plugin the catalogue does not know, for example a custom plugin, is counted under `plugin="unknown"` instead of getting a series of its own, so a dashboard or route keyed on `plugin="other"` or on a custom plugin name must switch to `unknown`. `YuzuPluginInitFailed` is unchanged and fires on `unknown` like any other series. This closes a displacement path: an agent could fill the old first-64-names label cap with invented names and push a real plugin's failure (for example Echo) into `other`, so the alert still fired but lost its per-plugin attribution. New gauge `yuzu_fleet_plugin_init_failed_rejected{reason}` counts the agents whose tag carried names that were not labelled (`unknown_plugin`, `malformed`, `over_cap`), published every sweep including 0. Names are still agent-reported, so a hostile agent can name a real plugin that has not failed, or stay silent about one that has.
