- **Decommissioning a device now erases its Guardian compliance-census rows (#5675).** `DELETE /api/v1/sle/agents/{id}` fans out across nine stores; the `stores` map gains a `guaranteed_state` key. Erasure is partial: `deleted` means the census rows were erased and the pending census evidence retired, while the event log and DEX observations stay until retention expires (30 days by default; rows written while `guardian_event_retention_days` is 0 or below never expire). The device stops counting in `errored_rules` and `uncertain_rules`, the `yuzu_server_guardian_census_pending_events` gauge drops, and a re-registered `agent_id` inherits no stale errored state (a bare re-register keeps the old row). Stop the agent first: a still-running agent re-creates its row on its next census-bearing event (after a state change, an agent restart or a rule push; not on a schedule), and a journal replay cannot rebuild it. A pending event committed during the decommission, after its pending list was read, is not retired (tracker #7147), and a later pending event stays pending until retired. A rolling upgrade is outside the 0.15.0 deployment contract; if replicas of two builds overlap, one that has not been upgraded returns `200` without a `guaranteed_state` key and did not erase the census rows, so re-issue the DELETE after upgrading. An offline agent still counts with its last reported state.
