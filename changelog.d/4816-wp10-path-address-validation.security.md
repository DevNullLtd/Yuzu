- **Breaking: webhook and offload-target destinations in the link-local, cloud-metadata, unspecified, multicast and reserved address classes are refused, and agent plugins refuse network and device paths and non-public destinations.** This hardens specific sinks of the 2026-11-17 security scan (the scan's findings are listed in the pull request, not in the repository); it is not a general SSRF fix. *Server:* `POST /api/webhooks`, `POST /api/v1/offload-targets` and MCP `create_offload_target` refuse such a literal host, including numeric spellings (`2852039166`, `0xa9fea9fe`, `0`), audited `denied` / `destination_refused`; delivery resolves a name once through its own resolver pool, vets every answer, tries the vetted addresses in turn and declines (`destination_refused` / `destination_unresolved`, counted in the new `yuzu_server_{webhook,offload}_delivery_refused_total{cause}`, not in `_failed_total`, and audited as `webhook.delivery.declined` / `offload_target.delivery.declined`). A stored target that points at such an address does not deliver. Loopback and private ranges are NOT refused (opt-in policy: #4816, #3870, still open), and the other outbound sinks (`content_dist`, `netprobe`, `network_actions`, `wol`, the `firewall` probe target, analytics, health check, NVD, directory sync) are not changed. *Agent (enforced by the agent's own plugin code; the server does not enforce it):* one shared predicate refuses UNC, `\\?\UNC\`, `\\.\`/`\??\` and reserved DOS-device paths and non-fixed Windows drives, and POSIX paths on or symlinked into a mount of a listed network type, in `ioc.check`, `disk_space.free`, `http_client.download` (destination), `processes`/`procfetch` (image paths) and, on Windows, `filesystem` (lexical; a junction to a share is a residual there; `ioc` and `procfetch` open handle-relative on Windows). There is no operator override: Windows removable/optical/mapped drives and a network-rooted `/` (diskless NFS, WSL2/virtiofs guest, systemd automount) are refused. `ioc.check` gains `coverage` rows naming every path that was not examined, hashes only regular files under 512 MiB (never `/proc`, `/sys`, `/dev`) and caps 64 paths and 256 hashes. `processes` hashes Linux images through `/proc/<pid>/exe`. `http_client` resolves once, requires every answer to be public (cloud-metadata classes included) and connects to a vetted address; `download` accepts only 2xx, requires a complete body (Content-Length, chunked or `expected_hash`), verifies, then replaces the destination atomically (a failed or unverified transfer writes nothing). `windows_updates.patch_connectivity` caps caller targets at 16 and refuses loopback/link-local/metadata/multicast/reserved resolved addresses. `procfetch` returns an empty hash, never the SHA-1 of a truncated read. The `disk_space.free` `path` and the pre-flight `volume` refuse a leading double separator server-side. Windows code paths compiled on MSVC but were not run end to end in this change.
