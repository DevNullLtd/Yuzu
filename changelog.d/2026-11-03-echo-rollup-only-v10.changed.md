- **Breaking — Echo stores roll-ups only; `echo.db` is migrated to schema v10 on the first start.** Every event is folded into the hourly, daily and monthly tiers as it arrives. The sixteen raw `<source>_live` tables, the 15-minute aggregation pass and the rollup marks are gone, so `echo.query` and `echo.export` return hourly buckets and a per-event pid, command line or timestamp can no longer be read back; the `$<Source>_Live` names stay answerable as empty views, and an `echo.sql` reply over one carries a `constrained` result status (`retired_table:<name>`) so a stored query or result set can tell a retired table from an empty one. The migration converts the old summaries and every raw row not yet summarised in ONE transaction (a failure or power loss leaves the old file intact and the next start retries) and needs twice the database file's size free; otherwise Echo stays offline with `storage_state|offline|free_space` until space is freed and the agent restarts. Copy `echo.db` with its `-wal` and `-shm` sidecars before upgrading: an older agent cannot use the migrated file (it opens it and records nothing) and a rollback needs the copy restored. Raw rows older than the old roll-up mark are not carried into the tiers (the old roll-up already summarised them, apart from rows a process-event backfill wrote or the clock-gap skip left out) and the agent log reports how many; a mark found ahead of the clock is replaced by the edge of what the old summaries hold, a damaged mark or an old summary row that cannot convert refuses the migration with the row named, and the process rows the usage fold had not yet read reach usage in the same transaction. A migrated tier row carries the columns an older build did not record (`parent_name`, `abnormal_exit_count`, `failed_count`, the listen counts, `disconnect_count`, `partition_count`) as blank or 0, so a bucket spanning the upgrade holds two process rows per (name, user). `echo.purge_source` reports `dictionary_pending` (and a `constrained` status) when the dictionary sweep after the purge did not finish, instead of a bare `purged`. Default retention is now 90 days hourly, 180 days daily and a year monthly. The byte budget evicts hourly rows only (older than 48 hours, 5 days for `procperf`); an unusable `db_budget_bytes` value is read as unknown instead of the 250 MiB default and the pass is skipped. `status` reports `<source>_rows` (the finest tier's row count; `<source>_live_rows` carries the same figure for one release) and `netqual_boot_rows`, and the retired `budget_evicted_raw_rows_total` stays at its last value. A first-seen `SYN_SENT` connection that vanishes counts as `failed_count`, a listening socket as `listen_open_count`/`listen_close_count`, a process stop with a non-zero exit status as `abnormal_exit_count`, and a user session that disconnects as `disconnect_count` (only where the OS reports a detached session: Windows does, Linux and macOS never emit it). `fleet_snapshot_window_seconds` is accepted but no longer has an effect: `echo.fleet_snapshot` reports the connections ESTABLISHED at the sample instant only. `status` also reports `dict_gc_last_ts` and `dict_gc_starved_total`, the weekly dictionary sweep's last completed run and the number of sweeps whose scan ran out of time. Until the dashboard reads the tiers directly, the Echo pages and the canned queries in `echo_warehouse.yaml` label hourly buckets as the raw rows they used to show.
