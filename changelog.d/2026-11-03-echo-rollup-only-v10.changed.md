- **Breaking — Echo stores roll-ups only; `echo.db` is migrated to schema v10 on the first start.** Every event is folded into the hourly, daily and monthly tiers as it arrives. The sixteen raw `<source>_live` tables, the 15-minute aggregation pass and the rollup marks are gone, so `echo.query` and `echo.export` return hourly buckets and a per-event pid, command line or timestamp can no longer be read back; the `$<Source>_Live` names stay answerable as empty views. The migration converts the old summaries and every raw row not yet summarised in ONE transaction (a failure or power loss leaves the old file intact and the next start retries) and needs twice the database file's size free; otherwise Echo stays offline with `storage_state|offline|free_space` until space is freed and the agent restarts. Default retention is now 90 days hourly, 180 days daily and a year monthly. The byte budget evicts hourly rows only (older than 48 hours, 5 days for `procperf`); an unusable `db_budget_bytes` value is read as unknown instead of the 250 MiB default and the pass is skipped. `status` reports `<source>_rows` (the finest tier's row count; `<source>_live_rows` carries the same figure for one release) and `netqual_boot_rows`, and the retired `budget_evicted_raw_rows_total` stays at its last value. A first-seen `SYN_SENT` connection that vanishes counts as `failed_count`, a listening socket as `listen_open_count`/`listen_close_count`, a process stop with a non-zero exit status as `abnormal_exit_count`, and a user session that disconnects as `disconnect_count`. No release is cut between this change and the dashboard change that follows it (see the upgrade notes).
