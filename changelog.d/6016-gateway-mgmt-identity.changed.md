- **The shipped reference gateway configs (`gateway/config/sys.config.prod`, `deploy/docker/reference-gateway-sys.config`) now say `{mgmt_peer_auth_mode, pin}` explicitly and are otherwise unchanged (#6016).** An unset `mgmt_peer_auth_mode` is always `pin`, never the identity, so a configuration with no pins and no mode still refuses to boot on an exposed listener, exactly as before; setting `mgmt_peer_identity` while the mode is `pin` is ignored and logs a warning saying so. To use the identity, set `identity_or_pin` (keeping the pin), and move to `identity` only when both the server's `yuzu_server_identity_uri_present` reads `1` on every replica and, after real command traffic through the gateway, `yuzu_gw_mgmt_auth_admitted_total{method="identity"}` moved while `{method="pin"}` did not (neither is sufficient alone: the gauge describes the file `default-server.pem` and is set once at server boot, and a pin counter standing still on an idle gateway proves nothing). The gateway's rejection log line now ends `see mgmt_peer_auth_mode, mgmt_peer_pins)`.
