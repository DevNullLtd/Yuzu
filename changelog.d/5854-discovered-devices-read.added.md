- **Hosts found by network discovery can now be read through a bounded REST route, an MCP tool and a dashboard fragment.** `GET /api/v1/network/discovered-devices` (also `list_discovered_devices` over MCP and `GET /fragments/network/discovered`) lists discovered hosts newest last-seen first, capped at 500 rows, with host and subnet counts over the whole filter and a `truncated` flag, and takes an optional exact `subnet` filter. It needs `Infrastructure:Read`, refuses service-scoped API tokens, and is audited as `network.discovered.view` (the REST route refuses to serve if that audit row cannot be written). A store fault is reported as unavailable, never as an empty list, and no managed flag is returned because discovery does not yet match hosts to enrolled agents. The older `GET /api/discovery/results` is unchanged.
