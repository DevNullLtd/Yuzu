- **A NUL byte in an instruction or instruction-set id, or in a list filter, now answers "not found" or an empty list instead of a store fault.** The legacy `/api/instructions*` routes, the dashboard routes and the older MCP list/get/export tools passed such a value straight to the store, which since the Postgres parameter hardening reported it as a retryable `503` (or an internal error with a retry hint) and counted a store degrade. They now answer `404`, an empty list, or `{}` on the legacy export, as for any other unknown id.
