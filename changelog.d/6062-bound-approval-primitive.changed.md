- **Breaking: the `guardian.` instruction-definition id prefix is now reserved, beside `mcp.` (#6062).** Creating, importing or YAML-saving a definition whose id starts `guardian.` is refused (case-sensitive, exact prefix), and boot auto-import skips one. A definition that already has such an id keeps executing, but it cannot be re-imported, and the dashboard YAML editor refuses to save it if the document declares `metadata.id`. No shipped content uses the prefix. Before upgrading, run the read-only check and rename anything it lists (see the `guardian.` entry in the Server Administration upgrade notes and the Upgrading guide).
- **Approval store groundwork for bound approvals (#6062, four-eyes MVP PR2); no operator-facing feature creates a bound ticket yet.** Approvals schema migration v2 adds three default-empty columns (`request_json`, `request_digest`, `excluded_roots`), and `ApprovalManager::consume_ticket` now requires the caller to declare the surface it redeems for, so a caller that declares none, or a ticket with no recorded origin, always refuses. What is live today: the MCP approval recall declares `mcp`, and a recall refused by its pre-consume precondition (only `confirm_engine_rotation` supplies one) is now counted in `yuzu_approval_precondition_denied_total{origin}` and audited as `approval.precondition_denied`, in addition to its existing `mcp.*` denied row; add the new action to any SIEM audit-action allow-list. What is not live: nothing calls `submit_bound`, so no ticket carries a frozen request or a list of barred reviewers, the `guardian_deploy` origin cannot be minted, and there is no Guardian deploy approval gate (that arrives with #6063 and stays off until #6066). Rollback to the previous build is not supported once a bound ticket exists; see the Upgrading guide.
