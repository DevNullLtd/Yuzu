- **New read-only `shares` agent plugin — what a host is configured to serve over SMB and NFS, on Linux (the macOS and Windows legs are not read yet).** The single `list` action reports names, paths, read-only or read-write, whether anonymous access is configured and a few flags, and never ACLs or NFS client host lists (NFS clients are a count). On Linux it reads `/etc/exports`, `/etc/exports.d/*.exports` and `/etc/samba/smb.conf`. It reports the configuration as written, not live `nfsd` or `smbd` state, and the Samba registry backend, `include =` files and usershares are reported as constrained tokens instead of a wrong share list. Every source reports whether it was read, so a refused or failed read reports a constrained or permission-denied status with a token, never an empty result. Share names and paths can embed account names, so dispatch is gated at the infrastructure read permission and the stored result is readable by `Response:Read` holders, as for every plugin. The macOS and Windows legs each report one `unsupported` status row (`macos:planned`, `windows:planned`) until they ship.
