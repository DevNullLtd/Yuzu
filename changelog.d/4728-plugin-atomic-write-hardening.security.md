- **One exclusive-create atomic file write shared by the agent's state-file writers.** `asset_tags` (`asset_tags.json`), `tags` (`tags.json`), `filesystem` (`replace`, `write_content` on an existing file, `delete_lines`) and the agent's own client certificate and key writer now stage those writes through one shared primitive (`agents/shared/atomic_file_write.hpp`): a random-suffixed sibling temp created exclusively (POSIX `O_CREAT|O_EXCL|O_NOFOLLOW`, Windows `std::ios::noreplace`), fsync'd before the rename (POSIX only — `F_FULLFSYNC`, then `fsync`, on macOS; the Windows leg writes through `std::ofstream` and does not fsync), with the POSIX mode re-asserted on the still-open descriptor for owner-only state (a new ordinary file is created at `0666 & ~umask`; replacing an existing one keeps its rwx bits — owner, ACLs, hard links and a symlink at the path are not preserved, which for `tags.json` is a change from the previous in-place write). `filesystem`'s `append` and a `write_content` that creates a new file still write the target directly. `tags.json` was previously written in place (a crash could truncate it) and `filesystem`'s temp name was fixed and predictable. `asset_tags status` gains `persist_failures` and `last_persist_error`, and a `sync` whose owner-only mode could not be re-asserted or whose directory could not be fsync'd now reports `CONSTRAINED`. On startup, a client certificate that does not match its key, or a key that is unreadable or unparseable, now makes the agent treat the provisioned identity as missing, warn and re-enrol, rather than present a mismatched pair until the leaf expires (agents already holding such a pair re-enrol once on their first restart after upgrade) (#4723, #4725, #4726, #4727, #4728).
