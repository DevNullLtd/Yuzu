- **One exclusive-create atomic file write shared by the agent's state-file writers.** `asset_tags` (`asset_tags.json`), `tags` (`tags.json`), `filesystem` (`replace`, `write_content` on an existing file, `delete_lines`) and the agent's own client certificate and key writer now stage those writes through one shared primitive (`agents/shared/atomic_file_write.hpp`): a random-suffixed sibling temp created exclusively (POSIX `O_CREAT|O_EXCL|O_NOFOLLOW`, Windows `std::ios::noreplace`), fsync'd before the rename (POSIX only; Windows has no flush-by-handle), with the POSIX mode re-asserted on the still-open descriptor for owner-only state (ordinary files keep their `0666 & ~umask` creation mode). `filesystem`'s `append` and a `write_content` that creates a new file still write the target directly. `tags.json` was previously written in place (a crash could truncate it) and `filesystem`'s temp name was fixed and predictable. `asset_tags status` gains `persist_failures` and `last_persist_error`, and a `sync` whose owner-only mode could not be re-asserted or whose directory could not be fsync'd now reports `CONSTRAINED`. On startup, a client certificate that does not match its key, or a key that is unreadable or unparseable, now makes the agent treat the provisioned identity as missing, warn and re-enrol, rather than present a mismatched pair until the leaf expires (#4723, #4725, #4726, #4727, #4728).
