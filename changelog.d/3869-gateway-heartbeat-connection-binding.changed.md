- **The gateway now binds agent heartbeat admission to the connection that opened the session.** An agent `Heartbeat` is admitted only on the HTTP/2 connection that opened the session's `Subscribe` stream and only for a session the gateway node currently holds; any other heartbeat is answered `NOT_FOUND` (unknown session), counted in `yuzu_gw_heartbeat_rejected_total{reason}` or `yuzu_gw_heartbeat_session_mismatch_total{event="security"}`, and not forwarded. Rejections are summarised in one rate-limited log line that never carries a session id, and two gateway info log lines no longer include the session id (this reduces, and does not remove, session ids in logs). No wire, agent or server change: a rejected agent re-registers as it already does on `NOT_FOUND`. **Deploy with a gateway restart** (the session index is created at startup; hot code upgrade is not supported for this change). Agents must reach the gateway directly or through an L4 / TLS-passthrough path; an HTTP/2-terminating proxy in front of `:50051` is not supported for this check. Refs #1197, #3869.
