- **Breaking - gateways fronted by an HTTP/2-terminating proxy or service-mesh sidecar.** Check for such a hop in front of `:50051` before upgrading; agents must reach the gateway directly or through an L4 / TLS-passthrough path, otherwise every heartbeat is rejected (agents still enrol and receive commands). **Deploy with a gateway restart** (the session index is created at startup; hot code upgrade is not supported for this change, and a running node without the index rejects every heartbeat until restarted). The gateway now binds agent heartbeat admission to the connection that opened the session: an agent `Heartbeat` is admitted only on the HTTP/2 connection that opened the session's `Subscribe` stream and only for a session the gateway node currently holds; any other heartbeat is answered `NOT_FOUND` (unknown session), counted in `yuzu_gw_heartbeat_rejected_total{reason}` or `yuzu_gw_heartbeat_session_mismatch_total{event="security"}`, and not forwarded. A rejected agent re-registers through its `NOT_FOUND` recovery, which needs agent 0.13.0 or newer; an older agent only logs the failed heartbeat and does not re-register by itself (restart or upgrade it), which matters only if its heartbeats are rejected. There is no wire or server change and no agent change for the supported topologies. Rejections are summarised in one rate-limited log line that never carries a session id, and two gateway info log lines no longer include the session id (this reduces, and does not remove, session ids in logs). `/readyz` now reports `sessions_index` and answers 503 while the index table is missing. Rollback is redeploying the previous gateway (derived from the change, not tested). Refs #1197, #3869.
