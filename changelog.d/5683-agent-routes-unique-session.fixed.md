- **A gateway session id can now be held by only one agent.** Two agents racing to adopt the same unheld session id could both succeed, leaving two directory rows with one id (observed at 22% of racing pairs over gRPC). `GatewayRouteStore` migration v5 adds a unique index on `agent_routes(session_id)` (tombstoned rows excluded): the loser of the race is now refused (`FAILED_PRECONDITION` on `ProxyRegister` replay, counted under `yuzu_server_gateway_route_desync_total{outcome="session_held_by_other_agent"}`), and the same condition on a `NotifyStreamStatus` CONNECTED is refused with the placement unpublished (`op="announce_connected"`, a `gateway.session_held_by_other_agent` audit row, and `YuzuGatewaySessionHeldByOtherAgent` now covers both ops). The migration runs once at the first start of this version, takes an exclusive lock on `agent_routes` (about 6 s at one million rows), tombstones every row of any group that already shared a session id and reports the count as `yuzu_server_gateway_route_session_dedup_total`; see the upgrading guide. The safe-to-scale gate is unchanged: run one server replica.
