- **Dashboard results page: a late or dropped request no longer leaves the wrong table (#5623).**
  - Every request from the filter bar, the sort headers and the pagination now shares one replacing request scope, so a correction typed or a View switch made while a request is in flight is no longer dropped, and a late sort or page response no longer leaves rows under an empty header.
  - Sending a command aborts a results request still in flight, so a late response for the previous command can no longer replace the new command's table. The built-in `help` command and a TAR SQL query do not abort one yet (#5677).
  - The sort headers and Prev/Next buttons use the filter values currently shown instead of those of the last render.
  - An open Create Static Group form is now closed by every successful results response, so it can no longer create a group from filters that are no longer on screen.
  - The chart-deck refresh after a command is now started by the filter bar and carries its filter values, so it can no longer overwrite the pager, summary and Create Group button of a filtered view with unfiltered ones. It needs the filter bar to load, so an operator whose only grant is scoped to a management group does not get the chart deck, pager and summary yet (#5688).
  - Create Group from a result set of a definition whose columns are named differently from the plugin's now carries the filters chosen in the filter bar, instead of opening a form with no filters, "0 agents will be added" and a submit that answered 422 with nothing shown.
  - The Create Group button now percent-encodes the filter value, so a value containing `+`, `&`, `%` or `#` (a package version such as `0.8.0+~cs4.8.3-1`) no longer previews "0 agents".
