- **The NVD settings panel no longer shows proxy credentials.** `user:password@` is removed from the configured NVD HTTP proxy before `/fragments/settings/nvd` displays it. The NVD client also no longer keeps `user:password@` in the proxy host it connects to, or writes it to the startup log; only the host and port are used. A proxy port that is not a plain number in 1 to 65535 falls back to 8080 (a value such as `80x` is no longer read as 80), the scheme is case-insensitive, and surrounding whitespace is ignored. The client does not authenticate to the proxy, so a proxy that requires authentication answers `407`. A proxy value with no usable host (`socks5://`, an empty host, or a `?` or `#` ahead of the credentials) is refused: the server logs an error at startup and every NVD fetch fails as a connection failure instead of going direct.
