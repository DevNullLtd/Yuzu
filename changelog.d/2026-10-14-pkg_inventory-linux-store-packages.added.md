- **`pkg_inventory` gains a read-only `store_packages` action and real Linux legs.** `managers` on Linux now reports which of dpkg, apt, rpm, dnf, pacman, apk, snap and flatpak are present (apt source-file, snap-file and flatpak app and runtime counts as facts; versions are not read); `store_packages` lists installed snaps (name, revision, version and type from the mounted revision's snap.yaml, active state) and flatpak apps and runtimes (id, arch, branch, active commit) from the system installation. Both legs are bounded, no-follow filesystem reads with no subprocess; an unreadable or incomplete listing is a constrained status with a token, never an empty result, while a snap whose snap.yaml cannot be read is reported with version `-` and kind `unknown`, and a flatpak whose active link cannot be read with state `unknown`, rather than failing the action. The daily installed-software inventory collects the active rows as ecosystems `snap` and `flatpak` (flatpak version is empty: a branch is a ref, not a version), and a constrained `managers` answer that still names a present manager no longer skips the whole cycle. macOS reports `store_packages` unsupported by design (`installed_apps` lists applications); Windows is planned. Also carries #4881's descriptor and wording corrections (unsupported legs declared rung 0, the Linux roster owner named as `installed_apps.list_inventory`).
