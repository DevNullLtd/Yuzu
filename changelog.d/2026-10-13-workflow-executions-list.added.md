- **Workflow run list: `GET /api/v1/workflow-executions` and MCP `list_workflow_executions`.** The first way to list workflow runs (only fetch-by-id existed). Newest-first keyset paging (`cursor` / `next_cursor`), filters `workflow_id`, `status`, `since`, `until`, `limit`, and `latest_per_workflow=true` for each workflow's newest visible run (the Workflows table's "last run"). Rows are metadata only (`id`, `workflow_id`, `workflow_name`, `workflow_deleted`, `status`, `current_step`, `started_at`, `completed_at`); `agent_ids` and step results stay on the detail route. Gated on `Workflow:Read` through the fleet-read chokepoint: a confined caller (management-group or service-scoped) sees only runs with at least one agent in its scope, applied in the database before ordering and the page limit so hidden runs never take a page slot, shape a cursor or count toward `pagination.total`. Input is strict (unknown or repeated parameters are `400`), a store failure or the 1.5 s statement timeout is a `503` with `retry_after_ms` (never an empty list), and no audit row is written for a successful list.
