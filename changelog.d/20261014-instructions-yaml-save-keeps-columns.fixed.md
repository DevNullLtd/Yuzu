- **Saving a definition from the YAML editor no longer resets the columns the YAML does not carry.** `POST /api/instructions/yaml` with an `id` now loads the stored definition and keeps its instruction set, enabled flag, TTLs, result schema, visualization, response templates, platforms, minimum agent version, required plugins, readable payload and author. When the YAML omits `type`, `version`, `concurrency` or `approval`, the stored value is kept instead of being reset to `question`, `1.0.0`, `per-device` and `auto`, so a definition created with `approval_mode: always` is no longer silently downgraded by an editor save. A YAML value that differs from the stored one is still an intentional edit and is written; an `approval_mode` change is recorded in the `instruction.update` audit detail as `approval_mode: <old> -> <new>`. If the stored row cannot be read the save answers 503 and writes nothing.
