- **The OpenAPI document types the DEX score policy document.** The stored policy of `GET`, `PUT` and `DELETE /api/v1/dex/score-policy` (and the `document` of a `dry_run` answer) is now the `DexScorePolicyDocument` component, which `PUT` also takes as its request body, so a client generated from the OpenAPI document gets typed policy models, including the scoring model parameters (`model`, with each range and default). A client that sends `model` must set `version` to `2` explicitly. Do not set a model parameter during a rolling upgrade (see Upgrading).
- **The refusal of the Apps policy projection now names `model`.** A `PUT` that sends the Apps `policy` block is told to send `tiers.edges`, `tiers.names`, `weights`, `model` and `overrides`. `PUT` and `GET` carry the `model` block only when a parameter is in use; a document that uses none reads back as version 1.
