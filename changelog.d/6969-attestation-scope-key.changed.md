- **Breaking: an access-review attestation must name the scope of the grant (#6969).** `POST /api/v1/access-reviews/{id}/attestations` and the MCP `record_attestation` tool now require `scope` (`fleet` or `management_group`); `scope_group_id` is absent or empty for `fleet` and a nonempty string of at most 64 bytes for `management_group`. A request that omits `scope` is refused with `400` (REST) or invalid params (MCP). Each attestation row in `GET /api/v1/access-reviews/{id}` and `get_access_review` carries `scope`, `scope_group_id` and `scope_group_name` (every row is fleet-wide in this build), both campaign tables show a Scope column, and the `access_review.attested` / `access_review.flagged` audit detail gains ` scope=fleet` or ` scope=management_group scope_group_id=<id>`. The access-review store moves to schema v4, which adds `scope_group_id` to both attestation tables and their keys. A dashboard page loaded before the upgrade answers `400` on Attest until it is reloaded. Start one replica first, because the migration takes `ACCESS EXCLUSIVE` locks on both tables. An older build is not blocked from a v4 database: do not run one; recovery is a fresh database. See `docs/user-manual/upgrading.md`.
