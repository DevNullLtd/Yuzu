- **The gateway image ships Erlang/OTP 28.5.0.8, and the release image gate also scans with grype, which sees that runtime (WP15/S9).** This supersedes statements in two other entries of this release (the WP15/S9 image entry and the `linux/amd64`-only gateway entry): the Alpine gateway does not stay on OTP 28.5.0.2, its Erlang/OTP runtime is now scanned (by grype), and the re-pin to an older `erlang:28-alpine` index (#6740) no longer applies, because the builder is now `hexpm/erlang`; the image stays `linux/amd64` only. `yuzu-gateway` is built on `hexpm/erlang:28.5.0.8-alpine-3.23.8`, pinned by digest, so it no longer ships OTP 28.5.0.2 (1 CRITICAL and 22 HIGH fixed CVEs as grype reports them); its build adds rebar3 3.27.3 only through a sha256-checked download. The image stays `linux/amd64` only and its runtime stays Alpine 3.23. Trivy does not identify the OTP runtime the gateway bundles, so the release image gate (`scripts/ci/image-vuln-gate.sh`) now runs a pinned grype 0.121.3 on every image as well, on a `docker save` of the image's local ID (never a registry), and refuses the push when EITHER scanner reports a fixable CRITICAL that its acceptance file does not accept: `.trivyignore.yaml` for Trivy, the new `.grypeignore.yaml` for grype (scoped by package name and exact version, with the same statement, expiry and approval-field rules, checked for format only). grype's vulnerability database is taken from its publisher's listing, checksum-checked, refused when it or one of the sources the gate relies on (NVD, Alpine, Debian, Ubuntu) is older than 72 hours, and recorded in each report; it is not signed upstream. A gateway image in which grype does not find the Erlang/OTP runtime is refused. A grype package name may not contain regular-expression characters, because grype reads it as a pattern. grype's reports (`grype-<image>.attempt-<N>.{json,txt,gate.txt}`) ship beside Trivy's with each release, and a release is refused when the published attempt lacks either scanner's reports; the pre-release QA scan writes them too. PostgreSQL itself and statically linked code remain unscanned. Details: `docs/ci-architecture.md` "Release image vulnerability gate" and `docs/erlang-gateway-build.md`.
