- **Hardware roster: a failed device-roster read is no longer shown as an empty fleet.** `OfflineEndpointStore::query_stale_within` now reports a failed read (pool timeout / query error) as a typed error, counted on `yuzu_server_agent_presence_store_failed_total{op="query_stale_within"}` and logged at warn. The Hardware list shows the "Hardware roster unavailable" banner and `GET /api/v1/hardware` answers `503` with the A4 envelope and `retry_after_ms`. The dashboard CI record says "roster unreadable" when no record can be shown and otherwise serves it with an identity-degraded note on the Overview lens; `GET /api/v1/hardware/{id}` answers `503` instead of `404` when the device was not otherwise found (CI record readable-and-absent, no software, no tags) and otherwise serves the record with `identity_state: "degraded"` (a degraded CI store alongside a degraded roster is a `200` with both `identity_state` and `ci_state` `degraded`). Whenever the roster read failed, the Hardware audit rows (`inventory.devices`, `inventory.device.ci`, `inventory.device.software`) record `result=failure`, including when a record is still served. `GET /api/v1/hardware/{id}`, `POST /api/v1/hardware/{id}/sync` and the Hardware CI fragments answer `400` for a device id over 256 bytes or containing a byte below `0x20` (agent registration refuses both, so a registered device is not affected). `/api/v1/viz/fleet/topology` and MCP `get_fleet_topology` keep rendering the live fleet and carry `offline_roster_degraded: true` when the durable offline-host read failed.
