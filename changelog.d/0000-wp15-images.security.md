- **Published container images carry current packages, `yuzu-postgres` moves to PostgreSQL 18.6, and a release refuses to push an image with a fixable CRITICAL vulnerability that its scanner can see, which excludes the operating-system packages of four images (WP15/S9).** `yuzu-postgres` (and `yuzu-postgres-ha`) moves from 18.4 to 18.6 (there was no 18.5); deploy it on a fresh data volume, as this release's deployment contract requires (`docs/user-manual/upgrading.md`). It stays on Debian bookworm (collation version `2.36`) and keeps its PostgreSQL packages at the pinned minor. The server, gateway and postgres images upgrade their distribution packages at build time, and a package index that cannot be fetched fails the build. Before `release.yml` pushes any image, `scripts/ci/image-vuln-gate.sh` (pinned Trivy, by image ID) refuses a fixable CRITICAL that `.trivyignore.yaml` does not accept (a scoped, expiring entry whose approval fields are checked for format only: review of the change is the control), a vulnerability DB older than 72 hours, an OS release with no advisory data, and an image whose OS packages it cannot see unless that image is listed as not covered. `yuzu-server-chisel`, `yuzu-gateway-chisel`, `yuzu-agent-chisel` and `yuzu-agent-bundle-chisel` are listed: their OS packages ship unscanned. PostgreSQL itself, the gateway's Erlang/OTP runtime and statically linked code are not seen either. Each image is pushed with no release tag (the agent bundle under a `candidate-<run>-<attempt>` tag), and `:X.Y.Z` (with `:X.Y` and `:latest` on a stable tag) moves only after the pushed digest is checked against the scanned image, signed and attested, behind a write-ahead publish journal per attempt. Every attempt's gate reports and journal ship with the release (inside `SHA256SUMS`; the agent bundle's are attached afterwards with a signed checksum list per attempt), and a re-run never replaces a refused attempt's report. Candidate digests are left in GHCR, the release process deletes no image, and no release tag is moved by hand: a wrong or superseded release is fixed by a new patch release. The pre-release QA rescan of all seven published images fails on the same conditions, except that it honours (and reports) an acceptance still pending approval; it is detective only. The chiselled gateway's builder moves to OTP 28.5.0.8; the Alpine gateway stays on 28.5.0.2 (#6740). On a stable tag, `:latest` and `:X.Y` move before the GitHub Release exists (`docs/user-manual/release-verification.md`). Scope, residuals, the journal contract and the recovery runbook: `docs/ci-architecture.md` "Release image vulnerability gate".
