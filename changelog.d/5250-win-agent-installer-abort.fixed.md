- **The Windows agent installer no longer leaves a running agent stopped when an upgrade fails.** If an upgrade fails after the installer has stopped the `YuzuAgent` service (for example, a file in the program directory cannot be replaced, which an unattended `/SUPPRESSMSGBOXES` install answers with Abort, exit code **5**), the installer now starts the service again before it exits if it was running or still starting, even when `/NOSTART` was given. It waits for a slow stop to finish and then records in the Setup log (`/LOG=`) the state it actually saw: RUNNING, or that the service could NOT be started, with `sc.exe`'s exit code. Files the failed upgrade had already replaced are not put back, so run the installer again. Earlier installers left the agent offline until someone ran `sc.exe start YuzuAgent` or rebooted. A trust-anchor refusal (exit code **7**) still happens before the service is stopped. Its message now also says what the attempt left at `%ProgramData%\Yuzu\agent-certs`: when the lock on a new directory is blocked, nothing is created there, and an existing directory's own permissions are never changed. The agent and server installers' messages now say `sc.exe`, never plain `sc`, which PowerShell reads as Set-Content. (#5250)
