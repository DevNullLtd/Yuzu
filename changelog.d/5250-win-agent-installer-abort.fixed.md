- **The Windows agent installer no longer leaves a running agent stopped when an upgrade fails.** If an installation stops after the installer has stopped the `YuzuAgent` service (for example, a file in the program directory cannot be replaced, which an unattended `/SUPPRESSMSGBOXES` install answers with Abort), the installer now starts the service again before it exits and logs whether that worked. Files the failed installation had already replaced are not put back, so run the installer again. Earlier installers left the agent offline until someone ran `sc.exe start YuzuAgent` or rebooted. A trust-anchor refusal (exit code **7**) still happens before the service is stopped, so it leaves the service as it was. The refusal message now also says what the attempt left at `%ProgramData%\Yuzu\agent-certs`: when the lock on a new directory is blocked, nothing is created there; an existing directory's own permissions are never changed. A failed lockdown never leaves the directory less protected than it was found. (#5250)
