- **`GET /api/v1/openapi.json` conditional requests match weak validators, lists and `*`.** Release 0.15.0 answered `304` only when `If-None-Match` held the exact `ETag` and nothing else, so a proxy that weakened the tag (`W/"..."`) or a client that sent a list of tags got the full document every time. A request whose `If-None-Match` is a weak form of the tag, a list that contains it, or `*` on its own now answers `304` with no body, after the `Infrastructure:Read` check, for the default form and for `?guides=true` alike. A validator for the other form, or a malformed header, is still answered with the full document and a `200`. The `ETag` and `Cache-Control: no-cache, private` headers are unchanged.
