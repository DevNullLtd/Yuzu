- **The `component_inventory` agent plugin has a second action, `native`, that lists the versioned shared libraries shipped inside applications on Linux and macOS.** It reads `.so` files under `/opt` and `/usr/local/lib` on Linux and `.dylib` files under `/Applications`, `/usr/local` and `/opt/homebrew` on macOS, and reports each library's name, version and where the version was read from (the file name, the library's own declared name on Linux, or its version field on macOS), with path, size and application folder, at most 5,000 rows. Each library's header is read in-process within fixed limits, so a damaged or hostile file cannot make the agent read outside it; a library whose header cannot be read is still listed from its file name, and a file that only looks like a library is not listed. The package manager's own directories are not read: on Linux `/usr/lib` and its siblings are not scanned at all, and on macOS the Homebrew package folders are skipped and counted, so a finished answer names them (`package_tree_skipped`). Like `scan`, it works to a 400,000-entry, 45-second budget and marks the answer constrained, with its cause, when it could not see everything. **It is switched off until an operator enables it**: the server refuses `native` until an operator lifts the switch it seeds off at boot, and `PUT /api/v1/plugin-config/component_inventory/kill-switch` with `action` set to `native` turns it on; `scan` is unaffected. Run it on demand as `crossplatform.components.native`. Windows, extension-less macOS framework binaries, fleet cost counters for this action and inclusion in the daily software report are not in this release.
