- **Agent plugins no longer open operator- or user-supplied paths and hosts as given.** One shared predicate (`agents/shared/local_path_policy.hpp`) now refuses UNC, `\\?\UNC\`, `\\.\`/`\??\` device and reserved DOS-device paths, non-fixed Windows drives and POSIX paths under network mounts before any filesystem call, so a Windows LocalSystem agent can no longer be made to authenticate to an attacker-chosen SMB host through `filesystem`, `ioc.check`, `disk_space.free`, `http_client.download`, or the image path of a process a standard user launched (`processes.list_tree`/`list_hashed`, `procfetch`). `processes` on Linux now hashes through an open of `/proc/<pid>/exe` instead of re-resolving the readlink text, and `ioc.check` hashes only regular files within a size cap, deadline and path/hash count cap (a FIFO no longer blocks a command worker). `http_client` resolves the host once, requires every answer to be a public address (IPv4-mapped, NAT64, 6to4 and IPv4-compatible forms included) and pins the connection to the vetted address, closing the DNS-rebinding gap (#647); `download` now buffers, verifies `expected_hash` and atomically replaces the destination, so a failed or unverified transfer writes nothing. `windows_updates.patch_connectivity` caps caller-supplied targets and refuses loopback, link-local and metadata addresses. The Windows halves were not compiled or run in this change.
