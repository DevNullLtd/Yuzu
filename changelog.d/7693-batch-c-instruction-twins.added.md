- **Instruction definitions and instruction sets can now be authored over REST v1 and MCP (#2146, twin batch C).** Nine REST routes, each with an MCP twin: `POST /api/v1/instructions` (`create_definition`), `PUT` and `DELETE /api/v1/instructions/{id}` (`update_definition`, `delete_definition`), `POST /api/v1/instructions/import` (`import_definition`), `POST /api/v1/instructions/yaml` (`save_definition_yaml`, a JSON body in place of the legacy form), `POST /api/v1/instructions/validate-yaml` (`validate_definition_yaml`, a JSON error list in place of the legacy HTML fragment), and `GET` and `POST /api/v1/instruction-sets` and `DELETE /api/v1/instruction-sets/{id}` (`list_instruction_sets`, `create_instruction_set`, `delete_instruction_set`). Every write twin writes an `attempted` audit row before it changes anything and refuses (503 with `Sec-Audit-Failed: true`, or an MCP error) without changing anything when that row cannot be stored. `PUT` and `DELETE` take an optional `expected_updated_at` and answer 409 when the stored definition has moved on; the MCP `update_definition`, `delete_definition` and an id-bearing `save_definition_yaml` require the version at the supervised tier, and a version that no longer matches is refused before an approval ticket is minted or consumed. The twins refuse an unknown field and bound `name` (1 to 128 characters), `version` (1 to 64), `description` (at most 512 on the JSON routes; the YAML routes bound `name`, `version` and a `description` of at most 16384 bytes), `instruction_set_id` (at most 128), `type` (`question` or `action`), `plugin` and `action` (at most 128 characters of `A-Za-z0-9._-`), `gather_ttl_seconds` (1 to 86400) and `response_ttl_days` (1 to 3650), the same on REST and MCP. The legacy dashboard routes do not apply the field bounds (the store checks `type` on create only), and the operator import (legacy and v1) applies the `name`, `version`, `description`, `instruction_set_id`, `plugin` and `action` bounds and the TTL ranges. A `validate-yaml` / `validate_definition_yaml` result of valid now means the save will not refuse the document as invalid, because it also checks `plugin` and `action`. The import twins admit 4 MiB where the legacy import route admits 16 MiB; an import carrying a `signature` has it verified against the `publicKey` supplied in the same request, so the signature proves the integrity of the document, not the authorization of its author, and an export carries no signature, so a signed document is produced outside the product (`POST /api/product-packs` is the other signature-gated route). An unsigned import is refused unless the server runs with `--allow-unsigned-definitions`. A create without `approval_mode` stores `auto`, which means later runs by schedules or operator-tier callers need no human approval. A `PUT /api/v1/instructions/{id}` or `update_definition` that changes `name`, `description`, `version`, `type`, `plugin`, `action` or `approval_mode` on a definition with a stored YAML clears that `yaml_source` so a later YAML round trip cannot revert the edit, recording which of those changed and the cleared text's size and SHA-256 in the audit detail; a `503` after the `attempted` row says the outcome is unknown and carries no `retry_after_ms`. The v1 and MCP update success rows record a change of `plugin`, `action`, `approval_mode`, `concurrency_mode` or `enabled` as `old -> new`, and the v1 and MCP delete rows carry the deleted definition's dispatch tuple. The OpenAPI document gains nine operations with these operationIds: `postInstructions`, `putInstructionsById`, `deleteInstructionsById`, `postInstructionsImport`, `postInstructionsYaml`, `postInstructionsValidateYaml`, `getInstructionSets`, `postInstructionSets` and `deleteInstructionSetsById`. The new alert `YuzuApprovalSubmitRefused` (warning) fires when `yuzu_server_approval_submit_refused_total` moves for `approval_queue_full` or `approval_cap_reached` within 15 minutes, because the MCP supervised-tier ticket mint for these tools shares the queue and the per-principal cap with every other approval-gated call; its runbook is server-admin.md, "Approval submissions refused: queue full or per-principal cap (#2146)". The counter `yuzu_server_event_emit_failed_total` gains the pre-seeded `event_type` values `instruction.created`, `instruction.updated` and `instruction.deleted`.
