- **The seven `/crypto` MCP tools moved out of `mcp_server.cpp` into their own registry file.** `get_crypto_libraries`, `list_crypto_library_devices`, `export_crypto_cbom`, `list_crypto_widgets`, `get_crypto_dashboard_layout`, `set_crypto_dashboard_layout` and `get_crypto_ca_stats` now live in `mcp_tools_crypto.cpp`, which the MCP registry seam-closure check covers. Names, schemas, annotations, gates, service-scope classes, audit rows and error envelopes are unchanged; the six read-only tools' descriptions gain a closing "Read-only." sentence (the registry A5 floor requires it). One difference: a non-object `arguments` (null, array or string) is now refused by the dispatch chain's shared check, with the generic `-32602` and an `mcp.<tool>` denial row, before the tool runs; for the four `Inventory:Read` tools (the three confined reads and `get_crypto_ca_stats`) this now also precedes that permission check. The error code is unchanged. The message text is unchanged for `get_crypto_libraries`, `list_crypto_library_devices`, `export_crypto_cbom` and `set_crypto_dashboard_layout`; `list_crypto_widgets`, `get_crypto_dashboard_layout` and `get_crypto_ca_stats` no longer say "takes no arguments" for a non-object value (a call with extra keys still gets that message). `set_crypto_dashboard_layout` also fails closed, changing nothing, when the audit sink is missing or throws or the caller's identity cannot be re-resolved.
