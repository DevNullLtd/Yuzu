- **New `wsl` action on the `virtualization` plugin: which WSL distributions does each user on this Windows machine have.** For every local profile it returns the account (the profile folder name), the distribution name, WSL version (1 or 2), install state, whether it is that user's default and its flavor, read from the profile's WSL registry key. A profile that is logged on is read directly; a logged-off profile is read through the same guarded offline `NTUSER.DAT` mount that `installed_apps.list_per_user` uses (loaded hive first, then the privilege-bearing offline arm under the process-wide offline-hive lock and the default-on hive-file guard; no new privilege, and no deadline on the mount calls, only a bound on the work). A `summary` row carries the distribution count, the version-2 count (not a VM count: every WSL 2 distribution shares one utility VM whose running state is not read), the profiles read, the profiles whose hive could not be reached and the WSL package version. A profile whose hive could not be reached, or whose mount could not be released, is reported on its own `profile` row with a typed outcome and the status becomes `constrained`, never read as having no distributions. Install and disk-image paths, SIDs, user ids and the mount name are never emitted, and e-mail-shaped names are redacted. Per-user data, so the action is `Inventory`:Read behind admin-or-approval, on by default. Linux and macOS answer one `unsupported` status row. New instruction `windows.virtualization.wsl` (role-gated); `virtualization` plugin 1.1.0. An agent still running `virtualization` 1.0.0 answers `error: unknown action: wsl` (exit 1), and the server does not compare plugin versions at dispatch, so upgrade the agents first or scope the instruction to devices already on 1.1.0 (for example by tag).
