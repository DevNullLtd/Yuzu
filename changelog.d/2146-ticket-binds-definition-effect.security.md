- **A supervised-tier approval ticket now binds the `plugin.action` a stored definition resolves to, for `execute_instruction_definition`, `create_result_set_from_instruction_result` and `reevaluate_result_set`.** For the two result-set tools the ticket was bound to the tool name and the call's arguments only (`execute_instruction_definition` is new in this release and ships with the binding), while the action is read from a stored definition when the call runs, so a definition repointed between approval and re-call from one ungated action to another the caller may run (`tags.get` to `tags.delete`) ran under an approval granted for the first. The ticket's subject now leads with the resolved effect (plugin, action, approval mode, concurrency mode), shown first in the approver's scope text and part of the pending-ticket dedup key, and the re-call recomputes it before the ticket is consumed. A repoint is refused `-32003` "the definition changed since this approval was requested" (`error.data.reason = definition_changed`, `retry_after_ms` null) with the ticket unspent, shown only to the principal who requested it and only while it is unspent, and repointing back restores it. A repoint landing after that check but before dispatch runs nothing and answers `definition_changed` (`-32602` for `execute_instruction_definition`) or `RESULT_SET_DEFINITION_CHANGED` (`-32003`) for the two result-set tools, with the ticket spent. For the two result-set tools, a supervised token without `Execution:Execute` is now refused before any ticket is minted, and a definition store that cannot be read refuses `-32603` and mints and spends nothing (`retry_after_ms:5000`, `error.data.reason = effect_unresolvable_store_fault`; a store that was never wired answers `effect_unresolvable_store_unwired` with no retry hint). Approval tickets pending, or approved but not yet redeemed, for the two result-set tools when this change is deployed must be re-requested: a ticket without the effect is refused as an ordinary mismatch. The tickets still never lift the action's own admin-or-approval gate.
