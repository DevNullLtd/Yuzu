- **The dashboard executions list and MCP `summarize_working_set` (execution kind) now use the management-group-aware fleet-read gate.** `GET /fragments/executions` and `summarize_working_set` with `kind=execution` previously used a plain `Execution:Read` check; they now use the same gate as `GET /api/v1/executions`, so a group-scoped-only operator gets a confined view (counters and error preview projected to their visible agents, the filter applied before the 50-row limit) where they used to get `403`, and a service-scoped token gets the same confined view from the fragment. This is hardening and an admission change, not a fix for a reachable leak: the old gate only admitted global-grant callers, who were never filtered. A degraded store is now `503` on the fragment and an error with `retry_after_ms` on the MCP tool instead of "No executions yet" or "was not found", and an execution outside the caller's scope reads exactly like an absent one (audited `denied`). `summarize_working_set` stays denied for service-scoped tokens, and its `fleet` and `result_set` kinds still return an unscoped whole-registry agent count (tracked in #3526 and #4753).
