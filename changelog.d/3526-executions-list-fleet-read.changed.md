- **The dashboard executions list and MCP `summarize_working_set` (execution kind) now use the management-group-aware fleet-read gate.** `GET /fragments/executions` and `summarize_working_set` with `kind=execution` previously used a plain `Execution:Read` check; they now use the same gate as `GET /api/v1/executions`. On the dashboard fragment a group-scoped-only operator gets a confined view (counters and error preview projected to their visible agents, the filter applied before the 50-row limit) where they used to get `403`, and a service-scoped token gets the same view when RBAC enforcement is on and the tag store is reachable. `summarize_working_set` keeps its plain `Infrastructure:Read` first gate, so a group-scoped-only operator still gets `403` there; only a caller with a global `Infrastructure:Read` plus a group-scoped `Execution:Read` is newly admitted, and it stays denied for service-scoped tokens. This is hardening and an admission change, not a fix for a reachable leak: the old gate only admitted global-grant callers, who were never filtered, and there is no admission change for a global grant. New for every caller: the gate answers a retryable `503` when the authorization or management-group store is not open. The fragment's own failure notes now render at HTTP `200` with a `data-degraded` attribute (the dashboard drops `4xx`/`5xx` bodies) instead of `503` or "No executions yet", a confined caller with no visible executions sees "No executions visible in your scope.", and the MCP tool returns an error with `retry_after_ms` instead of "was not found" on a degrade. SIEM: for `action=mcp.summarize_working_set`, a confined caller's absent or out-of-scope execution id is now audited `result=denied` (it was `result=success` for an absent id), with the id neutralised and capped; an unconfined caller's absent id stays `success`, and the `denied` row cannot tell a typo from an out-of-scope probe. `summarize_working_set` `kind=fleet` and `kind=result_set` still return an unscoped whole-registry agent count (#4753), as does `kind=execution`/`kind=agent` with an empty id; `GET /api/v1/execution-statistics/agents` is still unscoped (#3526).
