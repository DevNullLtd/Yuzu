- **`device.filesystem.find_by_hash` is bounded and reports what it skipped (#5624).** It used to run one hashing command per file with no limit, so a large tree could run for minutes. The agent now hashes in-process, so detection tooling sees the agent opening files itself and no per-file `sha256sum` or `shasum` child. It stops at the first of 20 seconds, 50,000 entries visited, 4 GiB hashed or 100 matches (a search ordinarily ends within 20 seconds; one blocked read or directory listing is not interrupted); the limits are fixed, so scan a large tree one subdirectory at a time. Results change as follows. A `truncated|<reason>|visited=N|...` row precedes `matches_found|N` when anything was skipped or the search stopped early (any symlink counts, so most scans have one). The status is `CONSTRAINED`/`PARTIAL` when a limit was hit, something was unreadable or a network mount was skipped. Below the search root symlinks are not entered (the final path component only, on Windows and Linux before 5.6), and a symlink to the target file is no longer reported; empty files are now hashed; Linux never enters `/proc`, `/sys` or another pseudo-filesystem; on Windows compressed and deduplicated files are hashed, cloud placeholders and other reparse points are counted unreadable, and a root on a non-fixed drive or a UNC share is refused. Definition 0.4.0 declares `row_kind`, `path` and `size`. An existing server keeps definition 0.3.0 until it is replaced after every agent is upgraded (see the upgrade note). Result-set column matchers split a key-value plugin's rows on every pipe, so a row is a data row only when its field count equals the declared width.
