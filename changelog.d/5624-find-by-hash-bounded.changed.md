- **`device.filesystem.find_by_hash` is bounded and reports what it skipped (#5624).** It used to run one hashing command per file with no limit, so a large tree could run for minutes. The agent now hashes in-process, so detection tooling sees the agent opening files itself and no per-file `sha256sum` or `shasum` child. It stops at the first of 20 seconds, 50,000 entries visited, 4 GiB hashed or 100 matches (a search ordinarily ends within 20 seconds; one blocked read or directory listing is not interrupted); the limits are fixed, so scan a large tree one subdirectory at a time. Results change as follows. A `truncated|<reason>|visited=N|...` row precedes `matches_found|N` when anything was skipped or the search stopped early (any symlink counts, so most scans have one). The status is `CONSTRAINED`/`PARTIAL` when a limit was hit (a file larger than the remaining 4 GiB budget is skipped and counts as `byte_cap`), something was unreadable or a network mount was skipped; REST, MCP and result-set matchers do not see that status, so a matcher cannot select partially covered devices (read the `truncated` row). Below the search root symlinks are not entered (the final path component only, on Windows, on Linux before 5.6 and where a seccomp profile denies `openat2`), and a symlink to the target file is no longer reported; empty files are now hashed; Windows match rows are now UTF-8 (they were in the ANSI code page); Linux never enters `/proc`, `/sys` or another pseudo-filesystem; on Windows compressed and deduplicated files are hashed, cloud placeholders and other reparse points are counted unreadable, and a root on a non-fixed drive or a UNC share is refused. Definition 0.4.0 declares `row_kind`, `path` and `size`. An existing server keeps definition 0.3.0 until it is replaced, and until then column matchers on this instruction bind the wrong columns (`path` sees the literal `match`), so none is trustworthy; replace it after every agent is upgraded, because the 0.4.0 description promises a bounded walk that never follows symlinks, which an older agent does not do (see the upgrade note). Result-set column matchers split a key-value plugin's rows on every pipe, so a row is a data row only when its field count equals the declared width.
