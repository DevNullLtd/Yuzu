- **The server now detects a gateway node that silently stops answering on the management channel (HA WS-13 slice 13.7, #7062).** The server's connection to each gateway's management port sends a keepalive ping every 30 s with a 10 s timeout, also while idle, so a node that drops traffic without closing the connection is found in about 40 s (from the code and a unit test, not yet measured against a real silent-drop fault) instead of every forward waiting for its 300 s deadline. The shape the HA spike exercised for several gateway nodes is one name in front of all of them that passes TCP through (the gateway certificate must carry that name, and every node needs the same management peer settings); a multi-address DNS name was not tried, and a spike finding (some commands accepted and not delivered behind that address) is still open (#7051). An address-list syntax is deferred, and the server still has no second address or failover of its own. A forward that fails UNAVAILABLE is retried up to 3 times with the same command id, which the agent's dedup store makes effectively-once. See "Management address" in the gateway manual.
