- **HEAD on a dynamic route is answered `405` with `Allow: GET`, and dynamic responses are brotli-encoded at quality 5.** An authenticated `/api/v1/` route, dashboard page or fragment, or `/metrics` no longer runs its handler for a `HEAD` request: it answers `405 Method Not Allowed` with `Allow: GET`. The four health probes, static assets, the sign-in pages, the sign-in start and callback `GET` routes, the SCIM `GET` routes and the public CA files keep answering `HEAD`; a `POST`-only route in that set does not gain a `HEAD` handler. The `Allow` header names `GET` only, even on a path that also accepts writes. A dynamic body the client accepts as brotli is now encoded at quality 5 instead of the library's 11, which cost about 2.5 s of one worker for a 2.5 MB page against about 9 ms now, for output about 25 percent larger. A monitor that sends `HEAD` to an authenticated route must send `GET`.
- **The DEX Apps error panel says which cause stopped the read, and the coverage caption counts the live observers.** A busy server, a read the database cancelled for taking too long, an unusable score policy and a database failure each get their own wording, with the cause as a code token; a throwing or unwired Apps handler still answers `200` with a visible panel and logs once per minute. The caption keeps the shipped-design sentence ("Complete and partial describe what the agent collects on each platform by design") and adds `Observers now`: per platform, how many online devices report the crash and hang observer armed, not armed or not reporting. `yuzu_server_guardian_read_degrade_total{source="guardian_state"}` counts a cancelled Apps read as `reason="statement_timeout"` instead of `query_error`. The `503` message and MCP error for a degraded Apps read end with the cause.
