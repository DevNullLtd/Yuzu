- **The installed-software lookup changes two existing behaviours (schema v12).** The `format=csv` export of `GET /api/v1/inventory/software` grows from 14 to 22 columns (`hostname`, `last_seen`, `status`, `last_confirmed_at`, `install_type`, `install_scope`, `install_location` and `instance_key` after `source`), so a consumer that pinned 14 columns must read by header name. The upgrade resets the catalogue rollup's freshness stamp (the new `catalog_rollup.row_count` column starts at 0), so until the first catalogue refresh after the server starts the catalogue reports `building` (its CSV export and versions drill answer a retryable `503`) and the `totals` block of a name lookup without a version filter is `null` with `totals_omitted: "building"`; rows, exports and any version-filtered lookup are live and unaffected. `match=prefix` and `status=` reads of `GET /api/v1/inventory/software` now run under the same 5-second statement bound as `q` and `match=contains`, degrading to the audited retryable `503` instead of holding a pool connection to the 30-second default.
