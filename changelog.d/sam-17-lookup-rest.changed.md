- **The installed-software lookup changes two existing behaviours (schema v12).** The `format=csv` export of `GET /api/v1/inventory/software` grows from 14 to 22 columns (`hostname`, `last_seen`, `status`, `last_confirmed_at`, `install_type`, `install_scope`, `install_location` and `instance_key` after `source`), so a consumer that pinned 14 columns must read by header name. The catalogue rollup gains a nullable `catalog_rollup.row_count` column: until the first catalogue refresh after the server starts, and for any title row whose count a refresh has not computed, the `totals` block of a name lookup without a version filter is `null` with `totals_omitted: "building"` (never `installs: 0`); the catalogue's freshness stamp is not reset, and rows, exports and any version-filtered lookup are live and unaffected. `match=prefix` and `status=` reads of `GET /api/v1/inventory/software` now run under the same 5-second statement bound as `q` and `match=contains`, degrading to the audited retryable `503` instead of holding a pool connection to the 30-second default.
