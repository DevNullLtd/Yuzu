- **A long server outage no longer wedges the gateway's heartbeat flush (#1197).** The gateway's heartbeat buffer used to retain heartbeats on a failed flush bounded by count only. Heartbeats from an agent with the TAR plugin can carry a topology snapshot of several hundred KB, so after a long enough server outage the retained batch exceeded the server's 4 MiB gRPC receive limit and every `BatchHeartbeat` failed until the gateway was restarted, which blocked the recovery of the agents' registrations. The buffer now keeps one entry per session (the newest snapshot is kept) and flushes in chunks of at most about 3 MiB, with a byte cap, `max_heartbeat_buffer_bytes` (default 64 MiB, valid 1048576 to 1073741824); `max_heartbeat_buffer` now counts sessions. New counters: `yuzu_gw_heartbeat_buffer_dropped_total{reason}` and `yuzu_gw_heartbeat_coalesced_total`. While a backlog is coalesced, `yuzu_heartbeats_received_total{via="gateway"}` on the server under-counts. Restart the gateway to deploy; no wire change. Refs #1197.
