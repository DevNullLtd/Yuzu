- **A long server outage no longer wedges the gateway's heartbeat flush (#1197).** The buffer kept heartbeats on a failed flush, bounded by count only. A heartbeat from a TAR plugin agent can carry a topology snapshot of several hundred KB, so after a long outage the retained batch exceeded the server's 4 MiB gRPC receive limit and every `BatchHeartbeat` failed until the gateway was restarted. The buffer now keeps one entry per session (the newest snapshot is kept), flushes at most 8 chunks of about 3 MiB a cycle, and has a byte cap, `max_heartbeat_buffer_bytes` (default 64 MiB); `max_heartbeat_buffer` now counts sessions. A heartbeat whose status tags are invalid or too large keeps its liveness and loses only its tags; one the server rejects is dropped and counted. New counters: `yuzu_gw_heartbeat_buffer_dropped_total{reason}`, `yuzu_gw_heartbeat_coalesced_total`. While a backlog is coalesced, `yuzu_heartbeats_received_total{via="gateway"}` under-counts. Restart the gateway to deploy; no wire change. Refs #1197.
