- **A long server outage no longer wedges the gateway's heartbeat flush (#1197).** The buffer kept heartbeats on a failed flush, bounded by count only. A heartbeat from a TAR plugin agent can carry a topology snapshot of several hundred KB, so after a long outage the retained batch exceeded the server's 4 MiB gRPC receive limit and every `BatchHeartbeat` failed until the gateway restarted. The buffer now keeps one entry per session, flushes at most 8 chunks of about 3 MiB a cycle, and has a byte cap, `max_heartbeat_buffer_bytes` (default 64 MiB). A heartbeat with invalid or oversized status tags (over 64 KiB each, 256 KiB in total) loses only its tags. One connection holds at most 8 agent session rows (`max_sessions_per_connection`), reserved when a `Register` is admitted; a closed connection's rows are removed after `dead_connection_grace_ms` (15000). New counters: `yuzu_gw_heartbeat_buffer_dropped_total{reason}`, `yuzu_gw_heartbeat_coalesced_total`, `yuzu_gw_session_limit_rejected_total`. Restart the gateway to deploy. Refs #1197.
