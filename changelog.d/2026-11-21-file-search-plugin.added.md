- **A new `file_search` agent plugin finds files and directories by name across the local disks of a device and reports the extents of every matched file.** Its `search` action takes an absolute root, a leaf-name pattern (`*` and `?`, no regex) and what to match, and answers one slice per call with a cursor to resume from, a per-volume coverage row and a verdict that says whether everything under the root was searched, so an empty result is never confusable with a failed or partial one. It reads names, types, sizes, times and extents only: a matched file is opened and never read, and no file content is read or hashed. Linux and macOS ship constrained legs (names compare byte for byte on Linux and by Unicode normalisation and case folding on macOS); the Windows leg is planned and answers one unsupported status row. The plugin is off until an operator enables its kill switch (`PUT /api/v1/plugin-config/file_search/kill-switch`). An administrator can launch a search and anyone else needs one approval for the whole search over MCP: the first slice spends it, and each later slice that carries the cursor, from the same caller with the same arguments, rides it for 24 hours (a catalogue row declares its resume parameter, so no other action changes). The server never keeps the cursor: it is erased from every stored copy of a request, and a schedule that carries one is refused. What a search stores is Forensics-tier and is readable only with `Forensics:Read` (the Administrator and ForensicsAnalyst roles by default, Administrator only while RBAC is off).
