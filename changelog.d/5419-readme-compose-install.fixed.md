- **The README's Docker Compose quickstart now works with the released images.** In 0.14.0 it downloaded `deploy/docker/docker-compose.yml` and ran `YUZU_VERSION=0.14.0 docker compose up -d`. That compose builds from a checkout of the repository (`build: context: ../..`), so a downloaded copy has nothing to build, `YUZU_VERSION` was ignored, and the stack never started. The quickstart now downloads `deploy/docker/docker-compose.reference.yml` from the release tag, which pulls `ghcr.io/devnullltd/yuzu-server` and `yuzu-postgres` at `${YUZU_VERSION}`, serves HTTPS on 8443 and keeps `/etc/yuzu/certs` on a named volume. It is three short steps that paste safely into bash or zsh: create the directory and a `.env` with the version and two different Postgres passwords, write the first admin account to `yuzu-server.cfg` (the server's interactive first-run setup exits when there is no terminal), then start the stack and check `/readyz` against the server's own CA. Pasting a step twice cannot replace the database passwords or a live admin account: step 1 stops if the directory or any of the project's volumes already exists, and step 2 never overwrites either copy of `yuzu-server.cfg`. The README says to set `YUZU_CERT_SAN` before the first start, never to clear `/etc/yuzu/certs` (it holds the secrets key, #5370), and that on 0.14.x `yuzu-server.cfg` is the admin password's live source (the server reads it at every start and its entry wins over the database) until 0.15.0 (#5274); the upgrade guide and the AuthDB agent notes that called the file a one-time seed are corrected. The server's warning when `--cert-san` names are missing from the existing certificates, and the `--cert-san` and certificate-rotation advice in the server administration guide, the PKI architecture notes and the certificate-expiry alert, no longer say to clear the certificate directory: to add names, rename `default-marker.json` aside (moving it back undoes this) and restart, which re-issues the certificates under the same CA. The README describes `deploy/docker/docker-compose.yml` as a development stack for a clone. A docs-suite test, `tests/test_readme_quickstart.py`, checks the downloaded compose (no `build:`, `${YUZU_VERSION}` image tags, 8443, a persisted `/etc/yuzu/certs`), that the compose URL's tag, the `.env` version and the compose default agree, that the steps are paste-safe and never overwrite, and that the admin seed matches the image's `--config` path and the server's PBKDF2 parameters.
