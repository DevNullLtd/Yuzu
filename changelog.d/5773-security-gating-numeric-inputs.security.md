- **Security-gating numeric inputs are now strict, in place on v1 (#4644).** Each of these accepted a value that wrapped, was unbounded or failed open: `POST /api/v1/tokens` `expires_at` (`-1`, or a value above 9223372036854775807 that wrapped to `-1`, minted a token that never expires), `POST /api/schedules` `interval_minutes` (`4294967297` minutes became an every-minute schedule), `POST /api/schedules/{id}/enable` `enabled` (`{"enabled":0}` armed the schedule), an `ip_subnet` auto-approve rule with a malformed prefix (threw out of agent registration), the enrollment batch `max_uses` and `ttl_hours`, a pre-flight version threshold (a malformed one read as version 0 and passed every device), a result-set matcher `n` or `kind` (a malformed one admitted every responder), and the TAR process-tree `from` and `to` window (a malformed one dispatched an unbounded query). Each now answers `400` (`-32602` on MCP) and creates or changes nothing. These narrow accepted input without a version bump because every value refused was a wrapped, unbounded or fail-open input, following the precedent of #5617; the policy gap for such narrowing is tracked in #5687. Disabling a schedule stays reachable: `enabled` still accepts a boolean, `0`, `1` and the exact strings `"true"` and `"false"`.
