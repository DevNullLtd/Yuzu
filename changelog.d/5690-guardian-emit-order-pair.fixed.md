- **The agent now stamps the Guardian events that feed per-rule status with an ordering pair, (`boot_epoch`, `emit_seq`), so a server can order verdicts independently of timestamp skew; the epoch still derives from the agent clock at boot, and the pair is agent-asserted and not authenticated.** `GuaranteedStateEvent` gains `boot_epoch` and `emit_seq` (fields 24 and 25), assigned when the agent decides the event's queue order, on both the legacy and the Spark emit paths. `boot_epoch` is claimed once at agent boot from a persisted counter and the boot time; `emit_seq` increases within a boot. A server that compares the pair orders by it; one that does not ignores it and keeps ordering by its census ordering key. Events replayed from the lifecycle journal, DEX observations, and events from an agent whose epoch claim failed carry no pair (0/0) and are ordered by the census ordering key. At boot the agent takes an exclusive lock on `guardian_boot_epoch.lock` in its data directory (an empty file it creates and keeps for the life of the process; it waits up to 5 seconds for a previous process to exit). A process that cannot take the lock, for example a second agent started on the same `--data-dir`, logs `Guardian boot_epoch claim: outcome=instance_lock_not_held` with `instance_lock=contended` or `failed`, and sends unordered events until it is restarted: stop the extra process or fix the cause, then restart. The lock covers processes on one host that run this code; on Linux and macOS it does not stop a user with write access to the data directory from removing the file, and on Windows a backup or security product holding the file open is reported as `contended` (`native_error=32`) like a second agent. The cases where epochs can repeat or regress are listed under Known limits in the Guardian design document, section 7.1. No operator action is needed for a routine upgrade; the procedure for recovering from a lost or regressed epoch will be described with the server change. The change is additive and wire-compatible in both directions. (#5690, #5674)
