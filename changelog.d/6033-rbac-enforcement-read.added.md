- **RBAC enforcement can now be read over REST and MCP (#6033).** `GET /api/v1/rbac/enforcement` and the MCP tool `get_rbac_enforcement`, the machine twins of the Users and roles enforcement panel, return `enabled` (this replica's cached view of the switch), `unconfirmed` (that view could not be re-confirmed) and an advisory `administrator` verdict (`may`, `may_not` or `unconfirmed`) on whether the caller's own credential could change it; the MCP tool adds `audit_persisted`. The verdict is computed from the durable stores independently of the cached view, and `may` is a hint that excludes MFA step-up, the MCP tier and approval ladder and the toggle's `409` destination check. Any signed-in session may call the route (a service-scoped token is refused, and nothing about other principals is returned). Each successful read is audited as `rbac.enforcement.read` on a deployment with a wired audit sink; REST fails closed with `503` and `Sec-Audit-Failed`, and MCP reports `audit_persisted:false`.
