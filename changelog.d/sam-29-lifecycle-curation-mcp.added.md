- **An agentic client can import, list and clear the software lifecycle rules, and curate software titles, over MCP.** Eight new MCP tools call the same functions as their REST routes, so the gate, limits, refusals and audit rows are the same: `list_software_lifecycle_rules`, `import_software_lifecycle_rules` and `delete_software_lifecycle_rules` for `/api/v1/inventory/software/lifecycle/rules`, and `get_software_normalization_status`, `list_software_curation_queue`, `curate_software_alias`, `reject_software_curation` and `replace_software_normalization_pack` for the five `/api/v1/inventory/software/normalization/` routes. Every tool needs the global `Inventory:Read` (reads) or `Inventory:Write` (writes) grant and refuses a service-scoped token; the five writes need a supervised-tier MCP token and are audited ahead of the change (a `requested` row that cannot be stored refuses the call and changes nothing). Over MCP the whole JSON-RPC request is also capped at 4 MiB before routing, so an import file or a pack whose JSON-escaped form plus the envelope passes that cap is refused by the transport. The catalogue identity and `package_id` half of the lifecycle surface is not part of this change (#6090).
