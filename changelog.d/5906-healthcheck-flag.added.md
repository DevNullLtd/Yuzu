- **`yuzu-server --healthcheck` probes a TLS-enabled server from inside the image.** Exits 0 only when the configured listener answers `GET /readyz` (or `--healthcheck-path /livez`) with HTTP 200; the certificate chain is verified only against the install CA (`default-ca.pem`) or, with `--https-cert`, against the first certificate in that file (the server certificate itself; certificates after it are not trusted, and a first certificate that is not a `-----BEGIN CERTIFICATE-----` block is refused, never the whole file) — never the system trust store; hostname is not checked, redirects are not followed, connect is bounded at 1 s, each TLS handshake step at 1 s, the request as a whole at 3 s, and the whole probe at 4 s. On failure one stderr line names the target, the status or TLS reason, and the trust anchor. Reads the server's own listener flags and environment, never `yuzu-server.cfg`. Images built before this flag exit on the unknown argument, so keep their existing probes. (#5906)
