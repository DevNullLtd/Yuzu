- **The server now stores software lifecycle dates and can resolve any title or operating system version to a lifecycle state (store and evaluator only; nothing reads it yet).** A new Postgres store `software_lifecycle_store` holds dated rules (end of support and end of life, by product key and version prefix, each naming the public page its date came from) and global host-declared facts, and a pure evaluator computes `supported`, `end_of_support`, `end_of_life` or `unknown` at read time, never `supported` for a version it has no date for. Source precedence is host-declared (while some host repeated the date in the last 48 hours) over external, imported and shipped rules; the earliest current declared date wins, disagreeing sources are flagged as a conflict, a corrected date replaces the old one once the old one goes stale, and a declaration no host repeats falls below every rule and reads as unconfirmed. The server ships 38 rules for PostgreSQL, Python, Node.js, .NET, Ubuntu, Debian and Red Hat Enterprise Linux in `content/software-lifecycle/rules.csv` and replaces its stored shipped rules with them at every start; it refuses to start when the store cannot open or the shipped rules cannot be parsed or loaded. There is no REST route, MCP tool or page for this yet, and no host reports lifecycle dates yet. Two counters, `yuzu_server_software_lifecycle_store_read_degrade_total{reason}` and `yuzu_server_software_lifecycle_store_write_degrade_total{reason}`, count reads and writes that could not complete (see the inventory and metrics chapters of the user manual).
