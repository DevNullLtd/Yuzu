- **Breaking — MCP `revoke_upload_grant` now audits before revoking and fails closed (#6169).** The tool records an `upload_grant.revoke` `attempted` audit row before changing the grant, then a `success` or `failure` outcome row, matching the REST `DELETE /api/v1/upload-grants/{grant_id}` twin. If the `attempted` row cannot be persisted, the call returns a retryable `-32603` error with `retry_after_ms` and the grant is NOT revoked. By owner decision, no transport can revoke a grant during an audit-store outage; the grant's TTL bounds the exposure. Clients that read `audit_persisted` from this tool must stop: it is no longer returned. A SIEM rule counting one `upload_grant.revoke` row per revoke now sees two; match on `result=success`. `mint_upload_grant` is unchanged. See `docs/user-manual/upgrading.md`.
