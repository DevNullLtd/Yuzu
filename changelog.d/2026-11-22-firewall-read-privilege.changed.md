- **Breaking —** **The firewall plugin's `state` and `rules` rows change on Linux agents that do not run as root, and a Windows rule field can read `unknown`.** On a packaged Linux agent on a firewalld host, `backend|firewalld`, `state|running`, `ruleset|unknown` becomes `backend|nftables`, `state|active`, `ruleset|<n>` with nft rule rows whenever the broker shows an active ruleset. On a packaged agent elsewhere, and on a non-root agent on an installer-provisioned host, `state|unknown`, `ruleset|unknown` becomes a real `backend|nftables` or `backend|iptables` answer; the count is the nft rule count plus the `-A` rules of every legacy iptables and ip6tables table. New row shapes are `rule|ip6|<kind>|<chain>|<spec>`, and `rule|<table>|<kind>|...` and `rule|ip6|<table>|...` for a legacy table other than `filter`. New error rows are `error|snapshot:<token>`, `error|snapshot:helper:<token>`, `error|nftables:snapshot:failed|absent`, `error|nftables:unrecognised_output`, `error|iptables:snapshot:failed|absent`, `error|ip6tables:snapshot:failed|absent` and `error|ip6tables:unrecognised_output`; `error|nftables:table:eperm` is written only when the snapshot does not answer. A root agent whose firewalld read was partial answers from an active nft ruleset, and firewalld zone and service names are sanitised. On Windows, `enabled`, `direction`, `action` and `profiles` can read `unknown`, a rule can be named `unknown`, a rule whose object could not be obtained is a counted all-`unknown` row so `ruleset|<n>` can be higher, and `S_FALSE` no longer reads `block`. On macOS, for a non-root agent with the grant, `pf|unknown` becomes `pf|enabled` or `pf|disabled` with the anchors, rule rows and count.
