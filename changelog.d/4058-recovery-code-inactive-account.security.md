- **Recovery codes are no longer accepted for an inactive account.** The recovery-code check now requires the account to be active, as the authenticator-code check already did. Removing a user through the product already deletes their codes, so this only matters for an account deactivated by a direct database change that still had unused codes: the code is now refused and left unused. On sign-in no session was ever returned in that case, because sign-in re-checks the account and revokes the one it just created. Active accounts are unaffected (#4058).
