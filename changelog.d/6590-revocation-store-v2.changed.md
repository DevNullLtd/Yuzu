- **CRL source store migration v2 (#6590).** The high-water reset (`POST /api/v1/crypto/revocation-sources/{id}/reset-high-water`, MCP `reset_revocation_source_high_water`) now requires `keep_key_sha256` (1 to 8 `ca_certificates[].cert_sha256` values already registered on the source) and `expected_config_version`: every key not named is removed with the CA's held CRLs in the reset's transaction, a key the source does not hold is `400`, a stale version `409`, and an empty body or `{}` is refused; the response adds `dropped_ca_certificates` and `config_version`. CRL URLs are now stored, compared and returned in one canonical form (scheme and host lowercased, default port dropped, leading port zeros stripped, IPv6 literals in RFC 5952 form, an empty path as `/`; path and query as sent), so a `PUT` that only respells a URL keeps its fetch status, and the store rewrites existing URLs to that form at start, refusing to open when two URLs of one source collapse into one. The `crl` and `rollback_high_water` tables share one CHECK-pinned scope key (`full` or `idp:<64 hex>`, then `:base` or `:delta`), with `crl.is_delta` generated from it.
