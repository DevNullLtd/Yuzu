- **New read-only `mgmt_posture` agent plugin — which management plane a device is under, on Linux and macOS (the Windows leg is not read yet).** The single `posture` action reports facts only and changes nothing. On Linux it reads `/etc/sssd/sssd.conf` and `/etc/sssd/conf.d/*.conf` for the active SSSD domains and reports the plane as `ad`, `ipa` or `none` (an IPA realm in `/etc/ipa/default.conf` also reports `ipa`), plus whether `/etc/krb5.keytab` is present; it reports the configuration as written, not the live join state. On macOS it reads MDM enrolment and the MDM server host from `profiles status -type enrollment`. An SSSD configuration the agent is not allowed to read reports `permission_denied` with plane `unknown`, never "not joined", and a failed or partial read reports a constrained status with a token instead of an empty result. The Windows leg reports one `unsupported` status row (`windows:planned`) until it ships.
