- **`msi_packages` gains a read-only `list_inventory` action for the daily installed-software inventory (Windows).** It lists machine-context Windows Installer products only — product code, name, version and publisher through MsiEnumProductsExW/MsiGetProductInfoExW — so a product installed for one user is never reported by this action. The daily sync collects the rows as a new ecosystem value, `msi` (kind `pkg`, `package_id` set to the product code), which now appears in the Software page, REST, MCP and CSV ecosystem values and filters; the product code is stored but not yet returned by the REST and MCP software routes. A Windows host normally lists each MSI product twice, once from this action and once from the registry walk, with no de-duplication. If the enumeration does not complete, or a product property cannot be read for any reason other than the product not having it, the action reports a constrained status and the daily installed-software report is skipped for that cycle (nothing is deleted and the last good state is kept). A product with no name, for example one that is advertised but not installed, is not collected. Install location and uninstall string are not collected (#5186). The existing `list` and `product_codes` actions are unchanged apart from an exception guard; macOS and Linux report the action unsupported.
