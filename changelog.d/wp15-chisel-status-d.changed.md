- **The chiselled images (`yuzu-{server,gateway,agent}-chisel` and `yuzu-agent-bundle-chisel`) now carry their OS packages as dpkg `status.d` records, so Trivy, grype and the image SBOMs list them.** Each Dockerfile cuts `base-files_chisel` and runs `deploy/docker/chisel-emit-status.py`, which writes one record per cut package (name, version, architecture and the archive's source package, at package granularity: a slice is recorded as its whole package) and fails the build if a slice's package is missing from the chisel manifest, a package has no archive record at its exact version, or the written set differs from the manifest. The release image vulnerability gate treats a listed chisel image that shows OS packages as covered (it warns that the listing is stale) and refuses a fixable CRITICAL in them from Trivy or grype; unfixed MEDIUM and lower findings are reported, not gated. The four not-covered listings stay until their removal change (#8415). This supersedes the earlier note that cutting `base-files_chisel` would not help: the scanners do not read the chisel manifest itself, and the records are emitted from it.
