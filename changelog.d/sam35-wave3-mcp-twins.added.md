- **Nine MCP tools for the installed-software read model and the software collection settings.** `list_software_hosts`, `get_software_host`, `list_software_changes`, `get_software_summary` and `get_software_plugin_health` return field for field what `GET /api/v1/inventory/software/{hosts,hosts/{agent_id},changes,summary,plugin-health}` return, and `list_software_collection_settings`, `get_software_collection_settings`, `set_software_collection_settings` and `get_software_host_collection_settings` do the same for the per-group collection settings routes. Each pair calls one shared function, so agentic clients and the REST routes cannot drift; the reads apply the caller's management-group scope (a device outside it answers the same not-found as an unknown device, and a confined caller's summary and plugin health are computed live over its own devices, never the fleet snapshot). `set_software_collection_settings` is supervised-tier and approval-gated, writes a `requested` audit row ahead of the change (refusing the write when that row cannot be stored), re-checks the write grant immediately before the store call, and never triggers a collection. The tools refuse an unknown argument or an out-of-range value where the REST routes clamp. See the MCP reference.
