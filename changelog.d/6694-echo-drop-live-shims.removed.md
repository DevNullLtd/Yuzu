- **Breaking - the Echo compatibility surfaces for the retired raw capture tables and the old plugin name are removed.** A query over a `$<Source>_Live` name (for example `$Process_Live`) now fails with `error|unknown table: $Process_Live` instead of returning no rows with a `constrained` status; the empty `<source>_live` views are no longer created, and a stored query, schedule or result-set producer that still names one has to move to the tier views (`$<Source>_Hourly`). `echo.status` no longer prints `<source>_live_rows` (read `<source>_rows`), `retention_days`, `budget_evicted_raw_rows_total`, `usage_gap_count`, `usage_gap_lost_events`, `usage_gap_last_ts` or `usage_lag_events`, and `echo.configure` no longer accepts `retention_days` (it was stored and shown but never changed what is deleted; a request carrying only that key is refused with `error|no valid configuration parameters provided`). The server no longer treats an agent that reports the retired plugin name `tar` as an Echo agent: it is not mapped to `echo`, Echo dispatches to it are refused with `plugin_not_found`, its `yuzu.plugin.tar.*` heartbeat tags are not read as `yuzu.plugin.echo.*`, and the high-availability route directory no longer carries a plugin-name flag (the unused `legacy_echo_wire_name` column stays in the table). The Device page and the retention-paused list no longer show an agent note for `<source>_live_rows`; a source with no `<source>_rows` shows a dash. Server and agents must be the same build; the Echo manual and the upgrade guide are updated to say so.
