- **`local_security_policy` `lockout_policy` no longer returns an empty result on a Linux host with no lockout configured.** When every source that exists (`/etc/login.defs`, `/etc/security/faillock.conf` and the PAM files `common-auth`, `common-account`, `system-auth`, `password-auth`) is read and none sets a lockout key, the action now writes one `lockout_policy|lockout_keys|not_found|<files>` row (status OK); a host without `login.defs` or `faillock.conf` reports that source as `absent` instead. It reports what was found in those files, not that lockout is off or unenforced: `faillock.conf` drop-ins, PAM include/substack targets, other PAM services such as `sshd`, directory-server (IdM/SSSD) policy and `fail2ban` are not read, so do not treat the row as a control verdict. An older agent returns an empty result for the same host. (#5620)
- **`local_security_policy` reads PAM lines the way Linux-PAM does.** The type is matched case-insensitively (`AUTH required pam_faillock.so` is an `auth` line) and a module given with a directory path is reported by its file name only (the directory is not shown), so a `pam_faillock` or `pam_pwquality` configured either way is no longer missed by `lockout_policy` or `password_policy`. (#5620)
