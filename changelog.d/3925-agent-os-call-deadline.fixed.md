- **Windows OS reads that could hang the agent now have a deadline.** The share, account, session, volume-snapshot, domain-join and network-adapter reads behind `shares.list`, `users` (`logged_on`, `sessions`, `local_users`, `local_admins`, `group_members`), `filesystem_posture.snapshots`, `device_identity.domain`, `network_config` (`adapters`, `ip_addresses`, `dns_servers`) and Echo's user and mapped-drive sources now run in the agent core with a time limit (5 seconds; 10 for local accounts, 15 for volume snapshots). A hung Windows service no longer holds an agent worker: the action answers at the deadline with a constrained result that names the cause (`deadline_exceeded`, `abandoned_call_pending` or `call_in_progress`), later calls answer at once until the service recovers, and Echo skips that tick instead of recording a change. On Linux and macOS `users.local_users` stops starting per-account tools after 30 seconds and reports the remaining accounts with unknown fields (#3925). The `users.local_users` `enabled` column is now a string (`true`, `false`, `unknown`; it was a bool), and on macOS it reads `unknown` when the login-shell read fails or is cut off, where it used to read `true`. When Windows refuses to list logon sessions, `users.logged_on` and `users.sessions` now report a constrained result with the Windows error code, and Echo skips that tick, instead of reporting nobody logged on.
