- **The agent's HTTP clients no longer decode compressed responses.** The `http_client` and `content_dist` plugins (and the local IPP calls of `printing`) now turn off cpp-httplib's response decompression, so a server an operator points them at can no longer feed a Brotli or gzip decoder inside the agent process, which runs as root or SYSTEM. Behaviour change: `http_client` `download` and `content_dist` `stage` store and hash exactly the bytes the peer sent, so a download whose server answers with `Content-Encoding: br` or `gzip` is the compressed file, not the decoded one (the `sha256` you supply must be that of the compressed bytes); `http_client` `get` and `head` now ask for `identity` and return an undecoded body if the peer compresses regardless.
