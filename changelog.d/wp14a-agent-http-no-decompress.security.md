- **The agent's HTTP clients do not decode compressed responses.** The `http_client` and `content_dist` plugins (and the local IPP calls of `printing`) turn off cpp-httplib's response decompression, so a server an operator points them at cannot feed a Brotli or gzip decoder inside the long-lived agent process, which holds elevated rights on some platforms (root on macOS, LocalSystem on Windows). `http_client` `download` and `content_dist` `stage` hash and store exactly the bytes the peer sends, so a pinned `sha256` is the hash of the bytes on the wire (`curl -s URL | sha256sum`, without `--compressed`). `http_client` `get` asks for identity encoding and answers `error|peer sent Content-Encoding <token>; body not decoded` if the peer compresses anyway, and refuses a body containing NUL or control bytes; `head` keeps httplib's default `Accept-Encoding` and never decodes.
