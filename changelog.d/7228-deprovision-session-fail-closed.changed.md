- **Breaking: a deprovision whose API-token revoke or durable session delete does not persist now answers `500` and leaves the account active (#4772).** This covers SCIM `PATCH`/`PUT` with `active:false`, SCIM `DELETE` of an active resource and the dashboard user delete. The SCIM resource and identity links are untouched; credentials whose revoke did persist stay revoked. The body is `failed to revoke <API tokens | sessions | API tokens and sessions> for one or more linked identities`, and the audit row is `partial` with `api_tokens_db_error=true` and/or `sessions_db_error=true`. A retry after PostgreSQL recovers completes the deprovision; there is no break-glass, so a connector that treats `5xx` as permanent needs attention. SCIM `POST /Users` with `active:false` is the exception: its token leg fails closed, the retry meets `409` (reconcile with `GET` and `PATCH`), and a failed session delete there is recorded with `session_leg_backstopped=true`; the call succeeds only if the account removal's own wipe persisted. See `docs/user-manual/upgrading.md` and `docs/user-manual/scim-provisioning.md`.
