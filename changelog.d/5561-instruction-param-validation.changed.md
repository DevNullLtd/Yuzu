- **Breaking - `POST /api/instructions/{id}/execute` now validates `params` against the definition's stored parameter schema and answers a strict `400` (`invalid params: <path>: <reason>`) before the approval gate, any approval ticket, the execution row and dispatch; a stored schema that cannot be prepared fails closed with `500`.** Undeclared names, wrong types, values outside `enum`, `pattern`, `minimum`, `maximum` or length bounds, missing required parameters, embedded NULs and a non-object `params` are refused, and `""` or `null` are no longer read as omissions for an optional integer, enum or pattern parameter. A definition that stores no schema (empty, whitespace or `{}`) is not validated, and the other dispatch surfaces (MCP `execute_instruction`, `/api/command`, schedules, workflows) do not validate yet. A schema is also checked when it is written (`POST /api/instructions/import` returns `400` for an invalid or over-262144-byte `parameter_schema`), and saving a definition through the YAML editor, `PUT` or response templates now keeps its stored schema instead of replacing it with `{}`. Six shipped definitions that under-declared what their plugin reads are corrected (`agent.content_dist.cleanup`, `agent.content_dist.execute_staged`, `device.wol.check`, `device.agent_actions.set_log_level`, `workflow.config_search_and_replace`, `workflow.version_compliance_check`); existing installs keep the stored schemas they have, and replacing one is the documented export, delete and re-import procedure. `agent.content_dist.cleanup` also bounds `hours` to 876000 in the plugin itself (a very large value overflowed the cutoff arithmetic on Linux and removed every staged file), and cleanup now leaves a file whose age it cannot read. New counter `yuzu_server_instruction_param_rejected_total{route,reason}` and `instruction.execute` audit rows record each refusal.
