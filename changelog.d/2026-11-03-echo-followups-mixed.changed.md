- **Breaking - the Echo rename migration refuses to start the server on a definition-id collision.** When a legacy `crossplatform.tar.*` definition id cannot be renamed because the Echo-named id already exists, `instruction_store` v3 aborts, the store does not open and the server refuses to start, instead of leaving dependent stores pointing at the wrong definition. Only a database carried forward from an earlier build can hit this; the plugin-configuration and response stores have already migrated by then, so the older build must not be run against that database. See "Definition id collision" in `docs/user-manual/upgrading.md` for the runbook.
- **Breaking - the agent refuses to adopt a legacy `tar.db` beside an `echo.db` log it cannot prove is its own.** The agent now writes an adoption-intent marker before moving a `tar.db` sidecar; a resume with an `echo.db-wal`, `-shm` or `-journal` present and no marker matching `tar.db` (an adoption interrupted by an older agent build, or on Windows a power loss right after the first move) refuses, names both files and moves nothing, and Echo does not start until the sidecar is copied aside and moved out. See "Three cases the agent refuses" in `docs/user-manual/upgrading.md`.
