- **Software inventory store accepts the extended software row.** `installed_software` gains `install_location`, `uninstall_string`, `package_id` and `source` (the plugin action that produced the row) plus a row id for keyset paging (migration v7, additive). The ingest seam parses 16-field blob records while 4- and 12-field records from older agents still parse; the server-side canonical hash covers the new fields only when present, so existing agents keep hash-skipping. The store query gains a case-insensitive `q` filter over name, publisher, ecosystem and source, exact `kind`/`ecosystem`/`source` filters and a keyset cursor (store-level only; no REST/UI change in this release). Deploy the server before any agent that emits the new fields. On first start after upgrade the migration rewrites `installed_software` under an exclusive lock, in time that grows with its row count (about 10-20 s at 4M rows); start one server replica first and let it finish before starting the rest, and above about 2 million rows stop every replica before starting that one (see the Upgrading note in the inventory manual). A server whose database is missing a column the software store queries now refuses to start with a clear log line instead of failing on the first request.
