- **Enrollment auto-approve rules are validated before they are saved, fail closed, and every rule change is audited before it is applied.** The four dashboard rule writes (add, mode, enable/disable, remove) now write an `attempt` audit row first and refuse the write with `503` (`Sec-Audit-Failed: true`) when that row cannot be stored, so an audit-store outage can no longer leave a live enrollment-policy change with no record; a success or error row follows. They also refuse a request whose `Origin`/`Referer` names another site (`403`), return the standard JSON error body on `400`/`500`/`503`, and put caller text in the audit detail only after tokenising it. The rule form rejects an unknown type (it used to fall back to a hostname pattern), an empty value, any `:`, carriage return, line feed or control character, a value over 253 or a label over 128 characters, a malformed `ip_subnet` (an IPv4 address with an optional `/0-32` prefix), a `trusted_ca` that is not a 64-character hex fingerprint, and the two match-everything forms (a hostname glob of only `*` and an `ip_subnet` of `/0`). A CIDR rule with a malformed prefix is a non-match and no longer raises while an agent registers. The policy file is now written to a temporary file and renamed into place, a failed write changes nothing and is reported (`500`), and on start a policy file with any malformed line (an unknown type, a short line, or a `mode:` other than exactly `any` or `all`) activates no rules and is kept as `auto-approve.cfg.rejected` instead of being partly loaded. The mode setting accepts only `any` or `all`. Rule changes write `enrollment.auto_approve.rule_add`, `.rule_remove`, `.rule_toggle` and `.mode` audit rows. The device-management guide now states that `hostname_glob` and `cloud_provider` rules match values the agent asserts about itself.
