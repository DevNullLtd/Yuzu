- **Enrollment auto-approve rules are now validated before they are saved, fail closed when evaluated, and every rule change is audited.** The dashboard rule form rejects an unknown rule type (it used to fall back to a hostname pattern), an empty value, any `:`, carriage return, line feed or control character in the value or label, a malformed `ip_subnet` (an IPv4 address with an optional `/0-32` prefix) and a `trusted_ca` that is not a 64-character hex fingerprint; a rejected rule is not saved. A rule whose CIDR prefix is malformed or out of range is treated as a non-match and can no longer raise an exception while an agent registers; a saved rule line with an unknown type is ignored on load. The mode setting accepts only `any` or `all`. Rule add, remove, enable/disable and mode changes now write `enrollment.auto_approve.rule_add`, `.rule_remove`, `.rule_toggle` and `.mode` audit rows.
