- **During agent shutdown the wait on a locked `kv_store.db` is now 1 second instead of 5 (#5604); normal operation stays at 5 seconds.** It applies to every writer of that store while the agent is stopping (plugin actions and a plugin's `shutdown()`, the sync scheduler, the license scan), so a storage write made during shutdown can fail where the longer wait would have succeeded, and a plugin's last shutdown-time write may not persist. A failed shutdown write is logged: the legacy-sink loss ledger (the per-agent counters behind the `yuzu_fleet_guardian_legacy_sink_*` metrics) and, once Spark detection is enabled, both a Spark baseline capture that could not be written and lifecycle-journal records still unsaved when shutdown ends (a count only; those audit records are lost with the process). The legacy-sink loss counters may show their previous value after a restart when that final write failed. Once Spark detection is enabled, any drift between a lost baseline capture and the next start is accepted as the baseline, so after an exit code 4 on such an agent treat `file-hash-equals` Guardian rules without an authored `expected_hash` as possibly re-baselined. Retries against a locked store are also capped at 10 milliseconds apart instead of climbing to 100 milliseconds.
