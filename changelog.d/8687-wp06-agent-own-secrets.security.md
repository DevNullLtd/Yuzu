- **The filesystem plugin refuses the agent's own secrets.** `filesystem.read`, `search`, `get_acl`, `file_hash`, `exists`, `list_dir` (a reserved entry is left out of the listing) and the writes, and every entry a `search_dir` or `find_by_hash` walk visits, refuse the agent's data directory (the default one when none is configured), certificate directory, log file, TLS CA, client certificate and key, enrollment token file, plugin allowlist, plugin trust bundle and update trust bundle, on Linux the agent's own `/proc/<pid>/` tree and fifteen named entries of any process, and on Linux and macOS `/dev/fd/N`, `/dev/stdin`, `/dev/stdout` and `/dev/stderr` (the agent's own open descriptors) (`environ`, `mem`, `maps`, `smaps`, `smaps_rollup`, `cmdline`, `fd`, `fdinfo`, `auxv`, `stack`, `syscall`, `mountinfo`, `cwd`, `root`, `exe`). The decision is by file identity (a hard link, `..` path or case alias is the same object), and any stat error other than "no such file" on a reserved object, one of its entries or an ancestor refuses, so a reserved tree this process cannot fully inspect (an unreadable or unsearchable directory or parent) refuses every multi-link file rather than reading as "not reserved". A write to a name that does not exist yet is refused when it is a symlink, a Windows junction or any Windows reparse-point leaf; the Windows junction refusal has not been executed on a Windows host by this change. It is a best-effort guard against a writer who controls a parent directory, `create_temp` and `create_temp_dir` refuse a `prefix` or `suffix` that holds a path separator (or, on Windows, a colon), and a client certificate, key or install CA found by auto-discovery is refused like a configured one (Windows certificate-store material has no file and is not covered). Not verified: Windows Volume Shadow Copy paths and macOS case, normalization and firmlink aliases.
