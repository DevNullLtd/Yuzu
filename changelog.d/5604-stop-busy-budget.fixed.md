- **Agent shutdown no longer runs past its 20-second deadline when another process holds the agent's local `kv_store.db` locked (#5604).** Each shutdown write used to wait the full 5 seconds for the lock and the shutdown makes several in a row, so the agent's own shutdown watchdog could end it (exit code 4, no log line) and a Guardian baseline capture that was still waiting to be written was lost. During shutdown the wait is now 1 second, and lowering it also cuts a write that is already waiting. Measured with the store locked throughout (Linux, one run per point, two for the journal rows): shutdowns that took 21 to 29 seconds on earlier code took 2.0 to 6.0 seconds, the top figures from a row that emulates one of the writes. A stalled disk write is not a lock wait and can still reach the watchdog. The Spark baseline and lifecycle-journal benefits apply only once Spark detection is enabled (it is off in every released agent today); the shorter shutdown wait itself is in effect now.
