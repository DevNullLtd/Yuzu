- **Echo holds `echo.db` to a configurable byte budget and writes far fewer raw capture rows.** The new `db_budget_bytes` setting (default 250 MB, minimum 32 MiB) caps used pages plus the write-ahead log; when the database is over it, the maintenance pass removes the oldest raw capture rows already summarised into hourly rows (never the newest 24 hours), then hourly rows older than 48 hours, and never daily or monthly rows or a paused source. `status` reports `db_budget_bytes`, `budget_over_bytes`, the two eviction totals and `db_auto_vacuum`; `db_size_bytes` is now used pages plus the log. A database created by an earlier version is converted to incremental auto-vacuum with one `VACUUM` once it is under budget and the volume has twice its size free. Raw capture rows are cut at the source: a TCP socket first seen already closing is recorded once per hour per process and remote, module loads are stored once per hour per loader, module and folder (unloads are not stored, risky loads always are), registry values are capped at 512 bytes with the old value no longer stored and the `bam` State subtree excluded, and `echo_state` is rewritten only when a baseline changes. Windows module signing now looks catalog-signed system files up in the system catalogs instead of reading them as unsigned. `logon_type` on Linux and macOS follows `ut_host` rather than the tty name. A Linux agent no longer aborts when a process exits while its `/proc` entry is being read.
