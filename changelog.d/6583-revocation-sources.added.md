- **Registered CRL sources (administrators only).** `POST /api/v1/crypto/revocation-sources` and the MCP tool `register_revocation_source` register a certificate authority (1 to 8 PEM CA certificates of one subject) and the CRL URLs the server may fetch for it; `GET` (list, detail), `PUT` (replace), `DELETE` and `POST .../reset-high-water` (clear the CA's anti-rollback marks) complete the surface, with MCP twins `list_revocation_sources`, `get_revocation_source`, `update_revocation_source`, `remove_revocation_source` and `reset_revocation_source_high_water`. The host of each URL is resolved at registration and refused, with no override, if it is loopback, link-local, cloud-metadata, unspecified, multicast, reserved or one of this server's own addresses; any other address class must be confirmed in the request. This release registers sources only: nothing is fetched and no certificate is judged yet, and there is no outbound proxy, so a site whose only route out is a proxy cannot fetch CRLs yet. The surface is admin-only in both RBAC states and **not grantable** (the new `RevocationSource` securable is seeded to Administrator only and every call also requires a durable Administrator role; `RevocationSource:Read` is in the authorization topology floor). The four mutations fail closed on audit (`crypto.revocation_source.*`), need MFA step-up on REST, and `RevocationSource:Write` joins the supervised MCP tier's approval list, so a supervised MCP token needs an approval ticket (an MCP-tier token is refused outright on the REST routes). `PUT` requires `expected_config_version` (REST and MCP) so a stale body cannot revert a newer configuration. The address check decodes NAT64 prefixes the operator declares (`--oidc-nat64-prefix`) and those the network advertises (RFC 7050); both come from ONE never-shrinking cache shared with the OIDC client, the network's prefixes can only tighten a verdict (a discovered unique-local prefix never turns a unique-local host public), and when a refresh fails the check applies everything learned earlier (audit `nat64=stale`, counter `nat64_discovery_stale`); if no lookup has ever answered, an IPv6 destination is a retryable 503 (60 s hint). **OIDC behaviour change:** the OIDC egress check now shares that cache and treats an NXDOMAIN/NODATA answer for `ipv4only.arpa` as an answer (no DNS64) rather than a failed lookup; its overflow is logged once, not per request. Residuals: a lying resolver can suppress discovery (declare `--oidc-nat64-prefix`), and a hostile answer with more than 64 prefixes freezes the set until restart (`yuzu_server_nat64_discovery_overflowed`). `register_revocation_source` and `update_revocation_source` are the first MCP tools annotated `openWorldHint: true`. The new `revocation_source_store` is in `/readyz`'s gating checks, and RBAC now seeds 39 securable types.
