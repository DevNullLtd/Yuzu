- **Add user, Remove user and Change role now refuse cross-site browser writes and fail closed on audit.** `POST /api/settings/users`, `DELETE /api/settings/users/{username}` and `POST /api/settings/users/{username}/role` refuse a cookie session whose `Origin` or `Referer` does not name this site (`403`), and the role change accepts only `application/json` (`415`). Each writes an `attempted` audit row before it changes anything; if that write fails the change is refused with `503` and `Sec-Audit-Failed`. The enforcement panel of the Users and roles page is no longer readable by a service-scoped API token, and the page refuses a session that has no username.
