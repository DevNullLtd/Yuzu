- **Kill-switch audit rows now carry the reason.** `plugin_config.kill_switch.set` (REST `PUT /api/v1/plugin-config/{plugin}/kill-switch` and MCP `set_plugin_kill_switch`) appends `, reason="<text>"` to the `attempted` and outcome rows when a reason was given (at most 512 bytes; a tab is flattened to a space and other control characters are refused; quote and backslash escaped). Previously the reason lived only on the current row and was overwritten by the next change, so the audit trail could not answer why a plugin was switched off.
- **Plugin signing and agent update panels: safer forms.** Uploading a trust bundle while one is loaded now asks for confirmation naming the certificate count and SHA-256 being replaced; saving the Require signed plugins flag while it is off asks first; the per-package rollout control is a required whole-number (0 to 100) text input prefilled with the current value (a blank value was previously read as 100), with no inline script; the package URLs are percent-encoded so a version containing `#`, `?` or `%` addresses the right package; the signing panel lists "first 16 of N" subjects when a bundle holds more than 16 certificates; and the Require hint no longer says it rejects unsigned plugins on agents (the flag is recorded here; each agent enforces its own `--plugin-require-signature`).
