- **Breaking - role names and management-group identifiers containing a control byte are refused.** MCP `unassign_rbac_role`, and the engine-role assign and unassign (REST `POST`/`DELETE /api/v1/engine-principals/{id}/roles` and the MCP `assign_engine_role`/`unassign_engine_role` twins), refuse a role name containing a NUL, other control byte (0x01-0x1F) or DEL: REST answers `400`, MCP answers invalid params (-32602), and the audit row is `result=denied` with the detail `invalid_role_name`. Any other role name is accepted unchanged, including one granted out of band. The management-group member and role routes (REST add, remove, assign and unassign, and the MCP `add_management_group_member` and `assign_management_group_role` tools) refuse a control byte in `agent_id`, `role_name`, `principal_id` or `principal_type` the same way, and the OTA package delete route (`DELETE /api/settings/updates/{platform}/{arch}/{version}`) refuses a control byte or invalid UTF-8 in the platform, arch or version with `400` (`invalid_package_field`). A deployment that holds a role, member, grant or OTA package created out of band with such a byte must remove it in SQL and re-create it under a clean name; see the upgrade note in `docs/user-manual/upgrading.md` for the queries that find them.
