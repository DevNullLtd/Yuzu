- **Breaking — `users.local_users` `enabled` is now a string, and a refused Windows session listing or an unanswered `users`, `device_identity.domain` or `network_config` read now fails the command.** `enabled` is `true`, `false` or `unknown` (it was a bool); on macOS it reads `unknown` when the login-shell read fails or is cut off, where it used to read `true`, so treat `unknown` as neither. When Windows refuses to list logon sessions, `users.logged_on` and `users.sessions` now fail (return code 1) with a constrained result instead of reporting nobody logged on; the Windows error code is in the agent log, and Echo skips that tick. A Windows read that misses its limit (5 seconds, per page for `shares.list`; 10 for the local account list; 15 for volume snapshots), even if it would later have succeeded, is reported constrained: `users`, `device_identity.domain` and `network_config` then fail the command, and `users.local_users`, `local_admins` and `group_members` write an `error` row, which is not an account or a member (in `local_users` its `enabled` field reads `unknown`). `shares` and `filesystem_posture` return 0. See `docs/user-manual/upgrading.md` (#3925).
