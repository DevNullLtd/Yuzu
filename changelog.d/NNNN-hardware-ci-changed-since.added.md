- **Delta pulls for the bulk device-CI read.** `GET /api/v1/hardware-ci` and MCP `list_hardware_ci_records` accept `changed_since` (epoch seconds) and return only the records whose content changed at or after it. Each row carries `changed_at`, stamped from the database clock only when `content_hash` changes (the daily sync that finds nothing new leaves it alone, unlike `last_seen`), and every page carries `next_changed_since`, the database clock minus 300 seconds, for the next pull. Delivery is at-least-once, so upsert by `agent_id` and run a periodic full walk as the backstop. A delta needs a global-read credential (a scope-confined caller is refused), and it carries no removal signal: confirm absence with `agent_id`. Migration v5 adds the column and an index; existing rows read as changed at migration time, so the first delta pull returns the fleet once. Put every replica on the new build before relying on delta pulls.
