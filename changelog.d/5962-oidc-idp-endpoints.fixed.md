- **Operator action — an IdP on loopback, RFC 1918, carrier-grade NAT or IPv6 unique-local addresses (or whose `jwks_uri`/`token_endpoint` are) now needs `--oidc-allow-private-networks` (env `YUZU_OIDC_ALLOW_PRIVATE_NETWORKS`), and link-local addresses and the listed cloud-metadata addresses are never allowed (Oracle Cloud's `192.0.0.192` lies in `192.0.0.0/24`, which the flag admits); use an `https` issuer outside a lab (an `http://` issuer on a non-loopback host puts the JWKS trust root and the client secret in the clear and now logs a warning; plain `http://` to a public address is refused outright, and `http://` to a private address with the flag set stays exposed to anyone on that network path); OIDC flags left configured but unused now become a live sign-in, and members of the `--oidc-admin-group` group can sign in as administrators, so review them before upgrading; there is no HTTP proxy on the discovery and JWKS path; a previously green Test Connection can now be red; a Settings save with a blank Redirect URI is now refused; an ID token that names a `kid` the IdP's key set does not hold (or whose `kid` is empty or not a string) is now refused instead of being checked against the first key, which breaks an IdP whose JWKS keys carry no `kid` while its tokens name one; signing keys are fetched afresh for every sign-in and never cached, so a key the IdP withdraws stops verifying at once, at the cost of one JWKS request per sign-in (it holds one HTTP worker of the pool shared with the dashboard and REST for up to about 10 s) and no sign-in while the JWKS endpoint is down (confirm the server can reach `jwks_uri`, that your IdP's rate limit for it covers your peak sign-in rate, and, under `--auth-mode=sso-only`, that a break-glass account is named); a Settings save no longer waits for sign-ins in progress (except when 16 replaced providers are each stuck in a token POST), and a sign-in whose exchange finishes after a save replaced the provider is refused (`sso_failed`, audit reason `provider_replaced`) rather than minted under the old admin group or issuer, and the callback checks again right after minting and deletes the session if a save intervened, so no usable session is created under the replaced configuration once the save has returned, though a session already live is not revoked and stays valid (end it with `DELETE /api/v1/sessions?username=oidc:<iss>#<sub>` or Settings > User Management > Revoke sessions) and a user who is mid-sign-in when a save lands must start again; the token POST still has no total time bound (#5983); a sign-in whose session cannot be stored now fails instead of reporting success; IdP host names must be ASCII (use the punycode form of an internationalized name); and the Windows token POST no longer follows redirects, so a token endpoint that answers 3xx fails the sign-in, and it refuses a URL whose host or port WinHTTP parses differently from the host and port the egress policy vetted.** The server resolves every OIDC request target itself, refuses addresses by class, and pins the connection to a permitted address (the Windows token POST is only pre-checked, and refuses an answer that mixes permitted and refused addresses); an IPv6 address inside a NAT64 prefix learned from RFC 7050 (`ipv4only.arpa`) or declared with the new `--oidc-nat64-prefix` is classified by the IPv4 address it embeds. **OIDC sign-in now works with IdPs whose endpoints are not the derived ones, and verifies ID tokens against the IdP's own JWKS (#5692).** The server pre-set the authorization and token endpoints from the issuer URL, which skipped OIDC discovery, so `jwks_uri` was never learned (every ID token failed signature verification) and an IdP such as Keycloak answered the sign-in redirect with an HTTP 404 (the authorization URL it does not serve). The three endpoints are now read from `{issuer}/.well-known/openid-configuration` on first use, with no fallback: the document's `issuer` must equal the configured issuer exactly and every endpoint must be an absolute URL on the issuer's scheme without a fragment (an existing query is kept, but an authorization endpoint query must not use the names of the OAuth request parameters Yuzu adds), otherwise the sign-in fails closed. The Settings "Test Connection" button applies the same validation and also fetches the JWKS. Discovery and JWKS requests are bounded (5 s per-operation timeouts and a total of twice that from the start of the request, covering connect and the response and the TLS handshake (measured on Linux, tested with a drip server on Windows); 256 KiB, no redirects; the token-exchange POST keeps per-operation timeouts only and caps its response at 256 KiB), endpoint URLs are length- and authority-checked, an issuer with a query or fragment is refused, and a sign-in that arrives while discovery is being fetched fails at once instead of waiting. The unused `exchange_script` plumbing is removed. See the upgrading guide: the server must now reach the issuer host at sign-in time.
