- **Header notifications bell.** Every shell page now carries a bell in the header that shows the unread notification count and a pop-over with the newest 10 notifications. Mark read and Dismiss each take a two-click inline confirm, because both remove the item for every operator and neither can be undone from the console. The bell uses the three existing `/api/notifications` routes and adds no route or permission: it appears only for callers the server already admits (with RBAC on, global Administrator and ITServiceOwner; with RBAC off, every signed-in user, read-only for non-admins), polls every 60 seconds while the tab is visible and the user has been active in the last five minutes, and stops for the page after a `401` or `403`. Notification text is placed with `textContent` only. Read and dismissed state is shared by all operators, and there is no retention, so a large fleet can show "99+".
