- **Breaking —** **Linux `services.set_start_mode` reads the unit's state back and fails if it does not match the requested mode.** After `systemctl enable|disable|mask` it runs `systemctl is-enabled` and returns an error unless the state is in a closed set for the requested mode (automatic: `enabled`, `static`, `indirect`, `alias`, `generated`; manual: `disabled`, `static`, `indirect`, `alias`, `generated`; disabled: `masked`; a `-runtime` state never matches because the verbs are persistent) or when the read-back command did not run, so a privileged helper that exits 0 without acting is not reported as success, and error text such as `not-found` is never accepted as a state. A successful call emits a `state|<state>` line, plus a `note|` line for `static`, `indirect`, `alias` and `generated` units, which cannot be enabled or disabled; for those four the result status is `CONSTRAINED`/`PARTIAL` (`services:start_mode_unchangeable`) while the exit code stays 0. A non-root agent with no root-owned `/usr/libexec/yuzu/yuzu-systemctl` answers `PERMISSION_DENIED` (`services:privilege_unavailable`); on the packaged unit (non-root, `NoNewPrivileges`) that is permanent.
