- **Breaking —** **Linux `services.set_start_mode` reads the unit's state back and fails if it does not match the requested mode.** After `systemctl enable|disable|mask` it runs `systemctl is-enabled` and returns an error unless the state is in a closed set for the requested mode (automatic: `enabled`, `static`, `indirect`, `alias`, `generated`; manual: `disabled`, `static`, `indirect`, `alias`, `generated`; disabled: `masked`; a `-runtime` state never matches because the verbs are persistent) or when the read-back command did not run, so a privileged helper that exits 0 without acting is not reported as success, and error text such as `not-found` is never accepted as a state. A successful call emits a `state|<state>` line, plus a `note|` line for `static`, `indirect`, `alias` and `generated` units, which cannot be enabled or disabled; for those four the result status is `CONSTRAINED`/`PARTIAL` (`services:start_mode_unchangeable`) while the exit code stays 0. `automatic` and `manual` run a best-effort `unmask` first, so a masked unit can be set back; if the change then fails, a unit that was found masked is masked again and the result carries a `note|remasked` line (`note|remask_failed` when that also fails). The privileged change itself goes through the root-owned `yuzu-svc-helper`; the readback is an unprivileged `systemctl is-enabled`.
