- **The activity-record feature is renamed Echo.** The agent plugin, API routes (`/api/v1/echo/...`), MCP tools (`list_echo_*`, `create_result_set_from_echo_query`), metrics (`yuzu_echo_*`), audit actions (`echo.*`), instruction ids (`crossplatform.echo.*`), heartbeat tags (`yuzu.plugin.echo.*`), enablement units, dashboard pages and documentation all carry the new name; the agent plugin is now `echo` (`echo.dll` / `echo.so` / `echo.dylib`). There are no aliases for the old names except while a fleet upgrades: an agent that still reports the old plugin name keeps receiving its commands. On first start the upgraded agent adopts its existing `tar.db` as `echo.db` (and its sidecar files) and renames its stored tables and key-value namespace; it refuses to create a new, empty `echo.db` beside an un-adopted `tar.db`. On first start the upgraded server migrates the stored references in definitions, schedules, executions, approvals, device tokens, policies, workflows, responses, plugin configuration, kill switches, enablement rules and persisted result sets; the one-off response-store update scales with the retained response history. Audit rows written before the rename keep their old action spelling and are matched by the new `echo.*` filters. Windows installers remove the old `tar.dll`. OpenAPI `operationId` values and tags change with the route names (see the operationId note in the upgrade guide).
