- **firewall plugin gains device containment.** New actions `quarantine`, `release`, `quarantine_status` and `quarantine_allow` on Windows (Windows Firewall rule group + profile default-block, every other enabled rule disabled for the duration and restored on release), Linux (own nftables table applied as one transaction, iptables fallback) and macOS (a pf sub-anchor that sorts ahead of Apple's own anchors and is never merged into the main ruleset, with a recorded pf enable token; release undoes the rules and the enable state, while the one-time pf state flush at apply is not restored). The allow set keeps the agent's control channel, DHCP, DNS to the configured resolvers and operator exceptions (address, prefix, port, protocol, direction); the agent verifies the control channel, and the block when given a probe target, and rolls a failed first apply back, re-applies containment at start so it survives a reboot (between boot and agent start the host is uncontained), repairs a macOS pf that another actor switched off, and completes an interrupted apply or release at start. A failed first apply writes its release intent before removing anything, so a crash during the undo never brings the failed containment back at boot; a Windows Firewall profile that is switched off, a Windows host whose firewall policy is Group Policy-managed, or an iptables host with no way to contain IPv6, is refused instead of reporting a containment that is not there; and a pf state flush that failed, a stale Windows rule that would not delete, or a rule the policy store would not disable keep the result partial. A time limit (`ttl_seconds`) is not available in this release and is refused (`refused|ttl_unavailable`). On Linux the packaged systemd unit (`NoNewPrivileges`, no sudoers grant) cannot run the privileged tool, so every mutating containment action is refused cleanly (`refused|privilege_unavailable`) before anything is written and Linux is marked constrained until the installer's sudoers grant is available to a unit without `NoNewPrivileges`; a host upgraded from an earlier agent keeps its old bare `nft` sudoers line until `scripts/install-agent-user.sh` is run again to narrow it. Containment covers the host's own IP traffic and the traffic it routes: L2-bridged guests, macvlan/ipvlan containers and Hyper-V external-switch guests are not contained. A kill switch, a per-OS withhold or a degraded plugin-config read refuses all four actions (a degraded read fails closed), so a contained host cannot be released remotely until the switch clears. The existing `quarantine` plugin is unchanged in this release.
