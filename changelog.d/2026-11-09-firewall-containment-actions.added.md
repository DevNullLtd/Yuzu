- **firewall plugin gains device containment.** New actions `quarantine`, `release`, `quarantine_status` and `quarantine_allow` on Windows (Windows Firewall rule group + profile default-block, pre-existing allow rules disabled for the duration and restored on release), Linux (own nftables table applied as one transaction, iptables fallback) and macOS (a pf sub-anchor that sorts ahead of Apple's own anchors and is never merged into the main ruleset, with a recorded pf enable token; release undoes the rules and the enable state, while the one-time pf state flush at apply is not restored). The allow set keeps the agent's control channel, DHCP, DNS to the configured resolvers and operator exceptions (address, prefix, port, protocol, direction); the agent verifies the block after applying and rolls back on failure, re-applies containment at start so it survives a reboot, repairs a macOS pf that another actor switched off, completes an interrupted apply or release at start, and accepts an optional time limit. A failed first apply writes its release intent before removing anything, so a crash during the undo never brings the failed containment back at boot; a Windows Firewall profile that is switched off, or an iptables host with no way to contain IPv6, is refused instead of reporting a containment that is not there; and a pf state flush that failed, a stale Windows rule that would not delete, or a time-limit trigger the agent could not register keep the result partial. The existing `quarantine` plugin is unchanged in this release.
