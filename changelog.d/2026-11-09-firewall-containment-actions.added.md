- **firewall plugin gains device containment.** New actions `quarantine`, `release`, `quarantine_status` and `quarantine_allow` on Windows (Windows Firewall rule group + profile default-block, every other enabled rule disabled for the duration and restored on release), Linux (own nftables table applied as one transaction, iptables fallback) and macOS (a pf sub-anchor that sorts ahead of Apple's own anchors and is never merged into the main ruleset, with a recorded pf enable token; release undoes the rules and the enable state, while the one-time pf state flush at apply is not restored). The allow set keeps the agent's control channel, DHCP, DNS to the configured resolvers and operator exceptions (address, prefix, port, protocol, direction); the agent verifies the control channel, and the block when given a probe target, and rolls a failed first apply back, re-applies containment at start so it survives a reboot (between boot and agent start the host is uncontained), repairs a macOS pf that another actor switched off, and completes an interrupted apply or release at start. A failed first apply writes its release intent before removing anything, so a crash during the undo never brings the failed containment back at boot; a Windows Firewall profile that is switched off, or an iptables host with no way to contain IPv6, is refused instead of reporting a containment that is not there; a Windows host where Group Policy or MDM controls any of the three firewall profiles is refused (`refused|gpo_override:<Profile>`) and nothing is changed, because a rule or default written locally takes no effect there (a profile counts when its policy sets a default action or stops local rules merging, so a policy that itself sets block and block is refused too; a host that acquires the policy during a quarantine reads `degraded|gpo_override`); a Windows release switches back on the rules the quarantine switched off, matching a rule someone edited in the meantime by name, direction and profile only when exactly one rule in total carries them: switched off, it is switched on (`note|rules_reenabled_by_identity=<n>`); already on, it is counted (`note|rules_accounted_enabled=<n>`) and otherwise completing as `partial|rules_unmatched` with the count in `note|rules_unmatched=<n>`, and a default action that will not restore names its profile (`note|policy_restore_failed=<Profile>`); and a pf state flush that failed, a stale Windows rule that would not delete, or a rule the policy store would not disable keep the result partial. An optional time limit (`ttl_seconds`) ends the containment unattended; it is measured on the host wall clock while the quarantine blocks NTP (a clock stepped back means it never fires and `quarantine_status` says so with `note|clock_before_apply=1`; one stepped forward releases early), and an expiry release is logged on the agent only (`firewall: release -> inactive ttl_expired=1`) and is not recorded on the server until the server-side change ships, so check `quarantine_status` after a limit passes. An agent-local self-check every 60 seconds re-applies the stored allow set of an active containment the host stopped enforcing (a flushed table, restored profile defaults, pf switched off) through the same mutation gate, logs every repair and shows it in `quarantine_status` (`note|repairs=<n>`); a repair also admits the agent's live control address when the stored set lacks it, and a repair whose proof fails is kept as `active_unproven` rather than reverted; it never acts on an unreadable record, over an operation in progress, or over a legacy containment. The control set follows the address the agent is connected through at quarantine time (published by the agent daemon from the stream the server answered on, never resolved on the contained host), and the verification connects to that address; a server re-addressed after containment still strands the host until a `release` reaches it. On Linux the packaged systemd unit (`NoNewPrivileges`, no sudoers grant) cannot run the privileged tool, so every mutating containment action is refused cleanly (`refused|privilege_unavailable`) before anything is written and Linux is marked constrained until the installer's sudoers grant is available to a unit without `NoNewPrivileges`; a host upgraded from an earlier agent keeps its old bare `nft` sudoers line until `scripts/install-agent-user.sh` is run again to narrow it. Containment covers the host's own IP traffic and the traffic it routes: L2-bridged guests, macvlan/ipvlan containers and Hyper-V external-switch guests are not contained. A kill switch, a per-OS withhold or a degraded plugin-config read refuses all four actions (a degraded read fails closed), so a contained host cannot be released remotely until the switch clears. The existing `quarantine` plugin is unchanged in this release.
