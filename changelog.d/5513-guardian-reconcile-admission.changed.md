- **Guardian heartbeat reconcile is now admission-controlled per server replica, and a degraded tag or property store now aborts it (behaviour change).** A push that exceeds the replica's time budget is shed (no push, no audit row, no use of the agent's 25 s slot; the agent retries on its next heartbeat), counted by `yuzu_server_guardian_reconciles_total{result="shed"}`, and the new `yuzu_server_guardian_reconcile_duration_seconds` histogram is the sizing input. Three new per-replica flags set the budget: `--guardian-reconcile-budget-ms-per-s` (default 500), `--guardian-reconcile-burst-ms` (default 1000) and `--guardian-reconcile-max-per-s` (default 1000). The policy generation is read through a short cache, rule sets are held per generation, and scope membership is evaluated for the one agent instead of across the fleet. **Behaviour change:** if the tag or property store cannot be read while evaluating a rule's scope, the reconcile now aborts (`result="degraded"` and an `ABORTED` audit row, nothing sent) where it previously treated the agent as out of scope and pushed a narrowed rule set that disarmed the rule. This does not by itself make the server handle 500,000 agents: per-heartbeat Postgres writes and gateway forwarding remain separate follow-ups.
