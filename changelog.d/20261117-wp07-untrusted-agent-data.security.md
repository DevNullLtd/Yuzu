- **Malformed agent-supplied data is handled per device instead of failing a whole pass or stream (WP07).** A policy check response with wrong JSON types, invalid UTF-8 or nesting past the depth guard now scores only that device `error` (counted in `yuzu_server_policy_unevaluable_responses_total{reason}`) instead of aborting the compliance collect pass for every other device; each target in the pass is its own failure domain. The Hardware action-result fragment no longer parses or pretty-prints agent JSON nested past the shared depth guard (it renders text), which closes a stack-exhaustion crash. The shared `/events` SSE framing treats a bare CR and CRLF like LF, so an embedded CR in agent output or a hostname can no longer forge SSE fields. On the agent: the agent daemon replaces non-UTF-8 bytes in plugin output with `?` before it is buffered (a bad byte previously made the server reject the whole command-response frame), the Linux process name and command line (and the macOS process name) are scrubbed at collection, and Echo identity strings (process, connection, service, user, ARP, DNS, mapped-drive and software) are scrubbed at collection while its state baselines are serialised without throwing. Not fixed here: filesystem plugin rows still carry raw non-UTF-8 path bytes upstream of the host scrub (#6480), and one collect leg's exception can still skip the later legs of an Echo fast tick (per-leg isolation is open). Old agents keep sending frames the server rejects until they are upgraded.
