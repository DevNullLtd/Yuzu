- **Malformed agent-supplied data is handled per device instead of failing a whole pass or stream (WP07).** A policy check response nested past the depth guard, or whose evaluation throws, scores only that device `error` (counted in `yuzu_server_policy_unevaluable_responses_total{reason}`) and the compliance collect pass carries on with every other device; each target in the pass is its own failure domain. The Hardware action-result fragment does not parse or pretty-print agent JSON nested past the shared depth guard (it renders text), which closes a stack-exhaustion crash. The shared `/events` SSE framing treats a bare CR and CRLF like LF, so an embedded CR in agent output or a hostname cannot forge SSE fields. On the agent: the agent daemon replaces non-UTF-8 bytes in plugin output with `?` before it is buffered, the Linux process name and command line (and the macOS process name) are scrubbed at collection, and Echo identity strings (process, connection, service, user, ARP, DNS, mapped-drive and software) are scrubbed at collection while its state baselines are serialised without throwing. Not fixed here: filesystem plugin rows still carry raw non-UTF-8 path bytes upstream of the host scrub (#6480), and one collect leg's exception can still skip the later legs of an Echo fast tick (per-leg isolation is open).
