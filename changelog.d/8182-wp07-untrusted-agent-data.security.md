- **Malformed agent-supplied data is handled per device, not by failing a whole pass or stream (WP07).** A policy check response nested past the depth guard, whose evaluation throws, or whose compliance expression fails to evaluate scores only that device `error` (counted in `yuzu_server_policy_unevaluable_responses_total{reason}`) and the compliance collect pass carries on with every other device; each target in the pass is its own failure domain. The Hardware action-result fragment does not parse or pretty-print agent JSON nested past the shared depth guard (it renders text), which closes a stack-exhaustion crash. The shared `/events` SSE framing treats a bare CR and CRLF like LF, so an embedded CR in agent output or a hostname cannot forge SSE fields. On the agent: the agent daemon replaces non-UTF-8 bytes in plugin output with `?` before it is buffered, the Linux process name and command line (and the macOS process name) are scrubbed at collection, and Echo identity strings in its snapshot-diff sources (process, connection, service, user, ARP, DNS, mapped-drive and software), in the fleet snapshot and in module-load rows (process name, module name and directory, signer) are scrubbed at collection, and its state baselines and snapshot are serialised without throwing. Echo's cursor-based sources (registry, removable media, power) are deliberately not scrubbed: they keep their own cursor codecs (replacing, or allowlisted values only), and removable-media events keep raw path bytes in `echo.db`. Also not scrubbed: the macOS nstat connection stream, the start-up and history backfills and the network-quality rows. Not covered: filesystem plugin rows carry raw non-UTF-8 path bytes upstream of the host scrub (#6480), and one collect leg's exception can skip the later legs of an Echo fast tick (per-leg isolation is open).
