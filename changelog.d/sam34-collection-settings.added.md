- **Software collection settings can be stored per management group, and the effective settings for a device can be read.** Each group holds one document: how often installed software is collected (1 hour to 7 days), an optional local-time window (only with a whole-day interval), a time zone, a switch per collector (registered apps collection cannot be turned off) and a priority. `PUT /api/v1/inventory/software/collection-settings/{group_id}` replaces a group's document, `GET` reads it, and `GET /api/v1/inventory/software/collection-settings` lists every document with the built-in default. Settings are managed by fleet administrators: a read needs the global `ManagementGroup:Read` grant and a write the global `ManagementGroup:Write` grant, checked again immediately ahead of the write; group-scoped delegation is not part of this build. A write names the version it replaces, a stale version is a `409` carrying the current document, the time zone is checked against the database's zone table, and every write is audited as `software_estate.collection_settings.update`. `GET /api/v1/inventory/software/hosts/{agent_id}/collection-settings` resolves the one document that applies to a device across all its groups (nearest group in a branch, priority between branches, the root group's document as the fleet default layer, kill switches always winning). This build sends no settings to agents: they take effect only when the settings push lands, and saving a document never starts a collection.
