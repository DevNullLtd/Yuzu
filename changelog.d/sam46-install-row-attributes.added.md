- **Installed-software rows can carry validated attributes, starting with the MSI `upgrade_code`.** Wire slot 14 of the blob-v3 install row, reserved and always empty until now, is a `key=value` attribute field (pairs joined by `;`, keys ascending, each once, at most 1,024 bytes), defined once in `common/include/yuzu/install_row_attributes.hpp` and included by both the agent and the server. The server stores it in a new `installed_software.attributes` column (schema v13, a constant-default `ADD COLUMN`, so metadata-only) and covers it in the section hash; a row with no attributes hashes to the same bytes as before, so no stored section hash moves and no agent resends. A section whose slot 14 is not already canonical is refused with the new reason `bad_attributes`; the agent drops a value it cannot validate before sending. The `msi_packages.list_inventory` adapter accepts an optional sixth token, the product's UpgradeCode, and records a braced GUID as `upgrade_code={UPPER-CASE}`. The field is stored only: no REST route, MCP tool or page returns it yet, and an attribute-only change at the same version writes no change-feed entry. The `uninstall_string` reservation of #5186 is withdrawn (ADR-0016 Update 2026-11-21).
