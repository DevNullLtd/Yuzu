- **`cancel_execution` needs no approval ticket at the supervised MCP tier; the new instruction execute route caps pending approvals per principal.** `cancel_execution` is the one MCP tool on a closed approval-exempt list (`kApprovalExemptTools` in `mcp_policy.hpp`): it only marks a tracker record cancelled, starts no work and stops nothing on a device, and it still writes an `attempted` audit row first. The exemption is MCP only: `POST /api/v1/executions/{id}/cancel` still refuses a supervised-tier token with `403`, and `record_execution_rerun` and `execute_instruction_definition` stay approval-gated at that tier. Separately, `POST /api/v1/instructions/{id}/execute` refuses a principal that already holds about 25 pending approvals with `429` (`approval_cap_reached`), the same per-principal soft bound the MCP tools apply, so one looping client cannot spend the shared approval queue; the check reads the count and then submits, so concurrent requests can briefly exceed it, and the legacy `POST /api/instructions/{id}/execute` does not apply it.
