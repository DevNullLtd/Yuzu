- **`/test --instructions` runner can drive Destructive and Forensics definitions at one chosen agent.** `scripts/test/instructions_runner.py` gains `--target-agent-id`, `--confirm-target` (the agent's hostname, checked against `GET /api/agents` before anything is sent), `--manifest` and `--allow-remote`, and those classes now require the existing `--params-override` and `--run-id`. They are opt-in, run one at a time against exactly one agent on a loopback dashboard (unless `--allow-remote`), and only with an explicit parameter entry per definition. Every dispatch is written to a manifest (created exclusively, never reused) before it is sent. Only a 4xx, a 503 with a known pre-dispatch reason, a pending-approval 202 or a refused connection mean "not executed"; anything else ends the run as `dispatch_unknown`, including the generic 503 "no agents reached". Ctrl-C, Ctrl-Break (Windows) and SIGTERM stop dispatching and exit 130. A run without those classes (the `/test` default) sends the same requests as before, but the runner is stricter for every run: proxy environment variables are ignored, a redirect on the execute POST is not followed, a malformed `--params-override`, an invalid `--run-id` or a `--dashboard` with userinfo exits 2, and `--output` refuses a symlink or a multi-link file. See `/test` SKILL.md, "`--instructions` mode".
