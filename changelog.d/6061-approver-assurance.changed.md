- **Breaking: approving or rejecting an approval request now needs an interactive session and a fresh MFA step-up; MCP can no longer approve (#6061).** `POST /api/approvals/{id}/approve`, `POST /api/approvals/{id}/reject`, the dashboard Approvals page and the MCP tools `approve_request` / `reject_request` now require an interactive cookie session (local or OIDC), a fresh MFA step-up, a human principal and not an engine principal; the reviewer-is-not-the-submitter rule is unchanged. API-token and MCP bearer sessions are refused with a typed `403` (A4 envelope). Every MCP session is bearer-authenticated, so `approve_request` / `reject_request` now always return the typed refusal (an exception recorded in ADR-1005's exception ledger, entry 2026-10-18: human review is a human-session act); the tools stay registered and listing pending approvals through MCP is unchanged. **Automation that approved over MCP or with an API token will fail, and SAML users cannot approve while MFA step-up is on** (SAML sessions can never pass step-up, #4935). "Fresh MFA step-up" is the existing step-up gate, which can only ask for a factor the account has: a local account that never enrolled in MFA, an OIDC session whose identity provider asserted no `amr` proof under the default `--mfa-enforcement=optional`, and any session when `--mfa-step-up-window-secs=0` all pass it, so approval is not guaranteed to be backed by a second factor. A requirement that the approver holds an enrolled factor is tracked in #6079. With `--mfa-step-up-window-secs=0` the assurance drops to an interactive session only; alert on `approval.approve` audit rows if you run that way. Also: an unresolvable session now fails closed with `503` and the ticket stays pending, where it used to record the reviewer `unknown` (#4128); the approval attempt is audited before the decision is applied, and approve/reject return `503` with nothing changed when that audit row cannot be written (#5823; cancel is unchanged); the MCP tier/permission mapping for the two tools is `Approval:Approve` (it was `Approval:Write`, #3151); and an approved ticket not consumed within 7 days of its review is refused at consume using database time, even if no new submit has swept expiry. See `docs/user-manual/instructions.md` "Who can approve" and `docs/user-manual/upgrading.md`.
