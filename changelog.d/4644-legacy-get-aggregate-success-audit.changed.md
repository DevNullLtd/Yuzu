- **Breaking: the legacy `GET /api/responses/{id}` and `GET /api/responses/{id}/aggregate` write fail-closed audit rows, like the legacy export and their v1 twins (#4644).**
  A global (unscoped) caller left no audit row at all on either route, and a scoped caller left only the scope-drop `denied` row. Each now emits `response.read` with `result=success`, `target_type=Execution`, `target_id=<instruction_id>` and `detail=legacy response query cid=<correlation_id>` (get) or `detail=legacy response aggregate cid=<correlation_id>` (aggregate) on every served read, after the store read and before the body is built, using the same verb as the v1 routes so the twins are countable together. Both routes are now fail-closed: when the success row, or the scope-drop `denied` row, cannot be persisted, or the audit pipeline throws, the route answers `503` (A4 envelope, `retry_after_ms: 5000`, `Sec-Audit-Failed: true`) and serves no data. Before this, both routes answered `200` with the data even when the audit write failed. Scripted consumers must retry on `503`.
