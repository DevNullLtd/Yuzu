- **On Windows, every cpp-httplib HTTPS client that keeps default trust now relies on the Windows certificate store (Schannel) as the sole chain verifier, and Windows is asked for the `serverAuth` usage along the chain.** cpp-httplib 0.37.1 requested no usage and required both OpenSSL and Schannel to accept the certificate chain; 0.59.0 no longer consults the OpenSSL chain verdict whenever Schannel verification is on. That is the case unless the client sets its own CA file, directory, PEM or store, turns system-CA trust off, disables Windows verification, or installs a server certificate verifier. Yuzu's clients that keep the default are the agent plugins `http_client` and `content_dist` and, on a Windows server, the OIDC discovery and JWKS fetches (when TLS verification is not skipped), webhook delivery, analytics sinks, offload targets and the NVD client. The OIDC token exchange and directory sync use WinHTTP on Windows and are unchanged, as is the healthcheck probe, which loads its own trust anchor. Two effects follow: a chain that Windows accepts is now accepted even where OpenSSL would have refused it (and 0.59.0 gives Windows the certificates the server presented, where 0.37.1 offered only the leaf), and a root that Windows trusts only for purposes other than `serverAuth` is now refused. Whether a chain is refused depends on what Windows can build a chain to (Windows may fetch missing roots and intermediates on demand); manage trust with `certlm.msc` or group policy, and install a root in the machine store, since a root in one user's store is not necessarily trusted by a service under another account. An agent-side refusal reads `connection failed` (`http_client` `get` and `head`), `download failed: HTTP connection error` (`http_client` `download`, `content_dist` download) or `failed to open upload session (HTTP 0)` (`content_dist` upload, which retries with backoff before it reports), the text each gives for any request with no response, with no certificate detail; before upgrading, run `certutil -verify -urlfetch <certificate file>` on the Windows host against the chain each target presents (not confirmed to test the `serverAuth` usage, so a clean result does not rule out the new refusal). Revocation checking is unchanged from 0.37.1 (an end-certificate check), and `content_dist` artifacts are still hash-verified.
