- **Four privileged REST routes now refuse a cross-site browser write.** `PUT /api/v1/rbac/enforcement`, `POST /api/v1/rbac/roles/{name}/assignments`, `DELETE /api/v1/rbac/roles/{name}/assignments/{principal_id}` and `POST /api/v1/guaranteed-state/push` answer `403` `cross-site request refused` and write a `csrf.denied` audit row when a session-cookie call carries no `Origin` or `Referer`, or one naming another site (an entry from `--csrf-trusted-origin` is accepted). The check runs after the authorization gates and MFA step-up and before the body is read, the same rule the password, response-template and policy-generation raise routes already apply. This is a behaviour change: a script that signs in with a cookie and calls one of these routes without an `Origin` or `Referer` header now gets `403`. Use an API token, or send an `Origin` matching the dashboard origin. API, MCP and engine token callers are not affected.
