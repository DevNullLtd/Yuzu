- **Registering a CRL source no longer reports a committed registration as a failure.** The new source is read back inside the registration's own transaction instead of on a second database connection afterwards, so a slow pool after the commit can no longer turn a successful `POST /api/v1/crypto/revocation-sources` (or MCP `register_revocation_source`) into a `503` whose audit row says `failure` with no source id. A connection lost during the commit itself still answers `503` with an unknown outcome (read the sources to check), as before.
