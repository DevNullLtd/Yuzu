- **Breaking —** **The dev/UAT installer (`install-agent-user.sh`, Linux) sets no file capability on the agent binary and strips any it finds.** A file capability such as `cap_net_admin,cap_net_raw,cap_dac_read_search,cap_sys_ptrace` on a 0755 binary whose invoker chooses the plugin directory it loads would let any local account on a multi-user dev host obtain it. On every run the installer checks the binary and runs `setcap -r` when it carries a file capability or `getcap` cannot verify it, exits 5 when a capability may still be live (after the helper and sudoers steps), and, when a binary exists at the path, treats a present capability or a missing `getcap` as `--check` drift; `--no-cap-cleanup` skips the strip and says so. `start-UAT.sh --as-user` refuses a binary that still carries one and grants `cap_dac_read_search` ambiently with `setpriv`. The installer and capability changes do not touch the packaged unit (it has neither); the separate `/proc` status change does. See the WP13 section of `docs/user-manual/upgrading.md`.
