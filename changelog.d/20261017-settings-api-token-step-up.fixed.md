- **Dashboard API-token create and revoke now match the REST token routes.** `POST /api/settings/api-tokens` and `DELETE /api/settings/api-tokens/{id}` require a current MFA proof from the signed-in session, exactly as `POST /api/v1/tokens` and `DELETE /api/v1/tokens/{id}` do. Creating an MCP-tier token with no TTL, or a TTL over 90 days, is now refused as an input error instead of being reported as a CSPRNG failure (which returned 503, raised `yuzu_secure_random_failure_total` and wrote a false `csprng_unavailable` audit row). The create audit row now records the granted tier. The dashboard Settings page cannot yet prompt for the MFA code itself: an operator whose proof has expired must sign in again before creating or revoking a token there.
