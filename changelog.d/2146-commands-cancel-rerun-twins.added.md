- **`POST /api/v1/commands`, `POST /api/v1/executions/{id}/cancel` and `.../rerun`, and the MCP tools `cancel_execution` and `record_execution_rerun`.** `POST /api/v1/commands` is the REST v1 twin of `POST /api/command` and of the MCP `execute_instruction`: it applies the same targeting-shape check, Destructive and Forensics gates and management-group confinement, creates an execution row and returns its `execution_id`, writes a `requested` audit row before anything is sent and refuses with `503` (nothing dispatched) when that row cannot be stored, and answers a command that reaches no agent as a typed error (`invalid_scope`, `quarantined`, `plugin_not_found`, `kill_switched_os`, `containment_unreadable`, `route_unreadable`, `os_gate_unreadable`, `no_agents_reached`) with an honest `retry_after_ms`. The cancel and rerun twins share one admit, audit, change, audit sequence with the legacy routes: cancel only marks the tracker record cancelled and rerun only creates a `pending` record linked through `rerun_of`; neither sends anything to a device (the rerun body says `dispatched_to_devices: false`). Each publishes the same platform event as its legacy route once, on success. The audit log gains the result values `requested` and `pending`, and `metrics.md` documents two new counters, `yuzu_server_approval_submit_refused_total` and `yuzu_server_event_emit_failed_total`.
