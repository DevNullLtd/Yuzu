- **`GET /api/v1/execution-statistics/agents` and MCP `get_execution_statistics_by_agent` are now management-group confined (#3526).**
  Both gated on a bare `Execution:Read` check, which admits only a holder of a global grant, and returned one row per agent across every execution with no per-agent filter. A management-group-scoped-only operator was refused with `403`. They now gate solely on the fleet-read chokepoint (ADR-0017 admit-then-filter, the same primitive as `GET /api/v1/executions` and MCP `list_executions`), and the visible-agent set is applied in SQL before the grouping and the limit. A scoped-only operator goes from `403` to a `200` with only the agents it can see, a global grant is unchanged, and an empty visible set returns no rows, never the fleet. On REST, a service-scoped token goes from `403` to the confined view when RBAC enforcement is on, subject to the `ITServiceOwner` authority ceiling (the seeded role holds `Execution:Read`) and then the token's service tag scope, a degraded tag store answering `503`; on MCP the tool stays denied to a service-scoped token. **Confinement is effective only with RBAC enforcement on:** with RBAC off (the shipped default) the rollup is unfiltered for every authenticated caller other than a service-scoped token or an engine principal, and a service-scoped token is refused with `403`. REST also rejects a negative `since` with `400`, matching the MCP twin. `GET /api/v1/execution-statistics/definitions`, the fleet summary and MCP `get_execution_statistics_by_definition` carry no agent identity and are unchanged.
