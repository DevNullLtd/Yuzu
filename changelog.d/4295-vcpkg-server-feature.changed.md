- **`vcpkg.json` splits server-only dependencies into a `server` feature, so agent-only builds stop compiling them (#4295).** The base manifest now lists only what the agent links (grpc, protobuf, abseil, spdlog, nlohmann-json, cli11, cpp-httplib, sqlite3, openssl, libxml2); libpq, xmlsec, zlib and drogon move to `server` (zlib is declared there but still arrives through grpc), catch2 to `tests`, and an empty `agent` placeholder is declared. `default-features` is `["server", "tests"]`, so every existing `vcpkg install --x-manifest-root=.` resolves the same package set as before (checked with `vcpkg install --dry-run` on arm64-osx and x64-linux; x64-windows could not be planned on the authoring host). `Dockerfile.agent` and `Dockerfile.agent.chisel` now pass `--x-no-default-features`: on `x64-linux` that is 23 → 16 target ports (no libpq PostgreSQL source build, no drogon/trantor/jsoncpp). Developers building only the agent can do the same; `-Dbuild_tests=true` additionally needs `--x-feature=tests`. See `docs/build-guide.md` "Dependency features".
