- **`vcpkg.json` splits server-only dependencies into a `server` feature, so agent-only builds stop compiling them (#4295).** The base manifest now lists only what the agent links (grpc, protobuf, abseil, spdlog, nlohmann-json, cli11, cpp-httplib, sqlite3, openssl, libxml2); libpq, xmlsec, zlib and drogon move to `server`, catch2 to `tests`, and an empty `agent` placeholder is declared. `default-features` is `["server", "tests"]`, so every existing `vcpkg install --x-manifest-root=.` resolves the same package set as before. `Dockerfile.agent` and `Dockerfile.agent.chisel` now pass `--x-no-default-features`: on `x64-linux` that is 23 → 16 target ports (no libpq PostgreSQL source build, no drogon/trantor/jsoncpp). Developers building only the agent can do the same; `-Dbuild_tests=true` additionally needs `--x-feature=tests`. `scripts/ci/vcpkg-triplet-sentinel.sh` gains an optional `[profile]` argument that is hashed into the cache key, so an agent-only and a full install of one triplet can no longer be mistaken for each other; omitting it keeps every existing key's inputs unchanged.
