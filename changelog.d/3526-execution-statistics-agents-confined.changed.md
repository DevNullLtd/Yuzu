- **Breaking: `GET /api/v1/execution-statistics/agents` and MCP `get_execution_statistics_by_agent` are now management-group confined (#3526).**
  Both returned one row per agent across every execution behind a bare `Execution:Read` check, so a caller holding the flat permission saw every agent's execution counts, success rate and last execution time with no per-agent filter. They now gate solely on the fleet-read chokepoint (ADR-0017 admit-then-filter, the same primitive as `GET /api/v1/executions` and MCP `list_executions`) and the visible-agent set is applied in SQL before the grouping and the limit, so a confined caller sees only the agents it can see (a global grant is unchanged, and an empty visible set returns no rows, never the fleet). On REST, a service-scoped token now gets the chokepoint's confined view where the bare gate refused it outright; on MCP the tool stays denied to a service-scoped token. REST also rejects a negative `since` with `400`, matching the MCP twin. `GET /api/v1/execution-statistics/definitions`, the fleet summary and MCP `get_execution_statistics_by_definition` return definition-level and fleet-level aggregates with no agent identity and are unchanged. Two behaviour changes follow for callers: a management-group-confined operator now sees fewer rows (only its visible agents), and on REST a service-scoped API token, which the bare gate refused with `403`, is now admitted as a confined view (only the agents tagged for its service) when RBAC enforcement is on and the minting principal holds `Execution:Read`, a degraded tag store answering `503`; the MCP tool still denies service-scoped tokens.
