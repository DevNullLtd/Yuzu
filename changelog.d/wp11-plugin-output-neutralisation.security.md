- **Breaking —** agent plugin result rows now neutralise `|`, CR and LF in endpoint-controlled fields, and the `network_config` `proxy` action redacts proxy URL credentials. `filesystem` (`list_dir`, `search_dir`, Windows `get_version_info`), `installed_apps` (`list`, `query`, `list_per_user` on every OS leg), `processes` (`query` was raw; `list`, `list_hashed` and `list_tree` now also fold a trailing backslash), `procfetch`, `wmi` and `network_config` no longer let a file name, registry value, process name, WMI property or proxy setting forge rows or columns. Through the shared `agents/shared/row_field.hpp` these plugins escape `|`, fold CR/LF to a space, keep interior backslashes (`C:\x` stays `C:\x`) and fold only a trailing backslash to `/` (so it cannot glue onto the delimiter); `installed_apps` `list` previously folded every backslash to `/` and no longer does. The `network_config` `proxy_address` value is `REDACTED@` plus the text after the last `@` whenever it contains any `@` (the scheme and earlier entries of a Windows proxy list are dropped, and a decoy `@` in a path makes the whole value read `REDACTED@<tail>`); a value with no `@` is unchanged apart from the row escape, and only `user:password@` userinfo is scrubbed (not PAC query strings or `bypass` rows). Newly collected rows only: already stored rows keep any credential an earlier agent sent until the response retention reap removes them (default 90 days, `--response-retention-days`, 0 or less disables the reap; there is no purge), so rotate proxy credentials that were exposed through `*_proxy` variables. During a mixed-version rollout agents on the previous build keep sending the previous output. See [Upgrading](docs/user-manual/upgrading.md). The redaction logic is hoisted from `update_source_trust` into `agents/shared/uri_userinfo_redact.hpp`.
