- **Breaking —** agent plugin result rows now neutralise `|`, CR and LF in endpoint-controlled fields, and the `network_config` `proxy` action redacts proxy URL credentials. `filesystem` (`list_dir`, `search_dir`, Windows `get_version_info`), `installed_apps` (`query` and `list_per_user` on every OS leg), `processes` (`list`, `query`, `list_hashed`, `list_tree`; a trailing backslash on a name or path folds to `/`), `procfetch` and `wmi` no longer let a file name, registry value, process name or WMI property forge rows or columns; `procfetch`, `wmi` and `installed_apps` rows also render a literal backslash as `/`. The `network_config` `proxy_address` value is `REDACTED@` plus the text after the last `@` whenever the value contains any `@` (the scheme and any earlier entry of a Windows proxy list are dropped, a path `@` is over-redacted); a value with no `@` is unchanged, and `bypass` rows are escaped. This removes URL userinfo (`user:password@`) from newly collected rows only: already stored rows keep any credential an earlier agent sent until they are pruned (about 90 days), so rotate proxy credentials that were exposed through `*_proxy` variables. During a mixed-version rollout agents on the previous build keep sending raw values. See [Upgrading](docs/user-manual/upgrading.md). The redaction logic is hoisted from `update_source_trust` into `agents/shared/uri_userinfo_redact.hpp`.
