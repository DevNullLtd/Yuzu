- **`device.filesystem.find_by_hash` is bounded, never follows symlinks and reports what it skipped (#5624).** The walk used to fork one `sha256sum` or `shasum` per file with no deadline, cap or cancel, so a large tree ran past the Instructions gate's 30-second poll. It now stops after 20 seconds, 50,000 directory entries, 4 GiB hashed or 100 matches. When anything was skipped or the walk stopped early, one trailing `truncated|<reason>|visited=N|hashed=N|skipped_...=N` row says what was not examined. The result is `CONSTRAINED` / `PARTIAL` when a bound tripped, an entry could not be read, or a network mount was skipped. Symlinks and junctions are counted and never entered, and a file that is not a regular file is never opened. The open refuses a symlink in any path component on macOS and on Linux 5.6 or later where `openat2` is allowed, and in the final component on older Linux kernels, where a seccomp profile denies `openat2`, and on Windows. Subtrees on network mounts are skipped before anything under them is read, on Linux, macOS and Windows, and a Windows root on a non-fixed drive or a UNC share is refused. Linux and macOS now hash in-process instead of running a tool per file, empty files are hashed, and `max_depth` no longer miscounts when the search root is `/`. The definition is at version 0.4.0 and declares the columns `row_kind`, `path` and `size`. A run that skipped nothing writes the same rows as before, except that a match path containing `|`, CR or LF is escaped or folded and a trailing backslash becomes `/`; a symlink to a regular file, which used to be followed and reported as a match, is now counted as skipped. The Instructions gate searches a private per-run directory seeded with known files instead of the shared temp directory. Result-set column matchers now split a key-value plugin's rows to the declared width, so a matcher over `row_kind`, `path` or `size` can match.
