- **TAR no longer opens network-path images on Windows, opens local images through a no-reparse handle, and keeps `tar.db` owner-only on every OS.** The `module` and `procperf` sources classify an image path before any file or trust API is called: UNC, `\Device\Mup` and the other redirectors are never opened, so the agent (which runs as LocalSystem) no longer authenticates its machine account to a share host or stalls on the SMB round trip; the module row keeps an unknown signing verdict and the procperf version is empty. A drive-letter image is opened only on a fixed drive, and an NT volume path on any local volume (removable included) is still opened by the module source, once, through a handle that follows no reparse point (`NtCreateFile` with `OBJ_DONT_REPARSE`). The modification time, the verdict and the signer all come from that handle: a symbolic link or junction anywhere in the path leaves the verdict `unknown` (not counted risky), and compressed, deduplicated and cloud-placeholder images verify normally. On Linux and macOS, `tar.db` and its `-wal`/`-shm`/`-journal` files are set to owner-only (0600) each time the database is opened. On Windows they get a protected DACL (SYSTEM, Administrators and the agent account), created or re-applied before SQLite opens them, so a rollback journal planted beside the database is never replayed; a sidecar owned by any other account or carrying more than one hard link is replaced, and a foreign-owned or hard-linked `tar.db` refuses the open, with the file, its owner and the remedy (move the files aside or remove them, or remove the other link) in the log; a file that denies the agent the right to change its permissions gets the same owner and link checks. The app_usage plugin applies the same owner and link test to the files it reads. Other files in the agent state directory, such as `kv_store.db` and the logs, are not covered and keep the directory's inherited ACL.
