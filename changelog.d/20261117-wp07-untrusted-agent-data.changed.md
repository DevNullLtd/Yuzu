- **Behaviour changes from the WP07 malformed-data hardening.** `split_output_lines` now deletes EVERY carriage return from a result line (previously only a trailing one), so a CR-separated or CR-embedded payload becomes one row; the result-set matcher and the device-page live splitter deliberately keep their own CR handling. Non-UTF-8 bytes in plugin output now read as `?` instead of failing the frame. `yuzu::util::sanitize_utf8` (SDK) now also replaces overlong, surrogate and out-of-range sequences. A policy check whose response cannot be evaluated now scores that device `error`; the check result carries `{"reason":"unevaluable_response"}` only when evaluation threw, while an over-deep response keeps its usual check-result summary.
- **Breaking - a plugin write the agent could not buffer is now reported as incomplete.** When a plugin output write is lost to an allocation failure, the agent forces the command's typed result to `constrained`/`partial` (provenance `host:output_dropped` unless the plugin gave one), marks any capture truncated so the installed-software and other daily-sync sections ship status-only instead of a short roster, increments the agent-local counter `yuzu_agent_plugin_output_dropped_total{plugin}` (NOT scraped by the server) and reports the heartbeat tag `yuzu.output_dropped` (a count, omitted while 0). The host-forced downgrade is documented in `sdk/include/yuzu/plugin.h`.
- **Breaking - plugin `heartbeat.*` tag values are scrubbed to UTF-8.** A non-UTF-8 byte in a plugin heartbeat tag value now reads as `?`; it used to make the server reject the whole direct heartbeat RPC. The `yuzu_ctx_set_result_status`, `get_config`, `storage_set`, `storage_get`, `storage_delete`, `storage_exists` and `storage_list` entry points no longer let an exception (allocation failure) unwind into the plugin; a failed call returns its error value.
- **Added.** The server warns once at start, and sets the gauge `yuzu_pg_server_encoding_not_utf8` to 1, when the PostgreSQL database encoding is not UTF8 (warning only; it does not refuse to start), and the new alert `YuzuPolicyCollectSkipped` fires when the policy collect pass skips targets.
