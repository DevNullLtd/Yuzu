- **Behaviour changes from the WP07 malformed-data hardening.** `split_output_lines` now deletes EVERY carriage return from a result line (previously only a trailing one), so a CR-separated or CR-embedded payload becomes one row; the result-set matcher and the device-page live splitter deliberately keep their own CR handling. Non-UTF-8 bytes in plugin output now read as `?` instead of failing the frame. `yuzu::util::sanitize_utf8` (SDK) now also replaces overlong, surrogate and out-of-range sequences. A policy check whose response cannot be evaluated now scores that device `error` with a short `unevaluable_response` check result.
