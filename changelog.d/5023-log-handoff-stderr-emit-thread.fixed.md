- **The agent's log-error diagnostic is now written off its logging worker thread (#5023).** When a log sink fails (a full disk, no free file descriptors, a broken pipe) the agent prints a rate-limited diagnostic line to stderr. That write used to be made by the single logging worker thread itself, so a blocked stderr could stop it delivering any log line for as long as stderr stayed blocked. It is now made by a short-lived helper thread, at most one write at a time, using a plain write that holds no C-library lock; while one is stuck, further diagnostic lines are dropped and counted instead of blocking anything. This covers the diagnostic's own write only. When stdout or stderr is itself one of the agent's log sinks, a blocked stream still stalls the logging worker in that sink's own write, exactly as before: that is the case for the shipped systemd unit and container images (no `--log-file`, so a stdout sink) and for `--log-file` outside a Windows service (a stderr sink beside the file sink), and in those setups a stalled log collector still stalls log delivery. No flag or format change.
