- **Linux software inventory reads the dpkg and rpm databases in-process instead of running `dpkg-query` and `rpm -qa`.** The `installed_apps` plugin now reads the dpkg status file and the rpm database itself, read-only and bounded (20 seconds, 50,000 packages, fixed byte limits): rpm sqlite (Fedora, RHEL 9 and later), ndb (SUSE) and Berkeley DB hash (RHEL 7 and 8, little- and big-endian) are all supported, and no `dpkg-query` or `rpm` process runs any more (`pacman` and `apk` are unchanged). The rows, the wire format and the section hash are unchanged on every host measured, so nothing is resent on upgrade. Other differences: a host whose packages live only in `/var/lib/dpkg/status.d/` (distroless-style images, which `dpkg-query` never read) now reports them as new install rows; the package manager is chosen by its database file rather than its binary; a tab, pipe or newline inside a maintainer or vendor no longer truncates the value; an rpm sqlite database without its WAL sidecars is readable by an unprivileged account; and a failed read is a degraded collection with a named reason (`installed_apps:<source>:<cause>`, for example `rpm_sqlite:locked`) in the agent log, the `list`/`query` error row and the result's provenance, with no rows and the server keeping its stored ones. A damaged database record fails the whole read rather than publishing a shorter list.
