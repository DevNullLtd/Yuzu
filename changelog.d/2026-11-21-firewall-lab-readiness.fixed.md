- **Firewall `state` and `rules` no longer report a failed read as a healthy answer.** On macOS every read is gated on the command having run, finished in time, not been clipped and exited zero, and a read that did not complete is named by an `error|appfirewall:...` or `error|pf:...` row (`not_run`, `timeout`, `truncated` or `exit:<n>`) next to its `unknown` row, so an unprivileged agent reads as "could not read" rather than a firewall with no rules or nothing to report (#4891, #6611). The pf rule lines are sanitised at the rule site, and the Windows rule and count rows are built by pure functions that every host's test suite pins (#4375). On Linux, an nftables probe now compares the ruleset generation the kernel stamps on each dump and reads once more when a commit landed between dumps (#4400); every failed dump gets its own row, not only the first (#4401); a ruleset that keeps changing reads `torn_persistent` after three probes in a row, a socket-open failure is reported once per probe, and `ufw` or `iptables` output that is not in the expected shape reads `unknown` with an `unrecognised_output` row instead of "no rules" (#4402).
