- **A sidecar whose copy fails part-way no longer leaves a truncated file in a corrupt-database quarantine set.** When a corrupt `echo.db` or `command_dedup.db` is set aside and a `-wal`, `-shm` or `-journal` file cannot be renamed, it is copied into the set; a copy that failed part-way (a full volume) left a partial `<name>.corrupt-<epoch>-wal` that read as the real sidecar. The partial copy is now removed where possible, and the log says whether it was. The copy also no longer runs when anything, a dangling symbolic link included, already sits at the quarantine name: that entry is left as found and the sidecar's content is reported as not kept. On Linux and macOS the copy itself is now made by descriptor: the sidecar is opened without following a link and must be a regular file, and the quarantine file is created exclusively (owner-only, flushed to disk), so a link swapped in at the sidecar's name is never copied through and an entry that appears at the quarantine name is never overwritten or written through; a copy that fails part-way removes the file it created. On Windows the copy is unchanged and still by name.
