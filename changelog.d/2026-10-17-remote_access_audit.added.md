- **New read-only `remote_access_audit` agent plugin — who can log in to a host over SSH, on Linux and macOS (the Windows leg is a planned placeholder).** The single `list` action reports the `sshd_config` values that govern inbound access as written (Include files are followed and the first value wins, as in `sshd`; `Match` blocks are counted but not evaluated), a SHA-256 fingerprint and the option names for every public key in each account's `authorized_keys` (a certificate reports the fingerprint of the key it carries, matching `ssh-keygen -lf`), and whether the `sshd` service is enabled. It never emits a key comment, an option value or a key-file path. A home or file the agent cannot read is reported as refused with a reason token, never as an empty result, and a symlinked key file or a network mount is refused or skipped rather than followed. It does not read every way to log in: a certificate authority, keys or principals supplied by a command, a principals file and host-based authentication are not read (a host that sets one in `sshd_config` is reported as constrained rather than fully supported), and only homes under `/home` and `/root` (Linux) or `/Users` owned by uid 500 or above and `/var/root` (macOS) are walked. On Linux the agent runs unprivileged and usually cannot open other users' homes, so the Linux leg is declared constrained and a constrained result is the common outcome there. The plugin is Forensics-class: it ships off behind the plugin-config kill switch and is gated at `Forensics:Read` with approval, one device at a time. The Windows leg reports one `unsupported` status row (`windows:planned`) until it ships.
