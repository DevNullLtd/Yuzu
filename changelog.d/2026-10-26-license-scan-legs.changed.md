- **Breaking — on Linux, a refused or unusable `/etc/pki/entitlement` now pauses the whole daily licence sync for that host; `license_scan` also reads binary macOS `Info.plist` files and RHEL entitlement certificates in-process.** `entitlement_certs` is an authoritative surface, so any error on it makes the agent keep the last good state and send nothing that cycle: every licence row of the host (RPM/dpkg, FlexLM and entitlement) stops updating until the cause is cleared. Three causes newly pause the sync: a directory the agent may not list (it used to read as an empty surface, and the daily sync then wiped the host's stored entitlement rows while the other rows kept syncing; it is now `cert_permission_denied` with result status `PERMISSION_DENIED`), and a `.pem` larger than 64 KiB (the `openssl` runs parsed any size; it is now a parse failure for that file), and a directory or file past the new scan limits (more than 4,096 directory entries or 64 certificate files, or more than 16 certificates in one `.pem`; the scan also now stops starting new files after 10 seconds, where it was 60). An unreadable, empty or unparseable `.pem` already paused the sync before. Rolling an agent back to an earlier build restores the silent wipe. Whether an unprivileged agent can read the directory on a real RHEL host has not been measured. The first sync after the upgrade also changes some rows: a `.pem` holding several certificates now yields one row per certificate, up to 16 per file (the `openssl x509` runs read only the first), entitlement rows are ordered by file name rather than directory order, so each host re-syncs once, and on macOS a bundle with a binary `Info.plist` now reports its display name and version where it reported the bundle name and an empty version, an XML `Info.plist` is read whole up to 4 MiB (a 256 KiB prefix before), and a non-regular `Info.plist` falls back to the bundle name. On macOS a bounded decoder returns the display name and version of a binary `Info.plist` as `plutil` reports them (measured at euid 501 over the seven binary bundles on one Mac), and the macOS leg is declared supported; the Mac App Store receipt itself is still not validated and vendor-plist rows stay presence-only. On Linux the entitlement certificates are parsed with libcrypto inside the agent instead of two `openssl x509` runs per certificate, so the `openssl` binary is no longer needed and the `openssl_unavailable` reason is gone. See [Software licence detection](docs/user-manual/software-licensing.md#when-the-entitlement-directory-is-refused) and [Upgrading](docs/user-manual/upgrading.md).
