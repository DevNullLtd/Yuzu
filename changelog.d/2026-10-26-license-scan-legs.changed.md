- **license_scan reads binary (`bplist00`) macOS `Info.plist` files and RHEL entitlement certificates in-process, and reports a refused entitlement directory or certificate as `PERMISSION_DENIED`.** On macOS a binary `Info.plist` (GarageBand, iMovie, Keynote, Numbers and Pages among the App Store apps on a typical Mac) used to fall back to the bundle name with an empty version; a bounded decoder now returns the app's display name and version, byte-for-byte what `plutil` reports, and the macOS leg is declared supported (the Mac App Store receipt itself is still not validated and vendor-plist rows stay presence-only). On Linux the entitlement certificates under `/etc/pki/entitlement` are parsed with libcrypto inside the agent instead of by two `openssl x509` runs per certificate, so the `openssl` binary is no longer needed and the `openssl_unavailable` reason is gone. A directory or certificate the agent may not read is now `cert_permission_denied` with result status `PERMISSION_DENIED` (rows already read are kept) instead of an empty surface or a parse failure; because `entitlement_certs` is an authoritative surface, the daily `software_licensing` sync keeps the last good state and skips the cycle while that refusal persists. Whether an unprivileged agent can read the directory on a real RHEL host is not yet measured.
