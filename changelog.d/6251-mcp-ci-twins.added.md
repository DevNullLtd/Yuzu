- MCP tools `list_hardware_ci`, `get_hardware_ci` and `list_quarantined_devices`, twins of `GET /api/v1/hardware`, `GET /api/v1/hardware/{id}` and `GET /api/v1/quarantine`. They apply the same fleet-read confinement as the REST routes and return the same records in the same field order: the two hardware tools return the REST `data` object (for a confined caller `list_hardware_ci` replaces `devices_omitted`, the count of devices outside the caller's scope, with `scope_basis: "authority_scoped"`, so the hidden-device count is never disclosed), and `list_quarantined_devices` returns `{quarantined,count,more}`. The quarantine list is capped at 500 records per call with no paging (`more:true` signals truncation); the REST route still returns the complete list. The two hardware tools carry personal data (serial, UUID, MAC) and withhold it when their audit row cannot be written; `list_quarantined_devices` returns its list and flags `audit_persisted:false` instead.
