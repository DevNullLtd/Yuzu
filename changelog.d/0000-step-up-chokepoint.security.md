- **MFA step-up is now enforced by one central check.** The step-up decision for the 31 routes that already required it moves from each handler into a single table-driven check that runs before the route's own authorization and CSRF checks, so a stale or missing MFA proof is answered with the step-up envelope first (refusals are audited with `stage=pre_authz`). A server whose authentication store is unavailable now answers `503` on those routes, and the server refuses to start when a mutating route has no step-up classification. The Guardian guard update and delete buttons now show the refusal as a toast. New metric `yuzu_auth_mfa_step_up_gate_total` and alerts `YuzuStepUpGateUnavailable` and `YuzuStepUpWindowDisabled`; see [Upgrading](docs/user-manual/upgrading.md).
