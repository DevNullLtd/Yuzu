- **A server that starts against a database a newer build has already migrated now says so.** `PgMigrationRunner` logs a warning for each store whose database is ahead of the build (`store '<name>' is at schema v<N> in the database but this binary only knows migrations up to v<M>`; some stores run the check more than once per start) and carries on; it still applies nothing and does not refuse to start, because many releases are additive and an older build can run against them. Builds from before this change stay silent. Operating a build against a database a newer build migrated is still outside the supported procedure (rolling upgrades and a return to an earlier build are not supported at this stage); `docs/user-manual/upgrading.md` gains a "When a server build finds its database ahead of it (every Postgres store)" section that explains what the warning means (#3894).
