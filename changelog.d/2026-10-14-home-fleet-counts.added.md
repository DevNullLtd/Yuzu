- **Fleet roster and per-policy compliance counts computed in SQL.** `OfflineEndpointStore::fleet_state_counts` returns the roster total, heartbeat-stale count and a per-platform split (Windows, Linux, macOS, Other) from one `COUNT(*) ... FILTER ... GROUP BY lower(os)` statement, so no row crosses the wire and the 100,000-row roster cap no longer understates a large fleet; a failed read is a typed error, never a zero. `PolicyStore::compliance_by_policy_checked` (exposed as `ComplianceApi::compliance_by_policy`) returns every policy's compliance counts from one cached `GROUP BY policy_id, status` read in place of one query per policy, and `AgentRegistry::known_agent_count` counts the online set without building the id list. `fleet_state_counts` also returns an exact SQL `live` presence count that stays correct past the 100,000-row live-id cap, where `known_agent_count` reports unavailable. The failure counter `yuzu_server_agent_presence_store_failed_total` gains an `op="fleet_state_counts"` value. Both fleet-wide reads are unconfined by design: callers must apply the fleet-read gate and use the existing roster path for scope-confined operators. No route, MCP tool or migration changes.
