- **The legacy `GET /events` live stream needs unrestricted `Response:Read` and `Execution:Read`.** It carries every non-Forensics command output row, command status and agent / pending-agent id for the whole fleet and cannot be filtered per device, so it uses the same admit-then-filter gate as `GET /api/v1/events` and refuses a caller whose read authority is confined to a management group or service (`403`, audited as `events.stream.access_denied`); an engine principal is admitted only if it holds both through an explicit RBAC grant. The scope and the credential are checked once, at connect: a stream already open keeps delivering fleet-wide output after the grant is removed, the session is revoked or expires, or the account is deprovisioned, until the client disconnects or the server restarts (no maximum lifetime, #7815); restart the server or close the connection at the proxy to end open streams. The dashboard console's live panel is unavailable to a scoped role.
