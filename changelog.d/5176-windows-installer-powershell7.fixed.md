- **The Windows agent installer no longer aborts when started from PowerShell 7.** The installer checks the update trust-anchor directory's permissions with Windows PowerShell. Started from PowerShell 7 through another process (a script calling the installer, for example), Windows PowerShell inherited PowerShell 7's module path and couldn't load `Get-Acl`. The check couldn't run, and the install stopped with "the permissions could not be read" (0.14.0-rc3). Every PowerShell step in the installers now uses Windows PowerShell's own modules. The unsupported Windows server installer had the same problem in its configuration step: there `Set-Acl` failed with only a warning, so a server installed that way may have `%ProgramData%\Yuzu Server\yuzu-server.cfg`, which holds the password hashes, readable by local users. Check and restrict its permissions, and change the admin and operator passwords if other users had local access. (#5176)
