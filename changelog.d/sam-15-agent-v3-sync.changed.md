- **Breaking - the agent reports installed software as a sectioned blob (contract v3), one section per source plugin, and the v2 blob writer is gone.** Each of the eleven sources (`installed_apps.list_inventory`, `pkg_inventory.managers`/`packages`/`store_packages`, `windows_optional_features.list`, `msi_packages.list_inventory`, `runtimes.python`/`dotnet`/`jvm`, `middleware.ibm_mq` and the new `hardware.drivers_inventory`) is its own section: its rows in full the first time and after any `need_full`, then only a row-hash delta (`-` the rows that left, `+` the rows that arrived, with the section hash the agent will hold), and nothing at all while it is unchanged, so an unchanged device sends its report hash alone. A source that cannot answer sends a status-only section naming why (`constrained`, `timeout`, `oversize`, `not_collected`) and costs only itself; its other sources are still reported. **A constrained answer no longer replaces or removes what was stored.** Under v2 a constrained `runtimes.python` or `middleware.ibm_mq` read deleted that source's rows and a constrained `runtimes.dotnet`/`jvm` or `pkg_inventory.managers` read kept only the rows it had seen; now the server keeps the source's last confirmed rows and shows them as unconfirmed until a full section confirms them. An empty but clean read still retires the source's rows (an honest-empty full section), and an empty `installed_apps` listing is reported `constrained` (`no_rows`) rather than as "everything uninstalled". The agent and server of this build move together (hard cutover): the agent has no v2 writer to fall back to.
- **Each source runs on its own bounded worker.** `installed_apps`, `windows_optional_features` and `hardware.drivers_inventory` get 120 seconds, every other source 60. A source that is still running from an earlier day is reported `timeout` with token `busy` and is not started twice; when no worker can be started the token is `rejected`. A first contact larger than one call (20,000 rows or 3 MiB) is split across successive collections, 30 seconds apart; a source whose full section alone cannot fit is reported `oversize` (`rows=<n>` or `bytes=<n>`) and sends no rows. Shutdown waits up to 3 seconds for any worker still inside a plugin and then exits with code 3 rather than unload the plugin under it. A stop that arrives while a source is waiting out its 120 seconds still ends in the existing 20-second shutdown watchdog (exit code 4), as an unbounded collection did before.
- **Device drivers are now reported by the daily sync.** `hardware.drivers_inventory` is a software source: kind `driver`; ecosystem `windows` (Windows PnP signed drivers, publisher the driver provider, else the signer) or `kernel_module` (Linux loaded kernel modules; the fixed provider `kernel` is a label, not a vendor, so the publisher is `via:kernel_module`). macOS reports the source `not_collected`. `driver` is a new `kind` value on the software catalogue, inventory REST and MCP filters, and `kernel_module` a new ecosystem (family `linux`). Drivers carry no CPE identity and are not assessed for vulnerabilities.
- **The agent no longer reports a path under an account's home as an install location, and spells epoch and release one way.** `install_location` (now filled: the Windows `InstallLocation`, the macOS `.app` path) is blanked when it is under `<drive>:\Users\`, `/Users/`, `/home/` or `/root`; an rpm epoch of `0` or `(none)` and a release of `(none)` are written empty, so one package reads the same on every collection. The `installed_apps` `list_inventory` row gains a fourteenth token (`install_location`; a `|` in it is replaced with U+FFFD), and a clean pass of `installed_apps` and `windows_optional_features` now declares its result complete (`OK`/`FULL`) the way a degraded one already declared `CONSTRAINED`/`PARTIAL`. On Windows a failed read of the agent identity's own `HKCU` Uninstall key no longer marks the machine inventory degraded, and a missing `WOW6432Node` Uninstall key does on a 64-bit OS.
