- **Breaking — agent-bundle build now verifies the release's cosign signature.** `scripts/build-agent-bundle.sh` (and the `docker-publish-agent-bundle` job) previously described `SHA256SUMS` as signed but never checked the signature, and accepted a file whose hash appeared on any manifest line. It now runs `cosign verify-blob` against the exact, tag-bound `release.yml` identity before reading the manifest, requires each download to match its own manifest line, and refuses to build otherwise. For operators who run it by hand: `cosign` is now required (no skip flag); `--version` is validated strictly; new flags `--signer-repo owner/repo` (prints a `[!!]` warning when it differs from the era table) and `--verify-only`; releases with only the legacy `SHA256SUMS.bundle` (v0.7.x) or with no signature file (v0.8.0-rc0 to v0.10.0) are refused. Each run now stages in its own temporary directory under `deploy/docker/`. The image ships `UPSTREAM-SHA256SUMS.sigstore` so the manifest can be re-verified later. `release.yml` also verifies its own `SHA256SUMS` signature before publishing, and every published `cosign verify` command now uses an exact tag-bound identity instead of a wildcard. The bundle READMEs no longer claim the macOS agent is signed or notarized. (#7529)
