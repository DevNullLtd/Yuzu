- **New opt-in proof of identity for re-registering an already-enrolled agent id (`--agent-reregistration-proof`); by default it only AUDITS, so the takeover it addresses is still possible until you set `enforce`.** `Register` and the gateway-relayed `ProxyRegister` re-admit any already-approved `agent_id` with no credential: a caller that knows the id (an identifier operators can see, not a secret) replaces the real agent's live session and is issued a CA-signed client certificate in its name. Both paths now run one shared decision (`agent_reregistration_gate.hpp`): an id that holds a **live** (active, unexpired) leaf in `ca_issued` is re-admitted only when the caller presents that leaf (direct: the mTLS peer certificate; through the gateway: the certificate the gateway *witnessed* in the agent's TLS handshake, in the new gateway-authoritative `RegisterRequest.gateway_attested_peer_cert_pem` / `gateway_attests_peer_cert`, overwritten unconditionally by the gateway and ignored on the direct path) or a fresh **single-use** enrollment token (`max_uses` 1; a multi-use fleet token is not proof of an existing id and is not consumed by the check). A revoked identity with no live leaf is refused outright, and so is a live leaf beside an operator-revoked one (before any token is spent). The gate also runs for an id whose enrollment row was deleted but which still holds a live leaf. The refusal is a gRPC status (`UNAUTHENTICATED`, uniform message), never `accepted=false`, and happens before `register_agent`, so a refused caller cannot displace the real agent and the agent's own retry loop (including the #1894 forced re-register) is unaffected. After a token re-enrolment the older live leaf is revoked (reason `reenrolled`) once the new one is issued, in one statement that revokes only OLDER leaves; this is best effort and a failure is audited (`ca.cert.supersede_failed`) and alerted. **The default mode is `audit`: it counts and audits (`agent.reregistration_unproven`, `yuzu_register_reregistration_total`) and ADMITS exactly as before.** The server logs a WARNING at every boot in `audit` and `off`. A wizard, demo, UAT or other plaintext-gateway fleet cannot satisfy `enforce`. Under `enforce` every leaf-holding agent that cannot show its certificate or a single-use token is refused; before setting `enforce`, set `witness_client_cert` on every gateway's agent listener, restart it, and soak in `audit` (see Upgrading). **Residual under `enforce`:** a holder of an unspent single-use enrollment token can still re-enrol any live-leaf agent id and supersede its leaf (accepted token-custody trust, tracked as #8171); treat unspent re-enrolment tokens as secrets. **Not covered, by design:** `--no-tls`, plain-TLS, operator-CA-certificate agents and expired leaves. `ca_store` schema v6 adds the partial index `idx_ca_issued_agent_subject`. New alerts: `YuzuAgentReregistrationWouldRefuse`, `YuzuAgentReregistrationUnattestedGateway`, `YuzuAgentLeafSupersedeFailed`, `YuzuAgentReregistrationModeMixed`.
