- **A running server replica now drops its cached operator sessions when the durable session write-generation changes to a lower value, not only a higher one.** After a point-in-time restore or a failover to a standby that was behind, the stored counter could be lower than a replica's cached value, so that replica ignored later revocations (a password change, **Sign out everywhere**, an admin force-logout) and kept serving cached sessions for up to the 8-hour session lifetime. The replica now treats any difference as a change and re-reads each session from its row, so a revocation takes effect within about the one-second poll interval. A counter that is exactly equal to the replica's cached value at its next poll is still not detected, so the recovery runbook keeps restarting every replica as defence in depth.
