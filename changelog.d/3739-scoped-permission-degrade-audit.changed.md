- **Breaking — the audit row for an ordinary-RBAC refusal on a per-agent permission gate changes shape, and now says when a store outage caused it.** For `auth.scoped_permission_required` rows written when the ordinary RBAC check refuses a Tag, device-page, agent-properties or other per-agent request, `target_type` is now `Agent` (it held the agent id), `target_id` is the agent id (it held the message) and `detail` carries the message (it was empty). `detail` reads `RBAC denied <Securable>:<Operation>`, with ` (read degraded: mgmt_group_store)` or ` (read degraded: rbac_store)` appended when a failed management-group or RBAC read means a missing grant could not be ruled out. The response is unchanged (still a fail-closed `403`). SIEM rules or saved queries keyed on the old placement must be re-keyed. Other refusal paths of the same action keep their earlier shape (#3219). See "Upgrading" (#3739).
