- **The gateway management plane can admit the server by its CA-issued identity instead of an SPKI pin, as an opt-in (#6016, ADR-2004).** New gateway settings: `mgmt_peer_auth_mode` (`pin`, `identity_or_pin` or `identity`; an unset value is always `pin`, so nothing changes until you set it), `mgmt_peer_identity` (optional; otherwise derived at boot from a management listener's `cacertfile` when that file holds exactly one certificate) and `mgmt_peer_denied`, a list of `{serial, Hex}` certificate serial numbers refused in every mode (keyed on the serial, never the key, because the server re-issues its leaf over the same key). Once you opt in, a server key renewal that keeps the identity needs no change on a gateway that has no pin configured (or runs `identity_or_pin`) and has no refusal window; in `identity` mode a configured pin must also match. New refusal reasons `no_uri_san`, `identity_mismatch`, `identity_unresolved` and `revoked` on `yuzu_gw_mgmt_auth_rejected_total` (in `identity_or_pin` with pins configured a peer that fails both paths because it has no identity is counted with the pin's reason, while `identity_unresolved` and `revoked` are always counted as themselves, and a pin that never resolved is reported even while the identity admits the traffic); new counter `yuzu_gw_mgmt_auth_admitted_total{method="identity"|"pin"}`; new alert `YuzuServerIdentityUriAbsent` (the built-in server certificate lacks the identity). An identity over a `cacertfile` that is not demonstrably exactly one readable certificate (more than one, or empty, unreadable or half-written) refuses boot (`identity_over_ca_bundle`) unless the mode is `identity` and a pin is configured. See "Authorizing the server by its identity" in the gateway manual.
