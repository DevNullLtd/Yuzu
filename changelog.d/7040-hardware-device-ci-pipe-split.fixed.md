- **A pipe inside a CPU model or a memory slot name no longer corrupts a device's recorded core, thread and RAM figures.** The daily device record worked out `cores`, `threads` and `ram_bytes` by splitting the processor and memory rows on every `|`, so a model such as `Foo | Bar` shifted the columns: the cores read 0 and the threads read the core count, or a module's size was dropped from the RAM total, and the wrong figure was stored as if it were right. The record now splits on an unescaped pipe, as the later sections already did, and the Linux and macOS legs escape a pipe in the CPU model (and the Linux leg in the DIMM slot, type and speed) the way the Windows leg already did. A device with no pipe, backslash or line break in those fields produces exactly the bytes it did before, so its record hash does not change; a device whose fields did contain one uploads once with the corrected figures. The device page's live Processors and Memory cards read the same rows and now show such a model or slot in its own cell. The disk, adapter and scalar fields of the record still split on every pipe, and the hardware plugin's own `processors` and `memory` output now shows `\|` and `/` where a pipe or backslash was (#7040)
