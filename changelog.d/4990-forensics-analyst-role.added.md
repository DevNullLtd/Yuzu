- **New built-in `ForensicsAnalyst` RBAC role: a read-only way to delegate `Forensics:Read` (#4990).** It holds exactly `Forensics:Read`, `Response:Read`, `Execution:Read` and `Inventory:Read`, with no `Execute` and no write, so a holder can read the stored responses of Forensics-tier plugins but cannot dispatch anything; collecting forensic data stays approval-gated. Assign it fleet-wide with RBAC enforcement on, through the Users and roles page, `POST /api/v1/rbac/roles/ForensicsAnalyst/assignments` or the MCP `assign_rbac_role` tool; it is created at server start, assigned to nobody, and does nothing while RBAC enforcement is off. Management-group-scoped assignment and engine principals are not supported, and a hand-authored management-group scoped `Forensics:Read` grant reads nothing from the stored-response routes. If a role with that name that is not a built-in role already exists, it is kept as it is, the grants are not added to it and the server logs an error at start-up; remove it (a role with grants or holders cannot be renamed; create a replacement under another name first if its holders need one) and restart to adopt the built-in role.
