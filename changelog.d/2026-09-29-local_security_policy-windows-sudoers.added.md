- local_security_policy plugin: Windows leg and the `sudoers` action. Windows reads `password_policy`, `lockout_policy` and `audit_policy` from one read-only `secedit /export /areas SECURITYPOLICY` (argv leaf, no shell, `argv[0]` under the resolved system directory); the export is staged in an agent-owned, owner-only scratch directory under `agent.data_dir`, removed on return and swept by a later dispatch if orphaned, and an export that does not end in the signed `[Version]` section reports `secedit:export_incomplete`, never rows. `sudoers` (Linux and macOS) reads `/etc/sudoers` and `/etc/sudoers.d/*`, lexed as sudo 1.9.16 lexes them, and reports one row per rule; an unreadable file is `permission_denied`/`unreadable`, never an empty result, and Windows reports a fixed `windows_has_no_sudoers` row. The action is `Security` read-only with a Medium risk tier.
