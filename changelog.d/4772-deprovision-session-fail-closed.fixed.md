- **Deprovisioning no longer reports success when a session survives (#4772).** SCIM deprovision (`active:false`, `DELETE`, create-inactive) and the dashboard user delete now fail closed (500, audit `partial`, `sessions_db_error=true`, account untouched so the IdP or operator can retry) when the durable session delete does not persist, matching the existing API-token behaviour. Previously a Postgres error on that delete was dropped and a deprovisioned user's cookie session could survive on another replica or after a restart.
