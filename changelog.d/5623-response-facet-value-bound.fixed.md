- **A very long field value no longer drops every facet of a command response (#5623).** A single field value too long for the database to index made the whole facet insert fail, so that agent silently fell out of the dashboard facet filter, group-from-results and the agent-count preview. Facet values over 2048 bytes are now left out of the facets (the response and its other facets are kept; a value of 2049 to about 2704 bytes that older servers indexed is no longer indexed), the per-response 5,000-facet limit keeps the facets on the most lines in a fixed order instead of hash order, and the new `yuzu_server_response_facets_dropped_total{reason}` counter makes dropped facets visible. The facet readers now refuse a filter value that can never match a stored facet instead of reporting no match (see the `changed` entry), and the new `yuzu_server_response_facet_filter_refused_total{surface}` counter counts each refusal.
