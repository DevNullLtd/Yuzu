- **A very long field value no longer drops every facet of a command response (#5623).** A single field value too long for the database to index made the whole facet insert fail, so that agent silently fell out of the dashboard facet filter, group-from-results and the agent-count preview. Facet values over 2048 bytes are now left out of the facets (the response and its other facets are kept; a value over 2048 bytes that older servers indexed, because it fit the database index tuple limit of about 2.7 KB for an incompressible value, is no longer indexed), the per-response 5,000-facet limit keeps the facets on the most lines in a fixed order instead of hash order, and the new `yuzu_server_response_facets_dropped_total{reason}` counter makes dropped facets visible. The facet readers now refuse a filter value that can never match a stored facet instead of reporting no match (see the `changed` entry), and the new `yuzu_server_response_facet_filter_refused_total{surface}` counter counts each refusal. On the dashboard results page every request from the filter bar, the sort headers and the pagination now shares one replacing request scope (the chart-deck refresh is deliberately outside it, #5669), so a correction typed or a View switch made while a request is in flight is no longer dropped, and a late sort or page response no longer leaves rows under an empty header. Sending a command now aborts a results request still in flight, so a late response for the previous command can no longer replace the new command's table, and the sort headers and Prev/Next buttons use the filter values currently shown instead of those of the last render.
