- **A very long field value no longer drops every facet of a command response.** A single field value of a few KB or more (the database cannot index it) made the whole facet insert fail, so that agent silently fell out of the dashboard facet filter, group-from-results and the agent-count preview. Facet values over 2048 bytes are now left out of the facets (the response and its other facets are kept; a value between 2048 bytes and about 2.6 KB that used to be indexed is now excluded too, so a facet filter can no longer match it), the per-response 5,000-facet limit now keeps the most frequent facets in a fixed order instead of whichever the server happened to hold first, and the new `yuzu_server_response_facets_dropped_total{reason}` counter makes dropped facets visible. A facet filter, group-from-results or agent-count preview on a value over 2048 bytes, or one containing a NUL byte or invalid UTF-8 (which a stored value never does), is now refused with an error (the dashboard shows a message, REST answers 400, MCP answers -32602) instead of reporting no match.
