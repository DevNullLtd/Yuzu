- **Echo reads are roll-up only on the server.** The canned Echo queries (recent processes, TCP by process, listening ports, service changes, user sessions, process tree, ARP, DNS, mapped drives) now read the hourly tier, so they return counts per hour rather than individual events and no longer carry a pid. `GET /api/v1/settings/data-retention` drops the `live` tier from `echo.tiers`, adds `budget_dependent` to every tier row (true for `hourly`, the tier a device over its byte budget trims first) and adds `echo.db_budget_bytes` (the 250 MiB default). A query over a `$<Source>_Live` name or a `<source>_live` table is refused when a result set is created from it or re-evaluated: both transports answer `RESULT_SET_REEVAL_STALE_SOURCE` and dispatch nothing, because such a query would otherwise rebuild the set as an empty membership with no error. Result sets now report `agents_failed` and `partial`: an agent whose query failed and never produced a matching row is counted instead of silently left out. The Device page reads a source's row count from `<src>_rows`, falling back to `<src>_live_rows` from an older agent.
