- **Echo Capture sources push is audit-first, and refused with 503 while the audit store is unavailable.** One `echo.sources.configure` `attempted` row listing the validated changes is stored before anything is dispatched; if it cannot be stored the push answers 503 with `Sec-Audit-Failed: true` and sends nothing. Permissions are decided again after that row, so a grant withdrawn meanwhile dispatches nothing. SIEM filters on `result != "success"` now match the `attempted` rows. The push toast is now sent by the server on every answer, and `yuzu_echo_sources_push_total{result}` counts the outcomes.
- **Echo `echo.sql` statements that run longer than 10 seconds now fail** with `query exceeded the 10 s statement deadline` instead of holding the agent's query connection. A statement error part-way through is now an error rather than a shortened result. The deadline is fixed.
- **Echo registry capture no longer stores Winlogon autologon passwords.** A value named `DefaultPassword` or `AltDefaultPassword`, under any watched key, is stored as `[REDACTED by Echo]` with no size and no hash, in the roll-up tiers, the baseline and the cursor row; a content-only change to such a value now writes no row. The list is closed at those two names, so other secret-bearing registry values are still stored. Rows written before the upgrade keep their value until retention trims them or the paused `registry` source is purged.
- **Echo no longer keeps process command lines in `echo_state`.** The process baseline holds pid, parent pid, name and user only, and a baseline written by an earlier build is rewritten without command lines when the agent starts.
- **Rejected Echo SQL now leaves an audit row.** A missing, oversized, non-SELECT, blocklisted or targetless query on the dashboard writes `echo.sql` / `denied`, and a missing, oversized or raw-capture-table `sql` on `from-echo-query` and `re-eval` writes `result_set.create` / `denied`, each with a fixed reason and never the SQL text.
