- **The Spark baseline-persistence signal is now visible fleet-wide (#5605).** Two new agent heartbeat tags, `yuzu.guardian_baseline_unpersisted` (the CURRENT count of baseline-on-arm captures staged and not yet written to the agent's local KV store) and `yuzu.guardian_baseline_rebaselined_at_boot` (rules whose boot re-arm found no persisted baseline record), join the existing cumulative `yuzu.guardian_baseline_persist_failures`. The server rolls the three up into the fleet gauges `yuzu_fleet_guardian_baseline_unpersisted`, `yuzu_fleet_guardian_baseline_rebaselined_at_boot` and `yuzu_fleet_guardian_baseline_persist_failures`, plus `yuzu_fleet_guardian_baseline_reporting` (the coverage count for the unpersisted gauge, published every sweep including `0`) and `yuzu_fleet_guardian_baseline_tag_rejected`. A new warning alert, `YuzuGuardianBaselineUnpersisted`, fires when the summed unpersisted count stays above `0` across 15 minutes of evaluations; read it as a persistence backlog, not as proof that a write failed or that a capture was lost, and fix the store first (a graceful restart while the store is still failing loses the staged capture, because the stop-time flush uses the same store; the runbook is "Fleet monitoring of baseline persistence" in `docs/user-manual/guaranteed-state.md`). Zero is not absent: the unpersisted gauge is absent, and `_reporting` reads `0`, while no agent runs with `prefer_spark`, so the gauge and the alert are dormant on every released agent today. The legacy detection path is NOT covered: a legacy persist failure is still only an agent log line. The boot-scan tag is the exception to the dormancy: it is live on every agent that carries this change, legacy path included, and its count is not proof of a loss (a never-captured target, a failed arm, a platform that cannot arm the file mechanism and a lost capture all read the same). Only a genuinely absent record counts; a malformed record, a boot read error and a retarget also re-baseline without being counted. On Linux and macOS no file-hash guard arms, so every agent with such a rule counts it on every boot and the value is not a baseline-loss signal there; meaningful readings come from Windows agents only, and it must never be alerted on. The alert's threshold and window are untuned against fleet data and are revisited at the Spark flip.
