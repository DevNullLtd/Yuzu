- **Decommissioning a device now removes it from every management group.** `DELETE /api/v1/sle/agents/{id}` gains a tenth cascade store, `management_group_memberships` (the response's `stores` map gains that key and `deleted` reaches 10 when every store is configured). Before, the agent id stayed a member of every group it had been in; because decommission does not unenrol the device, the same id was accepted again on its next registration and was back inside those groups' scope (visible to the group's operators, targeted by `group:` dispatch). Now the id leaves every group, static and dynamic and root alike. Decommission still does not unenrol: the same id can reconnect, and its next registration rejoins the All Devices group only, not the other groups it was in; un-enrolling is a separate tracked change. The removal is a point in time (an operator add, or a dynamic group created at the same moment, can put the id back in a group). With RBAC enforcement off, a device that is decommissioned but still connected is missing from the legacy-open device lists until it registers again. No schema change. See the Upgrading guide.
