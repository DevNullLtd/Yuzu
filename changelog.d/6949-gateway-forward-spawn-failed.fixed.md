- **A command the server cannot start a gateway-forward thread for now resolves as failed instead of staying `running` forever.** The server forwards each command queued for a gateway-connected agent on its own short-lived thread. Dispatch had already counted such a command as sent when it was queued, so when the operating system refused a thread (resource exhaustion), the unstarted command and every later one drained in the same pass were dropped with no terminal response, and their execution rows stayed `running` with a targeted count that could never complete. A failed thread start (or an allocation failure while setting the command up) now resolves that command, on a best-effort basis (the terminal write can itself fail under the same pressure, which is logged at error level), with the terminal failure reason `gateway_forward_spawn_failed` (listed with the other gateway-forward reasons in `server-admin.md`) and the pass carries on, so each remaining command gets its own start attempt and, failing that, its own failure. A pass in which every thread starts behaves exactly as before.
