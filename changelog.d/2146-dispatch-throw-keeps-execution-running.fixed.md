- **A dispatch that throws no longer marks its execution as cancelled.** When the dispatch of `POST /api/v1/commands`, `POST /api/v1/instructions/{id}/execute` or the MCP `execute_instruction_definition` threw part-way, the execution row was set to `cancelled` with zero agents targeted although some agents might already hold the command, and the error told the caller to check the execution history. The row is now left `running`, so results from any agent that did receive the command are still recorded against it, and the server closes it by itself if no agent ever responds; the error names the `execution_id` and still advertises no retry. A store that throws while the execution row is created now writes a `failure` audit row and answers `503` `execution_record_unavailable` (retryable, nothing dispatched) instead of unwinding with only a `requested` row.
