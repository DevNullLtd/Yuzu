- **Bulk device-CI read: `GET /api/v1/hardware/ci` and the MCP tool `list_hardware_ci_records`.** Pages through the stored hardware CI records of every device (the scalar CI block plus the stored `content_hash` and `blob_version`, no sections), 100 per page by default (the MCP tool defaults to 20) and 1000 at most, ordered by the byte value of `agent_id` and served from a new index on that byte order (created at server start, a pause of about half a second per million devices for writes to the device CI table), so a database collation change cannot make the walk skip or repeat a device, for a daily pull into an external CMDB without one call per device. It reads the stored CI table, not the 30-day roster, so a device offline for longer still appears while its record exists. Read-only; needs `Inventory:Read`; each served page is audited fail-closed as `inventory.devices.ci` and sent with `Cache-Control: no-store`. A present-but-empty `agent_id` is a `400`. A complete walk is not a snapshot, so confirm a device with `?agent_id=<id>` before retiring it. A caller with global read pages through any number of devices; a caller confined to a scope of more than 10000 devices is refused with a clear error unless it passes `agent_id`.
