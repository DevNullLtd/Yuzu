- **Agent plugins: thread safety, resource leaks and regex/scan cost.** The `tags` plugin now guards its in-memory tag map with a mutex, so concurrent dispatch-pool commands cannot corrupt it. `users.group_members` / `users.local_admins` and `filesystem.get_acl` use the reentrant `getgrnam_r` / `getpwuid_r` / `getgrgid_r` and copy results at once, instead of reading libc's shared static buffers. On Windows, `network_config.dns_cache` and `ioc.check` now free the resolver-cache list that `DnsGetCacheDataTable` returns (one shared RAII owner, `win_dns_cache_table.hpp`) and bound the walk; previously every call leaked the whole table. `filesystem.search` / `replace` with `regex=true` no longer hand an over-64 KiB subject to the recursive regex executor (a long line is skipped with a `skipped|` row; a regex replace over a larger file is refused). The e-mail redaction scan used by `browser_inventory` is now linear: a value over 1 KiB containing an `@` is treated as an address (over-match is the safe direction) instead of rescanning per `@`. The regex ReDoS guard remains a heuristic (#3866).
