- **Settings enrolment panels (Enrollment Tokens, Pending Agent Approvals, Auto-Approve Policies) now look and act like the Groups and enrolment page.** Token expiry is shown in UTC (it was epoch seconds) and the status is a pill, with active tokens first. The approval queue shows when each agent asked to join and gains Forget. Approve all and Deny all ask for confirmation with the total and the first ten hostnames, and are disabled while the list shows only part of the queue. Rules are described by what they match: the hostname and the cloud provider are marked as agent-reported and not verified, address rules are IPv4 only, and a CA fingerprint rule is marked as never matching at this release. The match mode, Enable and Add rule now ask for confirmation, and the Remove confirmation names the rule (so does Disable, which asks only in "all must match" mode). Long lists show the first rows and say how many are not shown. The "unlimited" token warning hides once a limit is typed.
- **Approve, Deny and rule changes refuse a stale click with `409`.** Approve and Deny act only on an agent that is still waiting; on one already decided they answer `409` with the refreshed list and an error message, where they used to overwrite the earlier decision. Enable, Disable and Remove on a rule that moved, changed or was removed since the list loaded are refused the same way.
- **A denial is now permanent for that agent id.** Nothing re-approves a denied agent, and a token or auto-approve rule it presents is refused. A machine denied by mistake can only come back as a new agent: reinstall it or wipe its agent data directory, and remove or tighten any token or rule that would admit it. See the upgrade notes.
- **Audit details changed.** `enrollment.auto_approve.rule_toggle` detail is now `type= value= enabled= by=` and `rule_remove` detail gains `type=`. New `result=denied` details: `stale_rule_view` and `rule_not_found` (rule toggle and remove, with a `409`) and `refused_wrong_status` (approve and deny).
- **A refused browser view of the three enrolment panels writes no `auth.admin_required` row.** The administrator decision is unchanged; tokens and every refused write still write the row.
- **The token and pending list responses (and token creation) are sent with `Cache-Control: no-store, private` and `Vary: Cookie`.** The re-rendered list returned by revoke, approve, deny, forget and the bulk actions is not.
