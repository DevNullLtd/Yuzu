- **The release workflow now refuses to publish over a tag that already has a published release (#5282).** A new first job in `release.yml`, `release-guard`, refuses any run that is not on a `vX.Y.Z[-{alpha,beta,rc}N]` tag, and fails the run before any build or push when `GET /releases/tags/<tag>` answers 200; it proceeds only on HTTP 404 and fails closed on any other answer. Every image push and the release creation additionally re-check that the tag still points at the run's commit (`scripts/ci/check-release-tag-sha.sh`). Every image-publishing job, the release job and the build jobs wait for it. Before this, a run started against an already-released tag (by mistake, or a superseded run) pushed new image digests over `:X.Y.Z` (and `:X.Y`/`:latest`) that no longer matched the release's signed `SHA256SUMS` and SBOMs, and `Create GitHub Release` then skipped with a notice and went green; that step now fails instead. Recovery for a failed job is "Re-run failed jobs" on the newest run for the tag (digests kept); there is no override, and redoing a published release means cutting a new version. Residual paths are listed in `docs/ci-architecture.md`, Release re-publish guard.
