- **The release workflow now refuses to publish over a tag that already has a published release (#5282).** A new first job in `release.yml`, `release-guard`, runs `gh release view` for the tag and fails the run before any build or image push when a published release exists; it proceeds only on gh's exact `release not found` and fails closed on any other gh error. Every image-publishing job, the release job and the build jobs wait for it. Before this, a run started against an already-released tag (by mistake, or a superseded run) pushed new image digests over `:X.Y.Z` (and `:X.Y`/`:latest`) that no longer matched the release's signed `SHA256SUMS` and SBOMs, and `Create GitHub Release` then skipped with a notice and went green; that step now fails instead. There is no override: to redo a release under the same tag, delete the GitHub release first, then start a fresh run. Release skill "Recovery" and `docs/ci-architecture.md` describe both.
