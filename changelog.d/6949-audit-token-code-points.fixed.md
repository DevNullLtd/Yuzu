- **Audit and log tokens no longer carry Unicode line separators or invalid UTF-8.** The shared `log_token` (and `audit_token`, which forwards to it) now folds the C1 controls U+0080 to U+009F, U+2028 and U+2029 to a single `_`, and maps bytes that are not well-formed UTF-8 to `_`, one per byte (the Guardian `log_id_token` output is unchanged). The 128-byte cut in the software sync audit token now falls on a character boundary instead of keeping half of a multi-byte character. The audit store already scrubbed invalid bytes before the insert, so no audit write could fail on them; the change closes the line-splitting characters that reached stored `detail` and log lines intact.
