- **New sudoers line for the macOS agent account: `/sbin/pfctl -s Anchors`.** `scripts/install-agent-user.sh` writes one more exact, read-only NOPASSWD line for the `_yuzu` account (the top-level pf anchor list; no wildcard, no argument). It reverses the earlier decision that the firewall `state` and `rules` reads do not ride the `pfctl` grants: those reads now use the three exact read-only lines `-s info`, `-s rules` and `-s Anchors`. Each `state` read makes up to three `sudo -n` pfctl runs and each `rules` read up to two, each within the plugin's 5 second deadline; there is still no bare `/sbin/pfctl` grant and no `pfctl` grant that takes a file name.
- **New read-only root broker on packaged Linux: `yuzu-fw-snapshot.socket`.** The `.deb` and `.rpm` ship a root-owned socket (`/run/yuzu-fw-snapshot.sock`, group `yuzu-agent`, mode `0660`, `MaxConnections=4`, removed when stopped) and a per-connection service that runs one fixed script as root with no input: `nft -a list ruleset` and each address family's legacy save tool by its own name (`iptables-legacy-save`, `ip6tables-legacy-save`) with literal arguments and a reset `PATH`, the reply cut at 4 MiB, in its own sandbox (bounding set `CAP_NET_ADMIN` and `CAP_NET_RAW`, a system call filter, `RestrictAddressFamilies` limited to `AF_UNIX`, `AF_NETLINK`, `AF_INET` and `AF_INET6`, a read-only file system with `/run` read-only by name, `RuntimeMaxSec=30`, `TasksMax=16`). The script changes no ruleset and writes no file; for the tables the kernel lists, the legacy reads load no module and take no lock; two reads can make the kernel load a module, both measured (ADR-3007 clause 3): an nft read on a host where nf_tables is not loaded makes the kernel load nf_tables, and a legacy save tool that asks for a table whose module is not loaded makes the kernel load that module (an empty table), which the broker's reads reach only when a table is removed while a read is under way. The broker service deliberately does not set `NoNewPrivileges`: with SELinux enforcing (measured on Rocky 9.9, systemd 252) the exec of `nft` was a denied `nnp_transition` under it and `nft` ran outside its own confined domain; the bounding set and the filters bound it instead, and on Ubuntu 26.04 its processes ran unconfined by AppArmor (measured). The agent unit's `NoNewPrivileges` and one-capability bound are unchanged and the agent gains no privilege, but the `yuzu-agent` account (and anything that runs as it) can now read the host's full nftables ruleset, rule handles and comments included, and every instantiated legacy `iptables` and `ip6tables` table. The agent checks that root created the socket, sends nothing and treats the reply as untrusted text. `IPAddressDeny=any` in the service unit takes effect only on hosts with the unified cgroup hierarchy (defence in depth). systemd's own activation limit applies to the socket (200 connections in 2 seconds, those refused at the limit of four included): past it the socket fails (measured on Rocky 9.9, systemd 252: 250 connections at once failed it and 150 did not; on Ubuntu 26.04, systemd 259, 600 did not fail it; ADR-3007 clause 4), and until it is reset and started the plugin answers as a host without the broker does: firewalld's own rows on a firewalld host, `unknown` elsewhere. `systemctl stop yuzu-fw-snapshot.socket` and then `systemctl mask yuzu-fw-snapshot.socket` opts out (`mask --now` alone left the socket file on Rocky 9.9, and the agent reported `error|snapshot:connect:refused`), and masking it before the package is installed keeps it from ever starting; the plugin then answers as a host without the broker does. The contract is ADR-3007.
