- **New sudoers line for the macOS agent account: `/sbin/pfctl -s Anchors`.** `scripts/install-agent-user.sh` writes one more exact, read-only NOPASSWD line for the `_yuzu` account (the top-level pf anchor list; no wildcard, no argument). It reverses the earlier decision that the firewall `state` and `rules` reads do not ride the `pfctl` grants: those reads now use the three exact read-only lines `-s info`, `-s rules` and `-s Anchors`. Each `state` read makes up to three `sudo -n` pfctl runs and each `rules` read up to two, each within the plugin's 5 second deadline; there is still no bare `/sbin/pfctl` grant and no `pfctl` grant that takes a file name.
- **New read-only root broker on packaged Linux: `yuzu-fw-snapshot.socket`.** The `.deb` and `.rpm` ship a root-owned socket (`/run/yuzu-fw-snapshot.sock`, group `yuzu-agent`, mode `0660`, `MaxConnections=4`, removed when stopped) and a per-connection service that runs one fixed script as root with no input: `nft -a list ruleset`, `iptables -S` and `ip6tables -S` with literal arguments, a reset `PATH`, the reply cut at 1 MiB, in its own sandbox (bounding set `CAP_NET_ADMIN` and `CAP_NET_RAW`, `NoNewPrivileges`, a system call filter, `RestrictAddressFamilies` limited to `AF_UNIX`, `AF_NETLINK`, `AF_INET` and `AF_INET6`, a read-only file system, `RuntimeMaxSec=30`, `TasksMax=16`). The agent unit's `NoNewPrivileges` and one-capability bound are unchanged and the agent gains no privilege, but the `yuzu-agent` account (and anything that runs as it) can now read the host's full nftables ruleset, rule handles and comments included, and the `iptables` and `ip6tables` listings. The agent checks that root created the socket, sends nothing and treats the reply as untrusted text. `IPAddressDeny=any` in the service unit takes effect only on hosts with the unified cgroup hierarchy (defence in depth). `systemctl mask --now yuzu-fw-snapshot.socket` opts out. The contract is ADR-3007.
