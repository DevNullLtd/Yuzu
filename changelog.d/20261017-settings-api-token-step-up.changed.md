- **Breaking — SAML operators can no longer create or revoke API tokens from the Settings page.** The dashboard API-token routes now match the REST token routes: `POST /api/settings/api-tokens` and `DELETE /api/settings/api-tokens/{id}` apply the same MFA step-up check as `POST /api/v1/tokens` and `DELETE /api/v1/tokens/{id}`. A SAML session cannot satisfy that check and is refused with `403`, as it already is on the REST token routes; a SAML-only deployment revokes tokens through an API-token or MCP caller, or through a local or OIDC administrator session. OIDC sessions are gated only when the identity provider attests MFA or `--mfa-enforcement` protects the role. A local MFA-enrolled operator whose proof has expired must re-authenticate before creating or revoking a token, because the Settings page cannot yet prompt for the code itself. Creating an MCP-tier token with no TTL, or a TTL over 90 days, is now refused as an input error instead of being reported as an entropy failure (which returned 503, incremented `yuzu_secure_random_failure_total` and wrote a `csprng_unavailable` audit row). The create audit row now records the granted tier. See [Upgrading](docs/user-manual/upgrading.md).
