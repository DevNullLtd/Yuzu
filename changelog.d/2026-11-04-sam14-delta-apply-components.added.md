- **The server now applies delta sections of the sectioned installed-software report, keeps a change history, and stores components.** A `delta` section is applied as row-hash removals and additions against the software the server already holds, then checked against the section hash the device reports it holds afterwards (a new seventh field, `expect`, on the section record); a section that does not check out is undone on its own and asked for again in full, while the other sections of the report still apply. Every stored section writes an install, removal or upgrade entry for what it changed (a re-report of the same software at the same version writes none, and a device's first report writes none), removed software is deleted outright, and entries older than 400 days are pruned under the retention clock guard. The `component_inventory` section is stored per device, and both new tables are removed with the device. New metric `yuzu_software_changes_total{kind}`; the section outcome `delta_unsupported` becomes `mismatch` and its alert `YuzuInventorySectionDeltaUnsupported` becomes `YuzuInventorySectionDeltaMismatch`. No shipped agent sends the sectioned report yet, and no dashboard, API or MCP read shows the history or the components.
