- **`BatchHeartbeatResponse` now reports the sessions the server does not hold (#1197, server side only; inert, does not fix #1197).** The gateway upstream `BatchHeartbeat` reply gains `unknown_session_ids` (distinct session ids in the batch that this server replica has no in-memory record of, at most 4096, each at most 64 bytes) and `unknown_session_ids_truncated`. The gateway does not consume them yet, so after a server-only restart `/health` `agents.online` can still stay 0 while the server logs `BatchHeartbeat: unknown session` and `0/1 acked`; the gateway-side replay that follows is tracked in #1197 and the new "Known limitation" note in the gateway manual describes what was observed on one local rig. Old gateways ignore the new fields and old servers leave them empty, so no upgrade ordering is required. A new `yuzu_server_gateway_route_desync_total{op="batch_heartbeat",outcome="malformed_session_id"}` series counts over-length session id entries the server does not hold (expected to stay at zero, no alert); such entries are no longer counted under `renew_leases`/`unknown_session`. The gateway manual's `BatchHeartbeat` interval default is corrected to 1000 ms (`heartbeat_batch_interval_ms`; it previously said 10 seconds).
