- **Read-only deployment list and detail over REST and MCP, and an NVD status card.** `GET /api/v1/deployments`, `GET /api/v1/deployments/{id}` and MCP `list_deployments` / `get_deployment` show your deployments from the live `/auto` pipeline without advancing the engine or writing a per-poll audit row. A deployment reads Running or Complete, with the failed or skipped count on a finished one ("Complete, 2 failed"); the installer URL and arguments are never returned. Store faults answer `503` rather than an empty list: a degraded store with a retry hint, a store that was never configured without one. The dashboard fragments `GET /fragments/auto/deployments` and `GET /fragments/auto/deployments/detail?dep=` render the same data. `GET /fragments/auto/nvd` shows the NVD feed status (CVE count, last sync, running, last error). The deployment list reports `truncated` (in `pagination` for REST, at the top level for MCP) instead of a total, so a client can tell a short page from the whole list; `limit` must be a whole integer, and `20junk` is `400`. Deployments with the same start time list in a fixed order (newest id first), so the cut at the limit does not flip between reads. On the dashboard fragment a list cut at 50 says it shows only the newest ones, and a `limit` that is not a whole integer falls back to 50. `GET /api/v1/deployments/preview` also keeps the A4 401 body. Devices inside a deployment are ordered by hostname, then agent id. MCP `get_deployment` refuses an id longer than 64 characters or one that is not lowercase hexadecimal, and publishes a typed result.
