- **New Linux-only `runtime_posture` action on the `virtualization` plugin: which container runtimes (docker, podman, containerd) are on this device, how they are configured, and which containers run with risky settings.** Off by default: with no endpoint configured the agent never opens a socket and reports only what a `stat` of the standard runtime sockets, config files and data roots shows, plus an allow-listed set of posture keys from `/etc/docker/daemon.json`. An operator opts in per host by setting `YUZU_AGENT_CONTAINER_RUNTIME_ENDPOINT` (or `--container-runtime-endpoint`) to a read-only unix socket they provide in front of the runtime, in `/etc/yuzu-agent/yuzu-agent.env` or a unit drop-in; the packaged unit is unchanged, the agent is not added to the `docker` group, and it reports `overprivileged` if a host change would let it connect to a default runtime socket. Over that endpoint the agent sends only four fixed `GET` requests (version, info, container list, per-container inspect) under a 20 s deadline, and refuses the four default runtime sockets as an endpoint (by path, and by inode while those sockets are present) with a typed `endpoint_refused` row; the operator's endpoint must admit only those four requests, matched exactly on every request. Container rows carry name, image, state, privileged flag, network mode and whether a runtime socket is mounted into the container; the action never reads environment, command line, labels, ports or other mounts, but the endpoint filters requests, not responses, so a compromised agent could be handed a container's full inspect document through it (see the design note). Endpoint and runtime outcomes are typed (`unset`, `endpoint_refused`, `permission_denied`, `unreachable`, `not_http`, `ok`; `not_detected`, `detected`, `served`), and a failed read makes the result `constrained` instead of an empty success. containerd is detected by presence only. Securable `Security`, operation `Read`, no approval gate. macOS and Windows answer one `unsupported` status row. The design and the privilege change are in `docs/virtualization-runtime-posture-design.md` and `docs/agent-privilege-model.md`.
