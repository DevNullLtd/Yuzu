- Settings: new **Security and sign-in** page (`/settings/security`, administrators only) hosting single sign-on, two-factor sign-in, dashboard HTTPS and agent mTLS in the new look. The four panels are the same fragments `/settings` loads, so no route, field name or audit row changes, and `/settings` keeps working. What changes in the panels: the OIDC form carries all six fields with current values (the client secret stays write-only) and its Test button no longer posts the typed secret; errors from saving SSO and from pasting a certificate are now visible instead of dropped or wiping the panel; saving SSO, replacing a certificate, regenerating recovery codes and changing the mTLS display switch each ask for confirmation, with wording that states what actually happens (an uploaded agent certificate is used after a restart only if `--cert`/`--key`/`--ca-cert` name it); the SSO status reads the live provider (Running, Saved but not running, Not configured); the mTLS switch no longer stays flipped when its confirmation is cancelled and its toast no longer claims the value was saved; recovery codes have an explicit "I have stored these codes" button; and the "Cancel setup" button is withheld under MFA enforcement, where the server would refuse it. `POST /api/settings/oidc` now trims issuer, client ID, redirect URI and admin group (a trailing space in the admin group silently demoted every SSO administrator). An SSO session sees that its two-factor is managed by the identity provider instead of "User not found". Documentation corrected: there is no HTTPS toggle or dashboard-certificate upload on the Settings page. The Multi-Factor Authentication panel is now titled Two-factor sign-in. Saving SSO with a blank client secret now reads the stored secret, rebuilds the provider and swaps it in under one lock, so two simultaneous saves cannot leave the running provider on an older secret than the stored one. See the upgrade notes for the full list of visible changes.
