- **Installed software can be exported as a stream, in JSONL or CSV, with a configurable size limit.** `GET /api/v1/inventory/software/export?format=jsonl|csv` takes the filters of `GET /api/v1/inventory/software` and writes every matching row as a chunked download: JSONL is one JSON object per line (the same row as the list route), CSV is the same 23 columns under one header row, with cells that begin with `=`, `+`, `-`, `@`, a tab or a carriage return prefixed so a spreadsheet reads them as text. `format` is required, and `cursor` and `limit` are refused. It needs `Inventory:Read` and nothing else, and a caller confined to some devices streams only their rows: a scope of up to 10000 devices is applied in the query, and for a wider one the server reads the rows and drops the out-of-scope ones before they are written. At most `--inventory-export-concurrency` exports run at once, server-wide (default 2, range 1 to 16, `YUZU_INVENTORY_EXPORT_CONCURRENCY`), because each holds an HTTP worker until it ends and takes one lease from the server's held-open stream budget (`--max-sse-streams`), like every other held-open response; a request over the limit, or one that arrives when that whole budget is full, is a `503` with `retry_after_ms: 5000`, a `Retry-After: 5` header and an audit row with `result=denied`. One `inventory.software.export` audit row (`stream=true`, with the format and a filter fingerprint) is stored before the first byte, and a row that cannot be stored sets `Sec-Audit-Failed: true` while the file is still served. One export writes at most `--inventory-export-max-rows` rows (default 5000000, range 1000 to 1000000000, `YUZU_INVENTORY_EXPORT_MAX_ROWS`) and `--inventory-export-max-bytes` bytes (default 1 GiB, `YUZU_INVENTORY_EXPORT_MAX_BYTES`), in JSONL and CSV alike; the page that would pass either is not written and the transfer is cut as below, counted as `result="limit"`. Once the headers are sent the status cannot change, so a store read that fails mid-stream, a transfer that runs past 900 seconds, or a server shutdown ends the response without its terminating chunk and the client sees a truncated or aborted transfer; a stream that ends cleanly is complete, and there is no trailer record. New metrics `yuzu_server_software_export_total{format,result}` (result `completed`, `degraded`, `deadline`, `limit` or `aborted`) and `yuzu_server_software_export_rejected_total{reason}` (`export_concurrency_cap` or `global_stream_cap`). The route has no MCP twin, because a streamed file is not a tool call; the ADR-1005 exception ledger records it. `GET /api/v1/openapi.json` now lists 301 operations, 299 of them typed, and the new operation is `getInventorySoftwareExport`.
