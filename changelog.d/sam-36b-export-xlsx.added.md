- **The installed-software export can be downloaded as an XLSX workbook.** `GET /api/v1/inventory/software/export?format=xlsx` returns the same filtered rows as the JSONL and CSV export, as a one-sheet workbook a person can open: the CSV's 23 columns in the same order, a bold header row that stays frozen, and every cell stored as text, so a value that begins with `=`, `+`, `-` or `@` is shown as it is and never evaluated. It takes the same filters and needs `Inventory:Read` and nothing else; a confined caller's workbook holds only its own rows. A workbook cannot be sent before it is finished, so unlike JSONL and CSV it is built whole (in constant memory, into a temporary file under `<data dir>/export-tmp`) before the first byte and sent with a `Content-Length`: a failure before the first byte is an ordinary error with the standard envelope (`413` when the result passes the sheet's own limit of 1,048,575 data rows, `--inventory-export-max-rows` or `--inventory-export-max-bytes`, naming the limit and saying to narrow the filters or use JSONL or CSV; `503` for a degraded store read, a server that is shutting down, the 900-second deadline, which covers the build and the delivery together, a data volume that cannot hold the file, an export directory that cannot be used, or a workbook that could not be written completely: the spreadsheet library does not report a write its volume refused, so the finished file is read back and checked, every part and the sheet against the rows counted, before it is served), and a `200` whose body reaches its `Content-Length` is a whole workbook. For XLSX `--inventory-export-max-bytes` bounds the uncompressed sheet as accounted, markup and escaping included, not the cell text. An XLSX export holds at most 3 times its accounted sheet bytes of the data volume while it runs (3 GiB per export at the default, 6 GiB at the default concurrency of 2) and is refused when that could leave the volume with under 1 GiB free; the directory is created owner-only at start-up and emptied of files at every start. One `inventory.software.export` audit row (`stream=false`, with `rows`, `bytes` and `truncated_cells`) is stored after the build, a failed build writes one `failure` row naming the outcome, and `yuzu_server_software_export_total` gains `format="xlsx"`. The server build gains the `libxlsxwriter` vcpkg port (with `minizip`) under the `server` feature, so the first CI run after this change is one cold vcpkg build. PDF is not offered.
