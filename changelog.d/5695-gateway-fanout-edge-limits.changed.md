- **The gateway's management listener holds up under a large fan-out.** Four changes to the connection the server sends commands over:
  - **No per-connection memory ceiling by default.** The `max_connection_memory_bytes` ceiling meant for anonymous agent connections also applied to the management listener, and killed the server's one connection, with every call on it, when the agents of a fan-out answered together with large responses. A listener that routes the `ManagementService` and does not serve the agent service now has no ceiling unless its `limits` set one; agent listeners keep theirs.
  - **Calls end a margin before the caller's deadline.** A call with a `grpc-timeout` is answered `DEADLINE_EXCEEDED` a tenth of the timeout early, at most 1 s (299 s for the server's 300 s calls), so the server gets the status instead of resetting the call. When thousands of calls expired together, their resets passed Cowboy's cancel-rate limit and closed the whole management connection.
  - **4096 concurrent streams by default** (was 1024). With 5,000 agents answering within 10 s a fan-out took about 31 s at 1024 and about 12 s at 4096 in a loopback measurement. `sys.config.prod` and the reference config set it explicitly.
  - **Quieter, safer logs.** Cowboy's per-stream warning for a message that reaches a stream that has already ended is written at most once per second per connection and no longer prints the message, which for a response frame was the response body.
- **`/healthz` and `/readyz` no longer stall behind an idle client.** The health port serves each connection in its own process and waits at most 2 s for a request (was one connection at a time with a 5 s wait).
