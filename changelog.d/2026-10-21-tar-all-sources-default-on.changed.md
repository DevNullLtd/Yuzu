- **Every TAR capture source is now on by default on every OS.** The eight sources that were opt-in (`procperf`, `netqual`, `module`, `software`, `arp`, `dns`, `netconn`, `mapdrive`) now ship enabled, so a fresh agent reports `<source>_enabled|true` in `tar.status` for all 16 sources. Existing agents are migrated once (tar.db schema v8): a stored `<source>_enabled` of `false` for those eight sources, including one an operator set explicitly, is reset to `true` and its `<source>_paused_at` marker cleared, atomically; an `errored` value (any stored value other than exactly `true` or `false`) and the eight already-on sources are left alone, and a failed migration logs `TarDatabase: v8 migration failed at`, rolls back and retries on the next start, with the old stored values in force until a start succeeds. An opt-out written after the upgrade sticks. **Before upgrading an agent on which you paused any of those eight sources on purpose, record its `config|<source>_enabled|false` lines from `tar.status` and export what you need with `tar.sql` (it reaches every table and tier; `tar.query` reads only some live tables):** the reset ends that source's retention exemption, and rows older than their tier cutoff start being pruned from the first rollup pass (every 15 minutes), irreversibly. A source whose `<source>_enabled` row cannot be read is treated as disabled for that tick (fail closed) and reported as `state_unreadable` in `tar.status` and the collect output instead of `source_disabled`, its rows are preserved, and `tar.purge_source` refuses to purge it. The DEX per-application empty states now say sampling is on by default and still name `procperf_enabled`.
