- **Gateway holds stream-status notifications instead of dropping them (gateway restart required).** When 10 notifications were in flight or the upstream circuit breaker was open, the gateway dropped `CONNECTED` and `DISCONNECTED` notifications, which could leave agents acknowledged by the server but not dispatchable until they reconnected. They are now held in memory only, in a bounded store keyed by agent, session and stream home (a notification lost after admission is not retried), replaced in place by newer events for the same key (except the key of an outstanding half-open probe: a newer event for it is held in the probe's reserved slot and supersedes the older one if the probe fails), and sent first in first out; past `notify_pending_max` a new key is still dropped and counted. While the breaker is half open one held notification is the probe (delivery at least once). The agent-supplied peer address is sanitised (a value that is not valid UTF-8 becomes `invalid`, one over 255 bytes is cut). New gauges `yuzu_gw_upstream_notify_pending` and `yuzu_gw_upstream_notify_inflight`, counter `yuzu_gw_upstream_notify_coalesced_total`, settings `notify_pending_max` (default 10000) and `notify_probe_timeout_ms` (default 15000, the gateway's own deadline for the half-open notification probe: a probe worker that has not reported by then is killed and the probe fails like any failed probe); `yuzu_gw_upstream_notify_dropped_total` now counts only `at_capacity`. Gateway warnings for refused or failed registrations are limited to one per second per kind, with a suppressed count. Refs #4632
