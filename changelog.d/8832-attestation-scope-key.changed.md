- **Breaking: an access-review attestation must name the scope of the grant (#6969).** `POST /api/v1/access-reviews/{id}/attestations` and the MCP `record_attestation` tool now require `scope`, either `fleet` or `management_group`. For `fleet`, `scope_group_id` is absent or empty; for `management_group` it is required, a nonempty string of at most 256 bytes without a NUL byte (the management-group id limit). A request that omits `scope`, or sends a `scope_group_id` that contradicts it, is refused with `400` (REST) or invalid params (MCP), writes no audit row and records nothing. Send `scope` (and `scope_group_id` for a management group), copied from the attestation row. Each attestation row in `GET /api/v1/access-reviews/{id}` and `get_access_review` now carries `scope`, `scope_group_id` and `scope_group_name` (every row is fleet-wide in this build), both campaign tables show a Scope column, and the `access_review.attested` / `access_review.flagged` audit detail gains ` scope=fleet` or ` scope=management_group scope_group_id=<id>` after `role=<role>`. A database created by this build is schema v4 of the access-review store: `scope_group_id` is part of both attestation primary keys and has no column default. This build supports a fresh database only. See `docs/user-manual/upgrading.md`.
