- **Per-OS plugin kill-switch rows.** The server-side plugin kill switch can now be narrowed per agent OS (`windows`/`linux`/`darwin`): a per-OS OFF row withholds dispatch of that plugin/action to agents of that OS, including agents connected through another replica, while other OSes keep the plugin-level state; a per-OS row only ever narrows, and existing plugin/action rows are unchanged on upgrade. An agent whose OS is unknown or empty is never withheld, the OS is agent-reported and matched exactly, and the MCP dry run cannot see the per-OS layer. Rolling back, or running an older replica, drops per-OS enforcement and an older replica applies a per-OS `PUT` as the plugin-level row (see *Upgrading*). The kill-switch REST routes and MCP tools accept an optional `os` (a present-but-blank `?os=` on REST answers `400`, and a non-string `os` on MCP is rejected as invalid params). A dispatch withheld this way answers `503` with `reason: kill_switched_os`, is recorded in the audit log as `command.dispatch_withheld`, and is counted on `yuzu_server_dispatch_target_rejected_total{reason="kill_switched_os"}`. When agent presence cannot be read while a per-OS switch is set, the dispatch fails closed with a transient `503` `reason: os_gate_unreadable` and `retry_after_ms: 5000`, is recorded as `command.dispatch_withheld`, and on the scheduled path is counted on `yuzu_server_command_outbox_deliver_retry_cause_total{cause="os_gate_unreadable"}`.
