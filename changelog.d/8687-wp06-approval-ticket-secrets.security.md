- **MCP approval tickets bind a digest of secret arguments.** The ticket's bound subject replaces every `secret`, `grant_secret`, `grant_id` and `client_secret` value, at any depth (including inside `params` and bundle `steps`), with a `<redacted:sha256:...>` marker before the ticket is minted, so the approvals reads never return them and a re-call with a different secret does not match the ticket. A request nested deeper than 32 JSON levels is refused at parse with `-32700` (not retryable). A string value under any key named `url` has only its userinfo replaced by a marker; the marker hashes the value's JSON text for every type and is an unkeyed SHA-256. A credential passed as text inside any other string-valued argument is not parsed; no approval-gated tool takes one today.
