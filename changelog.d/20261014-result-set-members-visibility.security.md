- **Result-set members are limited to the devices the owner can see now.** `GET /api/v1/result-sets/{id}/members`, the MCP tool `get_result_set_members` and the new `GET /fragments/result-sets/{id}/members` fragment checked ownership only, so an owner whose management-group scope had narrowed since the set was made still paged through ids of devices they could no longer see. Each now resolves the caller's current `Infrastructure:Read` scope and applies it in the query before the page limit: hidden ids are not listed, take no page slot and are never reached by the cursor. Response shapes and cursors are unchanged; a caller without `Infrastructure:Read` is answered `403` (a `200` note on the fragment).
