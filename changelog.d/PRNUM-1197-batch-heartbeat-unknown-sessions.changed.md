- **`BatchHeartbeatResponse` now reports the sessions the server does not hold (#1197, server side only).** The gateway upstream `BatchHeartbeat` reply gains `unknown_session_ids` (distinct session ids in the batch that this server replica has no in-memory record of, capped at 4096) and `unknown_session_ids_truncated`. The gateway does not consume them yet, so this does not by itself fix a restarted server failing to relearn the gateway's sessions; it is groundwork for the gateway-side replay that follows. Old gateways ignore the new fields and old servers leave them empty, so no upgrade ordering is required. A new `yuzu_server_gateway_route_desync_total{op="batch_heartbeat",outcome="malformed_session_id"}` series counts over-length session ids the server does not hold (expected to stay at zero, no alert); such ids are no longer counted under `renew_leases`/`unknown_session`.
