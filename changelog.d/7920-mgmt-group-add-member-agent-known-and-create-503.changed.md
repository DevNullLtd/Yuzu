- **Breaking — REST management-group create answers a store fault with 503 instead of 400, and the add-member success audit row's detail gains an `agent_known` flag (#7074).** `POST /api/v1/management-groups` now answers a fault of the group store, including a failed read of the parent group, with `503`, a fixed message and a retry hint, where it answered `400` with the store's own error text (and a failed parent read as `parent group not found`); a validation refusal and a name conflict stay `400`, and the Settings form escapes the refusal text it shows. Group names and parent ids are held to a stricter rule: a name over 256 bytes or holding a control character (a tab or newline was accepted before), or a parent id over 256 bytes or holding one, is refused with `400`, and REST add member and remove member refuse an `agent_id` over 256 bytes (`400`) and a path group id over 256 bytes (`404`); exactly 256 bytes is accepted, and a refused value is never written to an audit row. The `management_group.add_member` success audit row's `detail` changes from the bare agent id to `<agent_id> agent_known=<1|0|unreadable>`: `1` when the server holds an enrolment record for the id (pending, approved or denied), `0` when it holds none, `unreadable` when the lookup could not be made. The agent id is caller text, so filter on `result=success` first and read the last space-delimited token as the flag. The flag is point-in-time and exact-match (a wrong-case id reads `0`), is not evidence of enrolment, and `0` is also the normal value for a membership staged ahead of the device; an id with no enrolment record is still added, so the flag does not by itself protect a group's scope. This relates to #6967 and is not a fix for it. Nothing about enrolment status is returned in the REST response or the MCP result. `audit_persisted:false` on the MCP `create_management_group` result now means only that the closing outcome row was lost; it used to cover the tool's only audit row, and `audit_persisted` is an optional boolean in the output schemas of both group-write tools.
