- **The gateway no longer runs a management command whose request arrives after the call has already ended.** If the request body of a server-to-gateway `SendCommand` reached the gateway after the call's deadline had expired, or after the command's handler had already finished, the gateway's vendored grpcbox still ran the handler, so the command could fan out to agents after the server had recorded it as failed, or a second time. The vendored grpcbox now records that the stream has ended in both cases, and the existing #1422 guard drops the late data. Only the authenticated, pinned server could trigger this, and it needed an unusually delayed request, so it was not an authorization bypass. The same change applies on the agent listener: an agent request whose deadline expires before its body reaches the gateway now has no effect on the server, and the agent retries as it already does after a timeout. The same fix is proposed upstream in tsloughter/grpcbox#123. The related mismatch where the server's 300-second deadline equals the gateway's fan-out timeout is tracked separately in #5590 (#5591).
