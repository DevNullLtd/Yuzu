- **Release SBOMs now describe each shipped file, not the build workspace.** Every
  archive, `.deb`, `.rpm`, Windows installer and macOS `.pkg` gets its own CycloneDX
  and SPDX SBOM, named after the file (`yuzu-agent_X.Y.Z_amd64.cdx.json`,
  `YuzuAgentSetup-X.Y.Z.spdx.json`; the four archive SBOMs keep their names). The
  release unpacks the file, scans only that, and adds the vcpkg libraries its C++
  binaries are built with from the installed vcpkg tree: the real version, licence, a
  `pkg:github` or `pkg:generic` purl and, where NVD has one, a CPE. The Windows
  installer's SBOM lists the files of the agent zip that `yuzu-agent.iss` installs.
  The gateway's SBOMs list its Erlang/OTP release, with `pkg:hex` purls for Hex
  packages. Each SBOM records its file's SHA-256. Earlier SBOMs scanned the whole
  checkout: v0.15.0's Linux SBOM had 40,853 components, mostly the vcpkg ports
  catalogue, and none of the libraries that ship (it named OpenSSL 1.1.1t and 3.0.2
  and libpq 16.9; the release ships OpenSSL 3.6.5 and libpq 18.4). Measured locally:
  16 (agent `.deb`) to 22 (server and Linux archive) vcpkg libraries, and 18 Erlang
  applications plus ERTS for the gateway. The release now fails before publishing if a
  package has no SBOM, an SBOM belongs to no file of the release, records another
  file's hash, has more than 400 entries, or lists a path under `vcpkg/`,
  `vcpkg_installed/`, `build-*/`, `_build*/`, `site/`, `tests/`, `.git/` or `.github/`.
  The image SBOMs now use the same syft (v1.57.2). Not listed yet: code vendored into
  the source tree and compiled into `yuzu-server` (qrcodegen, and the web assets it
  embeds: htmx, ECharts, three.js, Cytoscape, IBM Plex fonts), the Windows installer's
  own InnoSetup runtime, and libraries the binaries load from the operating system; an
  SBOM whose file holds something it does not list is marked incomplete (CycloneDX
  `aggregate: incomplete`, SPDX `CONTAINS NOASSERTION`). See
  `docs/user-manual/release-verification.md` section 5 and the upgrade note in
  `docs/user-manual/upgrading.md`.
