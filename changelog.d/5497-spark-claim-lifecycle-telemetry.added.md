- **Guardian (agent and server): Spark claim-lifecycle health telemetry on the heartbeat and as fleet gauges.** Dormant until `prefer_spark` is enabled, which no released build does, with one exception: `yuzu.guardian_ack_maint_exceptions` has a push-apply source that runs on every agent and ships only if that step throws. Agents gain 13 sparse count tags (a zero count ships no tag) and two age tags, `yuzu.guardian_disarm_pending_age_seconds` and `yuzu.guardian_compensation_pending_age_seconds` (absent while nothing is pending, never a fabricated `0`). The server exposes them as 13 `yuzu_fleet_guardian_*` fleet sums and two `_max` age gauges, and counts forged values in `yuzu_fleet_guardian_health_tag_rejected`. A Disarm pending past a fixed 30 s, and a compensating teardown outstanding past its deadline (5 s after it became owed in production), are each counted once per claim and logged. This is observation only: nothing is released or cancelled, and no alert rule ships. The agent's Guardian heartbeat block is also now split into independently contained groups (journal maintenance, legacy-sink kick, the `yuzu.guardian_generation` tag, the older Guardian tags, and the new claim-health tags last), so a throw such as an allocation failure is contained instead of escaping the heartbeat loop, and no longer drops later tags. In particular the generation tag the server uses to trigger its missed-push reconcile survives a fault in any other group. Each group logs its first failure and every 100th with a running count; no fault metric ships yet.
