- **Local password change and admin reset (#5342).** A local account can now change its own password — Settings → User Management → **Change password**, or `POST /api/v1/users/me/password` with the current password — and an administrator can reset another local account's — **Reset password**, or `POST /api/v1/users/{name}/password` (`UserManagement:Write` + MFA step-up). Both accept interactive dashboard sessions only (API, MCP, engine and service-scoped tokens get `403`), require a same-origin `Origin`/`Referer` and `Content-Type: application/json`, and enforce one password policy of 12–1024 bytes (now also applied to account creation; `/login` answers an over-max password as a wrong one without hashing it). A wrong current password counts toward account lockout and a locked account gets the same `403`. Resetting an administrator needs a standing admin, not a JIT elevation, and the database write itself refuses an administrator row in that case, so a promotion racing the reset is refused too. A change or reset clears the lockout and revokes every session of the account on every server; the self-service change re-issues the caller's own cookie, while a reset leaves the target's API tokens in place and reports how many remain (`api_tokens_active`). Audited as `user.password_change` / `user.password_reset`; if that row cannot be written the password write is rolled back and the request fails `500`. SSO and SCIM accounts are refused `409`. There is no MCP tool for either action, by design (parity-ledger exception). New metric `yuzu_auth_password_changes_total{kind,result}`. The Settings "Sign out everywhere" button's post-logout redirect, which the dashboard CSP had been silently blocking, now runs.
