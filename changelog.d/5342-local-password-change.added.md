- **Local password change and admin reset (#5342).** A local account can now change its own password — Settings → User Management → **Change password**, or `POST /api/v1/users/me/password` with the current password — and an administrator can reset another local account's — **Reset password**, or `POST /api/v1/users/{name}/password`. The reset requires a **durable Administrator** (plus MFA step-up when enrolled): with RBAC off, the caller's own local account must hold the `admin` role; with RBAC on, the caller needs a user Administrator grant. A JIT elevation, an IdP-group admin role or a custom role holding `UserManagement:Write` is refused `403` (`durable_admin_required`). Both routes accept interactive dashboard sessions only (API, MCP, engine and service-scoped tokens get `403`), require a same-origin `Origin`/`Referer` and `Content-Type: application/json`, and enforce one password policy of 12–1024 **bytes** (UTF-8), now also applied to account creation; `/login` answers an over-max password as a wrong one without hashing it. A wrong current password counts toward account lockout, and a locked account gets the same `403`. Every session of the account — including your own after a self change — is revoked on every server **before** the password is written; if the revoke cannot be stored the request fails `503` (`session_revoke_failed`) and nothing is written. After a self change you are signed out and sign in again with the new password. A reset also clears the target's lockout and leaves its API tokens in place, reporting how many remain (`api_tokens_active`, or `null` with `api_tokens_unknown` when the token store cannot be read). The configured break-glass account cannot be reset (`403` `break_glass_target`); under `--auth-mode=sso-only` only an armed break-glass account may change its own password. Audited as `user.password_change` / `user.password_reset`; if that row cannot be written the password write is rolled back and the request fails `500`, and if the rollback also fails the response says so and `yuzu_auth_password_change_unrecorded_total{kind}` (alert `YuzuPasswordChangeUnrecorded`) increments. SSO and SCIM accounts are refused `409`. There is no MCP tool for either action (parity-ledger exception; a reset tool with a server-generated temporary password is #5357). The Windows server installer now refuses `/ADMIN_PASS` or `/OPERATOR_PASS` on an upgrade with exit code 11 instead of silently ignoring it (#5274), skips its account pages on an upgrade, and rejects a password over 1024 bytes. New metric `yuzu_auth_password_changes_total{kind,result}`. The Settings "Sign out everywhere" button's post-logout redirect, which the dashboard CSP had been silently blocking, now runs.
