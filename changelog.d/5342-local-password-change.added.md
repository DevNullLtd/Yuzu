- **Local password change and admin reset (#5342).** A local account can now change its own password — Settings → User Management → **Change password**, or `POST /api/v1/users/me/password` with the current password — and an administrator can reset another local account's — **Reset password**, or `POST /api/v1/users/{name}/password`. The reset requires a **durable Administrator** (plus MFA step-up when enrolled): with RBAC off, the caller's own local account must hold the `admin` role; with RBAC on, the caller needs a user Administrator grant. A JIT elevation, an IdP-group admin role or a custom role holding `UserManagement:Write` is refused `403` (`durable_admin_required`). Both routes accept interactive dashboard sessions only (API, MCP, engine and service-scoped tokens get `403`), require a same-origin `Origin`/`Referer` and `Content-Type: application/json`, and enforce one password policy of 12–1024 **bytes** (UTF-8), now also applied to account creation; `/login` answers an over-max password as a wrong one without hashing it. A wrong current password counts toward account lockout, and a locked account gets the same `403`. Each change or reset is **one database transaction**: the new password, the sign-out of every session of the account on every server (your own included after a self change), the discarding of an unfinished MFA enrolment, the target's lockout (reset only; `lockout_cleared` is `true` only when there was one) and the audit row are saved together or not at all — a refused or failed request changes nothing, and a session proven with the old password can neither survive the change nor be minted while it commits. An enrolment started under the old password cannot be completed afterwards. After a self change you are signed out and sign in again with the new password. A reset leaves the target's API tokens and any enrolled second factor in place, reporting how many tokens remain (`api_tokens_active`, or `null` with `api_tokens_unknown` when the token store cannot be read). The configured break-glass account cannot be reset (`403` `break_glass_target`); under `--auth-mode=sso-only` only an armed break-glass account may change its own password. Audited as `user.password_change` / `user.password_reset` inside that transaction; if the row cannot be written nothing changes and the request fails `503` (`audit_unavailable`, `Sec-Audit-Failed`). SSO and SCIM accounts are refused `409`. There is no MCP tool for either action (parity-ledger exception; a reset tool with a server-generated temporary password is #5357). The Windows server installer now refuses `/ADMIN_PASS` or `/OPERATOR_PASS` on an upgrade with exit code 11 instead of silently ignoring it (#5274), skips its account pages on an upgrade, and rejects a password over 1024 bytes. New metric `yuzu_auth_password_changes_total{kind,result}`. The Settings "Sign out everywhere" button's post-logout redirect, which the dashboard CSP had been silently blocking, now runs.
