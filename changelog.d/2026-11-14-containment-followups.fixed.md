- **A late apply after a confirmed release can no longer leave a contained device with no record.** A release is confirmed by the device's `inactive` answer, and an apply that reached the device after the observation behind that answer used to leave it contained under no record and with nothing owed. Every stored-record apply now claims the record first (schema v5, `apply_gen` and `apply_claimed_at`), and the write that ends a record presents the apply generation read before the command whose answer it uses; an apply claimed since refuses the end, `DELETE` answers `202` for one reconciler cycle, and the next status read settles it. It relies on commands to one device arriving in the order one server dispatched them; a reordering transport, an apply and a release dispatched by two server replicas, and a dispatch stalled past 120 seconds are documented residuals.
- **Heartbeat ingest no longer waits on quarantine store reads or dispatch.** A heartbeat from a device with an unconfirmed or releasing record now only marks it due; the reconciler thread, which does all reconcile work, acts within a second. A busy store pool or a slow dispatch can no longer delay heartbeat batches.
- **A re-verify no longer writes a false drift row.** The reconciler now reads the record again before it calls a confirmed record drifted: a record that ended or began releasing while the status command was in flight is handled as that, and a failed read re-verifies instead of concluding anything. A reconcile pass whose entry was reset in the meantime drops its result instead of overwriting the new entry.
- **The `release_sent` audit row is written once per agent session** for a releasing record, not once per cycle, so a device that keeps refusing the release no longer adds a row every cycle (the counter still counts every dispatch).
- **A gateway test timeout.** The first gateway test to start `gun`, `cowboy`, `telemetry` and `prometheus` in a cold VM could pass eunit's 5 second default and cancel the rest of its module; the tests that start applications now carry a 60 second timeout. The test plugin lists agree with the 72 shipped plugins.
- **`scripts/install-agent-user.sh` no longer fails validation of its sudoers file on a host whose `visudo` is sudo-rs** (the default on newer Ubuntu). sudo-rs has no `requiretty` setting and rejected the whole file over the `Defaults ... !requiretty` line, so no grant was installed there; the line is now written only when the host's `visudo` accepts it.
