- **A lost audit row on a cancel or rerun refusal is now signalled instead of dropped.** `POST /api/v1/executions/{id}/cancel`, `POST /api/v1/executions/{id}/rerun` and the MCP tools `cancel_execution` and `record_execution_rerun` write a `denied` row when a management-group-confined caller probes an execution it cannot see, and a `denied` or `failure` row for a rerun whose original vanished or whose store was unreadable. When that row could not be stored the refusal looked identical to one whose row was saved. The REST routes now add `Sec-Audit-Failed: true` and the MCP tools add `error.data.audit_persisted: false` to the refusal, the same signal the instruction execute twins already give; the status, code and message are unchanged, and a refusal with intact rows is byte-identical to before.
