- **Breaking - `--auth-mode=sso-only` now refuses to start when no SSO provider is usable.** The start-up check used to confirm only that a provider was configured, so a SAML IdP certificate that was missing, over 64 KiB, not a PEM certificate, or of a key type that cannot verify signatures (for example Ed25519), or an unusable SAML signing key, let the server start into a state where nobody could sign in. It now exits with `[SSO] Refusing to start` (the cause is the log line above it); with OIDC and SAML both configured, one working provider is enough. The refusal stops the whole server, and `--auth-mode=standard` as an escape re-enables local-password login for every account. In `standard` mode an unloadable SAML certificate now disables SAML at start-up. The check is local only: an IdP outage at restart does not block start-up. New gauges `yuzu_auth_{oidc,saml}_provider_{configured,enabled}`; `configured 1` with `enabled 0` means disabled at runtime. See "Hardened auth mode" in `docs/user-manual/upgrading.md`. (#4160)
