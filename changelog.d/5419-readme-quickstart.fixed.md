- **The README's Docker Compose quickstart now works with the released images.** In 0.14.0 it downloaded `deploy/docker/docker-compose.yml` and ran `YUZU_VERSION=0.14.0 docker compose up -d`. That compose builds from a checkout of the repository (`build: context: ../..`), so a downloaded copy has nothing to build, `YUZU_VERSION` was ignored, and the stack never started. The quickstart now downloads `deploy/docker/docker-compose.reference.yml`, which pulls `ghcr.io/devnullltd/yuzu-server` and `yuzu-postgres` at `${YUZU_VERSION}`, serves HTTPS on 8443 and keeps `/etc/yuzu/certs` on a named volume. It also lists the steps that compose needs on first boot: a `.env` with the version and two different Postgres passwords, and a pre-written `yuzu-server.cfg` holding the first admin account, because the server's interactive first-run setup exits when there is no terminal. The README now describes `deploy/docker/docker-compose.yml` as a development stack for a clone. A docs-suite test, `tests/test_readme_quickstart.py`, checks that the compose the README downloads has no `build:`, uses `${YUZU_VERSION}` image tags, publishes 8443 and persists `/etc/yuzu/certs`, and that the admin seed goes to the image's `--config` path with the server's PBKDF2 iteration count.
