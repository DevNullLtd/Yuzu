- **A Guardian policy push can no longer disarm a rule through a degraded scope read, and an agent no longer applies an older full push.** The REST, dashboard and MCP policy-push fan-out (also used by Baseline deploy and delete) now resolves the target scope and every enabled rule's scope before it sends anything; a degraded tag, property or management-group membership read aborts the whole push and sends nothing, where it used to omit the scoped rule from every agent's full push and record the new generation as delivered. The dashboard shows a warning toast and audits `degraded`, REST returns `503`, and MCP returns an internal error with a retry hint. On the agent, a `full_sync` push labelled with a policy generation below the one the agent holds is refused with a warning and changes nothing (agents that carry this check; an agent from before this release applies an older push); before, the older rule set was applied while the agent kept reporting the higher generation. A push at the held generation is still applied. Limit: after a server-side loss of the generation counter (for example a database restored to an earlier state), agents that carry this check and hold a higher generation refuse full pushes and do not receive edits until the server's counter reaches theirs, and no supported operation raises it at this release. The new counter `yuzu_server_guardian_agent_generation_ahead_total` flags this (at most one sample a minute per replica, with a warning log line) and the Guaranteed State manual has a manual restore runbook; check what rule set the server holds before raising the generation, because the raise converges every agent behind it to that rule set.
