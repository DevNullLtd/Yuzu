- **Behaviour change — `vuln_scan` gains the `UNREADABLE` severity and a seventh `summary` row; a WMI property-enumeration fault now fails the whole query for every `wmi_bounded` consumer.** `vuln_scan`: `scan` and `config_scan` emit `UNREADABLE|config|<title>|<path>: <cause>` for a failed read of `/proc/sys/kernel/randomize_va_space`, `/proc/sys/fs/suid_dumpable`, `/etc/ssh/sshd_config` or `/proc/mounts`, or an empty value in either `/proc/sys` file (previously a HIGH/MEDIUM false finding); `summary` always emits `summary|UNREADABLE|<n>` after `summary|INFO|<n>` (7 rows, was 6) and excludes it from the TOTAL issue count; an absent `sshd_config` reads INFO "not applicable" on both SSH checks (the password row is now emitted). Consumers: treat `UNREADABLE` as not assessed, neither pass nor issue; a `severity != 'critical' && severity != 'high'` policy passes an unreadable host; MEDIUM counts drop on hosts whose `sshd_config` the agent cannot read. `wmi_bounded`: `hardware`, `bitlocker`, `windows_updates`, `autoruns`, `antivirus`, `license_scan`, `wmi`, `firmware_posture` and `app_control` now report `wmi_property_enum_failed_<hr>` (the whole query failed) where one object's property fault used to yield a row missing a column; any enumeration return other than `WBEM_S_NO_ERROR` or `WBEM_S_NO_MORE_DATA` counts as a fault. The stage-aware `absent`-vs-`failed` rule `firmware_posture` introduced now lives in `agents/shared/wmi_error_token.hpp` and `app_control` uses it (an enumeration-stage `WBEM_E_INVALID_NAMESPACE` is a fault, not a missing class). `firmware_posture` detects Apple Silicon via `hw.optional.arm64` (first-generation M1 identifiers such as `MacBookAir10,1` were misread as Intel and reported `unreadable`), reports `version_source` as `unreadable` when the version is, keeps a row for a malformed or partial release field, carries the D-Bus error name in fwupd failure tokens, and reports Windows source failures per field (#4749, #4893, #4895, #4898, #4961, #4965).
