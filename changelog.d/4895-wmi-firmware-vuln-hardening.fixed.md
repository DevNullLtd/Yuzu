- **Stage-aware WMI absence across plugins; `firmware_posture` and `vuln_scan` read failures no longer masquerade as findings.** The stage-aware `absent`-vs-`failed` rule `firmware_posture` introduced now lives in `agents/shared/wmi_error_token.hpp` and `app_control` uses it (an enumeration-stage `WBEM_E_INVALID_NAMESPACE` is a fault, not a missing class); a WMI property-enumeration fault — at `BeginEnumeration` or `Next` — fails the query (`wmi_property_enum_failed_<hr>`) instead of silently dropping columns. `firmware_posture` detects Apple Silicon via `hw.optional.arm64` (first-generation M1 identifiers such as `MacBookAir10,1` were misread as Intel and reported `unreadable`), reports `version_source` as `unreadable` when the version is, keeps a row for a malformed or partial release field, carries the D-Bus error name in fwupd failure tokens, and reports Windows source failures per field. `vuln_scan config_scan` reports an unreadable or faulted `/proc/sys` setting or `sshd_config` read as `UNREADABLE` (excluded from the issue tally) instead of a HIGH/MEDIUM finding, and an absent `sshd_config` as not applicable (#4749, #4893, #4895, #4898, #4961, #4965).
