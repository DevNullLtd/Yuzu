- **`DELETE /api/product-packs/{id}` checks for referrers with a bounded number of store reads, however many items the pack carries.** The reference check that refuses a pack whose definition a schedule, a live workflow or a policy fragment still names used to read three sources once per InstructionDefinition item (1500 reads for a pack of 500) and one policy lookup per own policy fragment. It now reads each source once for all of the pack's definitions together, reads the policies that hold the pack's own fragments in one read, and stops as soon as it holds 21 referrers, so a pack with hundreds of referrers refuses at once. The `409` is the same text with at most 21 referrers counted (the count was already a lower bound), listed schedules first, then workflows, then policy fragments. A policy whose input, trigger or group rows cannot be loaded no longer fails the check for a pack's own fragment (only the policy id and name are read). The `503` from a failed reference check, or from the pack read before it, now carries `retry_after_ms` (nothing was deleted, so the same `DELETE` can be retried as is); the `503` for a check that is not configured still does not.
