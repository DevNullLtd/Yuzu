- **Echo registry source reads logged-off users' hives.** The curated per-user roots (Run, RunOnce, Policies, Winlogon) of each profile whose hive is not loaded and whose path the profile-list walk can resolve (at most 512 entries are walked) are baselined and diffed through the shared guarded offline-hive ladder on the hourly tick (every 12 slow ticks: hourly at the default 300 s), and on first sight of a newly found profile or a re-enable; their rows carry `source=offline` and `detail=attr:offline` (never correlated to a writer), a refused or failed mount is one `capture_gap` row per root naming the reason, an incomplete profile discovery keeps the known scope, and a baseline now carries across logoff and logon. Loaded roots are read first in each tick and the hives share the remaining read budget, so a long list of logged-off profiles is read over several ticks. When it starts, the registry source also unloads any `YUZU_HIVE_*` hive mount an earlier run left behind (an agent killed mid-mount, or an unload that failed), without force: one that is refused or fails to unload is logged and left for `reg unload`. The new value of each added or changed value is stored unmasked, as for loaded hives, with the old value's type and size but never the old value, and the mount enables the backup and restore privileges for its duration on those reads, and on every tick for a hive that is capped, deferred or owed a retry. `echo.status` gains `registry_offline_roots`, `registry_offline_roots_unreadable`, `registry_offline_roots_deferred` and `registry_offline_discovery_incomplete`.
