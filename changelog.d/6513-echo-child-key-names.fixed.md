- **Echo's registry source no longer loses siblings or merges names it cannot represent.** More than 32 child keys that deny read access no longer stop the walk: the rest of the root is read, so adds and changes under later siblings land, the read stays partial (no removals are derived), and the gap row says how many denied children are not named; it is written again when that count grows. A child key whose name contains U+0000 is never opened (it would open a different key) and is reported like a denied child, with the NUL shown as `<NUL>`; the gap row text now reads "denied read access or not openable". Value and key names that are not valid UTF-16 (a lone surrogate) now keep a distinct stored identity instead of collapsing into one replacement-character name, and a name that really contains U+FFFD is stored doubled; the same identity is used to match a change to the process that wrote it. A case-only rename stays a removed and an added row, as before.
