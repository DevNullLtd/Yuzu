- **`middleware.ibm_mq`: installed IBM MQ installations on Linux, fed to the installed-software inventory.** A new table-driven `middleware` plugin answers which installations of a middleware product are registered on a host and at what version; IBM MQ is its first product, and further products are table rows rather than new plugins. On Linux it reads `/etc/opt/mqm/mqinst.ini` and the file names in each installation's `swidtag` directory (`dspmqver` and `dspmqinst` are never run, and no process is started). The version is VRM (version.release.modification, for example `9.4.5`): the fix-pack level is not visible in that metadata, so fix pack `9.3.5.1` reports `9.3.5`. The action answers a `status` row first, and a failed or skipped read is a constrained status with a named token, never an empty success; an installation whose version cannot be read keeps its row with version `-`. A path on, under or containing a network mount is skipped and reported (`network_fs_skipped`), never opened. Windows and macOS answer a single `unsupported` row for now. Each row becomes one `IBM MQ` entry (ecosystem `ibm_mq`, kind `app`, publisher `IBM`) in a device's installed software through the daily sync, and the published `ecosystem` vocabulary on the REST and MCP software and crypto surfaces gains `ibm_mq`, so `ecosystem=ibm_mq` filters to these entries. A constrained read withholds only the IBM MQ rows from that day's report (the rest of the device's software is still sent, and its stored IBM MQ rows are removed until a read succeeds again). Unpacked copies that were never registered with the operating system are not listed.
