- **Decommissioning a device now also erases its presence row.** `DELETE /api/v1/sle/agents/{id}` fans out to a seventh store, `offline_endpoint`, and deletes the device's `endpoint_state` row: its last-known hostname, OS, agent version, architecture and heartbeat times. Until now the row was removed only on a graceful disconnect, which a decommissioned agent never sends, so it stayed in the database indefinitely, out of sight once stale. The response's `stores` map gains an `offline_endpoint` entry. If that delete cannot complete (for example the database is unavailable), the entry is `failed` and the request returns `500`; re-issue the DELETE. The delete applies to the shared database, so every server replica sees it. As with the other stores, erasure does not unenroll the agent: a device that is still enrolled creates the row again on its next heartbeat, so decommission the device first. (#5682)
