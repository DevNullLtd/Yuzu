- **Decommissioning a device now also erases its presence row.** `DELETE /api/v1/sle/agents/{id}` fans out to a seventh store, `offline_endpoint`, and deletes the device's last-known hostname, OS, agent version, architecture and heartbeat times, which were previously kept indefinitely. The response's `stores` map gains an `offline_endpoint` entry, `deleted` counts up to 7, and if that delete cannot complete the entry is `failed` and the request returns `500`; re-issue the DELETE. Erasure is point-in-time and does not unenroll the agent, so stop the agent first (see the REST API manual). During a rolling upgrade, a response with no `offline_endpoint` key came from a not-yet-upgraded replica and did not erase the row; re-issue the DELETE once every replica is upgraded. (#5682)
