- **Policy and instruction-definition YAML now parses as written whatever its line endings, so a policy can no longer silently target more devices than its YAML says.** Previously the server's YAML scanner split lines on LF only. In a Windows-authored (CRLF) file, a blank line inside a nested block (`spec.scope.selector`, `spec.execution`, `check.parameters`, a block list) ended that block early, and the predicates after it were silently dropped. A policy written as Windows devices tagged `prod` was stored as `ostype == "windows"` and evaluated against every Windows device, and a valid definition was refused with "Missing spec.execution.plugin". CRLF, lone CR and LF are now all line breaks, and a blank or `#` comment line inside a block no longer ends it (with LF endings, a comment line at a shallower indent did the same damage). Key lookups are anchored: a key matches only as the first token on its line, so a commented-out `# tags: [lab]`, a key mentioned inside a value, or a longer key such as `extratags:` is no longer read in place of the real one. Block lists now end at the first line outside them, so items belonging to an outer or sibling list are no longer absorbed as extra management groups. An inline list must close on the key's own line: comment text in a multi-line `[…]` list is no longer split into group ids. An unterminated `tags: [prod` used to be stored with the tag silently missing; it is now rejected. Two lookups also behave differently: a key in the middle of a line (for example `description: "see scope: x"`) is no longer matched as the key, and an inline list on the last line of a file with no trailing newline (`tags: [a]`) is now read rather than ignored. **Policies created before this change are not re-parsed:** a policy's scope is lowered once, when it is created, and stored policies are never re-lowered (#7004).

  Upgrade note: review policies created from CRLF YAML (`SELECT id, name FROM policy_store.policies WHERE yaml_source LIKE E'%\r%'`), or from YAML with comment lines inside `scope:`, and recreate any whose `scope_expression` is missing a predicate (#2123).
