- **The gateway now re-registers the agents a restarted server does not know (#1197).** After a server-only restart, the gateway reads the unknown sessions from the `BatchHeartbeat` response and replays exactly the ones it still holds. If the outage opened the circuit breaker (it did in rig runs, with up to 45 agents; one agent was back after 86.7 s), verdicts are dropped until the breaker's probe succeeds, and the breaker's own replay then re-registers the agents: wait, do not restart. A gateway restart disconnects every agent that node holds; released agents v0.13.0 and v0.14.0-rc6 did not re-register after a rejection in testing (inferred cause #2182, fixed by #5183, unreleased): upgrade the agents first. A management `SendCommand` while the command router is down now answers `UNAVAILABLE`, and its timeout is clamped to 1 to 3600 s. New counters: `yuzu_gw_registration_replay_triggered_total`, `yuzu_gw_heartbeat_unknown_truncated_total`, `yuzu_gw_heartbeat_verdict_dropped_total`. One core replica only. Refs #1197.
