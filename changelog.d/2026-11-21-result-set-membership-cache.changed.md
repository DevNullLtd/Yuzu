- Repeated scope previews and evaluations reuse materialized result-set membership within a bounded (16 MiB) per-server cache; ownership, expiry and readiness are still read live on every use. **Behaviour change:** an unpinned result set past its TTL is now refused as a `from_result_set:` scope (`404`) from the moment it expires, not only after the GC sweep deletes it, and using it no longer extends it; pin a set that a schedule or other recurring job targets. Result-set store migrations v6 (`result_sets.membership_generation`) and v7 (triggers on `result_set_members` that re-stamp it on any out-of-band member write) run at boot with no operator action; after a restore or repair that bypasses triggers, restart every server (see `docs/user-manual/upgrading.md`).
