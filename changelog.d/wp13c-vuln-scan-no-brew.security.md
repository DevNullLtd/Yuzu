- **macOS `vuln_scan` (`cve_scan`, `scan`, `summary`, `inventory`) does not execute Homebrew's `brew` as root.** The macOS agent runs as root and a Homebrew prefix is owned by the installing user, so `brew list --versions` ran a user-controlled script as root. The macOS software list is `system_profiler` applications only, so CVE findings and server NVD correlation are not produced for Homebrew formulae and casks (`pkg_inventory.packages` lists them without a subprocess; it does not match them). This covers `vuln_scan` only: `installed_apps` still runs `brew` until its own fix (#8184) lands. `cve_scan` and `scan` end with an `INFO|scan|Coverage|Homebrew formulae and casks are not scanned` row and `summary` with `summary|COVERAGE|...`; `inventory` stays pure name/version rows. When `system_profiler` fails, times out, exceeds the 8 MB output cap or returns no applications, no application is matched or listed, the "No vulnerabilities" row is not printed, and the run ends with an `UNREADABLE|scan|Coverage|...` row. A macOS configuration check whose tool cannot be read, or whose first output line is not the expected text, is an `UNREADABLE|config|<check>|Unknown (read failed)` row (counted in `summary`'s `UNREADABLE`), never a HIGH/CRITICAL finding or a pass. The agent log records `CONSTRAINED`/`PARTIAL` for these runs (`macos:vuln_scan:homebrew_not_scanned`, `:system_profiler_unreadable`, `:config_unreadable`). The macOS commands run as absolute-path argvs through the agent's bounded subprocess runner (no shell, no `PATH` search, a 60 s deadline for `system_profiler` and 10 s for the status tools, an 8 MB output cap), one `system_profiler` at a time with its result reused for 45 s.
