- **`vuln_scan` only: the macOS actions (`cve_scan`, `scan`, `summary`, `inventory`) do not execute Homebrew's `brew` as root.** The macOS agent runs as root and a Homebrew prefix is owned by the installing user, so `brew list --versions` ran a user-controlled script as root. The macOS software list is `system_profiler` applications only, so CVE findings and server NVD correlation are not produced for Homebrew formulae and casks (`pkg_inventory.packages` lists them without a subprocess; it does not match them). Restoring Homebrew CVE matching is tracked in #8256. `installed_apps` still runs `brew` until its own fix (#8184) lands.
- **macOS `vuln_scan` reports what it could not read.** `cve_scan` and `scan` end with an `INFO|scan|Coverage|Homebrew formulae and casks are not scanned` row and `summary` with `summary|COVERAGE|...`; `inventory` stays pure name/version rows. When `system_profiler` fails, times out, exceeds the 8 MB output cap, returns no applications, or returns applications more than half of which (counting unrecognised name or version lines) have no recognised English `Version:` line, no application is matched or listed, the "No vulnerabilities" row is not printed, and the run ends with an `UNREADABLE|scan|Coverage|...` row. A configuration check whose tool cannot be read, or whose output is not exactly the expected single line, is an `UNREADABLE|config|<check>|Unknown (read failed)` row (counted in `summary`'s `UNREADABLE`), never a pass; a bad line (for example `assessments disabled`) is reported whatever the exit code. The "Automatic update check" row covers the update check only, not installation, and is read through both the bare `com.apple.SoftwareUpdate` domain and the `/Library/Preferences` path, the worse answer winning. An application that matches a built-in CVE rule but has no usable version (empty, or not starting with a digit) is skipped and reported by an `UNREADABLE|scan|Coverage|<n> application(s) matching a built-in CVE rule had no usable version; not a clean result` row (`macos:vuln_scan:cve_input_incomplete`). Application names are capped at 1 KiB and versions at 256 bytes. There is no open-port check on macOS (one `UNREADABLE` Open Ports row). The agent log records `CONSTRAINED`/`PARTIAL` (`macos:vuln_scan:homebrew_not_scanned`, `:system_profiler_unreadable`, `:config_unreadable`). The status tools' good-state output and the path-form `defaults` key-absent output were measured on one macOS 27.0.1 host; the bare-domain `defaults` output, bad-state exit codes, enabled Firewall digits, `systemsetup` as a launchd daemon and a non-English `system_profiler` are unmeasured and read `UNREADABLE` when the text differs. A backslash in an application name is shown as `/`. The macOS commands run as absolute-path argvs through the agent's bounded subprocess runner (no shell, no `PATH` search, a 60 s deadline for `system_profiler` and 10 s for the status tools, an 8 MB output cap), one `system_profiler` at a time with its result reused for 45 s.
