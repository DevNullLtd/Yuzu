- **`vuln_scan` only: the macOS actions (`cve_scan`, `scan`, `summary`, `inventory`) do not execute Homebrew's `brew` as root.** The macOS agent runs as root and a Homebrew prefix is owned by the installing user, so executing `brew` would run a user-controlled script as root. The macOS software list is `system_profiler` applications only, so CVE findings and server NVD correlation are not produced for Homebrew formulae and casks (`pkg_inventory.packages` lists them without a subprocess; it does not match them). Homebrew CVE matching is tracked in #8256.
- **macOS `vuln_scan` reports what it could not read.** `cve_scan` and `scan` end with an `INFO|scan|Coverage|Homebrew formulae and casks are not scanned` row and `summary` with `summary|COVERAGE|...`; `inventory` stays pure name/version rows. When `system_profiler` fails, times out, exceeds the 8 MB output cap, returns no applications, or returns applications more than half of which (counting unrecognised name or version lines) have no recognised English `Version:` line, no application is matched or listed, the "No vulnerabilities" row is not printed, and the run ends with an `UNREADABLE|scan|Coverage|...` row. A configuration check whose tool cannot be read, or whose output is not exactly the expected single line, is an `UNREADABLE|config|<check>|Unknown (read failed)` row (counted in `summary`'s `UNREADABLE`), never a pass (the standing `Open Ports` row is `UNREADABLE` with no Coverage row and no status, and `inventory` emits no Coverage row); a bad line (for example `assessments disabled`) is reported whatever the exit code. The "Automatic update check" row covers the update check only, not installation, and is read through both the bare `com.apple.SoftwareUpdate` domain and the `/Library/Preferences` path, the worse answer winning. An application that matches a built-in CVE rule but has no usable version (empty, or not starting with a digit) is skipped and reported by an `UNREADABLE|scan|Coverage|<n> application(s) matching a built-in CVE rule had no usable version; not a clean result` row (`macos:vuln_scan:cve_input_incomplete`). A profiler line that does not fit the expected report shape (for example a name without a colon or at an odd indent, a four-space line that is not a name, a name starting `Version:`, a tab, a second `Version:` in a block, a `Version:` that does not directly follow its name line, or an orphaned property line at indent 3 or deeper after a blank) is counted and reported by `UNREADABLE|scan|Coverage|<n> line(s) of the software list were not recognised; applications may be missing; not a clean result` (`macos:vuln_scan:software_list_unrecognised`). Application names are capped at 1 KiB and versions at 256 bytes. Versions are compared as dotted numbers: a version with a pre-release or letter suffix may not be ordered correctly against a fixed version, and on macOS a numeric segment of more than 18 digits is treated as unusable (Linux and Windows saturate such a segment silently). Any non-numeric text in a version segment (`131.0b2`, `0.9 (rc)`, `1e2`) may be misordered (tracked in #8276). A NUL byte in a name or version is replaced with `?` and not detected as a dropped line, and a name line lost together with other faults the parser cannot attribute can still hide an application. There is no open-port check on macOS (one `UNREADABLE` Open Ports row). The agent log records `CONSTRAINED`/`PARTIAL` (`macos:vuln_scan:homebrew_not_scanned`, `:system_profiler_unreadable`, `:cve_input_incomplete`, `:software_list_unrecognised`, `:config_unreadable`). The five status tools' lines were measured on one macOS 27.0.1 host (the Firewall line is the disabled state), as were the path-form `defaults` key-absent line and the bare-domain key-absent text (on macOS 27.0.1 as euid 501 only); a bare-domain value of 0 or 1, system-plist shadowing, bad-state exit codes, the enabled Firewall digit, `systemsetup` as a launchd daemon, Full Disk Access/PPPC needs and a non-English `system_profiler` are unmeasured and read `UNREADABLE` when the text differs. `vuln_scan` shows a backslash in an application name as `/` (`installed_apps` preserves it). The macOS commands run as absolute-path argvs through the agent's bounded subprocess runner (no shell, no `PATH` search, a 60 s deadline for `system_profiler` and 10 s for the status tools, an 8 MB output cap), one `system_profiler` at a time with its result reused for 45 s.
