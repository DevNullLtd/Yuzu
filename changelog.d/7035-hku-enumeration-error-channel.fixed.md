- **A failed or unstable listing of the loaded user hives (`HKEY_USERS`) is no longer read as a complete list on Windows.** The `registry`, `installed_apps`, `license_scan`, `autoruns` and `privacy_permissions` plugins and Echo's mapped-drive history and start-up hive sweep took whatever `HKEY_USERS` enumeration returned, so an enumeration error part-way, or a hive loading or unloading during the walk, could make a logged-on user look logged off and send their profile down the offline-mount path, or hide a leftover mount from the sweep. The listing is now accepted only when two consecutive reads of it return the same names, and a failure is reported as `hku_list_incomplete` (an `error|hku_list_incomplete` line for `registry` and `installed_apps`, a constraint on the per-user sources for `autoruns`, `license_scan` and `privacy_permissions`, a skipped per-user leg with a warning for Echo's mapped drives). A run that previously returned partial per-user data from a failed listing now reports that failure for that run. Echo's start-up sweep logs one `hku_list_incomplete` warning naming the cause for each failed listing and retries once, before the next offline mount, then completes; a host that never mounts a logged-off hive does not retry, and what the sweep missed waits for the next agent start or `reg unload`.
