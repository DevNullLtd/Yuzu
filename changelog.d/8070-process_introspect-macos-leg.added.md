- **`process_introspect`: the macOS leg.** The plugin's `inspect` action now answers on macOS through libproc only (one `proc_pidinfo` call and the `kern.bootsessionuuid` sysctl; no task port is ever requested, and a lexical test pins it). Of the six facets only `sched` is read, and of it only the nice value (policy, realtime priority and CPU list read as a dash), reported as `constrained` with `macos:process_introspect:sched:nice_only`; `resource_limits`, `sigmasks` and `oom` answer `unsupported` (`not_exposed_by_libproc`) and `caps` and `seccomp` answer `unsupported` (`no_os_equivalent`), each as one status row that reads nothing. These macOS answers are permanent, not a degraded read: an agentic worker should not retry or alert on them. The `start_time` guard works as on Linux (a changed process answers `pid_reused`; the start time survives an exec, so the token does not tell a program from the one it exec'd into), and a process of another account answers `permission_denied` unless the agent runs as root (root and negative nice values were not measured). macOS never answers `torn_read`: identity and the nice value come from one kernel snapshot. The Linux leg is unchanged.
