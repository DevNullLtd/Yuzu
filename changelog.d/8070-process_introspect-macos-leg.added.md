- **`process_introspect`: the macOS leg.** The plugin's `inspect` action now answers on macOS through libproc only (one `proc_pidinfo` call, one `proc_pid_rusage` call and the `kern.bootsessionuuid` sysctl; no task port is ever requested, and a lexical test pins it). Of the six facets only `sched` is read, and of it only the nice value (policy, realtime priority and CPU list read as a dash), reported as `constrained` with `macos:process_introspect:sched:nice_only`; `resource_limits`, `sigmasks` and `oom` answer `unsupported` (`not_exposed_by_libproc`) and `caps` and `seccomp` answer `unsupported` (`no_os_equivalent`), each as one status row that reads nothing. These macOS answers are permanent, not a degraded read: an agentic worker should not retry or alert on them. For `sched` the `start_time` guard works as on Linux (a changed process answers `pid_reused`, including a recycled pid after a wall-clock step, because the token folds the monotonic start stamp with the wall-clock one; the start time survives an exec, so the token does not tell a program from the one it exec'd into; the other five facets are answered before any read, so no guard is checked for them), and a process of another account answers `permission_denied` unless the agent runs as root (root and negative nice values were not measured). macOS never answers `torn_read`: identity and the nice value come from one kernel snapshot. The libproc call is bounded: it runs on one worker owned by agent-core with a 5 second deadline, so a target stuck in the kernel exec step answers `deadline_exceeded` (never an empty success) instead of holding an agent command worker, while that abandoned worker is still blocked the next dispatch answers `abandoned_call_pending` instead of starting a second blocked thread, and a dispatch that overlaps another's healthy read answers `call_in_progress` (retry shortly); dispatches read normally again once the worker returns. The Linux leg is unchanged. This replaces the `macos:planned` placeholder: this plugin no longer emits that token. The plugin's kill switch is one all-OS row, so enabling it makes `inspect` dispatchable on Linux and macOS agents alike (the shipped macOS agent runs as root); nothing is read until an authorized operator (an administrator, or a non-admin with a delegated `Forensics:Read` grant and an approval) names a pid. To keep macOS agents out, add an off row for that OS with `PUT /api/v1/plugin-config/process_introspect/kill-switch?os=darwin` and `{"enabled":false}`.
