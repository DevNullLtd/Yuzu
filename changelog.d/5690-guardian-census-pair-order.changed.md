- **Breaking, fresh deployment only: the Guardian census now decides each verdict by the agent's emit-order pair, so a verdict that used to read clean can now be flagged, held or refused (#5690).** The pair `(boot_epoch, emit_seq)` that the server stored and counted since the previous change now drives the census row. While an agent's pair clock is fresh (refreshed under an hour ago on the database clock), an event with a lower epoch, or a sequence not above the highest seen in the live epoch, is refused and flags the row; an equal pair is refused as a duplicate; an event of a retired epoch is refused; and an event with no pair is held against a paired verdict. Once the clock is stale the next such event re-bases the clock (the old epoch is then retired for good, one slot), and an event with no pair applies by arrival, flagged. Every refusal, hold, re-base and change between pair and key ordering sets `order_uncertain`, so anything that gates on `uncertain_rules == 0`, `order_uncertain` or the "Compliant, ordering uncertain" badge will see the flag rise. A pair that is out of bound (`emit_seq` at or above 2^40, or an epoch more than ten years past receipt) is dropped and the event is judged as an unpaired one, counted as `implausible` on `yuzu_server_guardian_pair_rejected_total`. The decision of every census write is counted on the new `yuzu_server_guardian_census_pair_decisions_total{decision}` (ten labels, present at 0 from boot), and `currently_unordered` is now decided in SQL on every read, so it can change with no event and is also true when an agent's pair clock is recorded more than 300 seconds in the database's future. A redelivery repair of a pending event now takes the agent's order row `FOR SHARE` and decides in a read-only mode (it never moves the pair clock or fences the live epoch), runs its census statements under a 2 second bound per statement, and at most 4 repairs run at once in one server process: a repair that finds the cap full is shed at once, writes nothing and leaves its event pending, and because ingest outcomes never reach the agent that event is stranded (a later applying verdict on that pair, a rule delete or a decommission clears it); shed repairs are counted on the new `yuzu_server_guardian_repairs_shed_total` and logged as `repair shed`. A first delivery's per-agent order step is bounded at 3 seconds per statement. Known limits, all documented in the Guaranteed State manual: the retired-epoch fence has no operator clear and ends only when the agent restarts (#7977); an agent whose first deliveries all fail the order step is not counted in `unordered_agents` until its next first delivery (#7959); a `refused_regression` repair never retires its own event (#7960); the cap is fixed at 4 with no per-agent share (#7974, #7975, #7976); and no alert rule ships for any of these signals (#7149).
