- **The standalone `quarantine` agent plugin is removed; device containment is the firewall plugin's four actions.** The plugin (its sources, tests, README, installer entry, capability-catalogue and enablement rows, sink-manifest rows, generated plugin-docs page and nav entry) is deleted, together with its four actions (`quarantine.quarantine`, `quarantine.unquarantine`, `quarantine.status`, `quarantine.whitelist`), its four instruction-definition ids (`security.quarantine.isolate`, `.release`, `.status`, `.whitelist`; the definitions move to `security.firewall.quarantine`, `.release`, `.quarantine_status` and `.quarantine_allow`), the firewall plugin's refusal while the old plugin's rules were present, and the `/test --instructions-quarantine` ceremony with its scripts. This is a hard cut: there is no alias for the old action or definition names, no version-skew guard and no data migration, so an agent and a server must both be this build. The server's quarantine routes, MCP tools, dashboard controls and audit verbs keep the word "quarantine"; they drive `firewall.quarantine`, `firewall.release`, `firewall.quarantine_status` and `firewall.quarantine_allow`, which remain the closed set of protective actions that no kill switch, per-OS withhold, plugin-presence filter or degraded store may refuse. This build neither removes nor detects firewall rules left on a host by an earlier build.
