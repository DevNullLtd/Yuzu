- **BREAKING: `/metrics` requires authentication from every peer, loopback included.** A reverse proxy, sidecar or tunnel on the server host makes remote callers look like `127.0.0.1`. A scrape job sends a bearer token, or the server runs with `--metrics-no-auth`, or with the opt-in `--metrics-trust-loopback` (`YUZU_METRICS_TRUST_LOOPBACK`, default off; a direct loopback peer only, a request carrying a forwarding header is still treated as remote, and any local unprivileged process can then read `/metrics`). Any principal's API token is accepted (no permission is checked); the worked recipe (mint, `credentials_file` mode, rotation) is `docs/user-manual/metrics.md`, "Scraping /metrics with a bearer token". `deploy/prometheus/prometheus.yml` carries the `authorization` block (its token file is not shipped), `scripts/start-stack.sh` and the dev `docker-compose.yml` run the server with `--metrics-no-auth`, and the new `YuzuServerMetricsScrapeDown` alert reports a failing scrape.
