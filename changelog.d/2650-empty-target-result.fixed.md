- **Breaking —** A dispatch that matches no devices now says so (#2650). Instead of a `503` that read as a transport failure, `POST /api/command`, `POST /api/v1/commands`, both stored-instruction execute routes (legacy and v1) and the legacy diagnostic dispatch routes (`/api/chargen/*`, `/api/procfetch/fetch`) answer `422` with reason `no_targets`, not retryable, and the MCP execute tools return status `no_targets`. v1 workflow execute stays `503`, with `error.reason: no_targets`, not retryable. A target list that cannot be read answers `target_resolution_failed` (retryable), and a scheduled occurrence that hits it is delivered again. Scope and broadcast targeting consider only connected agents, so just after a server or gateway restart wait for agents to reconnect before treating `no_targets` as final. Naming a device id that does not exist, from a caller whose dispatch is not confined, still answers `no_agents_reached`.
