- **A pre-flight check whose response window is full no longer reports devices outside it as unanswered (#4644).** Each pre-flight check reads its newest 50,000 responses for a run (a sliding window), so on a very large cohort a device that answered earlier could be pushed out of the window and then read as "no response", while the runner kept re-dispatching and pushing more answers out. A device absent from a saturated window is now labelled `inconclusive: response cap reached`, stays **Incomplete** (never go, so it is not in Deploy's go cohort), and the runner stops re-dispatching that run's checks; the run still completes at its deadline. `PreflightCheckResponses` gains `truncated`, and `PreflightRunner::Deps` gains `response_fetch_cap` (a test seam; production keeps 50,000). Per-device paging of the read remains a tracked follow-up.
