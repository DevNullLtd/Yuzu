- **The server now stores the Guardian emit-order pair `(boot_epoch, emit_seq)`, orders census verdicts by it and reports the agents that send none (#5690).** `guaranteed_state_store` schema v5 (additive, for a fresh database) adds nullable `boot_epoch` and `emit_seq` to the event and census tables and a per-agent order table, `guardian_agent_order`, holding each agent's pair clock and counters. A pair is taken only when both values are set, each is below 2^62, `emit_seq` is below 2^40 and `boot_epoch` is at most ten years past receipt; a half-set or out-of-range pair is stored unpaired and counted on the new `yuzu_server_guardian_pair_rejected_total{reason}` (`half_set`, `out_of_range`), and an `implausible` pair (outside the 2^40 and ten-year bounds) is counted there too (`implausible`) and is judged as an unpaired event. `GET /api/v1/guaranteed-state/status` and the MCP tool `get_guardian_status` gain `unordered_agents` and `unordered_agent_ids` (the first 50, confined to the caller's scope): the agents whose latest accepted unpaired census-bearing event is later than the time their pair clock last advanced, including agents that never sent a pair, or whose pair clock is recorded more than 300 seconds in the database's future. `GET /api/v1/guaranteed-state/agents/{agent_id}/rules` and `get_guardian_device_guards` gain `ordering`, the device's order row (`null` when it has none). The new gauge `yuzu_server_guardian_census_unordered_agents` exports the fleet count. Between two events that both carry a pair the census verdict follows the pair (a higher epoch, or a higher `emit_seq` in the same epoch, applies), so a clock step on the endpoint cannot let an older verdict replace a newer one; while the agent's pair clock is fresh (refreshed less than an hour ago) a lower epoch or a lower sequence in the same epoch is refused, and so is an event without a pair against a paired verdict (held), each flagging the row `order_uncertain`; an equal pair and an event of a retired epoch are refused and flag it too, and a stale clock is re-based by the next event, applied and flagged. The decisions are counted on the new `yuzu_server_guardian_census_pair_decisions_total{decision}`, and the order row's counters (`pair_duplicates` included) count what the clock decided. Two events without a pair are still ordered by the census ordering key. Decommissioning a device (`DELETE /api/v1/sle/agents/{id}`) now also deletes its order row, first, in the same transaction; erasure of the `guaranteed_state` store stays partial. Two first deliveries for the same agent now run one after the other (a different agent is not delayed until the shared database connection pool saturates); measured on one development host with 10,000 pending events on one pair, a first delivery for another rule of that agent waited about 0.15 s. Each lock wait in the agent step is bounded at 1 s, and one step can wait more than once (Ensure, DECIDE and one re-run after a concurrent delete), so a pooled connection can be held for the sum of those waits; a wait that reaches the bound stores the event with pending census evidence and skips its census write.
