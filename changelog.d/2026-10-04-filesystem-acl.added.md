- **The `filesystem` plugin's `get_acl` action now reports the access-control entries on Linux and macOS, not just the basic owner, group and permission bits.** Linux decodes the POSIX ACL extended attributes (`system.posix_acl_access` and, for a directory, `system.posix_acl_default`) into one row per user, group, mask and other entry, with default entries marked. macOS reads the extended ACL and reports each entry's allow or deny, principal, permissions and inheritance flags. On Windows the descriptor's control flags are reported as a `control` row, each entry carries its inheritance flags, and a conditional or other unmodelled entry is reported as a row of its own instead of being dropped. A read that fails is reported as unreadable with a reason, never as a file with no ACL. Windows `ace` rows now carry a fifth field with the inheritance flags, an undecoded ACE type prints `-` for its mask instead of a zero, and a failed `GetAce` or `GetAclInformation` now ends the command with an error instead of silently returning fewer rows.
