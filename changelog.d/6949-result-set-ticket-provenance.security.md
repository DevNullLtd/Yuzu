- **`create_result_set_from_instruction_result` and `reevaluate_result_set` no longer let an approval ticket lift the admin-or-approval gate of a stored definition's action.** A definition's `plugin.action` is read from the stored definition when the call runs, and an approval of an action resolved indirectly from a store is not taken to lift that action's own gate (the ticket also binds the resolved action now, so a repoint is itself refused: see the separate ticket-binding entry). Both tools now leave the action's own gate in force: a non-administrator on a gated action is refused with `-32003` and `error.data.reason = approval_required` (permanent, no retry hint) before any execution record is created. Supervised-tier non-admin tokens can therefore no longer use a ticket to run a gated action through these tools; administrators are unaffected. `execute_bundle` is unchanged because the actions it runs are part of the ticketed arguments.
