- **Echo's registry source no longer loses siblings or merges names it cannot represent.** More than 32 child keys that deny read access no longer stop the walk: the rest of the root is read, so adds and changes under later siblings land, and the gap row says how many denied children are not named (the read stays partial, so no removals are derived). A child key whose name contains U+0000 is never opened (it would open a different key); it is reported as a skipped child. Value and key names that are not valid UTF-16 (a lone surrogate) now keep a distinct stored identity instead of collapsing into one replacement-character name, and a name that really contains U+FFFD is stored doubled. Names previously stored with a replacement character (a lone-surrogate name, or one that really contains U+FFFD) are reported once as a removed and an added row after the upgrade. A case-only rename stays a removed and an added row, as before.
