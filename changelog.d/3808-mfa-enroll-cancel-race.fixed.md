- **A pending MFA enrolment that changes while its first code is being confirmed is no longer reported as a store outage (#3808).** If the pending enrolment secret was cleared or replaced between loading it and committing the enrolment (a disable, a fresh enrolment, the stale-provisional sweep, `--mfa-reset` or a key rewrap), the confirm used to answer `503`, count a secret-unavailable degrade and write a critical "store unavailable" audit event. It now reports that the enrolment was cancelled or replaced and audits `mfa.enroll.cancelled` with the detail `reason=provisional_secret_changed; nothing enrolled`; nothing is enrolled either way. For integrators: `POST /login/mfa/enroll` answers `409` instead of `503` for this case (the pending token is spent, so sign in again), the audit verb is `mfa.enroll.cancelled` instead of `mfa.enroll.failed`, and `yuzu_auth_secret_unavailable_total{route="mfa_enroll"}` no longer counts it. In Settings the page now offers the Set-up button again.
