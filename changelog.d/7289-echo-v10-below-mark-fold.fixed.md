- **Echo's roll-up migration folds the raw rows the old roll-up skipped, where the converted tier shows they were never summarised, and no longer adds rows twice under a stepped-back clock.** This replaces the statement in the "Echo stores roll-ups only" entry that raw rows older than the old roll-up mark are not carried into the tiers. The schema v10 migration folds a raw row dated before the old roll-up's mark only when the converted hourly tier (the daily tier for `user` and `software`) holds no row for that row's bucket and key and the bucket is newer than the tier's oldest. Rows the old clock-gap clamp skipped and rows a backfill wrote are counted once where both tests pass; a row whose bucket and key the tier already holds (including one an old clock excursion stamped ahead of the clock, and one under a clock set back from a sane mark, as after a restored snapshot or a time step) is not counted again. The step that finishes the old hourly-to-daily and daily-to-monthly roll-ups does the same for an upper bucket and key the upper tier already holds. The migration log line reports the raw rows read below the mark, how many of their events were folded and how many skipped, and the roll-up rows left out because the upper tier already held them; a large skipped figure is normal, because most raw rows below the mark had been summarised before their hour aged out. Left out on purpose, so a total can read low but no row is added twice: rows at or before the oldest bucket the converted tier holds (an older build kept hourly rows for 24 hours, 31 days for `perf` and `procperf`, and daily rows for 31 days, so on most sources only about the last day before the upgrade is recovered), a row whose bucket and key the tier already holds although the row itself was never summarised, and a month the monthly tier already holds, which is not completed.
