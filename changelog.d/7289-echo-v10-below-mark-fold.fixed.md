- **Echo's roll-up migration no longer drops raw rows the old roll-up never summarised, or adds rows twice under a stepped-back clock.** An agent that upgrades from a build older than the one that introduced the roll-up tiers folds a raw capture row dated before the old roll-up's mark only when the converted hourly (or daily) tier is missing that row's bucket and key and the bucket is newer than the tier's oldest; rows the old clock-gap clamp skipped and rows a backfill wrote are now counted once instead of being discarded, and a row already in a converted bucket (including one stamped ahead of the clock, or one under a clock set back from a sane mark) is no longer counted again. The step that finishes the old hourly-to-daily and daily-to-monthly roll-ups does the same for an upper bucket and key the upper tier already holds. The migration log line reports the rows read below the mark, the events folded and skipped, and the roll-up rows left out. Left out on purpose, so a total can read low but never high: rows in the range the old byte budget evicted from the first tier, and the rest of a monthly bucket whose old range began mid-month after a clock-gap clamp.
