- **Breaking - a result set that is pending, failed or incomplete is refused where it could be misread.** A `from_result_set:<id>` scope now aborts (`result_set_unusable`; `retry_after_ms` 5000 for a pending set, null for a failed or incomplete one: re-run the producer) when the set is still pending or has failed, and when the set is incomplete (an agent answered with an error, never answered before the set was filled at the timeout, or had part of its answer lost) and is referenced where a missing member would match, such as under `NOT`. A positive reference to an incomplete set still resolves. Result sets record the number of unanswered agents in a new `agents_unanswered` column (schema version 5), and `agents_unanswered` is returned beside `agents_failed` on REST and MCP with `partial` true when either is above zero. A set created from a parent is refused with `RESULT_SET_NOT_READY` (REST `409`, MCP `-32602`) when the parent is still pending or has failed, and otherwise inherits the parent's incompleteness at creation (inherited counters sum along a lineage, so only `partial` is a reliable signal), and an agent whose answer, terminal or streamed, was counted but not fully stored stays recorded as unanswered once a set is filled. A result set can no longer be built from a Forensics-tier plugin (`RESULT_SET_SOURCE_NOT_SUPPORTED`, REST `400` and MCP `-32602`, before anything is dispatched).
