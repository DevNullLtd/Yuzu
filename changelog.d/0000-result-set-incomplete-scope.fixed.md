- **A result set that is not ready or is incomplete is no longer used under NOT.** A `from_result_set:<id>` scope now aborts (`result_set_unusable`) when the set is still pending or has failed, and when the set is incomplete (an agent answered with an error, never answered before the set was filled at the timeout, or had part of its answer lost) and is referenced where a missing member would match, such as under `NOT`. A positive reference to an incomplete set still resolves. Result sets record the number of unanswered agents in a new `agents_unanswered` column (schema version 5), and `agents_unanswered` is returned beside `agents_failed` on REST and MCP with `partial` true when either is above zero; sets filled earlier read 0 and are treated as complete. A set created from a parent is refused when the parent is not yet materialized and inherits the parent's incompleteness at creation (inherited counters sum along a lineage, so only `partial` is a reliable signal), and an agent whose answer, terminal or streamed, was counted but not fully stored stays recorded as unanswered once a set is filled. A result set can no longer be built from a Forensics-tier plugin (`RESULT_SET_SOURCE_NOT_SUPPORTED`, REST `400` and MCP `-32602`, before anything is dispatched).
