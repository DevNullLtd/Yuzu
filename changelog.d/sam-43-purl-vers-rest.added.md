- **The software lookup routes now return and filter by Package URL, and accept a `vers:` version range.** Each row of `GET /api/v1/inventory/software` carries `purl` (null when the row has none), the CSV export gains a 23rd column `purl`, and `purl=` selects rows whose stored purl equals the value exactly (it must start `pkg:`; a purl filter turns the totals off). Both `GET /api/v1/inventory/software` and `GET /api/v1/inventory/software/components` accept `vers=vers:<scheme>/<constraints>` for any range of versions, including several intervals and exclusions; it needs `name` with `match=exact` and is not combined with `version`, `version_min` or `version_max`. `generic`, `semver`, `maven`, `npm`, `pypi` and `nuget` are evaluated with the one catalogue version comparator (so a scheme's own edge ordering can differ), `deb` and `rpm` are refused by name, and any other scheme is a `400`. `version_min` / `version_max` now resolve through the same evaluator, and the CVE matcher shares its interval check. Rows have 23 fields and the CSV 23 columns, so a consumer that pinned a column count or position must read by name. The MCP tools are unchanged (tracked in #7749).
