- **Behaviour change: a Guaranteed State delta push (`full_sync=false`) that omits a still-unresolved rule no longer drops that rule's retry obligation (#5547).** The agent used to replace its open acknowledgment application on every push, so a delta that named only some rules forgot the pending, wedged or failed arm of the rules it left out, and the policy generation could then be acknowledged while an omitted rule was still unarmed with nothing left to retry it. A delta now carries the unresolved outcome of every rule it does not name into the new application (pending arms, retained wedges, drained arm failures and per-rule apply failures), so the generation stays held until a full push, or a push that names the rule, replaces it. On a Spark-enforcing agent a carried arm failure or wedge also keeps counting in `yuzu.guardian_arm_failed`; a carried per-rule apply failure and the application-wide latch hold the generation without being counted there, and the default `prefer_spark=false` agent emits no arm gauge. A carried failure is not retried by repeating the delta, and the REST and MCP push endpoints do not bump the generation, so a delta at the generation the agent already holds is not followed by an automatic full push: send a full push to retry it (a full push first tears down the agent's legacy Guards, and if the agent log shows it failed partway, fix the cause and send it again). An apply failure with no rule id (a full push's rule-key sweep, key delete or teardown failure, a failure to persist a rule, or an exception that unwinds out of a push) is now inherited by later deltas, on the legacy path too, and cleared only by a full push whose steps all succeed; before, the next delta forgot it and the generation was acknowledged. A boot re-arm failure is recorded against its rule, so an unrelated delta no longer clears `yuzu.guardian_boot_rearm_unresolved` (except when the boot application could not be opened, a known residual described in the Spark flip gate, AC-13), and a delta that names the rule clears it only when it arms the rule cleanly and nothing else is still unresolved; only a full push now counts toward the boot catch-up back-off. A push that names the same rule id twice is rejected before anything is changed, and an allocation failure after the agent has begun applying a push now leaves the application latched instead of acknowledgeable. The wedged-rule suppress budget still restarts on every replacement, as before, so with a carried hold alternating deltas and full pushes leave a hold with no elapsed-time bound, and `yuzu.guardian_arm_failed` can hold at a nonzero value across omitting deltas, including for a wedge that was adopted or settled before the agent retained it (see the Spark flip gate, AC-11 and AC-15).
