- **Engine credential mint and rotate fail closed when the token store cannot be read, on REST and MCP.** `POST /api/v1/engine-principals/{id}/credentials` and the MCP tool `mint_engine_credential` check for an existing active credential through the checked read, and answer `503` (REST, with `Retry-After: 2`) or a retryable error (MCP, with `retry_after_ms`) without minting when that read fails, so retrying after that failure is safe. If the credential was minted but cannot be read back, the secret is withheld and the audit row is `engine_principal.credential.mint` with `result=partial`; rotate the credential to obtain a secret. `POST /api/v1/engine-principals/{id}/credentials/rotate` and `rotate_engine_credential` read the new successor back before recording the reveal; when that read fails, or finds no linked successor, they answer `503` / a retryable error, withhold the secret and write `engine_principal.credential.rotate` with `result=partial` and no reveal row, instead of returning `200` with an empty `token_id`. A retry by the same operator within the grace window (about two minutes, same server replica) re-serves the same secret. The audit-log result vocabulary now lists `partial`.
- **The engine no-admin auditor fails closed.** `GET /api/v1/engine-principals/audit/no-admin` and `audit_engine_no_admin` now share one implementation that reads the grants, roles and role permissions through checked reads. A read that cannot be answered returns `503` / a retryable error with no partial list and an `engine_principal.audit.no_admin` row with `result=failure`, instead of `ok:true` over a deployment that could hold a violation. A `wildcard_grant` now names the role, a grant held through a `user`-typed row for an `engine:` id is caught, and the success audit row names up to ten detected `principal_id:reason` pairs.
