- **Breaking for alert rules — an OTA update refused because the agent's own trust bundle cannot be loaded is now counted as `yuzu_agent_ota_signature_refused_total{reason="bundle_unreadable"}` and logged as `OTA update <version> REFUSED: the update trust bundle could not be loaded`, no longer `reason="untrusted"` / `signature verification FAILED (untrusted chain)` (the grep string the 0.14.0 notes gave for #5196).** Rules, dashboards or saved searches keyed on the old reason or text for this fault need updating; for those faults (missing, permission-denied, not PEM) the refusal itself is unchanged, and the heartbeat total `yuzu.ota_signature_refused` (so `yuzu_fleet_ota_signature_refusing_agents`) still includes it. **New refusal: both `--update-trust-bundle` and `--plugin-trust-bundle` are now read bounded — a bundle over 1 MiB, one that is not a regular file, or (Windows) one currently open for writing by another process is refused, where 0.14.0 loaded it; with `--update-require-signature` or `--plugin-require-signature` that blocks every signed update or plugin, so check the bundle size before upgrading (see the upgrade notes).** Agent-only; no server change.
