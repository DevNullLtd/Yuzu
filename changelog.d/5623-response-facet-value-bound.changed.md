- **Breaking: an unmatchable facet filter value is refused instead of answered as zero (#5623).** `GET /api/v1/management-groups/agent-count-preview` now answers `400` (A4 envelope) and MCP `preview_management_group_agent_count` answers `-32602` for a filter value over 2048 bytes or containing a NUL byte or a line feed (REST also refuses invalid UTF-8; over MCP an invalid-UTF-8 byte or a lone surrogate escape fails the JSON parse of the request with `-32700` and a null id), where both used to answer `agent_count: 0`. The check runs before key resolution, so the same value under an unrecognised key is refused too, and on the REST route any query parameter other than `command_id` and `plugin` over 2048 bytes is refused. The dashboard results fragment answers HTTP `200` with a refusal row, and the create-group fragment with a refusal marker (both carry `data-filter-refused`), instead of an empty table or a preview. See `docs/user-manual/upgrading.md` for the rolling-upgrade caveat and what to change in scripts. The two malformed-`filters` MCP errors of that tool now carry the A4 `error.data` (code and message unchanged).
