- The server now refuses to open a Postgres store whose recorded migration differs from this build's (#7158); for nearly every store that stops the server from starting, but `analytics_event_store`, `crypto_dashboard_layout_store` and `leader_elector` degrade or keep booting instead (see the upgrade notes for the log line and metrics that show it). The migration runner records the SHA-256 of each migration it applies and checks it on every start; a mismatch means the database applied different SQL, and the store logs the version and both hashes and does not open. A database that predates the record is recorded as it is on its first start, so an existing development or UAT database is not refused for a change that was made before then; only an edit made after a database recorded a migration is. A hand-edited or damaged record is refused with its own message. See "a Postgres store refuses to open when its recorded migration differs from this build" in the upgrade notes.
