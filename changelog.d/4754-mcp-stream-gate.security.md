- **Require authorisation on the MCP stream endpoint.** `GET /mcp/v1/` now refuses service-scoped API tokens (`403`, audited `mcp.session.reject` `reason=service_scoped`), and MCP sessions are bound to the credential class that created them: a session id presented by a different class (authentication source, principal kind, MCP tier, service scope) answers the same `404` as an unknown session, audited `reason=credential_mismatch`. A service-scoped caller that sent no session id to `GET` now sees `403` rather than `400`; see "Upgrading" for client guidance.
