- **Breaking - require authorisation on the MCP stream endpoint.** `GET /mcp/v1/` now refuses service-scoped API tokens (`403`, audited `mcp.session.reject` `reason=service_scoped`), and MCP sessions are bound to the principal and credential class that created them (authentication source, principal kind, MCP tier, service scope; not elevation state): a session id presented by a different class answers the same `404` as an unknown session, audited `reason=credential_mismatch`. A service-scoped caller that sent no session id to `GET` now sees `403` rather than `400`. A client that sees `404` on a live session id must re-run `initialize`; see "Upgrading" for client guidance (#4754).
