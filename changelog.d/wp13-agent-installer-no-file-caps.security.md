- **Breaking —** **The dev/UAT installer (`install-agent-user.sh`, Linux and macOS) no longer puts file capabilities on the agent binary and no longer writes the `systemctl` or `launchctl bootstrap|bootout` sudoers globs.** It used to set `cap_net_admin,cap_net_raw,cap_dac_read_search,cap_sys_ptrace` on a 0755 binary whose invoker chooses the plugin directory it loads, so on a multi-user dev host any local account could obtain them. It now strips file capabilities (re-run it on every existing dev/UAT host; `start-UAT.sh --as-user` refuses a binary that still carries one and grants `cap_dac_read_search` ambiently with `setpriv`), and the `systemctl enable|disable|mask|unmask *` grants (which matched `enable --now <unit path>`) become one grant for a root-owned validating wrapper `/usr/libexec/yuzu/yuzu-systemctl`. A sudoers validation failure now fails the install (exit 3) and removes the previous file. The bare `iptables`, `nft -f *` and `pfctl` grants remain (#7634, #7629), so the file is narrower, not narrow. The installer and capability changes do not touch the packaged unit (it never had either); the separate `/proc` status change does. See "Upgrading".
