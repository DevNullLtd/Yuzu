- **Breaking —** **The dev/UAT installer (`install-agent-user.sh`, Linux and macOS) no longer puts file capabilities on the agent binary and no longer writes the `systemctl` or `launchctl bootstrap|bootout` sudoers globs.** A file capability such as `cap_net_admin,cap_net_raw,cap_dac_read_search,cap_sys_ptrace` on a 0755 binary whose invoker chooses the plugin directory it loads would let any local account on a multi-user dev host obtain it. It strips file capabilities on every run (`start-UAT.sh --as-user` refuses a binary that still carries one and grants `cap_dac_read_search` ambiently with `setpriv`), and the `systemctl enable|disable|mask|unmask *` grants (which matched `enable --now <unit path>`) become one grant for a root-owned validating wrapper `/usr/libexec/yuzu/yuzu-systemctl`. A sudoers validation failure fails the install (exit 3) and removes any existing sudoers file. The bare `iptables`, `nft -f *` and `pfctl` grants remain (#7634, #7629), so the file is narrower, not narrow. The installer and capability changes do not touch the packaged unit (it has neither); the separate `/proc` status change does. See the WP13 section of `docs/user-manual/upgrading.md`.
