- **An `agent_id` containing a NUL byte is now refused as defence in depth (behaviour change for the custom-properties store).** Text binds take the id as a NUL-terminated string, so agent `Register` (direct and through the gateway) now also rejects such an id with `INVALID_ARGUMENT`, counted in `yuzu_register_invalid_agent_id_total{reason="nul"}`, instead of relying on the earlier pending-status check alone. Separately, the custom-properties store now refuses a write or delete for an `agent_id` that is empty, contains a NUL byte or is longer than 256 bytes (`PUT` returns 400, `DELETE` 404, and `delete_all_properties` is a logged no-op), as the tag store already did, and its reads answer empty for such an id. The Guardian ingest warnings now neutralise the agent id, observation type, action name and store error text they print, the same way the rule id already was, and the log-injection tripwire now flags a raw `agent {}`, `agent={}`, `agent '{}'` or `agent: {}` in the Guardian and Spark sources.
