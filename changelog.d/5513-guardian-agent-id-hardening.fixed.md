- **Embedded NUL ids are refused up front on registration and by the custom-properties store.** Agent `Register` (direct and through the gateway) now rejects an `agent_id` containing a NUL byte with `INVALID_ARGUMENT`, counted in `yuzu_register_invalid_agent_id_total{reason="nul"}`, instead of relying on the AuthDB agent-id check alone. An id the enrollment store itself refuses (a control byte or `,`) is now counted as `yuzu_register_invalid_agent_id_total{reason="control"}` and logged at warn level instead of as an enrollment store failure; the response is unchanged. The custom-properties store now refuses a write or delete for an `agent_id` that is empty, contains a NUL byte or is longer than 256 bytes (`PUT` returns 400, `DELETE` 404) and answers reads empty for such an id, as the tag store already does. The registration, update-check and update-download logs, the agent certificate signing logs on the registration path, the agent registry's registration and revoke logs, the command-completion logs, the gateway stream-status and Guardian-forwarding logs, the custom-properties store's and the tag store's database error text, agent ids and tag keys, the custom-properties store's invalid-pattern warning, the runtime-config route's store error and key logs, the database pool's connect-failure and transaction-start failure text, and the Guardian ingest warnings now print agent-supplied values (agent ids, hostnames, scopable-tag keys, command ids, plugin names, gateway node names, gateway cluster ids, observation types and action names) and store error text in neutralised form. Log lines that print an agent id read back from the session table or the enrollment store (the Heartbeat, BatchHeartbeat, ReportInventory and ProxyInventory ingest paths and the shared ingestion modules they call, the Subscribe stream open and close lines, and the agent registry's removal and sweep lines) print it as stored: the enrollment store has already refused control bytes and `,` in it, so it cannot add a newline-delimited line, but an id enrolled or imported before the new-id character check may still contain a space, `=` or a non-ASCII byte, and so can add same-line `key=value` tokens. The exception text of the ingest catch-alls on those paths is printed as is.
