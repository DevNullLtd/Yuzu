- **Embedded NUL ids are refused up front on registration and by the custom-properties store.** Agent `Register` (direct and through the gateway) now rejects an `agent_id` containing a NUL byte with `INVALID_ARGUMENT`, counted in `yuzu_register_invalid_agent_id_total{reason="nul"}`, instead of relying on the AuthDB agent-id check alone. The custom-properties store now refuses a write or delete for an `agent_id` that is empty, contains a NUL byte or is longer than 256 bytes (`PUT` returns 400, `DELETE` 404) and answers reads empty for such an id, as the tag store already does. The registration, update-check and update-download logs, the agent registry's registration and revoke logs, the command-completion logs, the gateway stream-status and Guardian-forwarding logs, the custom-properties store's database error text and the Guardian ingest warnings now print agent-supplied values (agent ids, hostnames, scopable-tag keys, command ids, plugin names, gateway node names, gateway cluster ids, observation types and action names) and store error text in neutralised form.
