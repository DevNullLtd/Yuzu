- **New `process_introspect` plugin: read-only security posture of one process, one facet at a time.** The `inspect` action takes a numeric `pid` and one `facet` (`resource_limits`, `sigmasks`, `caps`, `seccomp`, `oom` or `sched`) and returns numbers, 16-digit masks and fixed tokens only; file or memory contents, environment values, socket payloads and command-line arguments are never read or returned. On Linux it opens `/proc/<pid>` once and reads every per-process file relative to that descriptor, and an optional `start_time` token from an earlier inspect refuses a recycled pid (`pid_reused`) while a process that changes during the read is discarded (`torn_read`); on a host that mounts `/proc` with `hidepid=2` or above, a pid that is not found answers `no_such_process_or_hidden` rather than claiming the process is gone. It is a Forensics-class plugin: default-off behind its plugin-config kill switch, `Forensics:Read` with an approval gate for non-administrators, and one device per request (scheduled runs excepted, see authz-model.md). macOS and Windows answer one `unsupported` status row (`macos:planned`, `windows:planned`) until their legs land.
