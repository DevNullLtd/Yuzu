- **Agent reconnect delays are now randomised (HA WS-13, #291).** After a lost connection the agent used to wait exactly 2, 4, 8 ... 256 seconds, so every agent that lost the same gateway node came back at the same instants. Each retry now waits a random whole number of seconds from a window around the same value (half to one and a half times it): the first retry 1 to 3 seconds, the second 2 to 6, and so on, never less than 1 second and never more than 300 seconds. Up to the 128 second step the average delay is unchanged, so a lone agent recovers as quickly as before. From the eighth retry on the window is 128 to 300 seconds (average about 214 seconds where the fixed delay was 256), so the longest single wait grows from 256 to 300 seconds. The first retry is spread over only three seconds, so a fleet that lost a node returns in a few flatter bursts rather than all at once. The pending-registration retry uses the same delays, so an approved agent can wait up to 300 seconds for its next attempt. This covers a lost connection only: a restarted agent still connects at once, and the heartbeat-driven re-registration cooldown is untouched. An agent whose operating system has no entropy source starts normally with a clock-derived seed and logs a warning. No configuration changes. The gateway manual also records the topology requirements for agent failover (certificate names, stable addresses for quarantine, agents of 0.15.0 or later).
