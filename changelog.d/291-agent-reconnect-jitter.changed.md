- **Agent reconnect delays are now randomised (HA WS-13, #291).** After a lost connection the agent used to wait exactly 2, 4, 8 ... 256 seconds, so every agent that lost the same gateway node came back at the same instants. Each retry now waits a random time centred on the same value (the first retry 1 to 3 seconds, the later ones up to half again either side), never less than 1 second and never more than 300 seconds. The average schedule is unchanged, so a lone agent recovers as quickly as before; a fleet that lost a node returns spread out instead of in waves. The pending-registration retry shares the same delays. No configuration changes, and the heartbeat-driven re-registration cooldown is untouched. The gateway manual also records the topology requirements for agent failover (certificate names, stable addresses for quarantine, agents of 0.15.0 or later).
