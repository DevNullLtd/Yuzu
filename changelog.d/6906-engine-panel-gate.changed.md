- **Breaking: the Settings Engine Principals panel now needs `EnginePrincipal:Read`, as `GET /api/v1/engine-principals` does (#5882).** With RBAC enabled, an account administrator who does not hold the permission (for example one whose only role is a custom role) is refused and sees "You do not have permission to view this panel" where the list was; grant `EnginePrincipal:Read` (the built-in `Administrator` and `Viewer` roles hold it) to restore it. Newly admitted: with RBAC enabled, a non-administrator who holds the permission, such as a `Viewer`, can read the panel at its URL although the `/settings` page stays administrator-only. An MCP-tier token is still refused by the panel. The panel now writes one `engine_principal.list` success row per view, as the route does, and the revoke cell of a revoked principal, now labelled "Detail (earliest retained record)", shows the audit trail's oldest retained committed revoke detail to callers who also hold `AuditLog:Read` (best-effort: audit retention, a revoke whose audit row failed to persist, or an MCP revoke given no reason can make it differ from the revocation's own record); before this change the lookup never matched and every revoked row read "(not recorded)". A refused browser session writes no denial row (the panel auto-loads); a refused token or engine credential does, and an API token that lacks `AuditLog:Read` writes one more denied row on a view that lists a revoked principal. The panel applies the route's permission test and differs from it in a few listed ways (see [upgrading](docs/user-manual/upgrading.md)).
