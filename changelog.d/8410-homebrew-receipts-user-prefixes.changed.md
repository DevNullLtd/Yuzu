- **Breaking - the `pkg_inventory.packages` Homebrew row grows from five to eleven fields, and a carried database records one remove and one install per Homebrew row on a Mac's first sync from this build.** A machine row now fills the installed-software `install_date` (formula rows only) and `install_location` (the machine prefix). A fresh database is not affected: the first full section for a facet is a baseline and writes no change-ledger rows, and a supported deployment starts from a fresh database. Only a development or UAT database that already holds a Mac's Homebrew rows from an earlier build is affected, because the install location is part of a row's identity and goes from empty to the prefix: on that Mac's first sync each Homebrew formula and cask row is recorded as one `remove` and one `install` at an unchanged version. They show in `GET /api/v1/inventory/software/changes`, the MCP `list_software_changes`, the summary's install and removal counts and `yuzu_software_changes_total{kind}`; the same device, facet `pkg_inventory.packages`, name and version on one `observed_at`, with no cause label, identify them. It happens once per Mac, the pairs are pruned with the ledger after 400 days, and no action is needed. An in-place upgrade is not a supported path ([Upgrading](docs/user-manual/upgrading.md)).
