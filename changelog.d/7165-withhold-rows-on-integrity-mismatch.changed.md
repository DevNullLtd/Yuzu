- **Device-record sections with a failed integrity check no longer carry their rows.** On `GET /api/v1/hardware/{id}` and the MCP tool `get_hardware_ci`, a section served with `server:row_count_mismatch` or `server:content_digest_mismatch` now has `rows: []`; its `status` (`constrained`), reason token and `complete: false` are unchanged. The rows read in that state are a partial set or not the values the agent reported, and a consumer that reads `constrained` as "partial but true" would otherwise take them as the device's hardware. This also applies when the agent's own level was already `constrained` (for example `server_cap:<n>`). `server:content_digest_unverifiable` keeps its rows, since nothing shows them to be wrong. A full device-record sync repairs either mismatch (#7165).
