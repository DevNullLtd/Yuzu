- **Plugin output can now be audited per action: the agent stamps `CommandResponse.action`, and the server mints `registry.write` audit rows from a `registry` plugin's `audit|` lines.** The agent stamps the dispatched action (the existing proto field 8, about 10 bytes per frame) on every output frame and on the final frame of every plugin command. The server turns the `audit|` lines a `registry` command streams from its mutating actions (`set_value`, `delete_value`, `delete_key`) into `registry.write` audit rows carrying the old and new values, `principal=agent:<agent_id>` and the `command_id` that joins each row to the operator's dispatch row. A row is minted only when the stamped action is one of those three, the plugin is `registry` (matched ASCII-case-insensitively) and the `command_id` has a shape the server could have minted (at most 160 bytes of `[A-Za-z0-9_.-]`); a read action never mints one, and an agent that predates the stamp mints none, so during a mixed-fleet rollout only upgraded agents are audited. A failed audit write ends that frame's rows and sets the gRPC audit-failed trailer on the agent's stream (the gateway path logs it). No `registry` plugin build emits `audit|` lines yet, so no rows are written and nothing else changes. See `docs/user-manual/audit-log.md` (`registry.write`).
