- **A degraded execution-statistics read is now `503` (REST) or a retryable error (MCP), not an empty or all-zero `200` (#4644).** `GET /api/v1/execution-statistics`, `/agents`, `/definitions`, `GET /api/v1/statistics` and the MCP tools `get_execution_statistics`, `get_execution_statistics_by_agent`, `get_execution_statistics_by_definition` and `get_fleet_statistics` collapsed every store failure (store not open, pool timeout, failed statement) into an empty list or a zeroed summary, so an outage read as "this scope has no executions". They now answer `503` with `retry_after_ms: 2000` on REST and a `retry_after_ms` error on MCP; a filter or confined scope that genuinely matches nothing is still `200` with an empty `data` array. `ExecutionTracker` gains `try_get_agent_statistics`, `try_get_definition_statistics` and `try_get_fleet_summary` returning `std::optional`; the plain `get_*` forms keep their collapse for callers that cannot report a degrade. Each degrade branch of the `try_get_*` readers logs a warning naming the reader and the cause. Scripted consumers should treat a `503` here as retryable.
