- **Breaking — for a gateway taking the reference config whose server's 8443 certificate is not issued by the install CA or does not carry the URL host: every management stream is refused (`revocation_unknown`) until `mgmt_crl_source` names the issuing CA or a `{file, Path}` source (#6016, PR 4b).** With `{yuzu_gw, mgmt_crl_source}` set (the reference gateway config `deploy/docker/reference-gateway-sys.config` sets it; `sys.config.prod` has it commented) the gateway fetches the CA's public CRL from the server's 8443 over verified TLS, trusts it by signature only, and refuses a listed server serial as `crl_revoked` on the streams it admits after its next fetch (5 s by default), with no restart; a stream already running is not cut. Every stream is refused (`revocation_unknown`, `revocation_stale`) when no usable CRL is held or the held one is past `nextUpdate` plus `mgmt_crl_grace_s` (24 h by default), in every mode including `pin`. A gateway with no source logs a WARN under `identity` or `identity_or_pin` and reads no CRL; a later release will refuse to boot there. For a gateway that sets the source, withdrawal no longer waits for a restart (the ADR-2004 withdrawal risk acceptance, still to be recorded by the approving reviewer, is narrowed to a gateway that does not set it); the other two acceptances are unchanged. A gateway process that starts afresh has forgotten the CRL it held and accepts the first validly signed one (ADR 2004 A6(d)), so a fresh start can re-accept an older CRL for up to its `nextUpdate` plus the grace. New alerts `YuzuGatewayMgmtCrlNotLoaded` (critical), `YuzuGatewayMgmtCrlStale` and `YuzuGatewayMgmtCrlRefreshStalled` (warning); `YuzuGatewayMgmtIdentityOutage` also pages on `crl_revoked`, `revocation_unknown` and `revocation_stale`. Upgrade the server first, and use a gateway image that carries this change: a `0.15.0` gateway ignores the key and checks nothing. Rolling the gateway back silently drops the check. The gateway loads only the CA's full base CRL: a delta, `issuingDistributionPoint`, indirect or `removeFromCRL` CRL, or one with an extension it cannot process that the CA marked critical, is refused `malformed` (the Yuzu server publishes none); a CRL covers only the peers its signing key issued, not every root that shares its subject name (those get `revocation_unknown`); and a CA whose key is not RSA, EC or EdDSA is refused `unverified`.
