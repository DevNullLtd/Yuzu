- **A File spark watch no longer stays silently deaf after its parent directory is renamed or replaced (Windows, #5719 item 5).** The watch held a handle that followed the renamed directory, so it kept reporting Healthy and never saw a change at the watched path. An idle watch now re-opens its directory path every 5 s and compares the directory identity with the one its handle was opened on; a different directory, or a path that names nothing, reports the watch faulted (`file watch parent directory renamed or replaced`) and re-discovers the path (shelter under an ancestor, or re-attach to the replacement). Detection is sampled (up to one interval late), a watch on a filesystem that gives no file id (a FAT32 volume was observed) is not verified, and an ancestor shelter whose own parent is renamed is not covered. No File spark is armed in production today (`prefer_spark_` is false), so this is visible only on rig-flipped agents.
