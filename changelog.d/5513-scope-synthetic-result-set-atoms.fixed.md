- **A scope that wraps a result-set reference in `LEN(...)` or `STARTSWITH(...)` is now treated like the bare reference.** `from_result_set:<id>` inside those functions was not recognised as a result-set reference, so the usual checks were skipped: with no result-set store available the scope was not refused, and the value read as empty, which a `NOT` turns into "member" for every agent. Such a scope now gets the same unresolved-set refusal and owner check as `from_result_set:<id>` itself. With a store and a principal such a scope used to read empty for every agent even for a valid owned set; it now resolves the set's real membership, so `LEN(...) > 0` matches members instead of nobody and `NOT` forms flip. Scopes that do not use these forms are unaffected.
