- **The gateway now re-registers the agents a restarted server does not know (#1197).** After a server-only restart, the gateway reads the unknown sessions from the `BatchHeartbeat` response and replays exactly the ones it still holds, so those agents are known to the server again without operator action: within one heartbeat interval, one flush and the drip position. If the outage opened the circuit breaker (it did with 10 and 30 agents in rig runs of 302 s and 152 s), the verdicts are dropped until the breaker's probe succeeds and the breaker's own replay then re-registers the agents, so the wait is the remaining backoff (up to 300 s; steps up to 160 s were observed). Restart the gateway to deploy; no wire change. A gateway restart disconnects every agent that node holds, and released agents v0.13.0 and v0.14.0-rc6 with default settings did not re-register after a rejection in testing (cause inferred: #2182, fixed by #5183, in no release yet): upgrade the agents to a build with that fix first, or restart the agent service on such an agent. `--no-auto-update` avoids the wedge but also disables the OTA update channel.
