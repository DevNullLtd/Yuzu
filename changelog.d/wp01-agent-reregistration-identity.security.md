- **An enrolled agent id can no longer be re-registered on the caller's say-so.** Before this change `Register` and the gateway-relayed `ProxyRegister` re-admitted any already-approved `agent_id` with no credential: the caller replaced the real agent's live session and was issued a CA-signed client certificate in its name, and the `agent_id` is an identifier shown to every operator role, not a secret. Both paths now run one shared decision (`agent_reregistration_gate.hpp`): an id that holds a **live** (active, unexpired) leaf in `ca_issued` is re-admitted only when the caller presents that leaf (direct: the mTLS peer certificate; through the gateway: the certificate the gateway *witnessed* in the agent's TLS handshake, carried in the new gateway-authoritative `RegisterRequest.gateway_attested_peer_cert_pem` / `gateway_attests_peer_cert`, overwritten unconditionally by the gateway and ignored on the direct path) or a fresh **single-use** enrollment token (a multi-use fleet token is not proof of an existing id). A revoked identity with no live leaf is refused outright. After a token re-enrolment the older live leaf is revoked (reason `reenrolled`) once the new one is issued. The refusal is a gRPC status (`UNAUTHENTICATED`, uniform message), never `accepted=false`, and happens before `register_agent`, so a refused caller cannot displace the real agent and the real agent's retry loop (including the #1894 forced re-register) is unaffected. **Rollout:** the new `--agent-reregistration-proof` flag (`YUZU_AGENT_REREGISTRATION_PROOF`) is `off | audit | enforce` and defaults to **`audit`** for this release (decide and count in `yuzu_register_reregistration_total`, admit as before); it becomes `enforce` in the next release. Upgrade every gateway first (the gateway agent listener now asks for, and witnesses, a client certificate: new `tls` key `witness_client_cert`, set in the shipped `sys.config.prod` and reference configs), watch for `outcome="no_proof"`, `"unattested_gateway"` and `"lookup_failed"` on real agents in audit mode, then switch to `enforce`. **Not covered, by design:** `--no-tls`, plain-TLS and operator-CA-certificate agents (no `ca_issued` agent leaf to prove against), and an agent whose leaf has expired (it re-enrols with a token as before). An agent that lost its key re-enrols with a fresh single-use token. `ca_store` schema v6 adds the partial index `idx_ca_issued_agent_subject`.
