- **The server now stores and counts the Guardian emit-order pair `(boot_epoch, emit_seq)` and reports the agents that send none (#5690); it does not compare the pair, so no verdict changes.** `guaranteed_state_store` schema v5 (additive, for a fresh database) adds nullable `boot_epoch` and `emit_seq` to the event and census tables and a per-agent order table, `guardian_agent_order`, holding each agent's pair clock and counters. A pair is taken only when both values are set and each is below 2^62; a half-set or out-of-range pair is stored unpaired and counted on the new `yuzu_server_guardian_pair_rejected_total{reason}` (`half_set`, `out_of_range`). `GET /api/v1/guaranteed-state/status` and the MCP tool `get_guardian_status` gain `unordered_agents` and `unordered_agent_ids` (the first 50, confined to the caller's scope): the agents whose latest accepted unpaired census-bearing event is later than the time their pair clock last advanced, including agents that never sent a pair. `GET /api/v1/guaranteed-state/agents/{agent_id}/rules` and `get_guardian_device_guards` gain `ordering`, the device's order row (`null` when it has none). The new gauge `yuzu_server_guardian_census_unordered_agents` exports the fleet count. `pair_duplicates` stays 0 until the comparison ships. One flag change, never a verdict change: a census row is now also flagged `order_uncertain` when an applied event changes the verdict or only its timestamp while the row's stored pair stays the same (for example two events of one agent with an equal pair); under schema v4 that row stayed clean. Decommissioning a device (`DELETE /api/v1/sle/agents/{id}`) now also deletes its order row, first, in the same transaction; erasure of the `guaranteed_state` store stays partial. Two first deliveries for the same agent now run one after the other (a different agent is not delayed until the shared database connection pool saturates); measured on one development host with 10,000 pending events on one pair, a first delivery for another rule of that agent waited about 0.15 s. Each lock wait in the agent step is bounded at 1 s, and one step can wait more than once (Ensure, DECIDE and one re-run after a concurrent delete), so a pooled connection can be held for the sum of those waits; a wait that reaches the bound stores the event with pending census evidence and skips its census write.
