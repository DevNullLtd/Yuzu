- **Audit read parity across REST v1, MCP and the legacy route.** `GET /api/v1/audit` now accepts `target_type`, `target_id`, `since`, `until` and `offset`, returns each row's `id`, and reports the real `start` and `page_size` in `pagination`. The MCP `query_audit_log` tool gains `target_id` and `offset`. `target_id` requires `target_type`; malformed or out-of-range values are rejected with an error rather than ignored. Rows with equal timestamps are now ordered by `id`, so the order within one timestamp is fixed (the log is live, so a walk by offset can still repeat or skip a row when rows arrive or retention deletes them).
