- **Hardware record: integrity faults are now counted, and a digest-provider failure is named.** `yuzu_hardware_section_integrity_total{reason}` (`row_count_mismatch`, `content_digest_mismatch`, `digest_unverifiable`) counts each faulted section once per `GET /api/v1/hardware/{id}` or MCP `get_hardware_ci` read composed with it, with a sampled WARN naming the device and section kind. A section whose digest the server could not compute is now served `constrained` with the new token `server:content_digest_unverifiable` (rows still listed) instead of `server:content_digest_mismatch`, because a re-sync cannot repair a server-side digest fault. A failed sections read now reports `reason="sections_query_error"` on `yuzu_inventory_read_degrade_total{source="device_ci"}` instead of sharing `query_error` with a failed record read.
