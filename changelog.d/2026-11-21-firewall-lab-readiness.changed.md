- **A device is never contained when its own control endpoint is one of its own addresses.** `firewall.quarantine` now answers `refused|self_host` when the agent's server or gateway address is loopback, unspecified or any address the host answers to, and `refused|own_addresses_unreadable` when the host's own addresses cannot be read, because containing it would cut the agent off from the server that has to release it. Nothing is changed or recorded, and there is no override. Only an operator's `quarantine` is checked; the repair, the boot re-apply, `release` and `quarantine_allow` never are, so a stored containment is still re-applied and can always be released. The record of a refused device stays unconfirmed until an operator ends it with `DELETE /api/v1/quarantine/{agent_id}`. A single-host stack (agent and server on one machine) cannot apply a containment; a server in a container or VM on the same host, reached at a bridge address, is not seen as the host's own.
- **A macOS agent that runs unprivileged now says why a pf read is unknown.** `state` and `rules` add `error|appfirewall:...` and `error|pf:...` rows (`not_run`, `timeout`, `truncated` or `exit:<n>`) beside their `unknown` rows, so `pf|unknown` and `ruleset|unknown` always come with the read that failed, and a global-state read that did not complete is `state|unknown` whatever its partial text said. Every such host sees up to three extra rows on `state` and two on `rules`.
- **The firewall containment ceremony has a remote mode.** `scripts/test/instructions_firewall_containment.py --remote` runs the round trip with the script on the server's host and the agent on another machine, bound by `--agent-hostname` (typed by the operator, and not one of this machine's names) and `--i-have-console-access-to-the-agent`; `instructions-tests.sh --target-agent-hostname <name> --console-access-to-agent` runs it. A one-host run ends `refused|self_host` (exit 2) by design. The run lock now tells a lock file it could not open from one another run holds, a refused dispatch ends `dispatch refused` (exit 1) instead of `RELEASE NOT CONFIRMED`, a status read that sits RUNNING and unchanged ends early, and `--record <path>` writes a 0600 JSON pass or fail record on every exit path of a run. `install-agent-user.sh --dry-run` reports the helper directory verdict and exits as the real run would.
