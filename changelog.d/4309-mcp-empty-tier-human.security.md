- **Breaking - `/mcp/v1/` refuses callers whose credential carries no MCP tier.** `GET`, `POST` and `DELETE` on `/mcp/v1/` now answer `403` / `-32003` ("/mcp/v1/ requires an MCP-tier bearer token") to any authenticated credential with an empty MCP tier: a browser session cookie, or an API token minted without `mcp_tier`; tokens with a tier (`readonly`, `operator`, `supervised`) and engine tokens are admitted. The refusal is audited as `mcp.session.reject` with `reason=tier_required` and counted on the new `yuzu_mcp_admission_refused_total{reason="tier_required"}`; there is no flag to turn it off. Mint a token with `mcp_tier` and an `expires_at` at most 90 days out (`POST /api/v1/tokens`, or Settings > API tokens) and send only `Authorization: Bearer`, never a session cookie alongside it, because a live cookie is resolved first and refused. See "Upgrading" (#4309).
