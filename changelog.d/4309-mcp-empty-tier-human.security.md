- **Breaking - `/mcp/v1/` refuses callers whose credential carries no MCP tier.** `GET`, `POST` and `DELETE` on `/mcp/v1/` now answer `403` / `-32003` ("/mcp/v1/ requires an MCP-tier bearer token") to any authenticated credential with an empty MCP tier: a browser session cookie, or an API token minted without `mcp_tier`; tokens with a tier (`readonly`, `operator`, `supervised`) and engine tokens are admitted. Every refusal is counted on the new `yuzu_mcp_admission_refused_total{reason="tier_required"}`; the `mcp.session.reject` audit row (`reason=tier_required`) is rate-limited per principal, and rows it suppresses are counted on `yuzu_mcp_admission_audit_suppressed_total`. There is no flag to turn the check off. A human operator must mint a token with `mcp_tier` and an `expires_at` at most 90 days out (Settings > API Tokens, or `POST /api/v1/tokens`) and the client must send only `Authorization: Bearer`, never a session cookie alongside it, because a live cookie is resolved first and refused. See "Upgrading" (#4309).
