- **Gateway-fronted agents' heartbeats, inventory reports and stream-status notifications now resolve on any server replica** (HA WS-5, `#4246` item 3, ADR-2002 section 7f). The gateway-upstream service looks a gateway `session_id` up in the durable route directory (one batched Postgres read per RPC) instead of only in a per-replica in-memory map, so a replica that did not process the agent's registration no longer answers "unknown session" (which caused gateway re-register storms, dropped inventory and rejected stream notifications). A `session_id` that matches more than one directory row is refused as ambiguous (`yuzu_server_gateway_route_desync_total{op="session_lookup",outcome="ambiguous_session"}`), and a degraded lookup is counted under `yuzu_server_gateway_route_write_failed_total{op="session_lookup"}`; during a Postgres outage `NotifyStreamStatus` rejects notifications (fail-closed) while `BatchHeartbeat` no longer triggers a re-register storm. The agent presence record also no longer has its `hostname` or `os` blanked by a heartbeat that carries empty values. This does not lift the HA safe-to-scale gate: running a second server replica is still unsupported.
