- **Enrolled agents that disconnect cleanly stay on `/hardware` as Offline with their real last-seen time.** In 0.14.0 the high-availability presence change deleted a device's stored record the moment it disconnected cleanly, so it vanished from `/hardware` instead of showing as Offline. A clean disconnect now clears only the record's live-presence marker (a departed agent is still never counted present for scope evaluation, though a heartbeat already in flight when it disconnected can briefly re-assert it, bounded by the presence TTL). Departed devices also show stale-flagged on `/viz/fleet` and in the MCP `get_fleet_topology` result for 7 days, so `yuzu_viz_offline_hosts_total` rises after the upgrade. Records are kept for 37 days (the 30-day roster window plus a 7-day margin), after which a clock-guarded hourly prune deletes them, at most 12,000 per replica per hour; the first pass runs about a minute after start and only records its clock anchor, so deletions begin with the next hourly pass, and an older backlog drains at that rate. Devices that disconnected under 0.14.0 were already deleted and are not restored: each reappears the next time it connects. Decommissioning a device deletes its record (#5682); a device that is never decommissioned ages out under the same 37-day rule (#5678, #1545).
