- **`update_source_trust` and `browser_policy` report what failed, where, and why.** `update_source_trust` bounds the input of one walk (16 MiB of bytes pulled from the kernel, failed reads included — `input_cap`), counts `invalid_bytes` only for bytes that reach the wire (a bad byte inside a redacted URL credential no longer flips the result to `CONSTRAINED`), and gains an injectable syscall seam so every failure token has a producing test and a CI gate keeps the README token tables in step with the code. `browser_policy` names the failing policy file or directory in a per-path `status` row, so a constrained read now emits N+1 `status` rows (the summary row is unchanged and still first, per-path rows follow). Both plugins report an exception that escaped a leg by category (`<os>:leg:exception:bad_alloc` / `:std_exception` / `:unknown`; match exception tokens by prefix, the bare `<os>:leg:exception` now carries a `:<category>` suffix) (#4873, #4874, #4876, #4877, #4879).
