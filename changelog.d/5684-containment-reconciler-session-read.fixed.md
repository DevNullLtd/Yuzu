- **The quarantine containment reconciler no longer reads an agent's session id while a reconnect may be rewriting it** (#5684). Its session-churn check, the session it records when it sends a `quarantine.status` verification and the session it compares at confirm time now read the id under the agent registry's lock instead of through an unlocked session pointer, removing a data race with a concurrent re-registration or gateway registration replay that could read a torn value. Confirmation behaviour is otherwise unchanged; a session that changes while the verification is being sent is now always treated as churn, so the device is re-verified rather than confirmed.
