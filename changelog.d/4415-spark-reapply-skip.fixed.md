- **A Guardian re-push no longer tears down and re-arms rules that are healthy and unchanged on the Spark path (#4415), and a wedged rule edited without changing what it watches is now applied instead of discarded (#5512).** Before, every full push, every forced safety-valve re-apply and every identical re-push rebuilt every rule it carried, so one stuck watch made the whole ruleset churn: watches and lifecycle records scaled with the rule count, and a healthy rule of the same mechanism type as a hung call was withdrawn and left unarmed for as long as the hang lasted. Now a rule that is attached, committed, active and identical (same key, spec and content, not in an Unknown episode, its key not faulted, no other claim on the key, and for a file-hash rule a non-empty pushed baseline equal to the live one) is skipped: no new incarnation, lifecycle record or receipt, and no repeated `guard.compliant`. A full push detaches only the rules it omits, plus kept rules on a faulted watch, and the agent's stored `rule:` rows are updated in place (only omitted rows deleted, unchanged rows not rewritten) on both detection paths. A rule that changed, is not healthy, is faulted or wedged, or has an empty or different baseline is still rebuilt. Changed content over a rule's own wedged arm now queues behind the wedge and arms the edited content on late success. Accepted: an identical re-push no longer repairs a lost recovery event or restarts the initial-observation demotion clock, and a faulted watch shared by several rules is repaired by a full push only (the other accepted cases are in AC-18). "Faulted" means the mechanism reported the watch unhealthy, or the agent's own health check says so when that report was lost; "baseline" is the file hash a rule compares against. Agent log: `full_sync cleared N prior rule(s)` is now `full_sync removed N prior rule(s) absent from the push` (not logged when no stored row is removed), and every full push logs a `full_sync preserved N rule(s) ...` line. The Spark path is not enabled in production (`prefer_spark` is off), so the skip is dormant there; the `rule:` row change is live. See `docs/spark-flip-gate.md` AC-18.
