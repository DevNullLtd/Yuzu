- **`/test` now installs its own browser and coverage tooling.** A failed Puppeteer install stops the run instead of skipping the browser gates, and a failed gcovr install is a WARN in default mode and stops a `--full` run. A new Phase 0b (default and `--full` modes) runs `scripts/test/ensure-puppeteer.sh`, which installs the `tests/puppeteer` dependencies (`npm ci --ignore-scripts`) and Chrome for Testing and proves the browser starts headless, and `scripts/test/ensure-gcovr.sh` (Linux), which installs `gcovr` from the hash-pinned `requirements-ci.txt` into a private virtualenv (an absolute path with no `.` or `..` segment). `node_modules` is trusted only when it carries a stamp of the current lockfile's hash. An existing `~/.local/bin/gcovr` link is replaced only when it already points into that virtualenv, and the script moves or deletes only a directory it can show is its own (a marker with its token and a virtualenv layout, never a file name alone). In `--full`, Phase 7b also fails the Coverage gate if gcovr is no longer usable when it re-checks it. A failed gcovr rebuild puts the previous virtualenv back, and the last line of the log is always the cause. The `Puppeteer` and `Browser smoke` gates now record FAIL, not SKIP, if the dependencies are absent when they run. The first run downloads a few hundred MB into `~/.cache/puppeteer`; `PUPPETEER_EXECUTABLE_PATH` skips the browser download. This supersedes the line in the browser-smoke harness entry saying the gate records SKIP without the install.
