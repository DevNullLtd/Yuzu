- **`/test` now installs its own browser and coverage tooling, and stops on a failed install rather than skipping the browser gates.** A new Phase 0b (default and `--full` modes) runs `scripts/test/ensure-puppeteer.sh`, which installs the `tests/puppeteer` dependencies (`npm ci --ignore-scripts`) and Chrome for Testing and proves the browser starts headless, and `scripts/test/ensure-gcovr.sh` (Linux), which installs `gcovr` from the hash-pinned `requirements-ci.txt` into a private virtualenv. `node_modules` is trusted only when it carries a stamp of the current lockfile's hash, and an existing `~/.local/bin/gcovr` link is replaced only when it already points into that virtualenv. A Puppeteer install that cannot complete stops the run; a gcovr install that cannot complete is a WARN in default mode (the coverage gate is report-only there) and stops a `--full` run (and fails its Coverage gate if gcovr is no longer usable when Phase 7b re-checks it); a failed gcovr rebuild puts the previous virtualenv back. The `Puppeteer` and `Browser smoke` gates now record FAIL, not SKIP, if the dependencies are absent when they run. The first run downloads a few hundred MB into `~/.cache/puppeteer`; `PUPPETEER_EXECUTABLE_PATH` skips the browser download. This supersedes the line in the browser-smoke harness entry saying the gate records SKIP without the install.
