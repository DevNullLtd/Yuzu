- **Breaking - `POST /api/v1/dex/devices/{id}/live` answers each zero-reach cause by name, shares one limit with the new MCP tool `get_device_live`, answers a throwing audit sink as `503`, and counts outcomes by word.** A send that reaches no agent used to be one retryable `503`; it now answers `409` `quarantined`, `422` `plugin_not_found` and `403` `kill_switched_os` (permanent, no `retry_after_ms`), and a retryable `503` with `error.reason` `no_agents_reached`, `containment_unreadable`, `route_unreadable` or `os_gate_unreadable` and `retry_after_ms` 5000; a `failure` audit row follows the `requested` row. The in-flight limit is now 2 per principal and 4 in all (it was 4 server-wide), taken from the shared held-open budget with the MCP tool and the confirmation wait of `DELETE /api/v1/quarantine/{agent_id}` (which still answers `202` without waiting when no slot is free); over it the route answers `429` with `Retry-After: 2`. An audit sink that throws on the `requested` row now answers `503` with `Sec-Audit-Failed: true` instead of an httplib `500`, and the poll reads only that device's rows, joins multi-row output and lets a failure row win. `yuzu_server_live_requests_total` is now `{surface, kind, outcome}` and `outcome` is a closed set of words (`ok`, `quarantined`, `over_budget_principal` and so on) instead of the HTTP status: a rule that selects `outcome="429"` or any other status matches nothing after the upgrade and raises no error; select `outcome=~"over_budget_.*"` for shed load.
