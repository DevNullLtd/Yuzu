- **A break-glass sign-in is refused at the MFA step's last arm check when this server saw the account as not armed during that check.** Under `--auth-mode=sso-only`, the check just before the session is created now refuses an "armed" answer when this server has recorded a "not armed" read since that check began, as the cache and the first check already did. This can also refuse a sign-in on an account that is armed now, when another break-glass sign-in on this server read it as not armed just before a `--break-glass-arm` took effect. Such a login answers the generic `401`, is audited as `auth.login` `failure` with `reason=break_glass_disarmed_before_mint`, and counts in `yuzu_auth_break_glass_pending_refused_total{reason="disarmed",stage="pre_mint"}`. A recovery code checked by that login is already spent: wait at least 5 seconds, run one break-glass sign-in at a time, and sign in again with TOTP rather than another recovery code (see the auth-db-recovery runbook, "Recovery codes at a break-glass login").
