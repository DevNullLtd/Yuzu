- **A break-glass sign-in is refused at the MFA step's second arm check when this server has seen the account disarmed since that check's own read started.** Under `--auth-mode=sso-only`, the check before the session is created now refuses an "armed" answer when the newest "not armed" read this server holds is at or after the check's own read started, as the cache and the first check already did. Such a login answers the generic `401`, is audited as `auth.login` `failure` with `reason=break_glass_disarmed_before_mint`, and counts in `yuzu_auth_break_glass_pending_refused_total{reason="disarmed",stage="pre_mint"}`. A recovery code checked by that login is already spent: confirm the account is armed and sign in again, preferably with TOTP rather than another recovery code.
