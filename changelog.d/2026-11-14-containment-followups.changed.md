- **A forced end answers `released: false`.** `DELETE /api/v1/quarantine/{agent_id}?force=true` still answers `200` with `state: "released"`, `forced: true` and `device_confirmed: false`, but `released` is now `false`: it reports the device's word, and a forced end does not release the device. The `202` response has a documented schema, and the whitelist limit of 512 characters is named in the `400`.
- **`GET /api/v1/quarantine?include=release_owed` and MCP `list_quarantined_devices` with `include=release_owed`.** The records an operator ended by force whose device has not yet confirmed a release are listed after the active ones with `status: "release_owed"` and the keys `released_at` and `release_owed_since`. Without the option the body is unchanged. Any other `include` value is a `400` (`-32602` on MCP).
- **`quarantine.enable` success rows carry `record_id=<id>`**, on REST and on the MCP `quarantine_device` tool (created and already-recorded paths), so they join to the later `quarantine.disable` and `quarantine.reapply` rows for the same record.
- **New reconciler signals.** `yuzu_server_quarantine_reapply_total` gains `result="drift"` (a record that read confirmed no longer does, counted apart from `unconfirmed`), the gauge `yuzu_server_quarantine_reconciler_last_tick_unixtime` records when a tick last finished, and two alerts follow: `YuzuQuarantineDriftRepeated` (three drifts in an hour) and `YuzuQuarantineReconcilerStalled` (no tick finished for five minutes while the release and unconfirmed gauges stay frozen).
- **Status replies the reconciler reads are kept 24 hours,** not the default retention, unless they changed what the server holds about the device (they ended a record, cleared an owed release, first confirmed containment, or showed drift).
- **Linux iptables sudoers grants are narrowed.** `scripts/install-agent-user.sh` no longer grants bare `iptables` and `ip6tables`; each tool gets nine argv shapes confined to the plugin's `yuzu-fwq-*` chains. They narrow the argv and do not confine the tool, as for `nft` and `pfctl`. Re-run the installer on a host that uses the iptables fallback.
- **Schema v5** adds `apply_gen` and `apply_claimed_at` to `quarantine_store.quarantine_records`. The reconciler's owed-release bookkeeping stays in memory, so a server restart sends one more release and writes the `forced_release_*` rows again.
