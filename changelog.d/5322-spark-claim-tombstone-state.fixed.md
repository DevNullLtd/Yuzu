- **Guardian (agent, spark backend only): a rule queued behind a stuck claim is no longer redispatched or refused, a claim that lost its rule's index mapping can no longer commit, and an orphaned watcher is cleaned up.** A claim whose index release failed is now retained and never dispatched again. The heartbeat maintenance pass retries its release and starts the rule queued behind it once the release succeeds. If that rule's claim deadline passes first, it ends as `CongestionExpired` instead of `AdmissionRejected`. An attach on a key that already has a committed watcher joins it instead of queuing behind it. An abandoned queued claim whose release fails keeps its index mapping tracked. A claim whose rule mapping was moved to another key by a wedge adoption is no longer committed, which closes a path that could resurrect a withdrawn rule. A File, Registry or Service watcher left with no rules is disarmed by the next heartbeat pass. This affects the spark backend only, which is not enabled in any released build (`prefer_spark` is off), so shipped agents are unchanged. The claim-commit ownership check is ordinary code that is dormant only behind that flag; the index-release failures the other paths handle can be provoked only through a test seam today (#4605, #5322, #5323).
