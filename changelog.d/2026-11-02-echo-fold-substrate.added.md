- **Echo's roll-up storage substrate is in the agent, ahead of the switch-over.** An interned string dictionary, one physical table per source and tier behind the existing tier view names (`$Process_Hourly` and the rest keep their columns), and a transactional fold-time writer that merges events into hourly, daily and monthly rows are built and tested, but nothing opens, writes or reads them yet, so stored data and every existing read are unchanged. There are no new settings: roll-up is the only storage model Echo is built toward. `echo.sql` no longer accepts `WITH` (common table expressions) or `NATURAL` / `USING` joins; no shipped query used them, a subquery or window function expresses the same reads, and a join is written with `ON`.
