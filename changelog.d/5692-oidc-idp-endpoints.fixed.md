- **Operator action — an IdP on loopback, RFC 1918, carrier-grade NAT or IPv6 unique-local addresses (or whose `jwks_uri`/`token_endpoint` are) now needs `--oidc-allow-private-networks` (env `YUZU_OIDC_ALLOW_PRIVATE_NETWORKS`), and link-local and cloud-metadata addresses are never allowed; use an `https` issuer outside a lab (an `http://` issuer on a non-loopback host puts the JWKS trust root and the client secret in the clear and now logs a warning; plain `http://` to a public address is refused outright, and `http://` to a private address with the flag set stays exposed to anyone on that network path); OIDC flags left configured but unused now become a live sign-in, and members of the `--oidc-admin-group` group can sign in as administrators, so review them before upgrading; there is no HTTP proxy on the discovery and JWKS path; a previously green Test Connection can now be red; a Settings save with a blank Redirect URI is now refused; an ID token that names a `kid` the IdP's key set does not hold (or whose `kid` is empty or not a string) is now refused instead of being checked against the first key, which breaks an IdP whose JWKS keys carry no `kid` while its tokens name one; cached signing keys are dropped one hour after the last successful fetch, so a JWKS endpoint that stays down for over an hour refuses every sign-in until it answers; a sign-in whose session cannot be stored now fails instead of reporting success; IdP host names must be ASCII (use the punycode form of an internationalized name); and the Windows token POST no longer follows redirects, so a token endpoint that answers 3xx fails the sign-in.** The server resolves every OIDC request target itself, refuses addresses by class, and pins the connection to a permitted address (the Windows token POST is only pre-checked). **OIDC sign-in now works with IdPs whose endpoints are not the derived ones, and verifies ID tokens against the IdP's own JWKS (#5692).** The server pre-set the authorization and token endpoints from the issuer URL, which skipped OIDC discovery, so `jwks_uri` was never learned (every ID token failed signature verification) and an IdP such as Keycloak answered the sign-in redirect with an HTTP 404 (the authorization URL it does not serve). The three endpoints are now read from `{issuer}/.well-known/openid-configuration` on first use, with no fallback: the document's `issuer` must equal the configured issuer exactly and every endpoint must be an absolute URL on the issuer's scheme without a fragment (an existing query is kept, but an authorization endpoint query must not use the names of the OAuth request parameters Yuzu adds), otherwise the sign-in fails closed. The Settings "Test Connection" button applies the same validation and also fetches the JWKS. Discovery and JWKS requests are bounded (5 s per-operation timeouts and a total of twice that from the start of the request, covering connect and the response and the TLS handshake (measured on Linux, tested with a drip server on Windows); 256 KiB, no redirects; the token-exchange POST keeps per-operation timeouts only and caps its response at 256 KiB), endpoint URLs are length- and authority-checked, an issuer with a query or fragment is refused, and a sign-in that arrives while discovery is being fetched fails at once instead of waiting. The unused `exchange_script` plumbing is removed. See the upgrading guide: the server must now reach the issuer host at sign-in time.
