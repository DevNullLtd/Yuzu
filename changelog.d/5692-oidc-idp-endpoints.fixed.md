- **OIDC sign-in now works with IdPs whose endpoints are not the derived ones, and verifies ID tokens against the IdP's own JWKS (#5692).** The server pre-set the authorization and token endpoints from the issuer URL, which skipped OIDC discovery, so `jwks_uri` was never learned (every ID token failed signature verification) and an IdP such as Keycloak answered the sign-in redirect with an HTTP 404 (the authorization URL it does not serve). The three endpoints are now read from `{issuer}/.well-known/openid-configuration` on first use, with no fallback: the document's `issuer` must equal the configured issuer exactly and every endpoint must be an absolute URL on the issuer's scheme without a fragment (an existing query is kept), otherwise the sign-in fails closed. The Settings "Test Connection" button applies the same validation and also fetches the JWKS. Discovery and JWKS requests are bounded (5 s per-operation timeouts and a total of twice that from the start of the request, covering connect and the response, and on Linux/macOS the TLS handshake (measured on Linux); on Windows the handshake is not covered; 256 KiB, no redirects; the token-exchange POST keeps per-operation timeouts only), endpoint URLs are length- and authority-checked, an issuer with a query or fragment is refused, and a sign-in that arrives while discovery is being fetched fails at once instead of waiting. The unused `exchange_script` plumbing is removed. See the upgrading guide: the server must now reach the issuer host at sign-in time.
