- **The server's built-in certificate now carries a server-only identity URI SAN, `yuzu://<ca-fingerprint>/server` (#6016), and an existing install has it re-issued once on first boot.** Only `default-server.pem` has the name; the HTTPS and gateway leaves and every agent leaf never do, and nothing an agent or gateway submits to the CA can obtain it. This is the first step of replacing the gateway management plane's SPKI pin with a CA-issued identity so a routine server certificate renewal no longer needs a pin update. The server mints the identity; the gateway can admit the server by it as an opt-in (`mgmt_peer_auth_mode`, #6016) and still admits it by pin by default, so no operator action is required. On the first boot after the upgrade `default-server.pem` is re-issued under the **same root and the same key** (so existing `mgmt_peer_pins` stay valid), the other leaves are untouched, and the previous certificate then shows as **revoked with reason `superseded`** in the CA inventory and the next CRL — bookkeeping, not a key compromise. If an operator revokes the old certificate for a real reason while the upgrade is running, the new certificate is revoked with the same reason and the audit row is a warning with `replacement_withdrawn=true`; re-key the set. The event is logged as a WARN line and audited as `server.default_certs_server_identity_upgraded`, and the new gauge `yuzu_server_identity_uri_present` is `1` once the certificate carries the URI. An install that had already revoked its built-in server certificate (or another certificate over the same key) for a reason other than `superseded` keeps it unchanged (re-certifying a withdrawn key would undo the revocation): that skip warns on every boot and leaves the gauge at `0` until the set is re-keyed. To keep that distinction reliable, a revocation reason typed by an operator that equals `superseded` or `unpublished` is now stored as `operator-supplied: <text>`. Any other failure to upgrade is logged and re-attempted on the next boot, and never blocks startup. See `docs/user-manual/upgrading.md`.
