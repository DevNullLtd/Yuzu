- **The agent now says whether it is verifying OTA update signatures.** At startup it logs its update-signature mode and the trust bundle path — `OTA update signature mode: off` (no bundle, so update binaries are not signature-checked), `bundle`, or `bundle+require`. When auto-update is enabled, the OTA update checker also warns, once, when it first starts (after the agent first connects) if the bundle is set but cannot be loaded. Every heartbeat carries the same mode as the status tag `yuzu.ota_signature_mode`; the tag is stored by the server, not yet surfaced in any view — the startup log line is the per-endpoint source of truth. The agent also warns at startup about any environment variable starting with `YUZU_UPDATE_` that it does not read, so a misspelling AFTER the `YUZU_UPDATE_` prefix (for example `YUZU_UPDATE_TRUST_BUNDEL`) no longer leaves signing silently off. The Windows `Environment`-value check script in the server administration guide now also rejects non-ASCII characters in the signing entries and the binary path, and requires `$stage` to be 1 or 2.
