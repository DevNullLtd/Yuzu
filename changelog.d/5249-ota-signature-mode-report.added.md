- **The agent now says whether it is verifying OTA update signatures.** At startup it logs its update-signature mode and the trust bundle path — `OTA update signature mode: off` (no bundle, so update binaries are not signature-checked), `bundle`, or `bundle+require` — and warns if the bundle is set but cannot be loaded. Every heartbeat carries the same mode as the status tag `yuzu.ota_signature_mode`. The agent also warns at startup about any environment variable starting with `YUZU_UPDATE_` that it does not read, so a misspelt `YUZU_UPDATE_TRUST_BUNDLE` or `YUZU_UPDATE_REQUIRE_SIGNATURE` no longer leaves signing silently off. An update refused because the agent's own trust bundle is missing, unreadable or not a PEM certificate file is now logged as such and counted as `yuzu_agent_ota_signature_refused_total{reason="bundle_unreadable"}`, instead of being reported as an untrusted signer (`untrusted chain`); it is still refused, and still included in the `yuzu.ota_signature_refused` heartbeat total. The Windows `Environment`-value check script in the server administration guide now also rejects non-ASCII characters in the signing entries and the binary path, and requires `$stage` to be 1 or 2.
