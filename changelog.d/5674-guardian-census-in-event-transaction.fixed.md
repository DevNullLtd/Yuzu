- **The Guardian compliance census is written in the same transaction as the event that causes it, and is removed with its rule (#5674).** Previously the census update ran after the event commit as a separate best-effort statement, so a failure left the event stored and the compliance view stale with only a log warning, and deleting a rule relied on a second best-effort statement to remove its census rows. `guardian_agent_rule_status` now has a foreign key to `guaranteed_state_rules` with `ON DELETE CASCADE` (`guaranteed_state_store` schema v3); the migration first deletes census rows whose rule no longer exists, including the phantom row such a rule left on a device's Guardian page. A census write that fails for a reason other than a missing rule is rolled back to a savepoint and does not affect the stored event; it is logged at error and counted on the new `yuzu_server_guardian_census_proj_failures_total`. The server now refuses to start unless the census table has that cascade key on `rule_id`, not deferrable. See Upgrading.
