- **Breaking - cookie-session writes require a same-site `Origin` or `Referer`.** One pre-routing check refuses any request other than `GET`, `HEAD` or `OPTIONS` that is authorised by the session cookie and carries neither header, or one naming another site (an entry from `--csrf-trusted-origin` or `YUZU_CSRF_TRUSTED_ORIGIN` is accepted), with `403` `cross-site request refused` and a `csrf.denied` audit row, after authentication and before step-up evaluation, challenge emission and route-handler effects, and before the body is read. Cookie-session requests that dispatch work are held to the same rule, decided by `Sec-Fetch-Site` (`same-origin` or `none` admitted) with the `Origin` or `Referer` rule as fallback, so a script that calls the dashboard's fragment endpoints with a login cookie must send one of them. A request that presents a valid session cookie is treated as a cookie-session request even if it also carries a token; requests authenticated only by a token are not gated. Existing per-route checks stay as defence in depth. On a server that terminates TLS itself the `Origin` or `Referer` must be `https://`; behind a TLS-terminating proxy, declare the public origin with its `https://` scheme so a plain-`http://` origin for that host is refused. **Before upgrading:** behind a reverse proxy, forward the client's `Host` unchanged, port included (nginx: `proxy_set_header Host $http_host;`) or declare the public origin with `--csrf-trusted-origin` on every replica, and create an API token for automation first, because creating a token from the dashboard is itself a cookie-session write. Scripts that reuse a login cookie must send `Origin` (or `Referer`) or switch to the token. For cookie-session callers the audit `target_id` is now the request method and path and `result` is `denied`, so rules keyed on the earlier per-route values need updating. New metric `yuzu_server_csrf_denied_total{path_class,reason}` and the `yuzu-web-writes` alert rules. See the upgrade guide.
