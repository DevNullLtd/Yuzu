- **`installed_apps`: bounded macOS bundle-id reads and a typed degraded status.** On macOS the `list` action's bundle-id pass runs through an agent-core bounded reader (30 s deadline, replacing the 120 s whole-collection budget for this pass; one pass in flight per agent process, i.e. one per device), so a wedged `CFBundleCreate` (a stale network mount) can no longer pin a dispatch worker; a timed-out, busy, rejected or capped pass leads the output with a `warning|bundle_id_timeout` / `bundle_id_busy` / `bundle_id_rejected` / `bundle_id_capped` row and reports `CONSTRAINED` (rows not read carry `-`); a bundle identifier is cut at 4 KiB at read. A degraded Linux/macOS `list`/`query`/`list_per_user`/`list_inventory` now also carries the typed `CONSTRAINED` status (`installed_apps:acquisition_degraded`) on the wire where it was `UNDECLARED`. The duplicated UTF-8 sanitiser is deleted in favour of the SDK's (#4710, #4713).
