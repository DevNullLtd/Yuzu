- **The root-owned firewall helper gains a read-only `snapshot` word.** `yuzu-fw-helper snapshot` prints the host's firewall listings (`nft -a list ruleset`, then `iptables-legacy-save` and `ip6tables-legacy-save`, or the kernel's table list for a family whose legacy save tool is not installed; each under its own header, at most 4 MiB) and writes no file or ruleset, so the agent account can read the host's whole nftables ruleset (rule handles included) and every legacy table through the sudo grant it already has. The word runs as root with no sandbox. Two reads can make the kernel load a module, both measured (ADR-3007 clause 3): an nft read on a host where nf_tables is not loaded makes the kernel load nf_tables, and a legacy save tool that asks for a table whose module is not loaded makes the kernel load that module, which the word's reads reach only when a table is removed while a read is under way. In one removal race a save tool also starts `modprobe` itself, for its family's core module (`ip_tables` or `ip6_tables`), as read in the tool's source (the same clause); nothing in the helper refuses that load, where the packaged broker's unit has `ProtectKernelModules`. No new sudoers line is needed: the line names the helper with no argument, and the word takes no argument of its own. `snapshot` is accepted only on a host provisioned with this build's `scripts/install-agent-user.sh`; `--check` reports a helper that differs from the installer's text. The firewall plugin's `state` and `rules` read it as the second Linux transport, after the broker socket, and the live containment harness reads it too.
