- **Gateway heartbeat batches now report their latency and wait on a failing presence store only once per batch** (#5686). A new histogram, `yuzu_server_gateway_batch_heartbeat_duration_seconds{outcome="ok"|"degraded"}`, records how long the server takes to handle each gateway `BatchHeartbeat`; `degraded` marks a batch in which the session directory read, the lease renewal or a presence write hit a Postgres problem. When the agent presence store fails during a batch (for example a saturated connection pool), the remaining entries in that batch no longer each wait up to 250 ms for a connection: their presence write is skipped and counted in the new `yuzu_server_agent_presence_upsert_skipped_total`, with one rate-limited warning. Those heartbeats are still acknowledged and their route leases still renewed, and the next heartbeat refreshes the presence row. Direct (non-gateway) heartbeats are unchanged. No alert ships for the latency histogram yet; see `docs/user-manual/metrics.md`.
