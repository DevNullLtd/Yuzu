- **Every plugin in a packaged Linux agent can now read any file on the host.** The capability granted to fix the serial number and UUID, `CAP_DAC_READ_SEARCH`, is held by the agent process, so every plugin it hosts can read root-only files, and `mgmt_posture` and `remote_access_audit` now return data they previously refused (`/etc/sssd/sssd.conf`, users' `authorized_keys`). The `filesystem` plugin's `read` and `search` actions, which need only `FileRetrieval:Read` (held by the Operator role, no approval gate), can now return the contents of root-only files such as `/etc/shadow`, and `exists`, `list_dir`, `search_dir` and `get_acl` can list, probe and read the permissions of root-only paths; `find_by_hash`, which needs admin or approval, can report whether a root-only file matches a hash. `content_dist` `upload_file` (admin or approval) can send a root-only file to the server, and `ioc` `check` can probe and hash-match caller-named paths. `file_hash` is unaffected on Linux because it hashes through a child process that gets no capability. It grants no permission to write file contents and no other capability bit, and the capability bounding set is exactly this one capability. The capability also authorizes `open_by_handle_at(2)` and `linkat(2)` with `AT_EMPTY_PATH`; neither the agent nor its bundled plugins call either. Scripts and other programs the agent starts do not inherit it (the exceptions are listed in the upgrade guide), because the agent clears its inheritable and ambient capability sets at start; if it cannot, it refuses to start. The upgrade guide in `docs/user-manual/upgrading.md` has the verify command and two opt-out drop-ins (capability only, or capability and firmware-table copy), and notes that an existing drop-in adding a capability must also extend `CapabilityBoundingSet=`.
