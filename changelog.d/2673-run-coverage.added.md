- **Execution results now count who a run was meant for and what happened (#2673).** `GET /api/v1/executions/{id}` and the MCP tool `get_execution_status` carry a `coverage` object: counts of intended, contacted, responded, failed, timed-out, not-delivered, unknown, offline, not-sent, withheld, pending and late devices, and whether only connected agents were considered. It gives counts only: no REST, MCP or dashboard read lists the devices that timed out or were never reached. Management-group-confined callers get counts over their visible devices, with `population` and `deadline_at` null. A device that sends nothing is marked `timed_out` after the response window (the definition's `gather_ttl_seconds` or 300 seconds, never less than 660) by a new server sweep that writes `execution.deadline_sweep` audit rows. New metrics: `yuzu_exec_tracker_deadline_sweep_total`, `yuzu_exec_tracker_conflicting_final_total`, and an `op="record_targets"` series on `yuzu_exec_tracker_bookkeeping_failed_total`. A run whose device list could not be saved reads `unrecorded`. Known limits: the per-device target rows are never pruned and have no erasure path, and gateway-routed commands are still ended at 300 seconds by the gateway forward, and one still running then reads `unknown`.
