- **Fleet gauges and a sample alert for agents whose command-dedup store failed to open (#3663).** The agent's durable command-dedup store fails open by design, so an agent whose store cannot be opened keeps running commands without replay protection, and until now the only trace was a raw heartbeat tag. The server now exposes `yuzu_fleet_agents_dedup_store_degraded` (a live count of such agents), the agent counts `yuzu_fleet_agents_dedup_replaying`, `..._claim_erroring`, `..._record_terminal_missing`, `..._record_erroring` and `..._release_erroring` (agents whose counter is above zero since their last restart), the coverage gauges `yuzu_fleet_agents_dedup_reporting` and `yuzu_fleet_agents_dedup_tag_rejected`, and `yuzu_fleet_dedup_rows_max`, an approximate largest store size reported through the new `yuzu.dedup_rows` heartbeat tag. `docs/prometheus/yuzu-alerts.yml` gains the sample alert `YuzuDedupStoreDegraded`; load that file and route `severity=warning` to use it. It covers only a store that failed to open (a store that opened and later failed writes is visible only on the `..._claim_erroring` gauge), counts agents seen in the last 90 s, and is per core replica. Agents that predate the tags contribute nothing, so check `yuzu_fleet_agents_dedup_reporting` before reading a 0. Runbook: "Fleet monitoring of the dedup store" in the security hardening guide.
