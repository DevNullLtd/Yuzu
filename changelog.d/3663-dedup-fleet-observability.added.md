- **Fleet gauges and a sample alert for agents whose command-dedup store failed to open (#3663).** The agent's durable command-dedup store fails open by design, so an agent whose store cannot be opened keeps running commands without replay protection, and until now the only trace was a raw heartbeat tag. The server now exposes `yuzu_fleet_agents_dedup_store_degraded` (a live count of such agents), counts of agents whose per-process dedup counters are above zero since their last restart, coverage gauges `yuzu_fleet_agents_dedup_reporting` and `..._tag_rejected`, and `yuzu_fleet_dedup_rows_max`, an approximate largest store size reported through the new `yuzu.dedup_rows` heartbeat tag. `docs/prometheus/yuzu-alerts.yml` gains the sample alert `YuzuDedupStoreDegraded`: load that file and route `severity=warning` to use it. It covers only a store that failed to open, counts agents seen in the last 90 s, is per core replica, and no page yet lists the affected endpoints. Agents that predate the tags contribute nothing, so check `yuzu_fleet_agents_dedup_reporting` before reading a 0. Runbook: "Fleet monitoring of the dedup store" in the security hardening guide.
