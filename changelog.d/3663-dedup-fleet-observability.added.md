- **Fleet-side visibility of agents running without command replay protection (#3663).** The agent's durable command-dedup store fails open by design, so an agent whose store cannot be opened keeps running commands undeduplicated, and until now the only trace was a raw heartbeat tag. The server now derives `yuzu_fleet_agents_dedup_store_degraded` (a live count of such agents) plus `yuzu_fleet_agents_dedup_replaying`, `..._claim_erroring`, `..._record_terminal_missing`, `..._record_erroring` and `..._release_erroring` (agents whose per-process counter is above zero since their last restart), and two coverage gauges, `yuzu_fleet_agents_dedup_reporting` and `yuzu_fleet_agents_dedup_tag_rejected`. Agents now also report the size of their dedup store as the `yuzu.dedup_rows` heartbeat tag, surfaced as `yuzu_fleet_dedup_rows_max` (absent when no agent reports it). The new `YuzuDedupStoreDegraded` alert (`> 0` for 15 minutes, warning) is behaviour-tested in `tests/prometheus/`; the runbook is "Fleet monitoring of the dedup store" in the security hardening guide. Agents that predate the tags contribute nothing, so read `yuzu_fleet_agents_dedup_reporting` before trusting a quiet graph.
