- **Webhook and offload target creation now refuses a destination URL with embedded credentials or control characters, and the offload create audit row records the URL.** `POST /api/webhooks`, `POST /api/v1/offload-targets` and the MCP `create_offload_target` tool answer `400` for a URL carrying `user:password@` or any control character (the URL, and the event types, name and credential for offload targets); existing rows are not changed. The `offload_target.create` audit detail is now `name=<name> url=<url>` (it was the bare name) on both the REST route and the MCP tool, so a SIEM rule that matched the old shape must accept both; the `webhook.created` analytics event carries the destination scheme and host only. `directory.sync` failures (missing credentials, invalid body, sync failure) are now audited, and `directory.group_mapping.update` reads the stored set back and writes a `success` row for the group-to-role pairs the store holds and a separate `failure` row for any it did not take (a failed read-back confirms nothing); a long list is split across several rows so every pair is recorded.
