- **The daily installed-software inventory now collects from every inventory action on the host.** Besides `installed_apps` (`list_inventory`), the agent reports Homebrew formulae and casks plus one Homebrew presence row from `pkg_inventory` (`packages`/`managers`, ecosystem `brew`) and every Windows optional feature, enabled or disabled, from `windows_optional_features` (`list`, ecosystem `optional_feature`, the DISM state in the `version` column). Every row now carries `source`, the producing plugin action; `package_id` stays empty for these producers and the reserved `install_location`/`uninstall_string` slots are still sent empty. An action that is not loaded or not supported on the OS is skipped (except `installed_apps`: without it the source stays idle, because it anchors the report); one that fails skips that day's report and keeps the last good inventory. Each agent sends one full report after upgrade (its content hash changes), at its existing phase-spread slot (about 24 h), then hash-skips as before; deploy the server (the extended-row store) first. The server has no admission control for inventory resends yet (planned, not built), so the lockstep cases are agents with no persisted sync state, agents already overdue at reconnect, and a fleet-wide "Sync now"; staging by management group is advisable for very large fleets, not mandatory. Disabled optional features are listed too, so the `/software` catalogue count (grouped by name) counts a host with a disabled feature as having it (see the inventory manual).
