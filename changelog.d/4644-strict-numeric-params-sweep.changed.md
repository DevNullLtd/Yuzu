- **Breaking: numeric query parameters are parsed strictly across the REST routes that read `limit`, `since`, `until`, `offset`, `index`, `machines_max` or `window` (#4644).**
  The execution-statistics routes, the executions lists, `GET /api/v1/audit` and `GET /api/audit`, `GET /api/analytics/recent`, the instruction, product-pack, workflow, policy and policy-fragment lists, the patch lists, the software-inventory list, the fleet-topology `machines_max` and the app-performance compare `window` read their numbers with `std::stoi`/`std::stoll` (or `strtol`), so `?limit=100abc` was read as `100` and `?since=junk` on the statistics routes meant `0`, "from the beginning". A value that is not one whole base-10 integer now returns `400` (a malformed `limit` on `/api/analytics/recent` and the patch lists, and a malformed `window`, used to be ignored). The shared primitive is `server/core/src/query_int_parse.hpp`. On MCP, `query_audit_log` and the app-performance compare tool answer `-32602` for a `since`, `until`, `limit` or `window` that is not a JSON integer or does not fit a signed 64-bit value (`18446744073709551615` wrapped to `-1`, an unbounded window), and the lenient integer readers now saturate instead of wrapping, so an oversized `limit` reaches the tool's own ceiling instead of `0`. The dashboard fragments' page-size helpers and the notification, webhook and offload list routes are not changed here.
