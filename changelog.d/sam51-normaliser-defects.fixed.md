- **Real software titles stop minting empty, wrong-edition or split keys.** The title normaliser now reads an edition word as an edition only after a title word, so `Home` is a title and `Pro Display Calibrator` has no `pro` edition (a lone edition word is still the value of an edition column). The word `edition` after an architecture or edition word is dropped (`7-Zip 26.04 (x64 edition)` is `7-zip`), a bare `-` separator is dropped (`... Redistributable (x64) - 14.38`), and a Homebrew `name@version` keeps the name and takes the version (`openssl@3` is `openssl`, version `3`). The vendor normaliser strips only a trailing run of legal-suffix words and never the last word, so `macOS Software Signing` and `Software AG` keep their names, `Software` is no longer empty, and `L.L.C.` is a suffix. The seed alias pack is `2026.11.2` and gains rows for `python3.14` and `postgresql-18`. A server with a stored alias pack keeps the keys it derived with the old rules until the pack is replaced (`POST /api/v1/inventory/software/normalization/pack` with the shipped CSV, or the MCP tool `replace_software_normalization_pack`); until then the seed title `Microsoft .NET Runtime - 8.0.1 (x64)` (line 78 of the earlier `aliases.csv`, whose stored key `microsoft .net runtime -` becomes `microsoft .net runtime`) stops resolving, the Homebrew `openssl@3` (line 113, key `openssl@3` becomes `openssl`) keeps resolving through the generic `openssl` row, and any title whose normal form changed records one remove and one install in the software change feed instead of an upgrade at its next version change. See [Upgrading](docs/user-manual/upgrading.md). Single-year Visual C++ Redistributable titles and compound legal forms such as `GmbH & Co. KG` are unchanged (#8450, #8451); the Office `Plus` and locale residue is not fixed (#8449).
