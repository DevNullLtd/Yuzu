- **Guardian (agent, spark backend only): each outbox send lane now holds back a younger event behind an older one in the other lane for a bounded, counted time (1 s, then up to 64 overtaking sends), and a stalled send on an emptied compliance lane is now counted.** (#3972) The lifecycle lane and the compliance/health lane each launch their own detached send, so a younger event could reach the stream between two older ones. A lane's next send is now held while the other lane has an older entry (by a per-entry enqueue sequence), either waiting at its head or still running. After a cumulative 1 s hold the lane is released for up to 64 overtaking sends, then needs a further 1 s hold, so a stuck lane holds the other for a bounded time instead of indefinitely; both values are compile-time defaults, not operator settings. A release lets the lane overtake the older entry, so events may still reach the stream out of enqueue order after a hold expires. Each release is counted and reported as the sparse heartbeat tag `yuzu.guardian_send_order_hold_releases` (server gauge `yuzu_fleet_guardian_send_order_hold_releases`; monitor-only, no alert rule). The same-second server tie, where an older `compliant` that reaches the server last can still win over a newer `errored`, is not closed here and stays tracked as #5690. (#3980) `yuzu.guardian_send_stalls` now also counts a send still running on a compliance lane whose queue was emptied (for example by a rule detach), and the drain worker no longer wakes every 200 ms for a send whose stall is already counted. This affects the spark backend only, which is not enabled in any released build (`prefer_spark` is off), so shipped agents are unchanged. (#3972, #3980)
