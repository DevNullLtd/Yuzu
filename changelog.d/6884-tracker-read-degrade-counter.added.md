- **Execution-tracker read degrades are now a metric, not just a log line.** `yuzu_server_execution_tracker_read_degrade_total{method,reason}` counts every time one of the tracker's five degrade-distinguishable readers (`query_executions`, `get_execution`, `get_agent_statuses`, `get_agent_statuses_for_executions`, `get_children`) returns a degraded answer instead of data, by where it failed (`store_not_open`, `pool_acquire_timeout`, `query_error`). All 15 series are pre-seeded to 0 at startup. It is a diagnostic, not an availability measure: it also counts the server's own periodic reads (about 4 per minute per replica with no users), `pool_acquire_timeout` also covers an unreachable database (check `yuzu_server_pg_reachable` before resizing the pool), and no alert rule ships with it yet. As part of this, `get_children_checked` now takes its connection lease before opening its transaction so the two causes can be told apart; the acquire budget and query are unchanged. See `docs/user-manual/metrics.md`. (#3834)
