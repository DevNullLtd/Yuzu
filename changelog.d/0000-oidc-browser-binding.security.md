- **OIDC sign-in is now bound to the browser that started it.** `GET /auth/oidc/start` sets a short-lived `HttpOnly` binding cookie (`__Host-yuzu_oidc_bind` over HTTPS, `yuzu_oidc_bind` over plain HTTP, which is weaker, as for the session cookie) and `GET /auth/callback` refuses a request that does not present it, so a callback only completes in the browser that began the flow. A refused callback does not consume the pending flow. The cookie is bound to the host it was set on, so start the sign-in on the same host name as `--oidc-redirect-uri`; with several replicas, route `/auth/oidc/start` and `/auth/callback` to the same replica (session affinity). A sign-in started before an upgrade must be restarted from the login page. Refusals are audited as `auth.oidc_login_failed` with `reason=browser_binding_missing`, `browser_binding_mismatch` or `browser_binding_unavailable`.
