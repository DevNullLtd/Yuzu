- **Instructions page writes are audited before they change anything, checked for concurrent edits and for cross-site requests, and a signed import can no longer be re-labelled.** Creating or deleting an instruction set now writes an `attempted` audit row first and is refused with `503` (`Sec-Audit-Failed: true`) when that row cannot be stored; set names are limited to 128 characters and descriptions to 512 by the API as well as the dialog. The YAML save, `PUT /api/instructions/{id}` and the response-template create, replace and delete apply only to the definition version they read and answer `409` after a concurrent edit; the editor sends the version it loaded. The dashboard's instruction writes (create, update, delete, import, YAML save, set create and delete, response templates, and `POST /api/instructions/{id}/execute`) refuse a browser request that carries no `Origin`/`Referer` or one from another site (`403`, audited as `csrf.denied`); API and MCP token callers are unaffected. A signed import now takes `plugin`, `action`, `type`, `approval_mode` and `concurrency_mode` from the signed `yaml_source` and refuses an envelope whose unsigned fields disagree. The dispatch form keeps Execute disabled until the definition has loaded, refuses to run if the page script is missing, and takes its write-only parameter list from the server (`secret_params` on the definition detail). A YAML that omits `description` keeps the stored one, the sets panel shows exact member counts, and the library name filter matches `%` and `_` literally.
