- **Operator action: an IdP that serves an RSA signing key under 2048 bits must re-issue it, because that key is now skipped and a token it signed is refused (`no matching JWKS key found`); under `--auth-mode=sso-only`, confirm a break-glass account is named and enrolled before upgrading. OIDC sign-in also accepts an ID token with no `kid` signed by any of the IdP's first 16 usable signing keys (#1901).** A token with no `kid` member used to be checked against the first published key only, so an IdP that omits `kid` while it publishes several signing keys, as it rotates, had sign-ins refused intermittently. It is now checked against each usable key in turn, at most 16, in the order published; a token that names a `kid` is still checked against that key alone and refused if the key set lacks it. A JWKS key whose RSA modulus is under 2048 bits is skipped when the key set is parsed (the log line reads `failed to parse JWK kid=... (RSA modulus under 2048 bits)`) and the other keys are kept, so a weak key can no longer verify a token; if every key the IdP serves is that small, no sign-in succeeds until it publishes a 2048-bit or larger key. Rolling back restores the old behaviour.
