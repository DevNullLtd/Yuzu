- **Breaking for service-scoped API tokens: `GET /api/v1/enrollment/pending-agents` and `GET /api/v1/upload-grants` now answer `403` (#3526).** The fleet-read gate now applies the `ITServiceOwner` authority ceiling that `require_permission` already applied, so a service-scoped token is refused unless that role itself holds the permission, whatever its minter holds. `ITServiceOwner` does not hold `Enrollment:Read`, so the pending-agents route, which used to return the minter's view narrowed to the token's tagged agents, now refuses the token. `GET /api/v1/upload-grants` used to evaluate only the minter, so a service-scoped token inherited the minter's view of every grant; it is now refused, as the MCP tool `list_upload_grants` already was. **Remediation:** call both routes with a non-service token. For the enrollment route that means an Administrator-minted token, which replaces a confined credential with an Administrator-grade one; no narrower option exists today. Non-service callers, elevated sessions and engine principals are unchanged, and `kServiceScopeGlobalSafe` is not widened. A failed read of the `ITServiceOwner` role now answers a retryable `503` (`retry_after_ms` 5000) on the fleet-read and `require_scoped_permission` gates (the latter answered `403` before, indistinguishable from a definitive deny); every case still fails closed. See [Upgrading](docs/user-manual/upgrading.md).
