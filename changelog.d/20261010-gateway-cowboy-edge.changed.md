- **UPGRADE ACTION (gateway): move the listener settings from `{grpcbox, [{servers, ...}]}` to `{yuzu_gw, [{grpc_listeners, ...}]}`; a gateway config that still has a `{servers, ...}` block refuses to boot.** The gateway's agent (`:50051`) and management (`:50063`) listeners are now served by the gateway's own gRPC layer over Cowboy instead of grpcbox; the wire protocol, the TLS postures and the management-plane peer pin are unchanged. Each listener is one map (`name`, `service_protos`, `services`, `listen`, `tls`, `auth_fun`, `acceptors`, `http2`, `limits`); an incomplete `tls` map (certfile, keyfile and cacertfile are all required) now refuses boot instead of running plaintext. Every shipped config and compose file is converted, and `gateway/config/sys.config.prod` is the reference (see `docs/user-manual/gateway.md`, "gRPC listeners"). `{grpcbox, [{client, ...}]}`, the upstream channel, is unchanged.
- **Gateway: the client address the gateway reports upstream is now decided by the gateway, and `YUZU_GW_AGENT_PORT` / `YUZU_GW_MGMT_PORT` now take effect.** `RegisterRequest.gateway_observed_peer` is set by the gateway to the TCP peer (or, for a listener behind a load balancer or router, the address a trusted proxy vouched for) and whatever the agent sent is discarded. A new per-listener `origin` option (`transport`, `proxy_protocol` for an F5 iRule or HAProxy `send-proxy-v2`, `forwarded_for` for a router that terminates TLS) names the proxies to trust; a claim from any other peer is ignored, not refused. New counters `yuzu_gw_grpc_origin_ignored_total{mode,reason}` and `yuzu_gw_grpc_dropped_data_bytes_total{reason}`. See `docs/user-manual/gateway.md`, "Client addresses behind a proxy" and "Moving the agent edge to mutual TLS".
