- **Breaking — gateway listeners move from `{grpcbox, [{servers, ...}]}` to `{yuzu_gw, [{grpc_listeners, ...}]}`; the gateway image and its `sys.config` are an atomic pair.** The agent (`:50051`) and management (`:50063`) listeners are now served by the gateway's own gRPC layer over Cowboy and Ranch instead of grpcbox; the wire protocol, the protobuf contracts and the management-plane SPKI peer pin are unchanged, and `{grpcbox, [{client, ...}]}` (the upstream channel) stays. Every shipped config and compose file is converted, but a config you wrote is not: a `servers` block now **refuses to boot** (`Refusing to start: {grpcbox, servers} is set`), as does an unset or empty `grpc_listeners` (unless `{allow_no_listeners, true}`), and **an old gateway image given a new-shape config binds no listener, logs nothing and still answers `/healthz` and `/readyz` with 200**, so upgrade and roll back the image and the config together. Each listener is one map with the keys `name` (mandatory, unique), `service_protos`, `services`, `listen`, `tls`, `auth_fun`, `origin`, `acceptors`, `http2` and `limits`; the maps `tls` (`certfile`, `keyfile`, `cacertfile`, `verify`, `fail_if_no_peer_cert`, `ciphers`), `listen` (`port`, `ip`, `socket_opts`), `origin` (`mode`, `sources`, `trusted_hops`), `http2` and `limits` (`max_connections`, `max_message_bytes`, `send_timeout_ms`) are closed too, so a legacy key (`grpc_opts`, `listen_opts`, `transport_opts`, `pool_opts`, `ssl`) or a typo refuses boot by name instead of being ignored. An `auth_fun` on any listener that serves the agent service (`agent_pb` in `service_protos`, or the AgentService itself among its `services`) is refused, a non-empty `grpc_listeners` with no entry that routes the AgentService (its `services` map has the key `'yuzu.agent.v1.AgentService'`) refuses boot too (unless `{allow_no_listeners, true}`, the literal `true`), and `socket_opts` may no longer carry `ip`, `ifaddr`, `fd`, `port` or `{local, _}`. The old `transport_opts` could carry SSL options the closed `tls` map does not: `versions`, `depth`, `crl_check`, `partial_chain` and an encrypted-key `password` are not supported and refuse boot (decrypt the key first; supporting them is a follow-up). `YUZU_GW_AGENT_PORT` and `YUZU_GW_MGMT_PORT`, which changed nothing before, now rewrite the port of the one listener that serves the proto (ignored with a warning when zero or several do), and `/readyz` now also requires every configured listener to be running and at least one to route the AgentService. The TLS 1.2 floor and the mutual-TLS and pin postures are unchanged, but the TLS options are not the OTP defaults any more: the cipher list is chosen by the certificate's key type (ECDHE-ECDSA AEAD suites for an EC key, ECDHE-RSA AES-GCM suites for an RSA key) unless `tls.ciphers` is set, the gateway's cipher order decides the suite (`honor_cipher_order`), and TLS session reuse is off (`reuse_sessions` false), so every reconnect is a full handshake and a reconnect herd costs more CPU; FIPS mode is not claimed. The shipped production and reference configs now set `limits` on both listeners: `max_connections => 60000` on the agent listener and `256` on the management listener (neither had a ceiling before), and an explicit `max_message_bytes => 4194304` (the default). `max_connections` bounds file descriptors and is not protection against a hostile peer: a peer that completes the handshake and keeps sending can hold agent-listener connections open and fill the ceiling (an accepted residual risk of the unauthenticated agent port; limit connections per source at the L4 balancer or firewall), and about 256 held connections would stop the server making new connections to the gateway (before the TLS handshake anyone with layer-4 reach can hold one, after it any holder of a certificate issued by the install CA, which every enrolled agent has), a known limitation that will not be fixed in the gateway, so firewall the management port (`:50063`) to the server replicas, bind it to the management interface with `listen.ip` and, where you can, multi-home the server onto a separate interface. See `docs/user-manual/upgrading.md`, "Gateway listeners move to `grpc_listeners`" (key mapping, an offline pre-flight check, roll-forward and roll-back) and `docs/user-manual/gateway.md`, "gRPC listeners".
- **Gateway: the client address reported upstream is now decided by the gateway, and an older gateway still lets an agent forge it, so upgrade every gateway first.** `RegisterRequest.gateway_observed_peer` is set by the gateway to the TCP peer, or, for a listener behind a load balancer or router, to the address a trusted proxy vouched for, and whatever the agent sent is discarded; the server's audit `source_ip` follows it. A new per-listener `origin` option (`transport`, the default; `proxy_protocol` for an F5 iRule or HAProxy `send-proxy-v2`; `forwarded_for` for a router that terminates TLS, reading the `x-forwarded-for` entry `trusted_hops` places from the right and ignoring everything to its left) names the proxies to trust by their address (`sources`); a claim from any other peer is ignored and the call is attributed to that peer. When a configured proxy gives no usable address the call is sent with no observed address and the server records `origin_observed=false`. A listener left in `transport` mode behind a proxy you did not configure attributes every agent to the proxy and flags nothing. New counters `yuzu_gw_grpc_origin_ignored_total{mode,reason}` and `yuzu_gw_grpc_dropped_data_bytes_total{reason}` and two alerts, `YuzuGatewayOriginUnusable` and `YuzuGatewayOriginSourcesMismatch`. Also new on the gateway: a queued `Register` or `Inventory` upstream call whose requesting gRPC call has already ended (the client reset the stream or its deadline passed) is now skipped instead of run, counted in `yuzu_gw_upstream_calls_dropped_total{rpc_name}`; the reservation a dying `Register` held is released at once; and the handler-failure WARN is limited to one line per second per node (`grpc_runner_warn_interval_ms`). See `docs/user-manual/gateway.md`, "Client addresses behind a proxy" and "Moving the agent edge to mutual TLS".
