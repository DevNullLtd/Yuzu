- **Guardian dashboard mutations fail closed on audit failure and refuse cross-origin posts.** Editing, deleting or enabling/disabling a Guard from the dashboard now writes its audit row before the change and refuses the change (503 with `Sec-Audit-Failed: true`; the toggle re-renders with a banner) when the row cannot be written, so a change is never applied without a record. Guard create, Enable/Disable and every Baseline create, edit, deploy and delete now refuse cross-origin requests the way Guard edit and delete already did. The Guard page's Enable/Disable button asks for confirmation, a degraded Guard read says so instead of "Guard not found", and the shared dialog helper refuses a URL that is not same-origin and replays the MFA step-up request with the exact body that was confirmed. Deployments behind a reverse proxy that rewrites `Host` must declare their external origin with `--csrf-trusted-origin`, as for the other same-site-gated actions, or these Guardian actions return 403.
