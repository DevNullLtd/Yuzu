- **A File spark watch now notices a renamed or replaced parent directory instead of staying silently deaf (Windows, #5719 item 5).** The watch held a handle that followed the renamed directory, so it kept reporting Healthy and never saw a change at the watched path. An idle watch now re-opens its directory path every 5 s and compares the directory identity with the one its handle was opened on; a different directory, or a path that names nothing, reports the watch faulted (`file watch parent directory renamed or replaced`) and re-discovers the path. Detection is sampled: it detects a renamed or replaced parent directory within about 5 s on filesystems that provide a directory id (validated on local NTFS only), and the watch then stays faulted until the 30 s retry. A watch whose check cannot decide 3 checks in a row is also reported faulted (`file watch parent directory unverifiable`). Not covered: an ancestor shelter whose own parent is renamed, filesystems that give no file id (a FAT32 volume was observed to go undetected), and detection between samples. No File spark is armed in production today (`prefer_spark_` is false), so this is visible only on rig-flipped agents.
