- **Parameter validation hardened.** Text bound into database statements is now refused when it contains an embedded NUL byte, instead of being silently cut at that byte. At the edges this means: a gateway stream-status notification with a NUL in an identifier is rejected; a directory-sync record with a NUL in a stored field is skipped and counted while the rest of the snapshot applies; the asynchronous result-set producers (REST and MCP) refuse a name with a NUL before anything is dispatched; and `unassign_rbac_role` validates its `role` argument (no NUL, control or DEL byte) before its guards run, using one resolved role value for the guards, the delete and the audit row. Invalid input is answered with a client error rather than a server fault where the surface allows it.
