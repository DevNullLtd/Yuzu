- Registry read output and every row rendered through the shared `sanitize_field` (the registry read actions, the `installed_apps` and `autoruns` hive-access lines, and the REG_MULTI_SZ and REG_LINK values that `autoruns` and the `execution_artifacts` AmCache walk read through `read_reg_value`) now drop trailing NULs and fold every control character except TAB (ESC, VT, FF, FS, GS, RS and an interior NUL among them), DEL, the C1 controls U+0080-U+009F (NEL, CSI and OSC among them) and U+2028 and U+2029 to `_`, beside the `|`, CR and LF folded before, and the `registry.write` audit tokens (which already folded the C0 controls and DEL) now fold the C1 controls, U+2028 and U+2029 too, so a registry name or value cannot split a log line, start a terminal escape or forge a row. An embedded NUL in a registry name or in `get_value` string data no longer cuts its output row short at the plugin C ABI (`get_user_value` still reads a string value up to its first NUL, as Windows does), which narrows the output-side twin of #6485. The rendered text is display text: the folded characters cannot be recovered from a row.
