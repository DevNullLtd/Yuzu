- **A successful second-factor login no longer keeps an old wrong code counting past its window.** The failure budget at `POST /login/mfa` and `POST /login/mfa/stepup` reserves an attempt before the code is checked, which also stamped `auth.users.mfa_last_attempt_at`; a correct code gave back the count but not that stamp, so regular successful logins kept one old failure alive and a later wrong code added to it instead of starting a new count. The refund now restores the stamp as well, while it is still the one that reservation wrote. The budget was never looser than configured, only tighter. Follow-up to #8626 (review finding C-02).
