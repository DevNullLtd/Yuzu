- **`/test --instructions` runner can drive Destructive and Forensics definitions at one chosen agent.** `scripts/test/instructions_runner.py` gains `--target-agent-id`, `--confirm-target` (the agent's hostname, checked against `GET /api/agents` before anything is sent), `--params-override`, `--run-id`, `--manifest` and `--allow-remote`. Those classes are opt-in, run one at a time against exactly one agent on a loopback dashboard (unless `--allow-remote`), and only with an explicit parameter entry per definition. Every dispatch is written to an append-only manifest before it is sent. Only a 4xx, a 503 with a known pre-dispatch reason, a pending-approval 202 or a refused connection mean "not executed"; anything else ends the run as `dispatch_unknown`, including the generic 503 "no agents reached". Ctrl-C, Ctrl-Break (Windows) and SIGTERM stop dispatching and exit 130. The default run (safe and mutating, no target) is unchanged. See `/test` SKILL.md, "`--instructions` mode".
