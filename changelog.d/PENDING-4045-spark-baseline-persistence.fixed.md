- **Guardian: a baseline captured on arm under SparkEngine is now persisted, so a `full_sync` or agent restart no longer re-baselines a drifted file as compliant.** A `file-hash-equals` rule with no authored `expected_hash` takes the file's content at arm time as its known-good baseline. Since #4021 the legacy detection path saved that baseline to the agent's local KV store, but SparkEngine's own capture lived only in memory, so the next policy re-push or restart captured whatever the file then held and reported it compliant. The Spark runtime now stages each capture and the agent's engine writes it through the same overwrite-guarded #4021 record (before any teardown or re-arm, at shutdown, and from the background delivery worker, independent of the server connection), and a re-armed rule is seeded from a capture that is still waiting to be written, so a capture recorded just as a policy push begins is not lost to the re-arm. A failing local KV store is deliberately fail-open (the rule keeps enforcing against its in-memory baseline) but is retried, error-logged, and counted in the new sparse `yuzu.guardian_baseline_persist_failures` heartbeat tag (monitor-only; no server gauge or alert rule yet). A crash between a capture and its write still loses that capture. Inert while `prefer_spark` is off, which is every released agent today (#4045).
