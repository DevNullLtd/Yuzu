- The TAR `module` and `procperf` sources on Windows no longer open an image on a network path. UNC, `\Device\Mup` and the other redirectors are classified before any file or trust API is called, so the agent (which runs as LocalSystem) no longer authenticates its machine account to a share host or stalls on the SMB round trip; the module row keeps an unknown signing verdict and the procperf version is empty. A drive-letter image is opened only on a fixed drive, and an NT volume path on any local volume (removable included) is still opened by the module source. On Linux and macOS, `tar.db` and its `-wal`/`-shm` files are set to owner-only (0600) each time the database is opened.
