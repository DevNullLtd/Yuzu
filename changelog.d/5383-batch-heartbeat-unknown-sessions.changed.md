- **`BatchHeartbeatResponse` now reports the sessions the server does not hold (#1197).** The gateway upstream `BatchHeartbeat` reply gains `unknown_session_ids` (distinct session ids in the batch that this server replica has no in-memory record of, at most 4096, each at most 64 bytes) and `unknown_session_ids_truncated`. The gateway consumes them in the same release (see the gateway heartbeat reconcile entry); without it, after a server-only restart `/health` `agents.online` can stay 0 while the server WARNs `GatewayRouteStore renew_leases guard rejected the write (outcome=unknown_session ...)` and `yuzu_server_gateway_route_desync_total{op="renew_leases",outcome="unknown_session"}` rises. Old gateways ignore the new fields and old servers leave them empty, so no upgrade ordering is required. A new `yuzu_server_gateway_route_desync_total{op="batch_heartbeat",outcome="malformed_session_id"}` series counts over-length ids the server does not hold (expected to stay at zero); they no longer count under `renew_leases`/`unknown_session`. The gateway manual's `BatchHeartbeat` interval default is corrected to 1000 ms (`heartbeat_batch_interval_ms`; it said 10 seconds).
