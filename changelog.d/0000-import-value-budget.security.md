- **A request body of more than 100000 JSON values is refused `400` on the definition import, create and update routes (#2146).** The legacy `POST /api/instructions/import`, `POST /api/instructions`, `PUT /api/instructions/{id}` and the JSON bodies of the v1 instruction and instruction-set authoring routes refuse a body that holds more than 100000 structural values (`[`, `{` and `,` outside a string) with `... too many values`, before parsing it; the import also applies the limit to each JSON-encoded string field it re-parses (`parameter_schema`, `result_schema`, `visualization_spec`, `response_templates_spec`). A 16 MiB body of `[],[],...` built a parse tree of 258 to 429 MiB per request, and eight concurrent ones by a holder of `InstructionDefinition:Write` were enough to get a process killed for exceeding a 2 GB memory limit. A definition is a few hundred values, so no real document is near the limit. The MCP `import_definition` applies the limit to the document after the JSON-RPC envelope was parsed (a tool error, `-32602`), which does not bound the envelope's own memory.
