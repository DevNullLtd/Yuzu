- **`yuzu-server.cfg` can no longer override a stored password (#5274).** Login used to check the password hashes loaded from `yuzu-server.cfg` before the PostgreSQL auth store, so after a password change every restart brought the old config-file password back on that server, and other replicas kept accepting the old password until they restarted. Login now reads the auth store only, and a login whose stored password changes while it is being checked is denied (the user retries; `yuzu_auth_credential_changed_during_verify_total`). The config file only seeds the first administrator into an empty database. **Behaviour change:** editing or regenerating `yuzu-server.cfg`, or re-running the Windows server installer with a new `/ADMIN_PASS`, no longer resets an existing account's password — use the new in-product change/reset (#5342) or the direct-SQL fallback in the auth-store recovery runbook. See [Upgrading](docs/user-manual/upgrading.md).
