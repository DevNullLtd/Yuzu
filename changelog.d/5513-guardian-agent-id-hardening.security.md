- **Agent-supplied values on registration and related log lines can no longer start a new log line.** The registration, update-check and update-download logs, the agent certificate signing logs on the registration path, the agent registry's registration and revoke logs, the command-completion logs, the gateway stream-status, gateway command-drop and Guardian-forwarding logs, the custom-properties store's and the tag store's database error text, agent ids and tag keys, the custom-properties store's invalid-pattern warning, the runtime-config route's store error and key logs, the database pool's connect-failure and transaction-start failure text, and the Guardian ingest warnings now fold agent ids, command ids, plugin names, gateway node names and cluster ids to a closed character set, so they also cannot add a same-line `key=value` token, and fold line breaks and control characters in hostnames, tag keys and store error text. Log lines that print an id read back from the session table or the enrollment store (the Heartbeat, BatchHeartbeat, ReportInventory and ProxyInventory ingest paths and the shared ingestion modules they call, the Subscribe stream open and close lines, and the agent registry's other log lines that print a session-table id (removal, rollback, session-timeout, sweep and dispatch-routing lines)) print it as stored. The enrollment store's agent-id check refuses control bytes and `,` but accepts a space, `=` and non-ASCII characters including U+0085, U+2028 and U+2029, so a legacy or imported id can add same-line `key=value` tokens and, for a log reader that also splits on those code points, extra lines. The exception text of the ingest catch-alls is printed as is.
