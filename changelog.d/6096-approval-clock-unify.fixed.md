- **One approval now runs exactly one scheduled occurrence, whatever the server clocks say (#6096).** An approval ticket's submission time was stamped from the submitting server's own clock and compared with the schedule's own run stamps to decide that an approved ticket was already spent, so a clock step or skew between submitting and firing could re-fire an occurrence (extra runs for up to 7 days) or let a skewed server pin the global pending-approval cap. Submission time is now database time like every other approval stamp, and a scheduled ticket is marked used (a guarded `consumed_at` transition) when its occurrence is queued, so no clock comparison decides it. The first time each schedule is processed after upgrading, its pre-upgrade approved or rejected tickets submitted at or before its last run are marked used; see `docs/user-manual/upgrading.md`.
