- **Breaking — the Compose files that run Grafana now require `YUZU_GRAFANA_ADMIN_PASSWORD`, and no longer start Grafana with the `admin`/`admin` login (#4817, #661).** `deploy/docker/docker-compose.yml`, `deploy/docker/docker-compose.uat.yml`, `deploy/docker/docker-compose.full-uat.yml` and `docker-compose.uat.yml` set `GF_SECURITY_ADMIN_PASSWORD=admin` and published Grafana on port 3000 on every interface, so anyone who could reach the host had full Grafana admin, including adding data sources that make Grafana request arbitrary internal URLs. These files now require `YUZU_GRAFANA_ADMIN_PASSWORD`, and **Compose refuses every command that reads them, `down` and `ps` included, until it is set** (for example `export YUZU_GRAFANA_ADMIN_PASSWORD="$(openssl rand -hex 16)"`, or a line in a `.env` file next to the compose file; for `down`, `ps` and `logs` any non-empty value works; the root `docker-compose.uat.yml` also needs `YUZU_GW_COOKIE`, and `docker-compose.full-uat.yml` run by hand also needs `UAT_CONFIG`). **An existing install still accepts `admin`/`admin`:** Grafana applies the setting only when it first creates its database, so on an existing `grafana-data` or `grafana-uat-data` volume change it with `docker compose exec grafana grafana cli admin reset-admin-password '<new password>'` (see the Upgrading guide). `scripts/docker-start-UAT.sh` and `scripts/win-start-UAT.sh` set it for you: `start` uses an exported value, the previously saved one or a new random one, saves it in `.uat/grafana-admin-password` (mode 0600 where the filesystem honours it), prints it and refuses `admin`, an empty value and surrounding whitespace, checking an exported value before it stops anything; `stop` and `status` only read it (`status` shows the saved login, an exported one with a caveat, or says the login is unknown), and the password is un-exported and passed only to each `docker compose` command, so the server, gateway and agent the launchers start do not inherit it. The Compose Wizard no longer defaults the field to `admin`, refuses an empty value, `admin`, and anything but printable ASCII without spaces, `$` or quotes (Compose changes those in `.env`), and writes the password only to the generated `.env`; the compose it generates requires it. The reference composes (`docker-compose.reference*.yml`) run no Grafana and are unchanged. A new check, `tests/test_compose_default_credentials.py`, fails if a tracked compose runs Grafana without a required password. Out of scope and tracked separately: ClickHouse's default credentials and all-interface exposure in the same files (#420), the fixed Yuzu dashboard password hash in `docker-compose.uat.yml` (#417) and `deploy/config/uat/yuzu-server.cfg` (#4790), the ClickHouse password the Compose Wizard still writes into the generated compose (#3876), the native Grafana that `scripts/start-stack.sh` starts with its built-in `admin`/`admin` login (#7053), and Grafana still being served over plain HTTP on every interface (#4818).
