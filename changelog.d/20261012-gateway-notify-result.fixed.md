- **A gateway now treats a failed stream-status notification as a failure of the server, and recovers an agent whose CONNECTED was lost (governance up-6).** The gateway tells the server about each agent's stream with a `NotifyStreamStatus` from a worker process, and a failed one was only logged: it never counted toward the circuit breaker, and a success after it never replayed the registrations. A server that restarted or dropped the connection at the wrong moment could therefore leave an agent connected to the gateway and unknown to the server until the agent reconnected on its own. The worker now reports its result to the upstream process, so a failed notification counts toward the breaker like a failed `ProxyRegister`, and a success after failures replays the agents the gateway holds. Expect the breaker to open after `circuit_breaker_failure_threshold` consecutive failures across calls and notifications together, not calls alone. Restart the gateway to deploy.
