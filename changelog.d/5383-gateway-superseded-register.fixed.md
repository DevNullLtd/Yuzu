- **A gateway now answers an overlapped `Register` as retryable, not as a registry failure (#1197).** When two `Register` calls of one agent id overlap on one connection, the older one is answered `UNAVAILABLE` (14) and logged at INFO as `Register superseded by a newer registration`; before, it was answered `INTERNAL` (13) with the WARN `Register failed: registry_unavailable`, which is now kept for a registry that cannot be reached. The agent retries any non-OK `Register` with its reconnect backoff, so no action is needed. A connection's reserved and pending rows are also removed after the grace by the connection's index and no longer by a scan of the pending table, which costs registry time in proportion to that connection's rows only; a row stored and not yet committed is removed by its own commit or by the pending time to live sweep. Restart the gateway to deploy. Refs #1197.
