- **Echo no longer fills the data volume when `echo.db` is corrupted repeatedly, and `echo.configure` no longer reports a partly applied change as success.** Each quarantine now keeps only the newest three `echo.db.corrupt-*` groups (the file and its sidecars) and deletes older ones, never the one just made; deletion is best effort, so a file that cannot be removed is logged and left for the next recovery. Every setting `configure` saves is now checked: a failed write exits `1`, and when earlier settings in the same call had already persisted the reply adds `partial|applied|<keys>` and the result status is `constrained` (`echo:configure_partial_commit`). Callers that read exit `0` as success against a busy database now see exit `1`.
