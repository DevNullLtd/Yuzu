- **`registry` 2.0.0: typed, verified writes on a link-checked handle.** `set_value` now writes all six value types (`REG_SZ`, `REG_EXPAND_SZ`, `REG_BINARY`, `REG_DWORD`, `REG_MULTI_SZ`, `REG_QWORD`) from text or exact `data_hex` bytes, captures the previous value, reads the new one back on the same handle and fails on any difference (`verify_mismatch`). Every mutation runs on a checked handle: on `HKLM` and `HKU` one open whose canonical kernel name is compared with the requested path (a registry symbolic link anywhere in the path changes that name and sends the call to the reference component walk), on `HKCU` and `HKCR`, for a missing key and whenever the open cannot decide, the walk itself, which refuses a link (`key_is_link`), creates missing components, refuses `concurrent_change` and hands over a handle only when its canonical kernel name is the requested path, so a link completed after its probe cannot redirect it (a walk that does not hand its leaf over deletes every key it created, by handle, and the audit line's `created=` reports any left). Keys are deleted by handle with `NtDeleteKey`, so a swapped path cannot redirect a write or a delete; `delete_key` still removes only a key with no subkeys and now reports `counted_keys`, `counted_values`, `dry_run` and `capped` (the count stops at 10,000 nodes: the key plus up to 9,999 values). Every mutating action emits one `audit|` line with the old and new values (hex, capped at 256 bytes), which the server records as a `registry.write` row when the agent stamps the action; the line grammar and the producer contract are published in the plugin README. The macOS and Linux legs are declared as planned stubs.
