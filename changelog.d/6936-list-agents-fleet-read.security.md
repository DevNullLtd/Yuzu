- **MCP `list_agents` now admits callers whose `Infrastructure:Read` comes only from a management-group role, returning only that group's devices.** With RBAC enforced, such a caller was refused with a 403 before. The result now carries `scope_basis: "authority_scoped"`, and `content[0].text` is the object `{agents, scope_basis}` for that caller. Per ADR-0017's 2026-07-24 update, a group allow is admitted even alongside a global deny. Callers with a global grant, callers with an engine grant, and non-engine callers while RBAC is off are unchanged: they read every connected agent, `content[0].text` stays the bare array, and no previously admitted caller loses a row. The tool now uses the same admit-then-filter fleet-read gate as `get_agent_details` and `GET /api/v1/devices` (#4041). An authorization-store failure now returns a retryable 503 with `retry_after_ms` where it returned a 403, and a denial is audited as `auth.fleet_read_required` rather than `auth.permission_required`. A service-scoped token is still refused on this tool. The access-review export does not yet list grants held through management-group roles (#6969), and a decommissioned device's group membership is not removed, so a re-enrolled `agent_id` inherits it (#6352).
