- **Breaking, fresh deployment only: several log lines and audit details change shape, so log parsers, SIEM rules and runbooks written against the earlier strings need updating (see "Upgrading").** Old to new: the agent line `Registered with server (session=<id>, ...)` is now `(session_fp=<8 hex>, ...)` (a SHA-256 fingerprint; take the id from the server's `ProxyRegister succeeded ... session=` line); Postgres connect-phase failures in the pool, the leader elector, the readiness probe and `yuzu_pg_canary` log a fixed cause (for example `server not reachable ...`, `no free connection slots ...`) instead of libpq's text, and the readiness probe's #4943 discriminator is that cause rather than libpq's `remaining connection slots are reserved` text, and `PgPool::last_error()` returns that cause; the `auth.saml_login_failed` audit detail and analytics event are folded and clipped to 128 bytes (`;` and `=` become `_`, no truncation marker; the log keeps 256) instead of the raw validator text; user names and NameIDs in the login, lockout and SAML/OIDC session log lines are folded. Fixes (a defined set of sites, not a complete audit of logging): CWE-117 log forging from the unauthenticated `POST /login` username and from identity values on login, SAML, OIDC and SCIM sites, from the SAML ACS error text, from `kek_meta.kcv_alg` and from journald-sourced DEX subjects and reasons; `log_key_token` and `audit_token` now fold every well-formed C1 control (a lone 0x80-0x9F byte or a trailing `C2` still passes in `log_key_token`); the connect-phase logs no longer quote libpq text (post-connect errors, for example in `ca_store.cpp`, still do), which could include part of a URI-DSN password containing an unescaped `/` or `@`. Not covered: the readiness probe's query-phase failures (after a connection exists) log the step plus the first line of libpq's message, folded and capped at 120 bytes, not a fixed cause; other store error lines still print libpq text after control-character folding (about 350 sites, #5964), and the agent session id is still emitted raw by `status.switch` and `diagnostics.connection_info`, so the session-credential finding (#8159) is only partly fixed (the Heartbeat and ReportInventory binding and a `PluginSecret` read tier are open).
