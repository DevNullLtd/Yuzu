- **Breaking — log and audit-detail strings changed (log parsers and runbooks, see "Upgrading").** Old to new: the agent line `Registered with server (session=<id>, ...)` is now `(session_fp=<8 hex>, ...)` (a SHA-256 fingerprint; take the id from the server's `ProxyRegister succeeded ... session=` line); Postgres connect failures in the pool, the leader elector, the readiness probe and `yuzu_pg_canary` log a fixed cause (for example `server not reachable ...`) instead of libpq's text, and `PgPool::last_error()` returns that cause; the `auth.saml_login_failed` audit detail and analytics event are folded and clipped to 128 bytes (`;` and `=` become `_`, no truncation marker; the log keeps 256) instead of the raw validator text; user names and NameIDs in the login, lockout and SAML/OIDC session log lines are folded. Fixes: CWE-117 log forging from the unauthenticated `POST /login` username and the SAML/OIDC/SCIM identity values on those paths, from the SAML ACS error text, from `kek_meta.kcv_alg` and from journald-sourced DEX subjects and reasons; `log_key_token` and `audit_token` now fold every well-formed C1 control (a lone 0x80-0x9F byte or a trailing `C2` still passes in `log_key_token`); the connect-failure logs no longer quote libpq text, which could include part of a URI-DSN password containing an unescaped `/` or `@`. Not covered: other store error lines still print libpq text after control-character folding (about 350 sites, #5964), and the agent session id is still emitted raw by `status.switch` and `diagnostics.connection_info` and may remain in log files written before the upgrade, so the F50 session-credential finding is only partly fixed (the Heartbeat and ReportInventory binding and a `PluginSecret` read tier are open).
