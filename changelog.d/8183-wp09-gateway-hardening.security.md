- **Breaking —** Gateway: the Erlang distribution cookie is checked before the VM starts, and `vm.args.src` has no fallback to the published value `yuzu_gw_secret_change_me` (finding F24 of the 2026-11-17 security scan; the in-VM guard alone runs only after distribution is already listening). The container entrypoint and the systemd unit (`ExecStartPre`, no override) refuse a cookie that is unset, empty, the published default, shorter than 32 characters, or contains a character outside `[A-Za-z0-9._~+=-]` (or starts with `-`/`+`), and print the reason; both use one shared policy file, `gateway-cookie-policy.sh`, installed next to the release by the image, the `.deb` and the `.rpm`. `YUZU_GW_ALLOW_DEFAULT_COOKIE=1` does not mean "use the published default": in the container an empty or exactly-default cookie is replaced by a random per-boot cookie and a custom cookie that is short or starts with the published literal is refused, so N replicas on the override are N singletons that cannot cluster; only a node advertising `127.0.0.1` also gets its distribution and EPMD bound to loopback. A manual systemd unit with no cookie (the override does not apply to the unit), a short cookie or an odd-character cookie fails to start; `.deb`/`.rpm` installs write a 64-hex cookie and pass. A cookie that contains the published default inside a longer value is refused (`... contains the published default value.`; under the override only when it starts with it). The in-VM guard under the override tolerates an empty, short or literal-containing cookie on an entrypoint-less start (`docker run --entrypoint`, hand-run `bin/yuzu_gw`, the chisel image), unlike the entrypoint. Cookies longer than 255 characters are refused too (the VM crashes on them). The release tarball ships `gateway-cookie-policy.sh` and `yuzu-gateway.service` inside its single top-level directory (extract with `--strip-components=1` into `/opt/yuzu_gw`). Gateway Erlang distribution is unencrypted plain TCP outside the PKI; the cluster network must be trusted and firewalled (TLS distribution is tracked as #8158, decision pending; owner: Fraser Jarvis; review by 2027-02-17). See "Gateway cookie is checked before the VM starts" in the upgrade guide.
- Gateway: a Register the server rejected (`accepted=false`, or an answer with no session id) leaves no pending registration that an empty `x-yuzu-session-id` on Subscribe could complete (finding F29 of the 2026-11-17 security scan). Subscribe refuses an empty or missing session header, and the registry refuses an empty pending key.
- Gateway: `scripts/check-proto-codegen.sh` empties its nested scratch directory in place instead of deleting and re-creating it by name (finding F74 of the 2026-11-17 security scan).
