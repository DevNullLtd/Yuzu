- **Breaking —** Gateway: the Erlang distribution cookie is now checked before the VM starts, and `vm.args.src` no longer falls back to the published value `yuzu_gw_secret_change_me` (finding F24 of the 2026-11-17 security scan; the in-VM guard only ran after distribution was already listening). The container entrypoint and the systemd unit (`ExecStartPre`, no override) refuse a cookie that is unset, empty, the published default, shorter than 32 characters, or contains a character outside `[A-Za-z0-9._~+=-]` (or starts with `-`/`+`), and print the reason; both use one shared policy file, `gateway-cookie-policy.sh`, now installed next to the release by the image, the `.deb` and the `.rpm`. `YUZU_GW_ALLOW_DEFAULT_COOKIE=1` no longer means "use the published default": in the container an empty or exactly-default cookie is replaced by a random per-boot cookie and a custom cookie that is short or starts with the published literal is refused, so N replicas on the override are N singletons that cannot cluster; only a node advertising `127.0.0.1` also gets its distribution and EPMD bound to loopback. A manual systemd unit that relied on the override, or a short or odd-character cookie, now fails to start; `.deb`/`.rpm` installs (64-hex cookie) are unaffected. A cookie that contains the published default inside a longer value is now refused (`... contains the published default value.`; under the override only when it starts with it). The in-VM guard is unchanged: under the override it still tolerates an empty, short or literal-containing cookie on an entrypoint-less start (`docker run --entrypoint`, hand-run `bin/yuzu_gw`, the chisel image), unlike the entrypoint. Cookies longer than 255 characters are refused too (the VM crashes on them). The release tarball now ships `gateway-cookie-policy.sh` and `yuzu-gateway.service`. Gateway Erlang distribution is still unencrypted plain TCP outside the PKI; the cluster network must be trusted and firewalled (TLS distribution is tracked as #8158, decision pending; owner: Fraser Jarvis; review by 2027-02-17). See "Gateway cookie is now checked before the VM starts" in the upgrade guide.
- Gateway: a Register the server rejected (`accepted=false`, or an answer with no session id) no longer leaves a pending registration that an empty `x-yuzu-session-id` on Subscribe could complete (finding F29 of the 2026-11-17 security scan). Subscribe refuses an empty or missing session header, and the registry refuses an empty pending key.
- Gateway: `scripts/check-proto-codegen.sh` empties its nested scratch directory in place instead of deleting and re-creating it by name (finding F74 of the 2026-11-17 security scan).
