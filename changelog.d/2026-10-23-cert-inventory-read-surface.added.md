- **Fleet certificate read surface.** `GET /api/v1/crypto/certificates` (one row per device and certificate, raw X.509 facts, keyset-paged) and `GET /api/v1/crypto/certificates/summary` (distinct-device and distinct-certificate counts grouped by key algorithm and size, signature algorithm, curve, issuer, store, plus a `not_after` histogram over edges you supply), with MCP twins `list_crypto_certificates` and `get_crypto_certificate_summary` and the `/fragments/crypto/certificates[/devices]` dashboard fragments. Every filter is strict and identical on REST and MCP, including the one-CA queries (`issuer_dn_contains`, `subject_dn_contains` with `is_ca=true`, `spki_sha256`, `aki_key_id`). At most one substring-filtered read per user runs at a time (a second is a retryable `503`, `retry_after_ms` 5000). Gated on the new dedicated `CertificateInventory:Read` securable (40th; Administrator only, admin-floored while RBAC enforcement is off, 403 for service-scoped tokens, confined to the caller's visible devices). Each read is audited with filter names and operators only (never values, subjects or SANs); the REST routes fail closed on a lost audit row (503 + `Sec-Audit-Failed`), the fragments and MCP proceed with a visible notice. A degraded read is a 503 with a retry hint, never an empty 200; `result_truncated` is the OR of every cut. Adds the `cert_inventory.fleet_store_status` background pass and the `yuzu_fleet_cert_store_status{os,status}` gauge. The substring filters resolve through a distinct-DN dictionary that a leader-gated BACKGROUND pass builds (`CREATE INDEX CONCURRENTLY`, a batched reconcile at every start, a prune scheduled hourly from the database clock; nothing scans or indexes the certificate table at upgrade or boot, so startup and ingest are never held up); until it has completed after a start the two filters answer a retryable 503 (non-retryable only for a failed dictionary), and the dictionary is erased with the certificates it names (best effort at decommission, otherwise by an hourly prune, paused while a dictionary index is missing or invalid). No PostgreSQL extension is required (`YuzuCertSubstringDictionaryMissing` and `yuzu_server_cert_inventory_substring_index_available` watch it). Every read has a 15-second wall budget; a summary past it for a very large visible fleet is a non-retryable `scale_limit` 503. A `YuzuCertStoreStatusUnavailable` alert watches the gauge pass. See `server-admin.md` "The substring-filter dictionary".
