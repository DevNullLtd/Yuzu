- **Breaking —** A run is now `succeeded` only when every intended device answered successfully (#2673). A run with a device that failed, timed out, could not be delivered to, has an unknown outcome or was never reached (offline, not sent, withheld) finishes as `completed`, and a run whose device list was not fully saved can be `completed` at best. The first final result from each device stands, except that a server- or gateway-made delivery failure (`not_delivered` when the command certainly never reached the device, `unknown` when it may have) gives way to the device's own later answer. `agents_failure` now includes `timed_out`, `not_delivered` and `unknown` devices; `agents_responded` includes those delivery failures but not devices the deadline sweep marked `timed_out` or `unknown`; `progress_pct` is success plus failure over targeted. A rerun with `failed_only` counts the devices of a recorded run without a successful result; devices never reached are not counted. Software sync runs count selected devices that are offline or too old as intended and not reached. On the Executions page a `completed` run is never shown as successful, and the status filter "With failures" is renamed "Completed, not fully successful".
