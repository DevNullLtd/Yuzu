- **Release image gate: an audited, expiring override for one stalled grype DB provider (WP15).** The gate refuses an image when a grype DB provider it needs (`nvd`, or the image's `alpine`, `debian` or `ubuntu` feed) was captured more than 72 hours ago. `.grypeignore.yaml` may now hold a `provider_waivers:` entry for exactly one such provider, parsed by the same strict parser: a statement with the evidence of the upstream stall, an expiry at most 14 days out, and the same approval fields as an acceptance (a `pending` one is not honoured by a release). It admits only that provider's stale capture: a missing provider, an unreadable or future capture time, the DB's own age, checksum, status or schema, Trivy's DB checks, a finding from either scanner, coverage, the OS cross-check and the gateway's `erlang` check still refuse. An expired, over-long, duplicate or unknown-provider waiver refuses the whole file. No workflow input, option or variable enables one (on GitHub Actions `YUZU_GRYPEIGNORE` and `YUZU_TRIVYIGNORE` may name only the repository's files, and the gate reads those paths). An image judged with a waiver keeps `gate: pass` but its grype `.gate.txt` names the waiver and says `DEGRADED: provider waiver in force`, as does the step summary; a report that used none says `provider waiver: none used`, and an `nvd` waiver that lapses during a run fails the images judged after it. The release procedure requires the release notes of a release scanned degraded to say so. See `docs/ci-architecture.md` "Provider waivers" and `docs/user-manual/release-verification.md`.
