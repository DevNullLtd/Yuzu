- **MFA enrolment and recovery-code generation now fail closed when the system random-number generator faults (#4763).** Previously a failed random read was ignored on Windows, which could enrol a TOTP secret of all zeros or issue a recovery code built from uninitialised memory; on Linux and macOS the failure threw an exception that the HTTP layer answered as a generic `500`. Now enrolment and regeneration are refused and nothing is written; a partly completed enrolment confirmation is rolled back, and the failure is logged. Starting enrolment at sign-in returns `503` with `Retry-After`; confirming it returns `503` without `Retry-After`; the Settings pages show an on-page notice with HTTP `200`. A failed Settings regeneration now reads "Could not regenerate codes. Your existing recovery codes should be unchanged; if you are unsure, regenerate again." Sign-in failures are counted under the existing auth-store counters; a refused Settings regeneration is audited but not counted, and there is no dedicated MFA counter. A healthy host is unaffected. The Windows path was not compiled or run for this change.
