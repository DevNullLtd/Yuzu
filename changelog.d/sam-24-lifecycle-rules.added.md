- **An administrator can import, list and remove the software lifecycle rules over REST.** `POST /api/v1/inventory/software/lifecycle/rules?format=csv|cle&name=<file name>` replaces the whole imported rule set from a CSV or CLE file (at most 4 MiB and 5,000 rules; CLE is ECMA-428 1st edition, schema 1.0.0). The file is read all or nothing, and the answer reports how many rules were stored and a `skipped` list by reason. An imported CLE rule applies to every version of a product: a CLE record that names one exact version or a version range is skipped and counted, never stored as a prefix. A CLE identifier that lists more than 5,000 aliases is refused. `GET` lists the stored rules of one source (`imported` by default, `shipped` or `external`) and `DELETE` empties the imported set; the shipped and external rules are never touched. Import and removal need the global `Inventory:Write` grant, are audited ahead of the write (`software_estate.lifecycle_rules.import` and `.delete`; a row that cannot be stored refuses the request) and answer `503` with a retry hint when the store is unavailable. Three new operations, `postInventorySoftwareLifecycleRules`, `getInventorySoftwareLifecycleRules` and `deleteInventorySoftwareLifecycleRules`, are added to the OpenAPI document. OpenEoX import is not offered; it is tracked in #8000.
