- **Reinstalling or upgrading the Windows agent no longer locks the agent out of its update trust bundle.** The installer's lockdown of `%ProgramData%\Yuzu\agent-certs` gave every file already in that folder, such as an operator-provisioned `update-trust-bundle.pem`, an empty permission list. That locked out SYSTEM, and so the agent service, while the step still reported success, so updates signed against that bundle could no longer be verified. Reinstalling or upgrading with this version repairs an affected folder. Without reinstalling, `icacls "C:\ProgramData\Yuzu\agent-certs\*" /reset /T` repairs it too. That resets the files inside the folder, not the folder itself, whose own permissions must stay as they are. The installer's check now also requires Administrators and SYSTEM to have full control of every item, so an empty permission list stops the install instead of passing. The manual procedure for endpoints upgraded over OTA (`docs/user-manual/server-admin.md`) had the same mistake and is corrected. Setup also no longer fails when the installing account's profile path contains a typographic apostrophe. Found while testing on Windows Server 2022; the 0.14.0-rc5 installer reproduces it. (#5196)
