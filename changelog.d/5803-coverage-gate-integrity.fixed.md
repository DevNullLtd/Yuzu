- The local `/test` coverage gate (`scripts/test/coverage-gate.sh`) now configures with `pkg_config_path` as well as `cmake_prefix_path`, on a fresh build directory and on a reconfigure, which fixes the undefined c-ares/zlib link errors (#5803). It validates `YUZU_COVERAGE_TIMEOUT_MULT` (default 3, a number of at least 1), clears stale `.gcda` counters before each run (a run where that fails is inconclusive) and no longer passes `--branches`, which gcovr 8.7 removed.
- The local `/test` coverage gate no longer presents an unreliable run as a coverage figure (#6112, #6113, #6114). A second concurrent run on one build directory, or a run next to a surviving `meson test`, is refused, and a `--build-dir` that cannot be resolved to an absolute path is refused. A run with failed or timed-out tests, libgcov counter-write errors or a nearly full disk (`YUZU_COVERAGE_MIN_FREE_KB`, default 262144) is reported as a WARN row with no metric and no baseline comparison, and `--capture-baselines` refuses it. An unknown line figure is no longer recorded as 0.0, a failed gate or metric DB write is reported, fails the gate in `--full` (default mode only logs it) and turns an otherwise-PASS Coverage row into a WARN, a truncated baseline is reported as unreadable, and `--capture-baselines` fails (leaving the old baseline) if it cannot write the file. Ctrl-C or SIGTERM stops the running `meson test` and its test processes, which are killed after `YUZU_COVERAGE_KILL_GRACE_SECS` (default 30) if they ignore the TERM (meson, and any process whose start time proves it is the same one; others are left running and logged). The gate now checks coverage on a Linux host only: on macOS it refuses up front with a WARN row (no metric, no baseline comparison, `--capture-baselines` fails) instead of comparing an incomparable Apple-clang figure with the Linux baseline (#6187).
