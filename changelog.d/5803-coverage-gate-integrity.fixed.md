- The local `/test` coverage gate no longer presents an unreliable run as a coverage figure (#6112, #6113, #6114). A second concurrent run on one build directory, or a run next to a surviving `meson test`, is refused, and a `--build-dir` that cannot be resolved to an absolute path is refused. A run with failed or timed-out tests, libgcov counter-write errors or a nearly full disk (`YUZU_COVERAGE_MIN_FREE_KB`, default 262144) is reported as a WARN row with no metric and no baseline comparison, and `--capture-baselines` refuses it. An unknown line figure is no longer recorded as 0.0, a failed gate or metric DB write now fails the gate, a truncated baseline is reported as unreadable, and `--capture-baselines` fails (leaving the old baseline) if it cannot write the file. Ctrl-C or SIGTERM stops the running `meson test` and its test processes, which are killed after `YUZU_COVERAGE_KILL_GRACE_SECS` (default 30) if they ignore the TERM. The gate now checks coverage on a Linux host only: on macOS it refuses up front with a WARN row (no metric, no baseline comparison, `--capture-baselines` fails) instead of comparing an incomparable Apple-clang figure with the Linux baseline (#6187).
