- **Guardian (agent, spark backend only): a hung arm no longer lets the policy generation be acknowledged, and identical server re-pushes are suppressed while it is outstanding.** Dormant until `prefer_spark` is enabled, which no released build does. The earlier three-re-apply acknowledgment of a wedged rule (the "K waiver", PR #4529) is removed: it stopped the server's re-push, so a hung arm that later failed, threw or was not adopted left the rule unarmed under an acknowledged generation with nothing to retry it. The agent now holds the generation while a wedged arm, or a compensating teardown (#4472), is outstanding, answers identical re-pushes without a teardown, and acknowledges only when the rule is armed. When the hung call returns, the next re-push re-arms the rule through the normal path, subject to the known limits in the Guaranteed State manual. After 10 suppressed re-pushes (about 330 s at the default 30 s heartbeat) one is applied in full as a safety valve; that cadence holds while every counted failure is the held wedge, and with a healthy rule of the same mechanism type in the push the first forced re-apply makes that rule's re-arm expire behind the hung call, after which every re-push is applied in full for as long as the hang lasts. The hold is unbounded for a call that never returns, the server applies no back-off, and each re-push writes a `guaranteed_state.reconcile` audit row (now documented in the audit-log reference). The manual names what ends a hold and what does not: a new generation does not. The `yuzu.guardian_arm_failed` fleet gauge HELP text and the `metrics.md` rows change accordingly. This replaces the note in the #4472 entry that this was an open decision (#5459).
