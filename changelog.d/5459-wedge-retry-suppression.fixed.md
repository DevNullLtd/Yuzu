- **Guardian (agent, spark backend only): a hung arm no longer lets the policy generation be acknowledged, and identical server re-pushes are suppressed while it is outstanding.** Dormant until `prefer_spark` is enabled, which no released build does. The earlier three-re-apply acknowledgment of a wedged rule (the "K waiver", PR #4529) is removed: it stopped the server's re-push, so a hung arm that later failed, threw or was not adopted left the rule unarmed under an acknowledged generation with nothing to retry it. The agent now holds the generation while a wedged arm, or a compensating teardown (#4472), is outstanding, answers identical re-pushes without a teardown, and does not acknowledge while a wedge it still tracks is outstanding. When the hung call returns, the next re-push re-arms the rule through the normal path. After 10 suppressed re-pushes (about 330 s at the default 30 s heartbeat) one is applied in full as a safety valve. The hold is unbounded for a call that never returns, the server applies no back-off, and each re-push writes a `guaranteed_state.reconcile` audit row (now documented in the audit-log reference). A new generation does not end a hold; the Guaranteed State manual names what does, and its known limits, including how a healthy rule of the same mechanism type changes the valve's cadence. The `yuzu_fleet_guardian_arm_failed` fleet gauge HELP text and the `metrics.md` rows change accordingly. This replaces the note in the #4472 entry that this was an open decision (#5459).
