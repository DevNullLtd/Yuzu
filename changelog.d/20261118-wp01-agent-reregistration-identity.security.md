- **New `--agent-reregistration-proof off|audit|enforce` (`YUZU_AGENT_REREGISTRATION_PROOF`, default `audit`): by default it only AUDITS, so a certificate-less caller that knows an enrolled agent id can still re-register it and be issued a certificate until you set `enforce`.** What an operator sees: the server logs a WARNING at every boot in `audit` and `off`; `yuzu_register_reregistration_total{path,outcome,mode}` counts every decision (the authoritative count; audit rows are bounded and can be dropped under load, see the audit log reference); `agent.reregistration_unproven` (audit-mode admission) and `agent.reregistration_refused` (enforce refusal) audit rows; `ca_store` schema v6 (a partial index; its build blocks `ca_issued` writers while it runs); eight alerts (`YuzuAgentReregistrationWouldRefuse`, `...UnattestedGateway`, `...ModeMixed`, `...Refused`, `...LookupFailed`, `...AuditWriteFailed`, `YuzuAgentReenrolTokenRefusedBurst`, `YuzuAgentLeafSupersedeFailed`). The agent id is an identifier, not a secret: `Register` and the gateway-relayed `ProxyRegister` used to re-admit any already-approved id with no credential. Both paths now run one shared decision (`agent_reregistration_gate.hpp`): an id that holds a **live** (active, unexpired) leaf in `ca_issued` is re-admitted only when the caller presents that leaf (direct: the mTLS peer certificate; through the gateway: the certificate the gateway *witnessed* in the agent's TLS handshake, in the new gateway-authoritative `RegisterRequest.gateway_attested_peer_cert_pem` / `gateway_attests_peer_cert`, which the gateway overwrites unconditionally and the direct path ignores) or a fresh **single-use** enrollment token (`max_uses` 1; a multi-use fleet token is refused without being consumed). The same decision runs for an id whose enrollment row is absent or pending but which holds a live leaf. A revoked identity with no live leaf, and a live leaf beside an operator-revoked one, are refused before any token is spent; an operator-revoked leaf is irreversible for that agent id for its life (recover by enrolling under a new agent id). The refusal is a gRPC status (`UNAUTHENTICATED`, uniform message), never `accepted=false`, and happens before `register_agent`, so a refused caller cannot displace the real agent. After a token re-enrolment the agent's OLDER live leaves are revoked (reason `reenrolled`, one transaction under a per-agent advisory lock, never a newer leaf; best effort: a failure is audited as `ca.cert.supersede_failed` and alerted). Under `enforce` every leaf-holding agent that cannot show its certificate or a single-use token is refused; before setting `enforce`, set `witness_client_cert` on every gateway's agent listener, restart it, and soak in `audit` (see Upgrading). A wizard, demo, UAT or other plaintext-gateway fleet cannot satisfy `enforce`. **Residual under `enforce`:** a holder of an unspent single-use enrollment token can still re-enrol any live-leaf agent id and supersede its leaf (accepted token-custody trust, tracked as #8171); treat unspent re-enrolment tokens as secrets. **Not covered, by design:** `--no-tls`, plain-TLS, operator-CA-certificate agents and expired leaves.
