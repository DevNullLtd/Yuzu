- **MCP `execute_instruction` progress now follows the caller's `Execution:Read` scope (#7817).** A caller with a global `Execution:Execute` grant but a management-group-scoped `Execution:Read` grant no longer receives `notifications/progress` counts for its own dispatch, and the final result carries the real `status` without `agents_success` or `agents_failure`, the same projection `GET /api/v1/events` applies; poll `get_execution_status` for the counts it may see. When the `Execution:Read` scope cannot be resolved the stream uses this restricted view, and a caller with Execute but no Read writes one `auth.fleet_read_required` denial row per streamed call while the dispatch still succeeds. Callers with an unrestricted `Execution:Read` scope are unchanged. See "Behaviour change" in `docs/user-manual/upgrading.md`.
