- **`GET /api/v1/config`, `PUT /api/v1/config/{param}` and the MCP tools `get_runtime_config` and `set_runtime_config`.** The runtime-configuration API now has v1 REST and MCP twins of the legacy `GET /api/config` and `PUT /api/config/{key}`. All four share one implementation, so the per-key caller rule from the administrator-only key fix, the value checks and the audit rows (`config.update`: `denied`, or `attempted` then `success` or `failure`) are identical on every surface. The v1 routes answer in the A4 envelope. `PUT /api/v1/config/{param}` needs a fresh MFA step-up proof for an MFA-enrolled local or OIDC cookie session. An MCP-tier token can write only the five keys that are not administrator-only (`heartbeat_timeout`, `response_retention_days`, `guardian_event_retention_days`, `auto_approve_enabled`, `log_level`); the rest answer a permission error with a `denied` audit row (`dex_score_policy` answers invalid params). The v1 `GET` and `get_runtime_config` show a caller only the overrides it could write and list the rest in `withheld_keys`. The legacy routes are unchanged.
