- **Agent reconnect delays now use decorrelated jitter (#5990, HA WS-13).** After a lost connection the agent used to wait exactly 2, 4, 8 ... 256 seconds, so every agent that lost the same gateway or server came back at the same instants, wave after wave. Each retry now waits a random whole number of seconds between 1 and three times the agent's own previous wait, never more than 300 seconds, and the wait returns to the start after a successful registration. The first retry is 1 to 3 seconds, so a fleet that loses a node first returns in three one-second steps, and each later retry spreads it wider. **What changes for load:** in a long outage an agent now retries about twice as often as before (a mean wait of about 135 seconds once settled, against 256; about 28 attempts in 30 minutes, against 13), so a gateway or server that is down sees more registration attempts from each agent than it used to, in exchange for a flatter fleet and, on average, a sooner return (the slowest 1% of agents can wait longer than before, simulated at about 285 seconds against 250). The pending-approval retries use the same waits; the enrolled-but-no-certificate retries use them with each wait at least 8 seconds, so they still outlast the server's 30-second one-certificate-per-agent window. No configuration changes; a restarted agent still connects at once, and the heartbeat-driven re-registration cooldown is untouched. An agent whose operating system has no entropy source starts normally with a clock-derived seed and logs a warning. The gateway manual also records the topology requirements for agent failover (certificate names, stable addresses for quarantine, agents of 0.15.0 or later).
