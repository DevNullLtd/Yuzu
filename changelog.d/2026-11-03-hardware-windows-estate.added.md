- **The hardware plugin now reads chassis, baseboard, swap and the machine id on Windows, and fills the CPU and DIMM identity columns.** `chassis` and `baseboard` decode the SMBIOS table (chassis type, serial and asset tag; board vendor, product and serial), `swap` reads the page files (`Win32_PageFileUsage`, with the configured maximum from `Win32_PageFileSetting` as the total when there is one), and `machine_id` ships only an HMAC-SHA256 of the registry `MachineGuid` under a fixed public label, so it is stable across reinstalls but is not secret from a party that already holds the raw id. `processors` rows gain the socket designation and stepping, and `memory` rows the DIMM manufacturer, part number and serial. Each estate action reports a typed status (`ok`, `constrained`, `permission_denied` or `unavailable`, with a named reason); firmware filler such as `To Be Filled By O.E.M.` is written `-` and the section stays supported, while a table that could not be fully read is reported `constrained`. All reads work without administrator rights. Linux and macOS still answer the `<os>:planned` status row.
