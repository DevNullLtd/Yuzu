- **Agentic workers get the software lookup and the paced sync over MCP, field for field what REST returns.** `query_installed_software` now takes the lookup filters of `GET /api/v1/inventory/software` (`q`, `kind`, `ecosystem`, `source`, `match`, `status`, `version_min`, `version_max`), returns the lookup fields (`hostname`, `last_seen`, `status`, `last_confirmed_at`, `install_type`, `install_scope`, `install_location`, `instance_key`, `purl`) and a `count` and `totals` block (null with a reason when the caller's scope or filters make a fleet total misleading), and a new `query_software_components` tool is the twin of `GET /api/v1/inventory/software/components`. `get_software_sync_status` reads how a sync run is going, the twin of `GET /api/v1/hardware/sync/{execution_id}`; `sync_hardware_software` now advertises `confirm` and `last_synced_before`, returns `skipped_fresh`, `delay_max_s`, `estimated_completion_at`, `joined` and `execution_id`, and writes a whole-fleet run's audit row under `software_estate.sync.fleet_wide`, as REST does. Each tool and its route call one shared function, so they cannot drift; the MCP tools are strict where REST clamps. The sync status tool is a read: a supervised-tier token reads a run's status without an approval ticket, where the REST route refuses that token. The `purl` and `vers` filters stay REST-only.
