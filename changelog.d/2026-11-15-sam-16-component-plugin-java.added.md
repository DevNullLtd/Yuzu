- **A new `component_inventory` agent plugin lists the Java archives inside applications on Linux and macOS.** Its one action, `scan`, walks the machine-wide application roots once and reports every `.jar`, `.war` and `.ear` it finds, and every library nested one level inside one, with name, version and where the version was read from (the file name, `pom.properties` or the manifest). The walk is read-only, starts no process, follows no link and does not enter network mounts. It works to a budget of 400,000 entries and 45 seconds, checked between directories and between archives. When it could not see everything (a budget ran out, a directory could not be listed, an archive's contents could not be read) the answer is marked constrained and names its cause, so a short list is never mistaken for a complete one; on a `supported` answer, a link or network mount the scan passed over on purpose is named too, without marking it constrained. Only machine-wide locations are scanned. Run it on demand as `crossplatform.components.scan`; it can be switched off per plugin with the existing plugin kill switch. Windows, Python and Node packages, and inclusion in the daily software report, are not in this release.
