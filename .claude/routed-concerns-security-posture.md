| `local_security_policy` plugin — read-only password/lockout/audit policy posture and sudoers content (`Security` securable, `ExecuteGate::None`, no mutation, no new securable). **CATASTROPHIC-IF-VIOLATED:** no host policy is ever written — Windows is a rung-2 `secedit /export` argv leaf, never `/configure`/`/import`/`auditpol` (`argv[0]` resolved via `windows_system_directory()`, never a literal) whose output — the WHOLE `SECURITYPOLICY` area — is staged in an agent-owned, owner-only `agent.data_dir` scratch dir, removed on return, and each Windows policy dispatch with `agent.data_dir` set and the system directory resolved first sweeps orphans older than one hour (a crash with no later dispatch leaves one); measured only as LocalSystem on one standalone host. macOS is a rung-2 `pwpolicy` leaf; a plist item not in the documented shape, or carrying nothing reportable (`missing_content`), is an `unreadable` row + `pwpolicy:<defect>` token, never the clean no-policy row; the run is classified from the runner's termination reason, never its convenience flags. A failed read is never absent or empty — a file source is an `unreadable` row + token, a failed `pwpolicy` run a `status` row, a failed Windows export a `constrained` row: on Linux/macOS files `PERMISSION_DENIED` only when every read was refused and nothing was readable, else `CONSTRAINED`; on Windows `PERMISSION_DENIED` only for `secedit:access_denied` on the agent's own export file, everything else `CONSTRAINED`. `sudoers` sources are opened without following a link (`O_NOFOLLOW`), must be regular, owned by uid 0 and not group/other-writable, else an `unreadable` row with `symlink_refused`/`insecure_owner_or_mode` — never followed, never returned as content (PAM sources deliberately still follow symlinks: authselect); `sudoers` is lexed as sudo 1.9.16's `toke.l` lexes it — a `:` inside quotes, an escape, an IPv6 host or a digest never splits a clause, and a `#` comment (glued or not) never continues a line — checked differentially against `sudo -ll`; a NOPASSWD:/PASSWD: tag still undecoded makes the line `unmodelled` plus `<file>:undecoded_passwd_tag` (CONSTRAINED). Limits: `nopasswd` is the tag only (`Defaults !authenticate` is separate); aliases and includes are not resolved; another sudo version's lexing, or a line sudo rejects, is best-effort; a secedit export not ending in the signed `[Version]` section is `secedit:export_incomplete`, never rows. In a container (`Dockerfile.agent`) the Linux leg reads the IMAGE's `/etc`, not the host's.
