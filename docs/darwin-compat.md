# Darwin (macOS) Compatibility Guide

This Claude instance is the designated **macOS/Darwin compatibility guardian** for Yuzu. The `cross-platform` agent loads this document on any change that may affect macOS builds, tests, or runtime behavior.

CLAUDE.md keeps a one-line pointer; this document holds the workflow and the standing pitfalls table.

## Standing workflow

When Windows-originated changes land on `origin/dev`, the standing reconciliation workflow is:

1. `git fetch origin && git status` — confirm branch state.
2. `git pull` — fast-forward to latest dev.
3. `git diff HEAD~N..HEAD --stat` — review what changed.
4. Identify which previous Darwin fixes are still present in the new tree.
5. `meson setup build-macos --reconfigure ...` if `meson.build` changed.
6. `meson compile -C build-macos` — fix any new compile errors.
7. `bash scripts/run-tests.sh all` — fix any new test failures.
8. Commit clean with a Darwin-fix commit message.

After **any** cross-platform change, always run `bash scripts/run-tests.sh all` on Darwin before committing.

## Standing Darwin pitfalls

| Area | Issue |
|---|---|
| SparkEngine (ADR-0021) | **SparkEngine starts with ZERO mechanisms on macOS: this is expected, not a fault.** All three factories (`make_{file,registry,service}_mechanism()`) return `nullptr` on Darwin: File/Registry are Windows-only, Service is Windows-SCM + Linux-sd-bus. `start()` with an empty mechanism map succeeds (the wheel thread runs, nothing is armed). The agent correctly reports `spark_running=1` with an **empty** `spark_mechs` CSV, and the server emits **no** `yuzu_fleet_spark_mechanisms{os=darwin,...}` series at all. **The absence of those series IS the correct signal, do not "fix" it by registering a stub mechanism**, and do not read the absence as breakage. (A Linux build without libsystemd, e.g. musl/Alpine, takes the identical path.) **Async-logging note (#4666 PR-2):** since macOS has zero Spark mechanisms today, regardless of what the multi-image registry measurement below found, the async log hand-off's non-blocking guarantee has nothing Spark-side to matter for here (there is no Spark-runtime log call on this platform to be blocking or non-blocking in the first place). Ordinary agent-core logging (Guardian, the trigger engine, etc.) is a separate question the same measurement — now DONE, see the row below — covers, and PLUGIN logging is a third, distinct question again. |
| spdlog registry identity across images (#4666 PR-2) | **Measured, on real hardware, 2026-09-25** (`tests/unit/test_log_handoff_multi_image.cpp`'s MI-1/MI-1b/MI-3, `tests/shell/test_spdlog_registry_identity.sh`'s MI-2 — both run on Linux and on an Apple Silicon macOS box). **Linux: ONE shared registry** across the exe, `libyuzu_agent_core.so`, and `agent_actions.so` — `main.cpp`'s exe-image swap in `LogHandoffEpilogue` is a harmless no-op there. **macOS: TWO SEPARATE spdlog registry singletons** (spdlog is statically linked per `arm64-osx`, so each image gets its own copy of the registry's static state) — confirmed both by `nm -m` symbol-table evidence (each of the exe and `libyuzu_agent_core.dylib` defines its own local `registry::instance()`, not an imported one) and by a direct runtime discriminator (MI-1b: tearing down the logger via the LIBRARY-image path alone, skipping the exe-image swap, did NOT destroy the sink — the exe's own registry still held a live reference; only `release_log_handoff_from_this_image()`'s own same-image swap finished the job). **Despite two registries, this is NOT the gap the row above worried about before this measurement existed**: `LogHandoff::install()` itself is compiled into `libyuzu_agent_core.dylib`, so its own internal `spdlog::set_default_logger()` call already sets the CORE LIBRARY's own registry correctly as a side effect of being called at all — independent of which image's code calls `install()` — so Guardian/TriggerEngine/SparkEngine logging (compiled into the core library) DOES reach the async hand-off logger, and does NOT fall through to spdlog's own unconfigured default. The exe-image half's job is narrower and load-bearing on the TEARDOWN side only: without it, the exe's own registry keeps the sink alive past `teardown()`'s bounded grace. **Plugin logging (measured for `agent_actions` only, via MI-3):** its `spdlog::set_level()` call also lands on the CORE LIBRARY's registry, mutating the SAME shared logger object both registries point at — so this plugin's logging is correctly covered too, on both platforms. **Still open, not yet measured for any plugin other than `agent_actions`:** a plugin that calls `spdlog::set_default_logger()` DIRECTLY (rather than a level-only mutation of an already-shared object) would only ever reach whichever registry its own compiled code binds to — likely the core library's, by the same static-linkage mechanism, but unverified for any specific plugin. No plugin does this today: `agent_logging`, the name that might suggest otherwise, has zero spdlog calls of any kind (verified by direct code read); it is a plugin about **collecting** log data, not one that touches the spdlog registry. Re-check this note if a future plugin ever does call `set_default_logger()` directly — don't assume it behaves like `agent_actions`'s level-only mutation. Separately, unrelated to the registry question: since macOS has zero Spark mechanisms today (row above), there is no Spark-runtime log call on this platform for the async guarantee to matter for regardless of the answer here. |
| Path comparisons | macOS `/var` → `/private/var` symlink: always call `fs::canonical()` on both sides before comparing paths in tests. |
| `installed_apps` macOS scan memoization | `get_inventory_macos()` memoizes its `system_profiler` scan for 10 minutes (`ProfilerCache`/`kProfilerCacheTtl`), keyed on an `lstat`-based signature covering both the Applications-type directories AND the two `pkgutil`-receipt directories (`installed_apps_macos_receipts.hpp`'s `kReceiptDirs`) — a receipts-only package install/removal (no app bundle: an Xcode CLT update, most vendor `.pkg` installers) must invalidate the signature exactly like an app-bundle change, or the cache silently serves stale data for the rest of the TTL window (governance Gate 3, HIGH: this was missing on first landing — the signature only covered the Applications trees). A degraded/empty scan is never memoized. `__sync__.now`'s server-side freshness poll only tracks `last_seen` (ADR-0016 server-receipt time), which advances on every sync regardless of whether the underlying scan was a cache hit — so a forced sync within the TTL window genuinely returns fresh receipt data (now that the signature covers receipts too) but does NOT force a fresh `system_profiler` re-scan of the Applications trees; that distinction only matters for an app-bundle-only change inside the same 10-minute window. |
| `getifaddrs` netmask `sa_len` | **An `AF_INET` netmask sockaddr from `getifaddrs` is routinely SHORTER than `sizeof(sockaddr_in)`** — measured 5 bytes on `lo0`, 7 on `en0`/`en1`, 8 on `utun4`. The kernel elides the trailing all-zero bytes and declares the real length in `sa_len`. Copying a full `sizeof(sockaddr_in)` out of it reads past the object; `getifaddrs` packs every sockaddr into one allocation so it usually goes unnoticed, but for the last sockaddr in that block it runs off the end. `memcpy` into a **zero-initialised** local clamped to `std::min(sizeof(dest), sa_len)` — the zero-init supplies exactly the elided bytes, so the value is correct as well as in-bounds. Same rule for `ifa_addr`. |
| `sockaddr_dl` MAC extraction | **The hardware address does NOT live at a fixed offset.** `sdl_data` is a 12-byte placeholder holding the interface NAME followed by the address, so the MAC starts at `offsetof(sockaddr_dl, sdl_data) + sdl_nlen` and for a long interface name it lies PAST the declared placeholder. Read it from the original bounds-checked buffer, never from a `sizeof(sockaddr_dl)`-capped local copy, and bounds-check `offsetof + sdl_nlen + sdl_alen` against `sa_len` first (a record too short yields `sdl_alen == 0` and is skipped). `route_sysctl_arp.hpp` documents the same discipline for its own `RTAX_GATEWAY` handling. |
| `SCDynamicStoreCopyProxies` scoping | **The returned dictionary is the CURRENT/PRIMARY service's proxy settings, not the host's.** Every other configured service sits under an undocumented `__SCOPED__` sub-dictionary keyed by interface (`en0`, `en1`, `utun4`…), and keys such as `HTTPEnable` appear ONLY inside those sub-dictionaries. Reading the top level alone reports "no proxy" on, for example, an Ethernet-primary Mac whose proxy is configured on Wi-Fi — a silent wrong answer on a compliance-relevant surface. `__SCOPED__` carries no `kSCPropNetProxies*` constant on the current SDK, so treat it as best-effort enrichment: type-check it, and degrade to top-level-only rather than failing. Distinct from `SCDynamicStoreCopyKeyList`, whose `pattern` argument IS documented as a `regex(3)` pattern (unlike `SCDynamicStoreCopyValue`'s exact-match key). |
| `ping -W` units trap | **`ping -W` means different units on Linux vs BSD/macOS.** On Linux (iputils) `-W <sec>` is the per-reply timeout in **seconds**; on macOS/BSD `-W <ms>` is in **milliseconds** and the whole-run deadline is `-t <sec>`. A POSIX `#else` branch that shells `ping ... -W 2 ...` therefore means "2 s" on Linux but "2 ms" on macOS — an instant timeout that reports a live host as **unreachable** (a silent false negative, since reachability plugins scrape ping stdout rather than trust the exit code). Any macOS ping shell-out must use `-t <sec>` via an explicit `#elif defined(__APPLE__)` arm. **Neither surviving in-tree consumer has this shell-out any more.** `discovery` (Wave-2 PR2.1c) and `wol` (Wave-2 PR2.2a) both replaced their `ping`/`system("ping ...")` mechanism with the native `yuzu::shared::IcmpSession` (`agents/shared/icmp_probe.hpp`), whose per-host budget is an explicit `int timeout_ms` on both the POSIX `poll()` and the Windows `IcmpSendEcho` path, so the units trap cannot arise there at all. This row is kept as a standing pitfall for any FUTURE ping shell-out, not as a pointer to a live site. |
| macOS ARP table via the routing socket | **`arp -a` is a text view over `sysctl({CTL_NET, PF_ROUTE, 0, AF_INET, NET_RT_FLAGS, RTF_LLINFO})` — read the sysctl, never the command.** `agents/shared/route_sysctl_arp.hpp` is the shared reader: `fetch_rt_flags_llinfo()` does the size-then-fill call, `parse_rt_flags_llinfo()` is a pure `rt_msghdr`-chain walk. The blob is an untrusted-shaped kernel buffer and the walk carries the same discipline as the `NET_RT_IFLIST2` row above: never dereference a typed struct through an unaligned pointer into the buffer (`memcpy` into an aligned local first — `sockaddr_inarp` for `RTA_DST`, `sockaddr_dl` for `RTA_GATEWAY`); reject `rtm_msglen` of zero (it would spin forever advancing by 0), shorter than `sizeof(rt_msghdr)`, or extending past the buffer; bounds-check every `sa_len` against the record before reading, **including the word-rounded (BSD `ROUNDUP`) advance** — a sockaddr whose unrounded length fits but whose rounded length does not must not push the cursor past the record; and stop the walk rather than reading out of bounds; and **reject an `rtm_version` that is not `RTM_VERSION`** — the same guard, for the same reason, as the `NET_RT_IFLIST2` row above. **Malformation must never be reported as a smaller table.** What the two walks DO about malformation differs deliberately: `NET_RT_IFLIST2` produces an *aggregate* (summed counters), where a partial sum is a wrong number, so it invalidates the whole sample; this produces a *set* of independently-valid neighbours, so it keeps what it decoded and **reports the shortfall** via `ArpParse::truncated` (set by any early stop of the outer record walk, including trailing bytes too short to form another header — but NOT by a single record's address chain ending naturally, which is the normal shape of a routing message and flagged every healthy capture when tried). Discovery maps that to `CONSTRAINED/PARTIAL` with reason `arp:table_truncated`, so an incomplete table can never present as a complete small one — the honesty requirement is met by reporting, not by discarding. Likewise `fetch_rt_flags_llinfo` returns `ArpFetch{blob, ok}`: a failed sysctl is `ok=false` (discovery: `UNAVAILABLE/PARTIAL`, `arp:read_failed`), never an empty buffer that reads as an empty neighbour table. A record with `sdl_alen != 6` is an unresolved in-flight probe and is skipped, matching `arp -a` dropping `(incomplete)` rows. The reader deliberately carries **no logging dependency** (`agents/shared` is a zero-dependency leaf per `docs/cpp-conventions.md`) — it returns the facts, the caller owns the reporting. Fixture-tested against a real 2296-byte capture in `tests/unit/test_route_sysctl_arp.cpp`, including malformed, truncated and bad-version cases. |
| Shutdown self-pipe (`pipe2`) | **macOS has no `pipe2`.** `common/include/yuzu/shutdown_watcher.hpp` (moved from `agents/core/src/` and shared with the server binary as of #3007) uses `pipe2(fds, O_CLOEXEC)` under `#ifdef __linux__` and falls back to `pipe()` + two `fcntl(F_SETFD, FD_CLOEXEC)` calls elsewhere — which leaves a window where a concurrent `fork`/`exec` inherits the fds, the exact race `pipe2` exists to close. The `fcntl` results are therefore checked and the watcher **fails closed** (degrades to the hard-exit handler — killable everywhere incl. pid 1) rather than shipping a pipe whose fds leak into every subprocess. **The window is currently unreachable, but for a reason the code does not state and you must not break:** the watcher is constructed in `main()` BEFORE `agent->run()`, and every fork/exec source (the trigger engine, plus the `ioc` / `firewall` / `services` / `software_actions` / `wol` / `license_scan` plugins) is only started INSIDE `run()`. Move the watcher's construction later and the race becomes real. **This precondition is agent-specific and does not apply to the server**: the server binary has zero fork/exec call sites anywhere (verified #3007), so the race this precondition guards against is structurally unreachable there regardless of construction order — not merely reordered to be safer, genuinely inapplicable. Two further Darwin traps in the same file: `O_NONBLOCK` goes on the **write end only** (a non-blocking read end makes the watcher exit instantly and SIGTERM silently stops being graceful while the process still dies via the default disposition — so nothing *looks* broken), and a bare `mktemp -d` is a usage error on BSD, which is why `scripts/test/agent-shutdown-smoke.sh` always passes a template. **What IS verified on macOS:** the fallback compiles on every PR (`meson compile -C build-macos`) and `tests/unit/test_shutdown_pipe.cpp` (guarded only by `#ifndef _WIN32`) RUNS on the macOS CI leg. **What is NOT:** the end-to-end smoke script — it is portable (it probes with `ss`/`lsof`/`netstat` and strips BSD's full-path `ps -o comm=`), but it is only wired into the **Linux** CI leg, so it has never actually run on Darwin; and no shutdown timing has ever been measured on real macOS hardware. `scripts/run-tests.sh` now SKIPS it on Darwin explicitly, because it has never been validated there — running an unvalidated script under a doc that mandates running it was the worst of the available options. Wiring it into the macOS CI leg is tracked in the governance follow-ups ledger (.spark-issues/governance-followups.md item 20) pending an issue number. |
| `default_cert_dir()`/`default_config_path()` euid gating | **A native (non-packaged) macOS server run as non-root previously hit silent EACCES against root-owned `/etc/yuzu/certs`.** macOS has no packaged server installer (ADR-0035 — server is Linux-only in production; macOS is agent-only), so `scripts/start-UAT.sh`'s dev/UAT rig always ran as the invoking user, and `server/core/src/auth.cpp`'s `default_cert_dir()`/`default_config_path()` used to return the same `/etc/yuzu/certs`/`/etc/yuzu/yuzu-server.cfg` on macOS as on Linux with no non-root fallback — `ensure_default_certs()`/the secrets-KEK bootstrap failed closed with `provider_failure`/`kek_unresolvable` and the server refused to boot. Fixed in 977b24ed8: both functions now gate on `geteuid() == 0` — root keeps `/etc/yuzu/{certs,yuzu-server.cfg}` (matches Linux and the packaged-install convention), non-root falls back to `~/Library/Application Support/Yuzu/...`. Mirrored agent-side in `discover_install_ca_path()` (`agents/core/src/cert_discovery.cpp`) so a non-root agent can find a CA a non-root server wrote. **Do not add an unqualified `$HOME` fallback to either function without the euid gate** — macOS `sudo` preserves `$HOME` by default (no `-H`), so `sudo yuzu-server` would silently redirect CA/KEK/config into the invoking user's home instead of the shared system location. |
| SQLite concurrency | All stores must open with `sqlite3_open_v2()` using `SQLITE_OPEN_READWRITE \| SQLITE_OPEN_CREATE \| SQLITE_OPEN_FULLMUTEX` flags — never plain `sqlite3_open()`. Application-level mutexes (`shared_mutex`) are retained as defense-in-depth and are **required** (not optional) for stores with cached prepared statements, because FULLMUTEX does not make bind-step-reset sequences atomic. |
| Antivirus posture (XProtect + EDR) | **Never assert XProtect is "active" — probe it.** The definition bundle at `/Library/Apple/System/Library/CoreServices/XProtect.bundle` is the checkable surface (`CFBundleShortVersionString` = definition version, unprivileged via `PlistBuddy`; bundle mtime = freshness); unreadable → report `unknown`. Third-party EDR/AV on modern macOS must register **endpoint-security system extensions** — enumerate `systemextensionsctl list` (unprivileged, tab-separated, parser in `agents/plugins/antivirus/src/antivirus_parsers.hpp`) instead of pgrep'ing process names; if a process fallback is kept, note the daemon names differ from Linux (CrowdStrike is `falcond` on macOS, `falcon-sensor` on Linux). The Remediator (`XProtect.app`) and MRT engine version reads assume macOS Ventura (13)+ — already covered by the project's `-mmacosx-version-min=13.3` floor; on any host missing those bundles `PlistBuddy` degrades to error prose, which the parser correctly discards as `unknown` rather than a crash. |
| Firewall state (pf ≠ Application Firewall) | **pf is NOT the macOS firewall.** `pfctl -s info` reports the BSD packet filter — off by default and unrelated to the Application Firewall that System Settings toggles; reading `/dev/pf` also needs root. The user-meaningful signal is `/usr/libexec/ApplicationFirewall/socketfilterfw --getglobalstate` (unprivileged; `(State = N)`: 0 disabled, 1 enabled, 2 enabled + block-all — parse the number, not the prose). The `firewall` plugin reports the Application Firewall as primary (`backend\|appfirewall`) with pf demoted to a secondary `pf\|<state>` row (parsers: `agents/plugins/firewall/src/firewall_parsers.hpp`); unreadable checks report `unknown`, never a false-safe value. |
| Erlang rebar3 ct | Always pass `--dir apps/yuzu_gw/test` together with `--suite` flags. |
| `curl -f` in tests | Do **not** use `-f` where 4xx is an acceptable response — it causes `|| echo "000"` fallbacks to contaminate the status code variable. |
| `prometheus_httpd` | Use `start/0` with `application:set_env(prometheus, prometheus_http, [{port, P}, {path, "/metrics"}])` — `start/1` does not exist. Call `application:ensure_all_started(prometheus_httpd)` first so `prometheus_http_impl:setup/0` runs before the first scrape. |
| nstat kernel control (TAR netqual + tcp lifecycle) | macOS netqual and tcp-lifecycle capture share one `NstatClient` (`agents/plugins/tar/src/tar_netqual_nstat.cpp`) that opens the private `com.apple.network.statistics` **kernel control** — a `PF_SYSTEM`/`SYSPROTO_CONTROL` socket (`<sys/kern_control.h>`), **not a framework** — so unlike Endpoint Security it needs **no Apple entitlement**. The trade-off: it is a **private, undocumented, layout-UNSTABLE wire protocol**. `nstat_msg_hdr`/`nstat_tcp_descriptor`/`nstat_counts` are transcribed from XNU's open-source `bsd/net/ntstat.h` at the minimum-target release (macOS 13.3, `__NSTAT_REVISION__` 9 / tag `xnu-8792.41.9`); Apple has changed field order and struct size across releases with no ABI promise. **Two guards, in layers:** (1) every transcribed struct pins its `sizeof` AND the `offsetof` of each field the decoder reads with a compile-time `static_assert` set to the literal XNU offset — because the header is XNU-private and cannot be `#include`d, this is the closest feasible cross-check and it catches any future reorder/width/padding drift at build time (a hand-transcription slip is exactly how the first cut shipped wrong constants and layouts); (2) a runtime length self-check validates each decoded message's declared length against `sizeof` and **falls back to `capture_method=none` on mismatch rather than emit plausible-but-wrong rtt/loss numbers** — a failed check must never be treated as a decode. The SRC_DESC check is a `>=` FLOOR (not exact) so a larger later-OS descriptor still decodes: every field we read lives in the stable 13.3 prefix, ahead of the fields Apple appended (persona_id/uid). Separately, **root is required for system-wide flow visibility**: opening the kctl socket needs no privilege, but an unprivileged process reliably sees only its own process's flows, so a non-root agent reports the honest `none` rather than a silently partial capture (mirrors the Windows ESTATS admin-only posture). The `proc_pidfdinfo` poll is retained as the tcp-lifecycle fallback/seed, not replaced. |
| CoreWLAN + Objective-C++ (`wifi` plugin `connected`) | `airport -I` (the private Apple80211 helper) was **removed in macOS 14 (Sonoma)**, so the old shell-out returned nothing and `wifi connected` always reported "Not connected" even while associated. `connected` now reads the live association via **CoreWLAN** in `agents/plugins/wifi/src/wifi_corewlan.mm` — the **first Objective-C++ (`.mm`) TU in the tree**. Meson wiring (`agents/plugins/wifi/meson.build`): `add_languages('objcpp', native: false)` (top-level `project()` is C++-only) + `dependency('appleframeworks', modules: ['CoreWLAN', 'Foundation'])`. Unlike EndpointSecurity, **CoreWLAN is a public framework in the base SDK — present with the Command Line Tools SDK**, so it is `required: true` (no no-op fallback). objcpp is a separate meson language from cpp, so the project's `-std=c++23`/`-fvisibility=hidden` are re-passed via target `objcpp_args`, plus `-fobjc-arc` (the `.mm` only reads autoreleased CoreWLAN objects). **Location Services caveat (macOS 14+):** `CWInterface.ssid`/`.bssid` are gated behind Location Services authorisation, which a background LaunchDaemon has no practical way to obtain — so both are typically withheld (returned nil) even for a live association. The authorisation-free signals (`powerOn`, a non-nil `wlanChannel` ⇒ associated, `rssiValue`, `security`) are still read, so an associated-but-SSID-withheld link reports `connected\|<ssid-withheld>\|<rssi>\|<security>\|-\|<channel>` — an honest connection, never a false "Not connected". `list_networks` is untouched (still legacy `airport -s`/`system_profiler`; a CoreWLAN scan needs the same authorisation and is out of scope here). |
| DNS resolver cache (network_config/dns_cache + network_actions/flush_dns) | Two related macOS DNS traps. **(1) Reading the cache is impossible.** macOS does not expose resolver-cache *contents* to userspace — `dscacheutil -cachedump` was gutted years ago and on macOS 26 prints `Unable to get details from the cache node` **to stderr and exits 0** (verified on 26.5.2). So `network_config/dns_cache` does **not** shell out on Darwin; it returns a single `dns_cache|unsupported|...` sentinel — a permanent capability gap, not a transient failure (never emit the ambiguous `not_available`, which invites a pointless retry). **(2) Flushing needs two steps, not one.** `dscacheutil -flushcache` alone does not reset the resolver on modern macOS — the load-bearing step is the SIGHUP `killall -HUP mDNSResponder`. `network_actions/flush_dns` runs **both** (absolute paths, PATH-injection discipline) and reports `status` from the **real exit codes** (`ok` only if both succeed), never a blind `status\|ok`. Both commands need **root** (the agent runs as root on macOS; the sudoers design in `agent-privilege-model.md` already lists both). |
| Network quality sampler — macOS throughput (`net_quality_sampler.cpp`) | `read_net_counters()` gets device throughput via `NET_RT_IFLIST2`: `sysctl({CTL_NET, AF_ROUTE, 0, 0, NET_RT_IFLIST2, 0})` (family 0 = all), size-then-fill into a `std::vector<char>`, then a bounds-checked walk driven by the common four-byte `(msglen, version, type)` prefix every routing-socket message shares, `memcpy`-ed into a local (never a typed cast into the kernel buffer). Require that prefix before every read; reject a zero or oversized `msglen`; require `sizeof(if_msghdr2)` **only** for `RTM_IFINFO2` records — the interface list interleaves `RTM_NEWADDR` address records routinely SHORTER than `sizeof(if_msghdr)` (which embeds a full `if_data`), so a full-`if_msghdr` precondition misreads a legitimate short trailing record as truncation and invalidates the whole sample (that was a real bug, caught by the live-host smoke test — do not restore it); a matching `RTM_IFINFO2` shorter than `sizeof(if_msghdr2)` invalidates the whole sample rather than being skipped (a short `RTM_IFINFO2` is a malformation the fail-whole-sample contract covers, unlike a legitimately-short `RTM_NEWADDR`); reject any `RTM_IFINFO2` whose `version` doesn't match `RTM_VERSION` (prospective guard against a future routing-ABI layout change). Matching `RTM_IFINFO2` records are `memcpy`-ed as `if_msghdr2`, summing non-loopback (`IFF_LOOPBACK` skipped) `if_data64.ifi_ibytes`/`ifi_obytes` (64-bit — no wrap concern); any malformation invalidates the whole sample rather than publishing a partial aggregate. Same coarse device-aggregate caveat as the Linux `/proc/net/dev` and Windows `GetIfTable2` paths. **RUNTIME PITFALL:** the global `net.inet.tcp.stats` OID reads back **ALL-ZERO** on current macOS (verified 26.5.2 / build 25F84, reproduced UNSANDBOXED — every one of its 228 `u32` counters is 0, and Apple's own `netstat -s -p tcp` agrees: 0 packets sent/received; meanwhile `net.inet.udp.stats` IS populated and `net.inet.tcp.pcbcount` shows live TCP PCBs, so this is not a permission/ABI-size/sandbox artifact — the global TCP counters are simply unmaintained on modern macOS). **Do not read this OID as a retransmit source** — `tcps_sndrexmitpack`/`tcps_sndpack` would always read 0, making a 'retransmit' claim false. Retransmit is therefore deferred on macOS to a per-flow source (a planned NetworkStatistics/`nstat` client); `retrans_valid`/`rtt_valid` stay `false` (absent, never 0) on macOS in v1. |
| EndpointSecurity framework (TAR process stream) | `EndpointSecurity` ships as `usr/lib/libEndpointSecurity.tbd` + `usr/include/EndpointSecurity/EndpointSecurity.h` in **both** the Command Line Tools SDK and the full Xcode SDK — it is **not** an `.framework` bundle, so **"needs full Xcode" is a myth**: what actually gates it is whether the SDK ships the ES lib+header pair at all (both shipping SDKs do) and, separately, the runtime entitlement below. **Known defect (governance-flagged, A0 fix round):** the top-level `meson.build` probe currently reads `dependency('appleframeworks', modules: ['EndpointSecurity'], required: false)`, which NEVER succeeds on any SDK (there is no such framework bundle to find) — the real ES client has never compiled via this probe. The correct probe is `cxx.find_library('EndpointSecurity') + cxx.has_header('EndpointSecurity/EndpointSecurity.h')`; tracked as a separate, isolated behaviour-change slice (`feat/macos-spark-a0.5-es-probe`) rather than folded into the A0 text-only fix. Once corrected: found → compile the real ES client (`-DYUZU_HAVE_ENDPOINT_SECURITY`, link `bsm` for `audit_token_to_pid`); ES SDK absent → `tar_proc_es.cpp` compiles its no-op path and the agent falls back to the `KERN_PROC_ALL` sysctl process poll. At **runtime** `es_new_client` additionally requires the `com.apple.developer.endpoint-security.client` entitlement (Apple-restricted, manual grant) + a signed/notarized binary + **root** (the LaunchDaemon already runs as root); without these `start()` returns false and the agent polls. **Status keys:** `process_stream_dropped` counts **userspace ring overflow** (the drain tick fell behind — not kernel-side ES drops), while `process_stream_kernel_dropped` counts **kernel-side** Endpoint Security drops detected as `seq_num` gaps; `process_capture_method` reports the live path. **Self-heal:** a NOTIFY-only ES client has no liveness API, so if it goes silent (no exec/exit) for longer than the idle threshold (~1h) the agent presumes it dead and re-arms the poll — deliberately long, because a quiet host is indistinguishable from a dead stream and a false trip drops a healthy stream to the inferior poll. **Parity gap:** the stream subscribes `NOTIFY_EXEC`/`NOTIFY_EXIT` only — a fork-without-exec child is invisible until it exits (Windows ETW fires on every create); `NOTIFY_FORK` capture is deferred (#1455). **NOTIFY-only is a hard rule — never subscribe AUTH events:** an AUTH subscription makes every exec on the host block on the agent's verdict (gates exec system-wide); a slow or wedged agent would stall the machine. macOS process rows are **names-only on both the ES and poll paths** (the poll blanks the `proc_pidpath` image it would otherwise store in `cmdline`). **Build (A0, macOS Spark/Reflex/DEX programme, 2026-09):** the ES probe and its `-DYUZU_HAVE_ENDPOINT_SECURITY -fblocks` args are defined ONCE in the top-level `meson.build`'s darwin block (`endpoint_security_dep`/`endpoint_security_deps`/`endpoint_security_args`) instead of TAR probing independently — TAR and `agents/core` (`es_client.hpp`'s pure `es_seq_gap`/`es_stream_is_stalled` today; a full shared ES client lands in a later slice) both consume the same probe result, and `tests/meson.build`'s darwin test-native block threads the same args through so a darwin test TU compiles consistently. |
| Unified log access (`log show`, `event_logs` plugin) | **`log show` can only open the local unified-log data store as root or within a real login session — not as a non-root headless process, even with Full Disk Access granted.** Proven by a differential probe (darwin-guardian investigation, PR #3578): the identical `log show --predicate ... --last ...` invocation succeeds (real rows, exit 0) as a root headless daemon AND under a developer's own interactive login session, but fails with `EX_NOPERM`/exit **77** ("Operation not permitted") as a non-root headless service account regardless of every Full-Disk-Access grant tried — FDA is a red herring for this specific failure mode; the axis is privilege tier (root, or a login session), not the FDA database. `event_logs_macos.hpp`'s `classify_log_show_result` distinguishes this exit code as `LogShowOutcome::store_permission_denied` (tag `permission_denied` in the plugin's honest-degrade sentinel row) so callers — the plugin's own action-dispatch test in particular — can tell "this environment structurally cannot open the store" apart from a genuine acquisition regression. **Production is unaffected**: the macOS agent runs as a root LaunchDaemon (`docs/agent-privilege-model.md`), which can always open the store. **CI is structurally affected**: every self-hosted macOS CI runner is a non-root headless service account by deliberate design (`deploy/macos/README.md`), so `tests/unit/test_event_logs_posix_actions.cpp`'s real-acquisition tests `SKIP` (not fail) when this specific tag is observed — a genuine regression on a host that CAN open the store (root, or an interactive dev Mac) still fails normally. Do not "fix" this by chasing FDA grants again; do not run the CI runner as root or as a persistent auto-login GUI session to make the test execute for real — both have real downsides and are a separate, deliberate decision if ever revisited. |
| Interaction dialogs (`message_box`) | **A GUI-less root LaunchDaemon cannot display a dialog — report `status\|not_reachable`, never a false button.** The macOS agent runs as a root LaunchDaemon with no Aqua/WindowServer session (see `docs/agent-privilege-model.md` → "GUI session access"), so `osascript 'display dialog'` fails. The `interaction` plugin's macOS `message_box` leg wraps the dialog in `try/on error number errNum` and decodes the sentinel via the pure `agents/plugins/interaction/src/interaction_parsers.hpp` (`parse_dialog_result`, unit-tested every host): a real button → `response\|<ok\|cancel\|yes\|no>` (return 0); AppleScript error **-128** → `response\|cancel` (user cancel, return 0); **any other error or unrecognised output** → `status\|not_reachable` **and terminal FAILURE (return 1)**, so a generic success/failure consumer never reads an undelivered dialog as SUCCESS. This is the honest-status invariant — the pre-fix code fell through to `response\|ok` for any unmatched osascript output, claiming a click on a dialog that was never shown. `input` and `survey` follow the same discipline: they split a genuine −128 user-cancel (`cancelled\|true`, return 0) from an undeliverable session (`status\|unavailable\|…`, return 1) via `run_command_capture`. Actually *delivering* a dialog to the logged-in user (a per-session helper) is the remaining deferred piece. |
| `Security/cssmapple.h` macro collisions | **Apple's SDK headers `#define` plain-looking identifiers as macros** — `kSystemKeychainPath` is one (`Security/cssmapple.h:1203`, expands to `kSystemKeychainDir kSystemKeychainName`), discovered when the `certificates` plugin's own constant of that name silently mangled at the `#include` site rather than failing to compile with a clear error. Any new identifier that reads like an obvious, generic name (`kSystemKeychainPath`, `kDefaultPath`, etc.) is a candidate — grep the relevant Apple framework header before naming a new constant if the name feels like it could already exist as SDK furniture, or rename it defensively (as `certificates` did, to `kDefaultSystemKeychainPath`) the moment a collision is suspected. |
| Security.framework per-process keychain-object caching | **A `chmod`/permission change on a keychain file this process has already opened (via `SecKeychainCreate`/`SecItemAdd`/etc.) is NOT observed on a later read — Security.framework serves its cached object, keyed by path, instead of re-checking the filesystem.** A test that wants to deny access must probe a path this process has never previously opened, not the original fixture path after changing its mode — denying the original produces a false negative (the read still appears to succeed) that has nothing to do with whether the permission logic under test actually works. The `certificates` plugin's `DeniedCopy` test fixture (`tests/unit/test_certificates_macos_actions.cpp`) works around this by chmod-000'ing a fresh COPY of the keychain file rather than the original `TestKeychain` path. |

## Per-OS build directory

The Yuzu source tree is built from multiple hosts (WSL2 Linux + native Windows on the same physical machine, plus this macOS dev box). `scripts/setup.sh` selects the canonical `build-macos` directory automatically and refuses to reconfigure a directory whose recorded source path looks like a different host's. See `docs/build-guide.md` → `### Per-OS build directory convention` for the full rule.

## macOS `/test` prerequisites

Before invoking `/test` (the pre-commit/pre-push gate skill) on a fresh macOS dev box, install:

| Tool | Install | Why |
|---|---|---|
| autoconf/automake/libtool | `brew install autoconf automake libtool` | vcpkg's libpq port (Postgres substrate, ADR-0006) runs autoreconf during `vcpkg install`; a fresh mac fails the configure phase without them |
| GNU bash 5+ | `brew install bash` | `mapfile` and `declare -A` are bash-4-only; stock `/bin/bash` 3.2 trips the version guards in `preflight.sh`, `perf-gate.sh`, `teardown.sh`, `test-fixtures-verify.sh` |
| Erlang/OTP 28 | via kerl (see `scripts/ensure-erlang.sh` or `scripts/darwin-activate-erlang.sh` if you've created a local shim) | Gateway build + EUnit + dialyzer |
| OrbStack or Docker Desktop | GUI / `brew install --cask orbstack` | Phase 1 image build + Phase 2 upgrade-test. Without a running Docker daemon both phases SKIP gracefully (the rest of `/test` continues), but you cannot exercise the upgrade-test surface |

UAT bring-up is `bash scripts/start-UAT.sh` (cross-platform; `linux-start-UAT.sh` is a back-compat shim). The `_portable.sh` helper auto-discovers OrbStack at `/Applications/OrbStack.app/Contents/MacOS/xbin/docker` and Docker Desktop at `/Applications/Docker.app/Contents/Resources/bin/docker` — you do not need either on PATH globally.
