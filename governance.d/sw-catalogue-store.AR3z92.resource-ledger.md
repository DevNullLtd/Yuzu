## Resource Ledger (C++)
- `pg::PgResult` values (every statement result in refresh, reads, `bounded_query`, the isolation `PQexec`): owner = the `PgResult` RAII wrapper (non-copyable); acquired by `exec_params`/`PQexec`; released in its destructor at scope exit; never transferred (parse lambdas take `const PgResult&`); no manual `PQclear` in the diff; early returns release by destructor.
- Pooled connection lease / transaction (`pool_.with_txn_for(timeout, lambda)` in refresh and `bounded_query`; `try_acquire_for` leases in the plain read paths): owner = `PgPool`'s lease/txn RAII; acquisition = pool checkout with a bounded wait (`kQueryAcquireTimeout`); release = the pool on lambda return; lambda `false` or any exception → ROLLBACK then release (keep-last-good); `PQexec(c, "SET TRANSACTION ISOLATION LEVEL REPEATABLE READ")` is the FIRST statement after the pool's BEGIN.
- Server-side cursor `newest_cur` (`DECLARE … NO SCROLL CURSOR`, `FETCH FORWARD kNewestFetchRows`): owner = the refresh transaction (cursors are transaction-scoped); closed by `CLOSE newest_cur` on the success path and implicitly by COMMIT/ROLLBACK on every other exit; no client-side handle outlives the lambda.
- TEMP table `newest_tmp` (`CREATE TEMP TABLE … ON COMMIT DROP`): owner = the refresh transaction/session; dropped at COMMIT or discarded on ROLLBACK; `ANALYZE newest_tmp` is transaction-local; memory bounded to one FETCH batch (10,000 rows) + one flush batch (5,000 picks) + one title of fold state, independent of title count.
- `NewestFold` + `std::vector<NewestPick>` + `std::string` members: plain value types, owned by the refresh lambda frame, no raw pointers, no transfer; `feed/finish` take the vector as a streaming sink.
- Cancellation callback `const std::function<bool()>& cancelled`: borrowed by reference for the duration of ONE `refresh_catalog_rollup` call; the only production argument is the worker's `[this]{ return stop_.load(acquire); }`, whose `this` outlives the call because the worker thread is joined before the object (and before the store/pool) is destroyed.
- Rollup worker thread (`std::thread thread_` + `std::atomic<bool> stop_` in `SoftwareCatalogRollup`): owner = the `SoftwareCatalogRollup` object; started by `start()`; `request_stop()` only sets `stop_` (no join, noexcept); `stop()` sets `stop_` then joins; the destructor calls `stop()`; the thread borrows `SoftwareInventoryStore&` and the metrics registry, so `stop()` MUST run before they are torn down (wired in `server.cpp` `stop()`); exceptions are caught inside `run()` (no `std::terminate`).
- Metrics: `yuzu_inventory_catalog_rollup_total{outcome}`, `…_duration_seconds`, `…_last_success_timestamp` — registry-owned; the diff only changes WHEN the counter increments (not for a shutdown cancel).
- No new fd/HANDLE/SOCKET/FILE*/sqlite handle/OpenSSL/BCrypt object/mapped library/temp FILE path/subprocess/shell string/`system`/`popen`/cast-over-lifetime in production code; tests add the shared template-clone fixture and one extra `PgPool` (migration-v8 case, `YUZU_REQUIRE_PG_MIGRATION_DB`, RAII by the macro).

## Independent ownership proof
Both proofs are static code reads at 77236397d, each with no blocking finding.

- security-guardian (Gate 2): no `PQclear`, `PQfinish`, `new`, `delete`, `lock()`, `unlock()`, `detach`, `system`, `popen` or cast in the added lines; the only raw `PQexec` is wrapped at once in `pg::PgResult`. `NewestFold` copies into owned `std::string`s, so nothing borrows from a fetched page; `run_in_txn` declares the transaction after the lease, so a false return or a throw rolls back and then releases; the cursor and the `ON COMMIT DROP` temp table die with the transaction; `CLOSE newest_cur` is an early, redundant release, not a required path. The `cancelled` borrow is a temporary `std::function` held for one synchronous call. The worker thread has one owner and teardown runs the rollup before the store and pool.
- cpp-safety (Gate 3): lambda captures cannot outlive `with_txn_for` (the `std::function` is a temporary forwarded by const reference and never stored); worker teardown is guaranteed both by explicit `stop()` order and by member destruction order; an exception in the refresh lambda unwinds through the transaction and lease, and the pool re-checks `PQtransactionStatus` on release, so a connection never returns inside an open cursor or aborted transaction; borrowed `PQgetvalue` pointers are copied into owning vectors while their `PgResult` is alive, each guarded by `PQntuples == 1`; the `-q.after->installs` negation is unreachable for a negative cursor. Resource Ledger: complete, claims match the code. Sanitizer coverage: ASan/UBSan via the existing Linux leg, TSan nightly only.
- Later delta (the governance r1 fix): the `failed` lambda borrows `const pg::PgResult&` and only reads `PQresultErrorMessage`; it adds no owner and no `PQclear`. No new resource class.
