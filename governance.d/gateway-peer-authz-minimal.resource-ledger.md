## Not-RAII and doubtful items (for the policy-floor judgement)

Nothing in the new production code does manual acquire/release outside RAII: the only native handle added to production is the
POSIX descriptor of R14, owned from the line after the open by `FdCloser` (R15), and the only `::close` in new production code
is that destructor. Items a reviewer should still look at:

- D1 `gateway_peer_cert.cpp:111,114,119` raw `X509_get_X509_PUBKEY`/`i2d_X509_PUBKEY` use a borrowed interior pointer and a raw
  cursor into a `std::vector`. No allocation, nothing to free; not wrapped because there is nothing owned. Not a floor violation.
- D2 (CLOSED) `server.cpp:8011-8013` audit sink captures `this` and is stored in the guard; `audit_store_` (:20908) is declared
  AFTER `agent_server_` (:20832), so member order does not cover it. Coverage, with the gRPC citation: `~ServerImpl` (:8021) calls
  `stop()` (:9834), which calls `agent_server_->Shutdown(deadline)` (:10071-10072) before `audit_store_.reset()` (:10951). In the
  vendored gRPC 1.76.0, `Server::ShutdownInternal` (`src/cpp/server/server_cc.cc:1274-1320+`) shuts the server down, waits the
  grace period, on timeout cancels all calls (:1301) and then waits with an infinite deadline, calls `UnrefAndWaitLocked()`
  (:1309), shuts down every sync `ThreadManager` (:1314) and then calls `value->Wait()` on each (:1319); `ThreadManager::Wait`
  (`src/cpp/thread_manager/thread_manager.cc:76-81`) blocks until `num_threads_` is zero. A started worker decrements it only in
