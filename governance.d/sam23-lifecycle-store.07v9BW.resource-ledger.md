# Resource Ledger: sam23-lifecycle-store

Every owning boundary the C++ in `2c3d0ac14..HEAD` (feat/sam-23-lifecycle-store) acquires: the `SoftwareLifecycleStore` (construction, `replace_rules`, `upsert_declared`, `rules_for`, `declared_for`, `evaluate_batch`), the pure `software_lifecycle_rules.hpp`, the embedded seed, and their registration and teardown in `server.cpp`. No fd, HANDLE, SOCKET, `FILE*`, `sqlite3*`, OpenSSL object, allocated C string, temporary path, subprocess, thread, callback context or `dlopen` is acquired, and no new thread exists.

## Decision lines

- **Boot posture is fail-closed with four arms.** Store open, seed parse, empty seed and seed load each log a `[PG] Refusing to start: ...` line and set `startup_failed_`; a lexical test pins all four, the Deps wiring, the `/readyz` row and the `stop()` reset.
- **Reads are authoritative; `upsert_declared` is fail-soft.** A read that cannot be answered is `std::nullopt` or `Unavailable`, never an empty or `supported` answer; a failed declared-fact write returns `false` and the next host report repeats the fact.
- **No state is stored.** The lifecycle state is computed at read from `lifecycle_rule` and `lifecycle_declared`; a precedence change or a corrected date never leaves a materialised copy behind.
- **Interfaces.** None: no REST route, MCP tool, dashboard page, proto field, plugin ABI or flag. The only external surfaces are the `/readyz` row, two Prometheus counters (pre-seeded to 0 for every reason) and the refusal log lines.
- **Declared facts have no prune yet.** Nothing writes `lifecycle_declared` until hosts report support-end dates; retention ships with that reporting (a `ponytail:` comment at the DDL names the ceiling), and the first-writer hardening is #7797.
