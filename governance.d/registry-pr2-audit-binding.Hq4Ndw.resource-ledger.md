# Resource Ledger -- the registry.write audit binding for plugin results

Range described: `eaa5d59c0..ed996bf4d` (branch `feat/registry-pr2-audit-binding`). Reviewed in the governance run recorded beside this file: `eaa5d59c0..dd392181a`, the first fix delta `dd392181a..470e74049`, the second, `470e74049..638025f01`, and the review-driven round `df3bfc291..ed996bf4d` (pr-review by fjarvis at `df3bfc291`: one blocking lifetime item and seven notes); the commits after `638025f01` answer findings, one of them about ownership, and are described here from the code.

Line numbers are the committed tree at `ed996bf4d`.

## Summary

This range introduces **no new resource owner of the kinds the policy floor lists**: no fd, HANDLE, SOCKET, `FILE*`, `sqlite3*`, OpenSSL or BCrypt object, allocated C string, mapped library, temp path, subprocess, thread, timer or ABI callback, and no manual cleanup. It changes the ownership of ONE existing object -- `ServerImpl::audit_store_` goes from `std::unique_ptr` to `std::shared_ptr` so that the new `registry.write` hook can hold it weakly -- and adds four small owners: a `std::weak_ptr<AuditStore>`, a `std::unique_ptr<DenialAuditBudget>` (its own mutex and two bounded maps), a `RundownGate` (a mutex, a condition variable and two scalars, with an RAII entry) and a `bool` local to a stream. Everything else is value types.

The review's one lifetime finding (a policy floor) was that the hook first read the raw `audit_store_` pointer on the detached forwarder threads of #3279 (`process_gateway_response` is reached from `forward_gateway_pending`'s per-command `std::thread(...).detach()` workers, which `Shutdown(deadline)` does not drain), while `stop()` nulls and frees the store. The first fix closed the OBJECT structurally (rows 1-3 below), the way `analytics_store_` was closed in #3350. It did not close the POOL the store borrows, and an earlier version of this ledger, the hook comment, the `stop()` comment and the architect's INFO grade all priced that as one lease ("small in practice, not zero") when the hook holds the store across up to 300 synchronous writes, each of which leases `pg::PgPool&`. `stop()` resets `audit_store_` and then `pg_pool_` with nothing between them that waits, the forwarder threads are never joined, and `~PgPool` waits only for leases and waiters it can see: a forwarder BETWEEN two rows is neither, so its next row would lease a destroyed pool. pr-review (fjarvis, `df3bfc291`) found that; it is closed by the rundown gate (rows 11-12): the hook enters it before it locks the store and checks it before each row, and `stop()` closes it and waits up to 15 s, force-exiting on timeout, before it resets the store and the pool. The retention thread is not part of this: `stop()` joins it at server.cpp:10396, before any of it, so `~AuditStore` has nothing to join wherever it runs (row 1). The first version of this ledger also said the hook "borrows the existing `AuditStore*` for the duration of one call"; that omitted the detached-thread reach and was corrected earlier.

The agent side adds one `std::string` and two header-only helpers that return the frame by value; the proto edits are comments only.

## What the change changed about lifetime

- `ServerImpl::audit_store_` is shared instead of unique. The eight raw `audit_store_` call sites in agent_service_impl.cpp are unchanged and none is in `process_gateway_response`. Every other use of the member in server.cpp is shared_ptr-compatible; `.get()` borrowers are unwired exactly where they were.
- New reach: the hook runs on every thread that stores an output frame (Subscribe handlers and the detached forwarders). On the forwarders it reads only the weak holder.
- Declaration order in the `ServerImpl` member block is unchanged: `metrics_` < `pg_pool_` < `agent_service_` < `audit_store_` < `credential_change_owner_`.
- `stop()` gains one bounded stage, `close_registry_audit()` then `wait_registry_audit_idle(15 s)` immediately before `audit_store_.reset()`, force-exiting on timeout like the web-thread and delivery-queue stages; the stacked shutdown bound in the documents goes from about 115 s to about 130 s (the shipped grace is 210 s). The retention thread's join at server.cpp:10396 is unchanged and precedes it.
- No statics, no `thread_local`, no new lock held across a store write, no new thread or timer.

## Test code (harness only)

- `IngestHarness`: members `metrics`, `bus`, `registry`, `auth_mgr`, `auto_approve`, `pool`, `std::shared_ptr<AuditStore> audit`, then `svc`. The order is load-bearing: `svc` holds `audit` weakly and `audit` and its pool outlive it. Only the weak reference is wired, so a hook that read the raw pointer would write no row and every positive case would fail.
- `LiveHarness` (a loopback `grpc::Server` and stub over the same members, plus `AuthDbPgShared`): `server` is declared after `svc` and the destructor calls `Shutdown(now + 5 s)`, a finite deadline, so `server` stops before `svc` is destroyed. An optional `configure` callback runs on the service before the server starts, so the budget is set while nothing can be reading it; the close-mid-frame case captures `clock_calls` (declared before the harness) and the service by reference in the budget's clock.
- `test_rundown_gate.cpp`: pure. Every thread is joined before the test body ends; the atomics, latches and promises the threads touch are locals declared before them; `give_up` and `stop` flags let a broken gate fail an assertion instead of hanging the run. `RundownGate::Entry` values are held in `std::unique_ptr` (built by guaranteed elision from `try_enter()`) where a test needs two at once.
- `TrackerScope` (tests/unit/server/test_tracker_scope.hpp, moved out of test_agent_service_impl.cpp): owns `std::unique_ptr<ExecutionTracker>`; the destructor runs `set_execution_tracker(nullptr)` then `tracker.reset()`; an optional `ExecutionEventBus*` must outlive it. The ordering test declares the two locals its bus listener captures BEFORE the bus.
- `SqlFault` (pre-existing helper): arms a real fault by renaming or constraining the audit table; `repair()` is idempotent and noexcept and the destructor calls it, so a failing `REQUIRE` between `arm()` and the explicit repair cannot leave the schema broken. It is declared after the harness.
- `LogCapture` (pre-existing, RAII): `stop()` runs before `text()` in every case that reads it.
- The budget cases inject a clock lambda that captures a local (`now_ms`, `clock_calls`) declared before the harness; the throwing-clock cases use that clock plus a captureless lambda that throws `std::runtime_error` or an `int` from inside `try_admit`.
- Agent tests build `CommandResponse` values in memory. The Erlang tests use message passing and `meck` with `meck:unload` in `after`; no port or path. The static gate (Python) only reads three source files.

## Independent proof

Ownership was proved entry by entry by cpp-safety over `eaa5d59c0..dd392181a` (the 8 pure cases compiled under ASan and UBSan, 395 assertions clean; a probe of the header over every byte value, the 4,096-byte UTF-8 cut and an `is_registry_plugin` oracle); it found the lifetime floor above, which security-guardian found independently. cpp-safety re-reviewed `dd392181a..470e74049` and confirmed the floor closed: ASan and UBSan over the pure header (11.4M checks) and TSan over a write-once weak holder with an owner reset and a shared budget (real and atomic clock), no reports; the live cases were not run sanitised (the shared binaries are not). It then re-reviewed `470e74049..638025f01` and found the lifetime and ownership claims in this ledger correct (the local strong reference released before the handlers run, one production setter call, non-escaping lambdas, the key bound clean under ASan and UBSan at 0, 3, 96 and SIZE_MAX), with one NICE: `book_rows` was not idempotent, so a throw after it ran would book the same rows again from a catch arm (an over-count of at most 300 rows; the evidence rows untouched). `7a87c09a5` makes it idempotent; the reviewer's fault-injection sweep over every allocating call of the hook body found 0 anomalies for that shape against 7 for the previous one. Sanitizer coverage still needed: ASan and UBSan, which the existing Linux leg over `[registry_audit]` and `[budget]` provides; no new TSan surface.
