# Resource Ledger: facet value bound, deterministic facet cap, dropped-facets counter (#5623, ingest only)

Covers `origin/dev..HEAD` on `fix/5623-facet-ingest-bound`.

No fd, HANDLE, SOCKET, `FILE*`, OpenSSL object, BCrypt handle, allocated C string, mapped library, temp path, subprocess or thread is added in production code. There is no `new`, `delete`, `malloc` or manual cleanup in the added C++. The libpq connection, `PgResult` objects and the SAVEPOINT are the existing ones in `ResponseStore::store`; no new libpq call site is added.

| resource | owner | acquired | released | transfer / failure cleanup |
|---|---|---|---|---|
| `PGconn*` lease used by the ingest transaction | `PgPool::Lease` (acquired by `with_txn_for` with `kIngestTimeout`), borrowed by the callback lambda | `with_txn_for` | lease destruction | unchanged; the callback returns success or failure and the pool commits or rolls back |
| `SAVEPOINT facet_batch` (database-side) | the transaction | the existing SAVEPOINT statement | `RELEASE SAVEPOINT` on success, `ROLLBACK TO SAVEPOINT` on a failed batch | unchanged; a failure of the savepoint machinery itself aborts the transaction and `with_txn_for` refuses to commit |
| `pg::PgResult` objects (`ins`, `sp`, `fi`, `fin`) | stack RAII in the callback | per statement | destructor | unchanged |
| `facets` (nested `std::unordered_map`) and `flat` (`std::vector<std::tuple<int,std::string,int>>`) | the `store` call frame | built from every field of every output line, then `flat` from the map | end of the facet block | frame-local, owns its strings and no OS resource. `facets` copies every distinct value including one over `kMaxFacetValueBytes` because the length filter runs while `flat` is built, so the count is of distinct excluded pairs; `flat` skips excluded values and is cut to `kMaxFacetsPerResponse` (5000) with an in-place `std::partial_sort` (O(n log cap), no allocation of its own). Peak memory is bounded by the 2 MiB ingest byte cap as before, but memory per input byte can be large (#5782, existing behaviour, not changed here) |
| three `std::size_t` facet-drop deltas (`facets_too_long`, `facets_capped`, `facets_batch_failed`) | the `store` call frame, captured by reference into the synchronous callback | zero-initialised before `with_txn_for` | end of `store` | plain integers, no cleanup. They are published with `note_facets_dropped` only after `with_txn_for` has returned success, outside the callback: an aborted or failed transaction (including a failed COMMIT) publishes nothing, so a facet counter only ever describes a stored response. If the COMMIT succeeds server-side but the client sees an error, the counters under-count (accepted trade-off) |
| `yuzu_server_response_facets_dropped_total{reason}` counter series | `yuzu::MetricsRegistry` (owned by `ServerImpl`, pointer held by `ResponseStore`) | `seed_response_facet_metrics` at startup (called once from the `ServerImpl` constructor), and on first use per reason | registry destruction | the three reason labels are fixed constants (bounded cardinality); `note_facets_dropped` is a no-op when `metrics_` is null and when the count is zero; no label is built from response content |
| borrowed `yuzu::MetricsRegistry*` in `ResponseStore` | `ResponseStore` (borrower only; `ServerImpl::metrics_` owns the registry) | `set_metrics` | with the store | no ownership transfer. Lifetime: `ServerImpl::metrics_` is declared before `response_store_`, so members destruct in reverse order and the store goes first (same precedent as the existing `note_ingest_dropped` counters) |
| test code | stack objects, the existing ResponseStore PG template and one new InstructionStore `PgTestTemplate` (`dashfraginstr`, see the addendum), both via `YUZU_REQUIRE_PG_DB_TPL` | per test | per test scope | an RAII `std::ifstream` to read `server.cpp`; a test-local trigger and function created in the cloned test database and dropped in-test; no raw owning pointers, no threads, no temp paths or fixed ports |

Platform notes: no `#ifdef` added; the bound is a plain `std::size_t`; the comparator is a captureless lambda over `std::get`. Behaviour intentionally unchanged: the 5000 facet cap value, the ingest byte cap, the schema and indexes.

## Addendum: additive unindexed-filter indication (PR 1 close-out)

No production resource added. `unindexed_filter_keys` (`group_agent_count_preview.cpp`) is a pure function: it reads `columns_for_plugin`'s function-local static column table by `const&` (no copy of the table), builds a local `std::vector<std::string>` of mangled key names (owns its strings, no OS resource, linear de-duplication over a handful of keys) and returns it by value. No `new`, `delete`, `FILE*`, fd, lock, thread or callback; the REST and MCP handlers serialise it through the existing `JArr`/`JObj` builders into the response string they already build. `render_create_group_form` and the group-from-results `422` build one more static `std::string` from `std::to_string(kMaxFacetValueBytes)` using the existing file-local `any_filter_value_too_long`.

Test code: the REST preview tests reuse the existing ResponseStore `PgTestTemplate` pattern (a TU-local template with the shared `responsestore` key, `YUZU_REQUIRE_PG_DB_TPL`), and `DeviceRestHarness` gains an optional borrowed `ResponseStore*` (test-scope lifetime). The MCP file adds a `PreviewRestTwin` (route owner declared before its `TestRouteSink`, TestRouteSink invariant 1) over a borrowed store. No threads, temp paths or fixed ports.
