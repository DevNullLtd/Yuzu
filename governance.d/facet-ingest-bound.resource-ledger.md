# Resource Ledger: facet value bound, deterministic facet cap, dropped-facets counter (#5623)

Covers `origin/dev..HEAD` on `fix/5623-facet-ingest-bound`.

No fd, HANDLE, SOCKET, `FILE*`, OpenSSL object, BCrypt handle, allocated C string, mapped library, temp path, subprocess or thread is added in production code. There is no `new`, `delete`, `malloc` or manual cleanup in the added C++. The libpq connection, `PgResult` objects and the SAVEPOINT are the existing ones in `ResponseStore::store`; no new libpq call site is added.

| resource | owner | acquired | released | transfer / failure cleanup |

Platform notes: no `#ifdef` added; the bound is a plain `std::size_t`; the comparator is a captureless lambda over `std::get`. Behaviour intentionally unchanged: the 5000 facet cap value, the ingest byte cap, the schema and indexes.

## Addendum: one over-bound rule (fix round 4)

No resource added. `facet_value_over_bound(std::string_view) noexcept` (`response_store.hpp`) is a pure inline comparison against `kMaxFacetValueBytes`: it takes a non-owning view, allocates nothing and owns nothing. Ingest (`ResponseStore::store`, on the sanitized value) calls it directly; the dashboard `any_filter_value_too_long` and `unindexed_filter_keys` reach it through `facet_filter_value_over_bound` (fix round 5, below), so the rule has one copy. The two `static_assert(kMaxFacetValueBytes == 2048, ...)` lines in `mcp_server.cpp` and `rest_api_v1.cpp` are compile-time only. Test code adds no resource beyond the existing ResponseStore `PgTestTemplate` and a `PgPool` aimed at an unroutable address (connect fails fast, no listener, no fixed port) for the degraded-store form case.

## Addendum: stored-form measurement of a typed filter (fix round 5)

No owning resource added. `facet_filter_value_over_bound(std::string_view)` (`response_store.{hpp,cpp}`) is NOT pure and NOT allocation-free, unlike `facet_value_over_bound`: for a raw value over 682 bytes it calls the TU-local `sanitize_pg_text`, which builds the scrubbed value as a local `std::string` (up to 3x the input, plus a second same-size copy when a NUL is present), freed on return; at or under 682 bytes it returns before any allocation. It owns nothing beyond those temporaries, takes a non-owning view, is not `noexcept` (a `std::bad_alloc` propagates to the HTTP/MCP handler), and no longer shares a noexcept context with its callers (`any_filter_value_too_long`, `unindexed_filter_keys`). `ResponseStore` binds a typed filter value through `sanitize_pg_text` as well (`append_facet_filters` and the single-filter count), so the value that is measured is the value that is queried. No `#ifdef`, thread, callback or fd. Test code adds no resource: the new helper cases are pure, the dashboard hint case reuses the existing ResponseStore `PgTestTemplate` pattern.

## Addendum: stored-form compare in the results line filter (fix round 6, scoped Gate 8 pass 8)

No owning resource added. `facet_filter_stored_form(std::string_view)` (`response_store.{hpp,cpp}`) returns a new `std::string` by value (it allocates, is not `noexcept`, owns nothing beyond that temporary) and is a thin wrapper over the TU-local `sanitize_pg_text`. `DashboardRoutes::render_results` builds one local `std::vector<std::string> filter_stored_values`, one element per active filter, before the per-response loop and indexes it by the filter's position; it lives for the call, so no iterator or view outlives it.
