# DEX fleet usage read model Resource Ledger (governance Gate 1)

Production-code ledger for the fleet application-usage read model, kept here so the ownership analysis is retrievable with the change. Files: `server/core/src/dex_usage_model.hpp` (pure model, new), `server/core/src/dex_app_usage_owner.{hpp,cpp}` (new query owner), and the tests under `tests/unit/server/`. Nothing constructs the owner in production yet: the wiring in `server.cpp` and the API seam belong to the later API change, so this change adds no lifetime ordering at shutdown.

## Resource Ledger (C++)
- New owner: one class, `DexAppUsageOwner`, the cross-schema query owner for usage, crash and hang counts. It holds `pg::PgPool&` (borrowed, never owned); its copy operations are deleted and it has no destructor logic. The pure model header is value types only (`std::string`, `std::vector`, `std::optional`, `std::function` closures, structs of `int64_t`, `int` and `double`).
- No new file descriptor, handle, socket, `FILE*`, sqlite object, OpenSSL object, allocated C string, mapped library, temp-file path, subprocess, shell string, thread, lock or retained callback is acquired, owned or released. No `reinterpret_cast`, `const_cast`, raw `new`/`delete` or manual cleanup path exists in the new code.
- Lease and transaction: each `read()` takes exactly one bounded lease through `PgPool::with_txn_for(3 s, ...)` (RAII lease and transaction guard), runs the callback synchronously and does not store it. `SET LOCAL statement_timeout = '10s'` is transaction-scoped, so it cannot leak onto the pooled connection. A failed acquire, failed statement or uncommitted transaction returns `std::nullopt`; there is no early-return path that skips release. The group and tag membership closures complete before the usage read starts, so no lease is held across another. The `PGconn*` handed to the `with_txn_for` callback is borrowed from the lease, used only inside the callback and never stored.
- Result handles: both statements return `pg::PgResult` (RAII `PGresult`). `PQgetvalue` pointers are read only while the `PgResult` is alive and are copied at once through `strtoll` into `int64_t`; no row keeps a pointer into libpq memory. The error lambda captures a local flag by reference and runs only inside `with_txn_for`, within the frame of `read()`.
- Borrowed data: `read()` takes `const DexUsageQuery&`. Text parameters go through `pg::to_text_array` (owning string, escapes); the integer and boolean arrays are built into owning strings of digits and `t`/`f` only; the bind parameter vector owns every value, and the two clamp constants are `std::to_string` of numeric `constexpr` values. Nothing outlives the caller's arguments and no caller text is interpolated into SQL.
- Closures in the pure model (`DexUsageSources`) are `std::function` members of a caller-owned struct passed by const reference and used only during the call; none is stored.
- Static state: one function-local `static const std::string` for the SQL text (built once, immutable, thread-safe initialisation). Constants are `constexpr`.
- Integer and floating-point hazards: every agent-reported value is clamped two-sided in SQL (`GREATEST(0, LEAST(value, cap))`), with caps chosen so a per-table sum stays below 2^63; counts are `int64_t` from `COUNT`; the rate divides by hours derived from a positive clamped total, and a non-positive total is withheld as `zero_usage`. No subtraction on unsigned types.
- Tests (harness only): the pure suite is memory-only with a fixed instant; the owner suite uses a database cloned from a pre-migrated template, ages freshness by an UPDATE (no sleeps) and adds no process spawn, socket or thread. A `static_assert` pins the result row type as trivially copyable (no agent id).
