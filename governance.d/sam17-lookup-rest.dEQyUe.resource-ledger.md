## Decision lines

- **The version-range read is scoped, not fleet-wide.** `resolve_range` passes the gate's `VisibleSet` (`swl::scope_ids`) into `installed_software_distinct_versions` / `component_versions`, so the 2000-version cut that answers `400` is a fact about the caller's own rows; a confined caller is answered for a title with 2000 versions outside its scope exactly as for an unknown title (pinned on both routes). The whole scope set is pushed, with no post-filter alternative: a cut distinct-version set cannot be filtered after the fact without re-leaking the fleet property. This refines, and does not reverse, the binding "live range resolution with the catalogue comparator".
- **`row_count` is `NOT NULL DEFAULT 0` and v12 resets the catalogue stamp.** A row already in `catalog_rollup` carries 0 until the next refresh recomputes it, so the same migration step sets `catalog_rollup_meta.refreshed_at` back to 0 (the v8 `building` state) and the totals read answers `totals_omitted: "building"` for one refresh interval, never `installs: 0` beside a non-zero device count. A nullable column with a `computed` marker was considered and dropped (ponytail-review r4): its only further trigger, a refresh by an older-ladder replica, is out of scope by the owner's ruling that no outdated servers will exist.
- **Every scan-shaped `query_software` read is bounded.** `match=prefix` (a sequential scan under a locale collation) and any `status` filter (a derived, non-indexable predicate) now run under the 5 s `SET LOCAL statement_timeout` like `q` and `match=contains`, degrading to the audited `503`; the index-driven exact-name and plain scope reads keep the bare lease (R2). Pinned by a lock-wait test whose elapsed time tells the 5 s bound from the pool's 10 s `lock_timeout`.
- **Keep-last-good on the components rollup is total.** One REPEATABLE READ transaction holds the DELETE, the INSERT and the stamp UPDATE; every failure path rolls all three back. The refresh's measured ceiling (44-47 s at 8.8M component rows against the 60 s statement limit, so about 11M rows) is recorded in `docs/clock-guarded-retention.md` and ADR-0016, latent until the component producer ships.
- **Totals are served only to an unfiltered caller for an exact name** (ADR-0017 Update 2026-11-09); a confined caller gets rows and `totals: null` with `totals_omitted: "scope"`, pinned by exact-key-set assertions on both routes.
- **Audit is set-and-proceed** (`detail::try_persist_audit`; `audit_persisted: false` / `Sec-Audit-Failed` on a lost row), with `success` on every served page, a paired `denied` on a scope drop or an out-of-scope `agent_id`, and `failure` with the stage name on every degraded `503`; a `400` writes nothing.
