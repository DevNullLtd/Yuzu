## Decision lines

- **No tombstones.** `installed_software` is keyed by instance and replaced by hard delete; a removal is a `remove` row in `software_changes` carrying name, publisher and version. Reversible: a `removed_at` column would need every read to filter.
- **Component placement.** `software_components` lives in this store's schema and is written by this store in the same transaction as the facet state and the report hash, because ADR-0012 section 3 forbids a cross-schema write from a second store.
- **Component retention.** No prune: current-state, bounded per device by the per-call record cap (a post-apply check refuses a delta that would leave a device over it), removed with the device. Recorded in the retention register as a disposition.
- **Ledger retention.** 400 days, 50,000 rows per pass, hourly, part 6 = Decline. The cap is a knob: the fleet mean must stay under 1.2M ledger rows per day, and the 2M-endpoint target needs a 5-minute cadence or a higher cap. Derivation in the retention register.
- **Mismatch is not a fault.** A section that fails its checks is rolled back to its savepoint and nacked; the agent resends the facet in full. Only a genuine SQL error aborts the call.
