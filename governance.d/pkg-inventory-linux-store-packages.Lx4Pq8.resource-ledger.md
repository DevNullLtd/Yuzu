# M.6 (pkg_inventory Linux store_packages and managers) Resource Ledger (governance Gate 1)

The production-code ledger for the Linux `pkg_inventory` legs. Files `agents/plugins/pkg_inventory/src/pkg_inventory_linux_parsers.hpp`, `pkg_inventory_legs.hpp`, `pkg_inventory_parsers.hpp`, `pkg_inventory_linux.cpp`, `pkg_inventory_plugin.cpp`, `agents/core/src/sync_source_installed_software.{hpp,cpp}`, and the server vocabulary headers (`software_catalog_rules.hpp`, `cpe_normalize.hpp`, `software_inventory_store.hpp`).

## Resource Ledger (C++)
- `posix::Dir` (move-only `DIR*`, `closedir` in the destructor; `pkg_inventory_legs.hpp`): `linux_manager_rows_at` holds `std::vector<posix::Dir> probes` (at most 4: `/usr/bin`, `/usr/sbin`, `/bin`, `/sbin`) to function end, and `count_entries` opens one `Dir` at a time as a local. `snap_rows` holds the snaps directory (1) plus `std::vector<posix::Dir> mounts` (at most 2) across the loop, and `snap_detail` opens `name_dir`, `rev_dir` and `meta` per snap as RAII locals released on every return. `flatpak_rows` nests `top`, `id_dir`, `arch_dir`, `branch_dir` (4 live at depth 3). Peak simultaneous directory fds is about 6 on the snap leg and 4 on the flatpak leg; the snap-leg `Dir`s are destroyed when `snap_rows` returns, before the flatpak walk starts. The vector of `Dir` relies on the noexcept move.
- fd hand-over in `finish_dir_open`: a `ScopedFd` owns the raw fd from `open`/`openat` until `fdopendir` succeeds, then `release()` hands it to `Dir{d}`; on `fdopendir` failure the `ScopedFd` closes it, with `errno` read before the close. Existing code, newly exercised by the Linux leg; the "walks leave the process's file descriptors exactly as they found them" test counts open fds before and after (default, `max_entries_per_dir=1` and expired-clock limits).
- snap.yaml read: `yuzu::shared::read_file_no_follow_at(meta.dir.fd(), "snap.yaml", 64 KiB)` (shared helper; the fd is owned by the local `FdCloser` in `read_open_fd`, so every early return closes it); `openat` with no-follow flags, `S_ISREG` check and a size cap; returns an owning `std::string`; the borrowed `meta.dir.fd()` outlives the call because `meta` is a live local.
- `readlinkat` buffer: `std::string buf(max_len + 1)` in `posix::read_link_name`; a heap string with no handle, and the text is validated as a bare component, never resolved.
- `WalkSlot` (process-wide single flight): `static std::atomic<bool> flags[kActionCount]` as a function-local static inside the inline `flag_for` (array grown from 2 to 3, `static_assert` ties `kActionCount` to `Action::store_packages`). Acquire is `exchange(true, acquire)` in `try_acquire`; release is `store(false, release)` in the destructor (move-only; move constructor `std::exchange`s to nullptr; assignment deleted), so it is released on every return and on exception unwind (the plugin's `run_guarded` catches above it). Hoisted from the macOS TU, not new logic.
- `WalkBudget` and `merge_tokens` (value types, hoisted unchanged from `mac::detail`); `StoreWalk` holds `const Limits&`, the accumulator and the budget by reference, and its lifetime is the `linux_store_rows_at` frame (the `Limits{}` default argument is a temporary that outlives the callee).
- Bounded buffers: rows are a `std::vector<std::string>` capped at 20,000 rows and 1 MiB (`StoreWalk::add`), per-directory listings at 4,096 entries, and the whole action at 200,000 entries and 10 s.
- Static caches and globals: only the `flags[]` atomics above; `kTools`, `kProbeDirs` and `kContainers` are `constexpr` (no dynamic initialisation, no destruction-order issue). All `std::string_view` members view static storage.
- Collector: `std::size_t seen` in `adapt_pkg_inventory` is a stack counter; no handle.
- NOT introduced in production code: no subprocess, thread, socket, sqlite handle, OpenSSL object, `FILE*`, mapped library, shell string, `system`/`popen`, temp file, raw `new`/`delete`, cast over a lifetime, or manual cleanup (every release is RAII). Test code: `TempDir` (`yuzu_test_pkg_inventory_linux_*` prefix) and `ModeGuard`, which restores modes so `remove_all` runs.
