The only new threads are the detached collector workers of R1, bounded by the per-action limit and drained before any plugin is unloaded.

## Decision lines

- **Workers are drained, never joined.** A worker abandoned at its time limit may stay inside a plugin for as long as the plugin keeps it; the single-flight flag stops a second worker piling in (`busy`), and the barrier turns a worker that never returns into a hard exit at shutdown rather than an unload under it. A plugin that never returns therefore makes the restart a hard exit; the 3 s drain, exit code 3, the 20 s watchdog (exit 4) and the Windows SCM restart are disclosed in the ADR Update and in the user manual ("Sections and deltas" and the `busy` troubleshooting entry).
- **The single-flight flag is RAII end to end (R2a).** There is no manual `end()` on any dispatch path: `admit` hands the flag to a ticket before anything else can fail, the ticket rides in the closure and the worker's local, and the primitive `try_begin`/`end` pair stays public only for the barrier tests.
- **Slot 13 is an allowlist.** `machine_install_location` keeps a canonicalised location only under `kMachineRoots` (one table in `installed_software_v3.cpp`) and blanks everything else, fail closed; the name, version, publisher and hash of the row are reported whatever the location. The list and the canonical steps are in the ADR Update and the user manual.
- **No weekly full resend.** The source sets `SyncSource::no_full_floor`; the server's per-section base and `expect` checks answer a diverged section with `installed_software:<facet>`, which the agent resends in full.
