# DEX score policy read side Resource Ledger (governance Gate 1)

Production-code ledger for the score policy read path, kept here so the ownership analysis is retrievable with the change. Files: `server/core/src/dex_score_policy_provider.hpp`, `dex_score_policy_json.hpp`, `dex_api.{hpp,cpp}`, `dex_api_local.hpp`, `dex_read_model.{hpp,cpp}`, `dex_read_builders.hpp`, `config_routes.{hpp,cpp}`, `runtime_config_store.cpp`, `server.cpp` (wiring) and the REST/MCP handlers in `rest_api_v1.cpp` and `mcp_server.cpp`.

## Resource Ledger (C++)
- `DexScorePolicyProvider` owns, by value, a `std::mutex mu_` (guards state only, never held across the store read), a `bool refreshing_` (single-flight flag), a `bool have_`, a `std::int64_t last_ok_ms_`, the cached `DexPolicyInForce` (value type: policy, two strings, a fault string) and the log-dedupe state (`bool outage_logged_`, `std::string logged_fault_`). Two `std::function` members (`ReadFn`, `ClockFn`) are moved in at construction; the read (and the parse of the stored text that follows it) runs without the lock held, the clock is sampled under it. The class is non-copyable and non-movable (deleted copy; held by `std::shared_ptr`).
- Acquire/release of `refreshing_`: set under `mu_` in `current()`, then owned by a local scope guard (`ClearRefreshing`) declared right after it. The guard is the single owner: on every exit from `current()` (the normal return, an exception from the injected read or from the resolve of the stored text, an exception from a handler that builds its message string, or an exception from the clock sampled after the re-lock) its destructor re-takes `mu_` if the unlocked window left it released and then clears the flag. There is no straight-line release, so no path can leave the flag set. `read_and_resolve()` still maps `std::exception` and `...` from the read or the parse to a failed read; an allocation failure inside its handlers escapes `current()` through the guard. A mutex that cannot be re-taken in the destructor terminates the process: a crash, never a wedged flag.
- Threads and callbacks: no thread is created in production code. `current()` is called from HTTP worker threads (the web thread pool); concurrent callers either hold `mu_` briefly, or return the cached policy / a typed error while a refresh is in flight. No callback is retained beyond the provider's own lifetime.
- Borrowed data: `dex_score_policy_store_reader(RuntimeConfigStore&)` returns a lambda capturing the store by reference; the `ReadFn` is stored in the provider, which is held by `std::shared_ptr` in `ServerImpl` (member declared after `runtime_config_store_`) and by the copies of that pointer inside the `DexScorePolicyFn` closure handed to `make_local_dex_api`. `rest_api_v1_` and `mcp_server_` are declared earlier than the store and hold `DexApi` closures with such a copy, so the provider object can outlive the store; it is the borrow that must not be CALLED after the store is gone. That holds because `web_server_->stop()` signals the web thread, `web_thread_` is joined in `stop()` (or the process exits when the 15 s wait times out), and `runtime_config_store_` is reset only after that, so no call can happen between the join and the reset. The store `get()` returns `std::expected<std::optional<RuntimeConfigEntry>, std::string>`; the lambda copies `entry->value` into the returned `std::optional<std::string>` before the entry dies. No pointer into the entry escapes.
- JSON parsing: `dex_policy_in_force_from_stored` runs outside `mu_` (inside `read_and_resolve()`). A stored text over `kDexScorePolicyMaxBytes` (256 KiB) is refused before it is parsed; otherwise it calls `nlohmann::json::parse(text, nullptr, /*allow_exceptions=*/false)` over the operator-stored text; the result is a local value that is validated and then copied into a `DexScorePolicy`; nothing references the parsed tree after return. The only document text a fault can carry is an unknown key, passed through `yuzu::log_key_token` (control bytes folded, capped at 256 bytes). nlohmann 3.12's parser and destructor are iterative (measured: a 1,000,000-deep array parses and frees without stack growth).
- `fnv1a64_hex` returns `std::format("{:016x}", h)`: a fresh string, no buffer, no retained pointer.
- `LocalDexApi` owns, by value, a `RefusalLogThrottle` (a `std::mutex` and a bounded `std::unordered_map` of last-warn times, at most 1024 keys; one key is ever used) that demotes the policy-unavailable warning to debug between intervals. No thread, handle or callback.
- Static state: none added (the log-dedupe state is per provider instance).
- No new file descriptor, HANDLE, SOCKET, `FILE*`, sqlite object, OpenSSL object, BCrypt handle, allocated C string, mapped library, temp-file path, subprocess or shell string is acquired, owned or released in production code.
- Tests (harness only): the provider tests use `std::promise`/`std::future` latches and a fake monotonic clock, `std::thread`s joined through the repo's `ScopeExit` guard, and a bounded `std::async` helper (`current_bounded`: a 10 s `wait_for` that releases the parked read and fails the case on timeout, so a waiting caller never hangs the shard) for the parked-read cases; the PG-gated cases open a real `RuntimeConfigStore` over a template clone (key directory is a `yuzu_test_`-prefixed `TempDir`); no sleeps, no process spawns.
