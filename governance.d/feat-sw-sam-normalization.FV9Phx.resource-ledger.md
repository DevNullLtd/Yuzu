# Resource Ledger: feat-sw-sam-normalization

Every owning boundary the diff adds or changes in C++: the software-title normalisation job and its owner (`software_normalization_job.*`, `software_title_dimension.*`), the pack parser (`software_normalization_pack.*`), the product registry schema v2 and pack load (`product_registry_store.*`), the `title_triples` rebuild in the catalogue rollup (`software_inventory_store.cpp`), the wiring in `server.cpp`, and their unit tests.

| ID | Resource / construct | Owner type | Acquired | Released | Transfer | Failure cleanup |
|---|---|---|---|---|---|---|
| R1 | The job thread `SoftwareNormalizationJob::thread_` | `std::thread` member of `SoftwareNormalizationJob`, held by `unique_ptr` in `ServerImpl` | `start()` (idempotent: guarded by `joinable()`) | `stop()` joins; the destructor calls `stop()`; `request_stop()` only signals. `ServerImpl::stop()` calls `request_stop()` when draining begins and resets the job BEFORE the dimension owner, both stores and the pool | none | the loop body is wrapped in a catch-all, so an exception never reaches `std::terminate`. Join latency is bounded: stop is polled in 5 s steps while parked, and a tick in flight is cancelled at its next poll (every 256 titles and before each write), so the join waits for at most one in-flight statement, which is bounded by the 60 s `statement_timeout` |
| R2 | `std::atomic<bool> stop_` | member, `release` stores / `acquire` loads | construction | destruction | none | it is the sole cancel flag: the tick's cancel predicate reads it, nothing else cancels |

Bounds: 2,000 titles per pass (`kPassLimit`); 100 passes per tick (`kMaxPassesPerTick`, 200,000 titles); 60 s pass budget (`kPassBudget`) equal to the `statement_timeout`; the cancel flag is polled every 256 titles and before each write; 60 s re-arm after a capped tick or a source-pending tick (`kBacklogRearm`); a 3600 s quiet interval; an open queue row is re-stamped at most once a day (`kQueueRestampSecs`); a title_triples triple is at most 2,400 bytes combined; a pack is at most 1 MiB, 5,000 rows and 256 bytes per field (the seed is 74 rows, `kMinSeedRows` is 50).

Persistent state: `normalization_pack` (one row), `title_dimension` (PERMANENT, unbounded by design: it grows with the distinct (name, publisher, ecosystem) titles ever seen), `curation_queue` (open rows mirror the current fleet, rejected rows persist), `title_triples` (rebuilt hourly inside the catalogue rollup transaction; inherits the rollup's ~6,000-endpoint ceiling). Two online migrations: registry v2 (constant-default column adds and three new empty tables) and inventory v9 (a new empty table). Metrics: seven families (closed label sets; `pack_info` holds one series per pack version this process has seen) and two alert rules. No files, sockets or subprocesses are added.

## Decision lines

- **Retention.** `title_dimension` is permanent and unbounded by design. The accepted bound is "distinct triples ever seen"; titles that embed a version in their name churn rows. There is no prune, because a dimension row is the identity later installs join to. A later prune would be a separate clock-based pass and routes through the clock-guarded-retention rule. `yuzu_software_titles` is the size signal.
- **Queue reconcile is a derived-set reconcile, not clock retention.** It is regenerable from `title_dimension` and deliberately has no would-wipe guard: an empty `title_triples` deletes every open queue row and only each row's `first_queued_at` is lost. Rejected rows are never deleted by it or by the pass.
- **Empty feed.** An empty or never-built `title_triples` is not "fully normalised": the ratio gauge is not set (absent until the first non-empty read, last value kept afterwards), the count gauges read 0, ticks succeed, and neither normalisation alert fires. The signal is the catalogue rollup's own alerts, which both annotations name. When the rollup stalls (for example past its ~6,000-endpoint ceiling) the normalisation gauges freeze.
- **Over-wide triples.** A triple whose name, publisher and ecosystem exceed 2,400 bytes combined is left out of `title_triples`, because Postgres refuses a btree entry beyond about 2,704 bytes and one such row would roll back the whole refresh. Such a title is not normalised. `catalog_rollup_grain_key` has the same class and is not changed here.
- **Source-pending re-arm.** A pass that selects nothing while `title_triples` is empty and `installed_software` is not reports `source_pending`; the tick then re-arms after 60 s. Self-bounding once the rollup has run; while a rollup never completes, the job costs a handful of cheap statements a minute.
- **A tick that is not clean never re-arms early** (`capped` and `source_pending` are cleared on error and cancel).

## Known limits of the provisional seed

The seed is a starting set, not a measured one. Its Windows rows bind only to ecosystem `windows` (an `msi`, `optional_feature` or `macos_pkgutil` title is queued); several raw names will not match what a collector really reports (a locale suffix, an edition word the real title omits); `title_version` is the first version-like word (`SQL Server 2019` records `2019`); a short generic name with an empty publisher (`git`, `curl`, `bash`) carries a product token, so `normalized` is NOT publisher-verified and the first consumer must not treat it as such; pack products use short canonical titles, so a deployment whose registry already holds a longer name for the same product may hold both identities. Automatic product creation is off (`kAutoBirthEnabled = false`, behind a `static_assert`).

## Mutation and falsification evidence (this round)

Each test below was run against a build with one deliberate defect and went red, then the defect was removed and the case went green (full-tree rebuild after every restore).

| Defect introduced | Case that went red |
|---|---|
| `kTitleTripleMaxBytes` raised to 2,000,000 | refresh_catalog_rollup leaves an over-wide triple out of title_triples and still succeeds (the refresh itself failed with the btree error) |
| queue delete without `status = 'open'` | owner pass keeps a rejected queue row when its title later resolves |
| `resolve_title` empty-title guard removed | resolve_title treats a name with no title token as unnormalized even when an alias is keyed on it (all four names) |
| gauge query back to `COALESCE(norm_status, 'pending')` | gauges count a normalized row that lost its product as pending |
| ratio gauge always set | gauges leave the ratio unset while the title source is empty |
| `source_pending` never reported | owner pass reports source_pending only while the catalogue rollup has not filled title_triples |
| reconcile UPDATE without the `IS DISTINCT FROM` guard | owner reconcile writes only queue rows whose count moved or that are a day stale |
| candidate order `device_count ASC` | owner pass selects the highest device counts first when a page is full |
| cancel after the dimension write commits instead of rolling back | owner pass cancelled after the dimension write rolls back both tables |
| `text_array` writing an unquoted array | owner pass round-trips awkward names through the array writes (and every owner case) |
| alias read ignoring the `sources` argument | read_normalization_aliases returns pack and curated rows for the requested alias keys and exact sources only |
| registry `origin` default changed from `matcher` | the v2 migration upgrades populated v1 rows with the matcher defaults (and existing writers keep working after v2) |
| `title_dimension` dropped from the projection list; `norm_status` CHECK loosened | ProductRegistryStore reports !is_open when a v2 column is missing; title_dimension refuses an unknown norm_status or method or category |
| `try_norm_lock` always true | owner reconcile skips while a peer holds the lock and catches up once it is released; owner pass skips when a peer holds the advisory lock |
| `capped` not cleared on error | owner tick clears capped when the queue reconcile fails |
| the previous `pack_info` label not zeroed on a pack change | gauges leave the ratio unset while the title source is empty and zero the old pack label on a pack change |
| cancelled tick counted as an outcome | SoftwareNormalizationJob counts a cancelled tick as neither success nor error |
| `source_pending` ignored by `rearm_interval` | rearm_interval waits the short backlog floor only after a capped tick |
| parser: conflict check, NUL check, reserved-cpe check, month range removed; a seed vendor put back to its old spelling | the four parser negatives, and the embedded seed gives every product ONE identity |
| alert window put back to 2h | the promtool case at a 61 minute period (evaluations at 182, 243 and 304 minutes) |

The unexpected-shape arm of `try_norm_lock` (zero rows or a value other than `t` or `f`) cannot be produced from a real Postgres, so it is pinned by inspection; the peer-held (`f`) and held (`t`) arms are exercised by the cases above.
