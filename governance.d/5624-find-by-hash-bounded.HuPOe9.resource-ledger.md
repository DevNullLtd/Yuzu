## Summary

The change replaces one `sha256sum`/`shasum` child process per file with an in-process bounded walk. It **adds no thread, no subprocess, no callback context that outlives its call and no temp path in production code**, and it **removes** the per-file subprocess. Every acquired resource is a local with a named RAII owner, apart from three short windows that are listed in the rows below (the raw `openat2` descriptor, the EPERM plain-open descriptor and the macOS thread policy).

Two rows of the author's Gate 1 ledger were wrong and are corrected here (the `BcryptSha256` constructor exception path, row 8, and the 16 MiB mountinfo bound, row 11); a third claim, that the shell's lambdas capture "the stack-allocated mounts vector", was also wrong (no lambda captures `mounts`; it is moved into `env.network_mounts` on POSIX and stays a local on Windows, row 14). The EPERM row of the latch (row 13) also changed after the first ledger was written.

## What the change changed about lifetime

- **Removed:** the per-file `sha256sum`/`shasum` child and its pipe/reaper path for `find_by_hash` (`file_hash` and `compute_hash_unix` still use a subprocess and are unchanged).
- **Added:** no thread, no timer, no subprocess, no callback context that outlives its call, no temp path in production code, no manual cleanup (every row above is RAII or a value), no new `static` besides the constant-initialised latch in row 13.
- **New reach:** the walk runs on the agent's command pool thread; the deadline, cancel and byte cap are polled between system calls, so a single blocked `open`, `read` or directory listing is not interrupted (see "Known residuals").

## Known residuals (disclosed, not resource defects)

These are limits of the no-follow and bounding design, stated in `agents/plugins/filesystem/README.md` (caveat 5 at line 703 and the paragraph at line 21), the YAML description and the changelog fragment.

- **Leaf-only no-follow on Windows and on Linux before 5.6 or where seccomp denies `openat2`** (#6348): an ancestor directory swapped for a link between enumeration and open is not refused there.
- **`access()` follows symlinks in `can_enter_posix`** (HPP:620): a component swapped to a symlink between classification and the probe is a plan-sanctioned residual of the same class (adversarial-review r1; dropping `access()` would change the accepted set, so it stays).
- **Blocked syscalls are uninterruptible** (#4875): the deadline, cancel and byte cap are polled between calls, so a single blocked read or listing, a stacked or bare-FUSE mount that the deny-list does not name, or a mount made mid-walk can overrun the 20 s bound; the agent has no per-command execution timeout.
- **A directory whose permissions change between `can_enter_posix`'s own open and the iterator's open is skipped without being counted** (UP-3, derived HIGH; rejected by the Architect and accepted by Alex on 2026-10-23): with `skip_permission_denied` the iterator gives no signal for a swallowed `EACCES`, and the only closure is an explicit directory stack (a rewrite of the walk core). A follow-up issue is to be filed.
- **Iterator descent on macOS is not no-follow:** `recursive_directory_iterator` has no no-follow option and `O_NOFOLLOW_ANY` covers only the file-hash open (adversarial-review r2, Kimi, accepted residual). **README caveat 5 does not yet name this** (the clause is owed).
