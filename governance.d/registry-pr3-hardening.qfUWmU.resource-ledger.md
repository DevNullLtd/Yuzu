# Resource Ledger -- registry 2.0.1 hardening (fail-closed kernel name, bounded get_value, shared line-break fold)

Range described: `0fdece08e..8567d7c72` (branch `feat/registry-pr3-hardening`). This is a DELTA ledger over `governance.d/registry-pr3-typed-writes.Xt7Qpa.resource-ledger.md` (the base fragment). It restates only the rows this change adds or modifies. **Rows 1-4, 9 and 10 of the base fragment are unchanged** (row 9 checked: the diff adds no `LocalFreeGuard` and no `ConvertStringSecurityDescriptorToSecurityDescriptorW` call), and so is the base fragment's Table 2 except for the two rows added below.

## Summary

The change adds no new kind of resource. It adds one early return to the get_value read (through the existing `RegKey` owner), one early return to `query_key_name` (before `out` is set), a 1 MiB bound on a buffer that was unbounded, an in-place string fold, and pure helpers moved out of the Windows shell. On the test side it adds one handle-based link sweeper in the dispatcher TU, one lone-surrogate case in the internals TU, and per-handle access masks in the fake registry. No fd, SOCKET, `FILE*`, SQLite, OpenSSL, BCrypt, thread, callback or subprocess is added in C++.
