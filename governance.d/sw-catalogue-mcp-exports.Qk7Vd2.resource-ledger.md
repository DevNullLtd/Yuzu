## Resource Ledger (C++)
- No new pooled connection lease, transaction, `PgResult`, file descriptor, socket, `FILE*`, sqlite handle, OpenSSL object, mapped library, temp-file path, thread, lock, subprocess or shell string in production code. The new store reads (`query_software` on the raw route with `agent_ids`/`after`/`version` fields, `catalog_rollup_meta()` on the MCP versions arm) reuse the existing store methods, each of which acquires and releases its own `PgPool::Lease` inside the store (`try_acquire_for(kQueryAcquireTimeout)`, released by the `Lease` destructor); no handler holds a lease across a call.
- Model borrowed pointers and views (`software_catalogue_model.cpp`): `first_param` (`:52`, the raw route's keep-the-first-value rule) returns a `const std::string*` into the caller's `Params` multimap (REST: `req.params`; MCP: the owning multimap `catalogue_params` returns, alive for the whole handler call) and is dereferenced only inside the `get` lambda of `parse_devices_params` and its `version` branch, which copy into owning `std::string`s (`:311-349`); `r.query.version` is an owning `std::optional<std::string>` copy, and the `version` pointer handed to `text_error` points at that member or at a function-local empty string and is used only inside that call. (`find_param`, `:38`, with its repeated-key `err` out-parameter, serves the catalogue and versions parsers, not this one.) `decode_devices_cursor` (`:504-528`): `split()` returns `string_view`s into `token`, the decoded payload is an owning `std::optional<std::string>` local, and `read_length_prefixed` returns `string_view`s into that local, consumed only inside the function; the returned `DevicesCursor` is built from owning `std::string` copies. `strict_args_error` (`:351`) borrows `args[...]` through `get_ref<const std::string&>` for the length check only and returns an owning `std::string` or `nullopt`. `devices_fingerprint` (`:452`) builds an array of `const std::string*` into the const query plus one function-local `static const std::string kNoVersion` (empty and immutable, with thread-safe initialisation; it is destroyed at process exit, after every reader has returned).
- Scope push-down (`read_devices_page`, `software_catalogue_model.cpp`): copies the caller's `authz::VisibleSet` (`std::optional<std::unordered_set<std::string>>`) into `q.agent_ids` (`std::optional<std::vector<std::string>>`) with `emplace(begin, end)`, so the query owns its ids and nothing aliases the gate's set; the over-bound arm leaves `agent_ids` untouched and post-filters with `authz::in_scope` over function locals, in a loop of at most `kWideScopeMaxReads` (4) store reads per call; each read returns an owning vector and releases its own pool lease inside the store, the only state carried between reads is the owning `last_scanned` key copy, the distinct-device set and the page's rows, and the cursor it mints holds only the last served row's key and a count.
- `catalogue_reads` / `versions_reads` / `devices_reader` (`software_catalogue_model.{hpp,cpp}`; one call per site in `rest_api_v1.cpp` and `mcp_server.cpp`): each returns a struct of `std::function` closures that capture the `SoftwareInventoryStore&` by reference (`[&store]`) and, for `catalogue_reads`, the `const DeviceApi*` by value (`[device_api]`, bound only when non-null, so the registry count stays empty otherwise; `stale` is always bound). Both objects are owned by `ServerImpl` (the store as a raw pointer; the registry as a `std::shared_ptr<const DeviceApi>` of which the handler closure holds a copy) and outlive the handler frame that consumes the returned struct synchronously: `read_catalogue_page`, `read_titles_export`, `read_versions` and `read_devices_page` take it by const reference and finish before the handler returns; it is never stored, returned past the frame or moved into a thread. The earlier `CoverageReads` / `gather_coverage` pair no longer exists: coverage is read inside `read_catalogue_page` through `CatalogueReads::connected` / `stale`, once per returned page.
- Route closure for the raw route (`rest_api_v1.cpp:9287`): every capture is by value (`fleet_read_fn` and `audit_fn` as `std::function` copies, the raw `SoftwareInventoryStore*` parameter of `register_routes`, and the `sw_503` closure, itself holding only an `audit_fn` copy); no `this` capture and no `[&]` on a registered closure. The store pointer is owned by `ServerImpl::software_inventory_store_` (`unique_ptr`) and outlives the closure under the same stop-then-join contract recorded in the core ledger (`~ServerImpl` -> `stop()` joins the web server before the store is reset). The degraded arm now calls `sw_503` instead of building the 503 inline: same audit row (`failure`, detail `store degraded; cid=...`), same A4 body and `retry_after_ms: 5000`.
- MCP handler (`mcp_server.cpp:9041` and `:8937`): both run inside the existing `[=]` handler returned by `build_handler`, which captures `software_inventory_store` (raw pointer owned by `ServerImpl`, same lifetime contract) and `device_api` (shared_ptr copy) by value. The new locals `reply`, `confined_deny`, `degraded` and `building` are `[&]` lambdas over handler-frame objects (`res`, `id`, `mcp_audit`, the target string), called synchronously in the same frame and never stored; `const auto read` is the `std::expected` returned by `read_catalogue_page` and `const auto& page = *read` binds to that local; `catalogue_params` (`:266`) returns an owning `Params` multimap by value. The file-scope `static_assert` equating `kCursorMaxBytes` with `kMcpCursorMaxLen` is compile-time only.
- Exceptions: neither new handler installs an exception handler (as in core); an allocation-class throw from a reader lambda, `parse`, nlohmann or `std::format` would reach the transport's existing top-level handling; no lock and no lease is held across such a throw (the store methods release theirs by RAII), and every new audit call goes through the throw-safe kernel (`detail::try_persist_audit` on REST, `mcp_audit`, which wraps the same kernel, on MCP).
- Tests (harness only): the new PG cases declare the pool, then the store, then the harness (`InvHarness`/`McpTestServer`), so the route owner dies before the store and pool (the #1786 false-green order); the MCP never-built cases (`test_mcp_server.cpp`, the building cases) hold one `PgPool::Lease` in an inline block for a single `exec_params`, whose `PgResult` temporary is the RAII `PQclear` wrapper, and the lease is released at the end of that block; the starved-pool cases hold the pool's one lease (`held`, `pool.acquire()`) for the case scope, declared after the pool and store and before the harness, so it is released after the harness is destroyed and before the pool is; the cross-transport case's `RestTwin` fixture is in-process (the `TestRouteSink`, no socket), declares its sink AFTER the `RestApiV1` owner it registers (#1786) and its fleet scope before both, and both transports read through the one shared `SoftwareInventoryStore`; the cases use the shared pre-migrated `swinv` template clone and a function-scoped database, and create no thread, sleep, socket or file. Hand-minted cursor strings in the tests are plain `std::string` values.
- No new `new`/`delete`/`malloc`/`free`/`PQclear`/`PQfinish`, `reinterpret_cast`/`const_cast`, C-style cast over a lifetime, `popen`/`system`/`fork`/`exec`, `std::thread`/`async`/`detach` or `sleep` in production or test code; every dynamic value in the new SQL parameters is bound through the store's existing `$n` placeholders (the `agent_ids` push-down uses the store's existing `= ANY($n)` array binding).
