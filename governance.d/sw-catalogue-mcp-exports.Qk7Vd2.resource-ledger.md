## Resource Ledger (C++)
- No new pooled connection lease, transaction, `PgResult`, file descriptor, socket, `FILE*`, sqlite handle, OpenSSL object, mapped library, temp-file path, thread, lock, subprocess or shell string in production code. The new store reads (`query_software` on the raw route with `agent_ids`/`after`/`version` fields, `catalog_rollup_meta()` on the MCP versions arm) reuse the existing store methods, each of which acquires and releases its own `PgPool::Lease` inside the store (`try_acquire_for(kQueryAcquireTimeout)`, released by the `Lease` destructor); no handler holds a lease across a call.
- Model borrowed pointers and views (`software_catalogue_model.cpp`): `find_param(..., strict=false)` returns a `const std::string*` into the caller's `Params` multimap (REST: `req.params`; MCP: the owning multimap `catalogue_params` returns, alive for the whole handler call) and is dereferenced only inside the `get` lambda of `parse_devices_params`, which copies into an owning `std::string` (`:284-330`); `r.query.version` is an owning `std::optional<std::string>` copy. `decode_devices_cursor` (`:510-535`): `split()` returns `string_view`s into `token`, the decoded payload is an owning `std::optional<std::string>` local and `view` is a `string_view` of that local used only inside the function; the returned `SoftwareCursor` is built from owning `std::string` copies. `strict_args_error` (`:330`) borrows `args[...]` through `get_ref<const std::string&>` for the length check only and returns an owning `std::string` or `nullopt`. `devices_fingerprint` builds an array of `const std::string*` into the const query plus one function-local `static const std::string kNoVersion` (empty, immutable, thread-safe initialisation, trivially destructible).
- Scope push-down (`read_devices_page`, `software_catalogue_model.cpp`): copies the caller's `authz::VisibleSet` (`std::optional<std::unordered_set<std::string>>`) into `q.agent_ids` (`std::optional<std::vector<std::string>>`) with `emplace(begin, end)`, so the query owns its ids and nothing aliases the gate's set; the over-bound arm leaves `agent_ids` untouched and post-filters with `authz::in_scope` over function locals.
- `catalogue_reads` / `versions_reads` / `devices_reader` (`software_catalogue_model.{hpp,cpp}`; one call per site in `rest_api_v1.cpp` and `mcp_server.cpp`): each returns a struct of `std::function` closures that capture the `SoftwareInventoryStore&` by reference (`[&store]`) and, for `catalogue_reads`, the `const DeviceApi*` by value (`[device_api]`, bound only when non-null, so the registry count stays empty otherwise; `stale` is always bound). Both objects are owned by `ServerImpl` (the store as a raw pointer; the registry as a `std::shared_ptr<const DeviceApi>` of which the handler closure holds a copy) and outlive the handler frame that consumes the returned struct synchronously: `read_catalogue_page`, `read_titles_export`, `read_versions` and `read_devices_page` take it by const reference and finish before the handler returns; it is never stored, returned past the frame or moved into a thread. The earlier `CoverageReads` / `gather_coverage` pair no longer exists: coverage is read inside `read_catalogue_page` through `CatalogueReads::connected` / `stale`, once per returned page.
- Route closure for the raw route (`rest_api_v1.cpp:9315`): every capture is by value (`fleet_read_fn` and `audit_fn` as `std::function` copies, the raw `SoftwareInventoryStore*` parameter of `register_routes`, and the `sw_503` closure, itself holding only an `audit_fn` copy); no `this` capture and no `[&]` on a registered closure. The store pointer is owned by `ServerImpl::software_inventory_store_` (`unique_ptr`) and outlives the closure under the same stop-then-join contract recorded in the core ledger (`~ServerImpl` -> `stop()` joins the web server before the store is reset). The degraded arm now calls `sw_503` instead of building the 503 inline: same audit row (`failure`, detail `store degraded; cid=...`), same A4 body and `retry_after_ms: 5000`.
- MCP handler (`mcp_server.cpp:9071` and `:8937`): both run inside the existing `[=]` handler returned by `build_handler`, which captures `software_inventory_store` (raw pointer owned by `ServerImpl`, same lifetime contract) and `device_api` (shared_ptr copy) by value. The new locals `reply`, `confined_deny`, `degraded` and `building` are `[&]` lambdas over handler-frame objects (`res`, `id`, `mcp_audit`, the target string), called synchronously in the same frame and never stored; `const auto read` is the `std::expected` returned by `read_catalogue_page` and `const auto& page = *read` binds to that local; `catalogue_params` (`:266`) returns an owning `Params` multimap by value. The file-scope `static_assert` equating `kCursorMaxBytes` with `kMcpCursorMaxLen` is compile-time only.
- Exceptions: neither new handler installs an exception handler (as in core); an allocation-class throw from a reader lambda, `parse`, nlohmann or `std::format` would reach the transport's existing top-level handling; no lock and no lease is held across such a throw (the store methods release theirs by RAII), and every new audit call goes through the throw-safe kernel (`detail::try_persist_audit` on REST, `mcp_audit`, which wraps the same kernel, on MCP).
- Tests (harness only): the new PG cases declare the pool, then the store, then the harness (`InvHarness`/`McpTestServer`), so the route owner dies before the store and pool (the #1786 false-green order); the `reset_to_building` lambda in the MCP building case holds one `PgPool::Lease` for a single `exec_params`, whose `PgResult` temporary is the RAII `PQclear` wrapper, and the lease is released at lambda exit; the cases use the shared pre-migrated `swinv` template clone and a function-scoped database, and create no thread, sleep, socket or file. Hand-minted cursor strings in the tests are plain `std::string` values.
- No new `new`/`delete`/`malloc`/`free`/`PQclear`/`PQfinish`, `reinterpret_cast`/`const_cast`, C-style cast over a lifetime, `popen`/`system`/`fork`/`exec`, `std::thread`/`async`/`detach` or `sleep` in production or test code; every dynamic value in the new SQL parameters is bound through the store's existing `$n` placeholders (the `agent_ids` push-down uses the store's existing `= ANY($n)` array binding).
