# DEX fleet usage API Resource Ledger (governance Gate 1)

Production-code ledger for `GET /api/v1/dex/apps/usage`, kept here so the ownership analysis is retrievable with the change. C++ files: `server/core/src/dex_usage_json.{hpp,cpp}` (new serializer), `dex_api.{hpp,cpp}` and `dex_api_local.hpp` (the seam and its cache), `dex_app_usage_owner.{hpp,cpp}` (owner hardening), `dex_window.{hpp,cpp}` (shared cut), `dex_usage_model.hpp` (request instant and the freshness width), `rest_api_v1.cpp` (route and OpenAPI text) and `server.cpp` (wiring), plus tests under `tests/unit/server/`.

## Resource Ledger (C++)
- Owner lifetime: `DexAppUsageOwner` is a `std::unique_ptr` member of the server (`dex_app_usage_owner_`), created beside the Guaranteed State store from the same `pg::PgPool` and `metrics_` (both borrowed, never owned) and reset at shutdown before the store. The route and seam capture the raw owner pointer, `mgmt_group_store_`, `tag_store_` and `this`; the web threads are joined by `stop()` before any of these is destroyed, and the owner has no thread of its own.
- Lease and transaction: each `read()` takes one bounded lease with `PgPool::try_acquire_for(3 s)`, moves it into `PgPool::with_txn_on` (RAII lease and transaction guard) with nothing in between, runs the callback synchronously and stores nothing. A failed acquire returns `kPoolTimeout`; a failed statement or uncommitted transaction returns `kStatementTimeout` (SQLSTATE 57014) or `kQueryError`. `SET LOCAL statement_timeout` is transaction-scoped and cannot leak onto the pooled connection. No early return skips release.
- In-flight budget: an RAII `Slot` guard increments `in_flight_` (a `std::atomic<int>`) at entry and decrements in its destructor on every exit, including the refusal path; the budget is checked after the increment, so a refused caller briefly holds a slot until it returns and never exceeds the budget. The budget (4) is pinned at compile time to the Apps store's read budget by a `static_assert`.
- Sustained-timeout state: one `std::mutex run_mu_` guards a plain `int` count and an `int64` run start; every access is under a `std::lock_guard`, the lock is never held across the pool acquire, SQL, metrics or log work, and `unavailable_detail` snapshots both under the lock and computes outside it. `unavailable_detail` and `consecutive_timeouts()` are not `noexcept` because the lock can throw.
- Usage cache: one `std::mutex usage_cache_mu_` guards an `unordered_map<string, UsageCacheEntry>` (value-type models, at most 32 entries, 30 s lifetime, expired entries erased first, else cleared). Every access is under a `std::lock_guard` and the lock is not held across a read. The key is the hex SHA-256 of a length-prefixed string of the request shape, the policy revision and the sorted visible `(agent id, os)` pairs; an empty digest bypasses the cache. `usage_.cache_ttl` and `usage_.now_epoch` are test-only fields of `DexUsageWiring`; production wiring leaves the defaults (30 s, wall clock).
- Metrics and logs: the owner increments `yuzu_server_guardian_read_degrade_total{reason, source="dex_usage"}` on a borrowed `MetricsRegistry*` (null-checked); the four reason series are pre-seeded in `server.cpp`. The warn line is sampled by a value-member `RefusalLogThrottle` and names no subject, agent or tag.
- Result handles: both owner statements return `pg::PgResult` (RAII `PGresult`); values are copied through `strtoll` while the result is alive, and no row keeps a pointer into libpq memory. The pure serializer and model are value types only; the JSON is built in a local `nlohmann::json` and returned as an owning `std::string`, with `error_handler_t::replace` so invalid UTF-8 in a label never throws.
- Borrowed data and casts: the route reads request parameters into owning strings, validates the group id over the owned text with the shared `mgmt_group_id_ok` predicate before the audit row and any read (a NUL, control byte or invalid UTF-8 is a 400, never bound to a statement), parses `floor` with `std::from_chars` over the owned text, and passes a `const DexUsageQuery&` that the owner copies from before returning. No `reinterpret_cast`, `const_cast`, raw `new`/`delete`, manual cleanup, fd, handle, socket, `FILE*`, sqlite object, OpenSSL object, subprocess, shell string, temp path or thread is added.
- Tests (harness only): the pure and seam suites use fixed instants and injected clocks (`now_epoch`, `cache_ttl`, the `unavailable_detail` time argument) with no sleeps; the `[pg]` owner and seam suites use a database cloned from a pre-migrated template and lock rows from a second connection to produce a real statement timeout, with one 500 ms bound on the timeout case.
- Governance fix round 1 (no new ownership): the freshness cut is an `int64` width (`DexUsageQuery::fresh_secs`) bound as `$10` and applied to the database's `now()` inside the one statement, so no replica-clock instant reaches the freshness comparison and the transaction, lease and slot ownership above are unchanged. The `group_members` closure now calls `get_members_checked` before `get_group_checked`: two sequential store reads, each taking and releasing its own bounded lease, neither held across the other, so no lock, lease or thread is added and a group deleted between them is `unknown_group` (a 400, never cached). The group-id check adds no allocation beyond the existing owned string. The risk-register lines that these three changes made stale (replica-clock freshness, the group read race, the unvalidated group id) are closed by them and by the tests that pin them: the `[pg]` owner case under skewed instants, the lexical read-order pin and the route 400 cases with zero audit rows.
