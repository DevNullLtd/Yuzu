## Resource Ledger (C++)
- **No new store, thread, lock, socket, file, subprocess, timer or held-open response.** Every added call runs inside the request that makes it and returns before the response is written.
- **One extra roster read and one totals read per lookup call, as REST.** An MCP lookup does what the REST route does: one scoped page read, one `source_last_seen_bulk` read, one device-roster read (`hostnames`, called once per page by `load_device_facts`), one live distinct-version read when a range is asked, and one totals read when the decision serves totals. Each is the existing store call over a pooled lease taken and released inside it (`PgPool::Lease` RAII, bounded by the store's own 3 s acquire and 5 s statement bounds). No lease is held across two reads or across an audit write.
- **`LookupReads` (`bind_lookup_reads`).** A value type of `std::function` closures built per call (REST: inside each route handler, after the null-store check) or once and kept (MCP: `std::optional<LookupReads>` member of `McpServer`, set before `build_handler`). Every closure captures `SoftwareInventoryStore&` by reference and the hostnames function by value. The store is `ServerImpl::software_inventory_store_` (`unique_ptr`) and outlives every closure under the same stop-then-join contract as `software_read_ctx_`, which already holds the same store pointer. The REST closures live for one request; the MCP copy is destroyed with the `McpServer`.
- **`lookup_installs` / `lookup_components`.** Take the request by value (the resolved version set is written into the copy), the reads by const reference and the scope by const reference; return `std::expected<LookupData, LookupError>` by value (rows, facts maps and strings owned by the result). No pointer or view outlives the call; `TotalsDecision::omitted` is a view of a static string constant.
- **`sync_status` (`software_sync_status.hpp`).** Pure: takes the already-read tracker row by const reference and returns an owned `nlohmann::json`. The two closures (`StatusReadFn`, `UnfilteredFn`) are `server.cpp` locals hoisted from lambdas that already existed (they capture `this`); one copy goes into `HardwareRoutes::Deps` and one into `McpServer`, both destroyed by `stop()` ahead of the tracker.
- **MCP handlers.** The two new branches and the widened one write one response and return; locals (`parsed`, `lookup`, `body`, the `JObj`) are frame-owned. `static constexpr ArgSpec` tables are constant storage. No exception handler is added: a throw from a reader, `nlohmann` or `std::format` reaches the existing top-level handler of the MCP dispatcher, with no lock or lease held across it.
- **Audit.** Every audit write goes through `detail::try_persist_audit` (throw-safe). The whole-fleet sync row of an MCP launch is written through `Audit::persist_fleet_wide`, which the handler binds to a lambda capturing the request and `audit_fn` by reference for the duration of `Runner::run` only.
- **Tests.** The model and sync-status cases use in-memory fakes (no process, file, clock or network); `FakeLookup` is not copied after `reads()` is taken because its closures hold `this`. The MCP cases use the existing in-process `McpTestServer` fixture.
