- Floor adjudication, recorded for the ledger: the new `fs::remove(side_dest)` is a single `error_code` compensating filesystem call on a name this call created, guarded by the free-name check, `copy_ran`, the `file_exists` exclusion and a no-follow regular-file check. Both the security and the cpp-safety review of this run ruled it not a manual-cleanup policy floor independently; recorded as adjudicated by the governance-agent reviewers, not by the change author.
- By-name residual (accepted, in the banner): the free-name check, the copy and the removal are by name with no identity check between them. A writer of the agent's data directory who puts a link, an empty directory or a file at the name inside that gap can have the copy write through a non-exclusive library copy, or have the removal act on what is there by name. It needs write access to the data directory. The banner also records the source side of the copy, which this change does not alter: the sidecar is checked regular without following a link and `copy_file` then follows a link at its source, so a link swapped in at the sidecar's live name inside that gap is copied through by name (same class, same write access).
