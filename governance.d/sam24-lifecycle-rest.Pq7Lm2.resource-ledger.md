## Decision lines

- **Access-control table (routed concern: security-guardian).** Three routes under `/api/v1/inventory/software/lifecycle/rules`: POST and DELETE behind global `Inventory:Write`, GET behind global `Inventory:Read`, checked ahead of the body, format and name. Rules are fleet-global reference data, so no per-agent scope applies; a management-group-confined caller is refused.
- **Audit-first, fail closed.** A `requested` row is stored ahead of every write (an unstorable row is a `503` with `Sec-Audit-Failed` and nothing written), then a `success` or `failure` outcome row. A refused request writes a `denied` row.
- **Body cap.** One new row in `kBodyCapTable` (`software_lifecycle_rules`, 4 MiB, JSON value scan off because a csv body is not JSON); the CLE parser applies its own depth and value budgets.
- **MFA step-up.** POST and DELETE are `kExempt` with reason `kLifecycleRules`; whether they need a fresh MFA proof awaits an owner ruling (tracked as a follow-up decision issue).
- **No MCP twin.** Recorded as an ADR-1005 exception-ledger entry (roadmap row SAM.7, revisit by 2026-12-31).
