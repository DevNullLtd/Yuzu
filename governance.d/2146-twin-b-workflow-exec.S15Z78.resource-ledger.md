## Addendum (covers the whole branch's new C++ beyond the Gate 1 line)

- PgPool leases (all RAII, move-only `PgPool::Lease`, released on every exit and throw; no manual cleanup): (a) the claim transaction acquires its lease up front with `try_acquire_for` and passes it BY VALUE into `with_txn_on`, which owns it for the transaction, with a SECOND lease in `claim_txn_outcome` for `pg_xact_status` after an ambiguous commit; (b) `acquire_within` (workflow_wait.hpp) back-off loop plus `kFinalizeStopBudget` (3 s) on the finalize path: a stop is consulted between tries only, an in-flight `try_acquire` (which can run to the pool's connect timeout) is not interruptible; (c) `WorkflowEngine::execution_table_estimate`: one lease via `pool_.with_txn_for(250 ms, fn)` (acquire and hand-off in one expression, PgTxn rolls back before the lease returns), `SET LOCAL statement_timeout = '250ms'` (transaction-scoped, the pooled connection is returned clean), a PgResult per statement, may wait on AccessShare of the run table bounded by that timeout.
- `WorkflowEngine::refresh_table_size_metrics() noexcept`: runs on the EXISTING `health_recompute_thread_` (joinable std::thread, joined in stop() before `pg_pool_.reset()`; no new thread, nothing detached); borrows the raw `yuzu::MetricsRegistry*` set once at startup (server.cpp:7773) before that thread exists; owns a `mutable RefusalLogThrottle sample_warn_throttle_` member (own std::mutex, leaf lock, max 1024 keys, 300 s interval; non-copyable, which WorkflowEngine already is); the catch arms bump `kWorkflowExecutionsStatsUnavailableMetric` inside `note_failure`'s own try/catch(...). Exception to record: none.
- `WorkflowEngine::claim_hooks_` (`ClaimTxnTestHooks`, std::function members): test-only seam, written without a lock (set-before-traffic), read on request threads in `execute()`; one hook receives a `PGconn*` valid only for the call. Not synchronised; INFO (g8-cpp-safety-4), no production writer.
- `WorkflowRunControl` closures (std::function), valid only for the synchronous `engine.execute` call on the handler thread: `stored_copy_first` (captures `&req` in drive_run and `&caller` in the legacy handler), `reauthorize`, `before_attempt`, `should_stop`, `on_admitted`, `on_interrupted`; none is stored by the engine beyond the call. Server-lifetime ports: McpServer setters `set_workflow_run_fn`, `set_workflow_digest_fn`, `set_workflow_reauthorize_retry_delay`, `set_draining_fn`.
- `stored_agent_ids_json` (workflow_model.cpp): no handle; transient heap only: `std::unordered_set<std::string_view>` (`seen`, reserve = input size, scoped and freed before the digest), `std::vector<const std::string*>` for distinct and kept (pointers into the caller's const vector, valid for the call), json DOM copies for the dump and the digest (the full distinct list is dumped once for the digest on the truncated path), `id_json_text` temporaries; all bounded by the request body cap (16 MiB legacy route, the dedupe set and the distinct list cost about 154 MiB at the cap, and the digest's JSON copy of the list, which already existed, coexists with the list, so the helper peaks at about 250 MiB (measured, release build, glibc: 247 MiB above the input list at 2,510,443 distinct ids; the handler's own parse before the helper peaks at about 290 MiB for that list); 10,000 ids on v1 and MCP). `sha256_hex` = stateless one-shot `EVP_Digest` over a temporary std::string, null digest on provider failure, no context object. Returned std::string owns its data; no view escapes.
- `admit_workflow_run` takes the `StreamBudget::Lease` (RAII local `acquired.lease`, MCP carries `std::optional<Lease>`) and then re-reads `draining()`; the refusal path releases the lease by destructor.
- Engine `InFlightRun` RAII guard around the `std::atomic<int> in_flight_` counter (inc after the open and dispatch_fn checks, dec after the final write, including rethrow); `interruptible_wait` (no thread).
- `WorkflowEngine::set_should_stop([this] {...})` (server.cpp, the engine-level default stop level): a STORED `std::function` (`WorkflowEngine::should_stop_`) capturing the `ServerImpl` `this`; it reads the atomics `stop_requested_` and `draining_` only. Valid because `workflow_engine_` is a `ServerImpl` member destroyed after the web server is joined; invoked from request threads only during a run.
- `WorkflowExecutePorts` (mcp_server.cpp `make_workflow_ports`): per-call `[&]` closures over the MCP request, session and audit state, valid only for the synchronous `execute_workflow` handler call and never stored beyond it. `wf_deps.revalidate` and `wf_deps.draining` (server.cpp, `[this]`): server-lifetime closures stored in the REST route deps.
- Tests only: `std::jthread releaser` + `std::shared_ptr<PgPool::Lease>` + `ReleaseOnExit` (finalize stop-cap case; releaser declared so unwind sets the flag and joins first); a second PG connection `PgConn holder` holding `LOCK TABLE ...
