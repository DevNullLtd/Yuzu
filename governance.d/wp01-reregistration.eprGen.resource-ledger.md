## Resource Ledger (C++)

- **PGconn leases.** `PgPool::Lease` is move-only RAII. `CaStore::revoke_older_agent_leaves` acquires one lease with `try_acquire_for(kWriteTimeout)` and moves it into `PgPool::with_txn_on` (a `false` return is "the held connection's transaction failed or rolled back", never "no connection"). `CaStore::agent_leaf_state`, `live_agent_serials` and `db_now` hold a lease for one statement and release it on return. `PgResult` is RAII in every path. `AuthDB::consume_and_enroll` (existing) gains only the `require_single_use` bind parameter inside its existing transaction: no new lease. No lease is held across a callback or a handler boundary.
- **Advisory lock.** `revoke_older_agent_leaves` takes `pg_advisory_xact_lock(hashtextextended('ca_agent_leaf:' || agent_id, 0))` as the FIRST statement of its transaction (ADR-0012): transaction-scoped, released by commit or rollback, never held past the call, never taken while another store's lock is held. Its UPDATE sets `status='revoked'` only; the `ca_issued_keep_revoked` trigger still forbids un-revoking or deleting. No lock surrounds certificate issuance (a recorded residual, #8254).
- **Process-static state (all function-local statics, header-only, `inline`).**
  - `detail::reregistration_unproven_budget()` (apply.hpp, function-local static) -> `UnprovenAuditBudget` (now defined in `reregistration_audit_budget.hpp`), two mutexes: `mu_` (window state) and `pending_mu_` (the pending queue); never held together, no callback runs under either. Per-window structures, all cleared when the window closes: `seen_` (<= `kMaxTrackedIds` 4096 ids), `source_rows_` plus `dropped_by_source_` (together <= `kMaxSources` 1024 distinct sources, the rest share the `other` bucket; the 45-byte cut of a source key applies only to `dropped_by_source_`, `source_rows_` keys are whole), `dropped_ids_` (a `set`) and `dropped_order_` (a `vector`), each <= `kMaxDroppedIds` 20000 ids (the excess is only counted in `dropped_ids_overflow_`), counters. Cross-window structures: `recent_` plus `recent_order_` (<= `kRecentIds` 8192 DISTINCT ids, FIFO eviction; `remember_locked` pushes the order entry first and undoes it if the set insert throws). The class-static `kOther` (`static inline const std::string`, not function-local, constructed once at program start) is the shared source bucket's key. Pending queue: a `deque<PendingRow>` of at most `kMaxPendingRows` 128 rows on enqueue (a full queue drops the NEW chunk, counted in `queue_full_dropped_`, its ids in `ids_truncated_`); a failed or timed-out row handed back by `requeue_front` / `requeue_front_unconditional` goes to the FRONT, so the deque can briefly hold 128 + 1 (one row is out with the flusher at a time); each row is one chunk of at most `kSummaryIds` 200 ids (about 5 KB, and carries its id count), so the queue is bounded at about 650 KB; a row is retried at most `kMaxWriteAttempts` 3 times, then dropped (reason `write_failed`, ids counted). Three `std::atomic<uint64_t>` carry counts to the flush (`ids_truncated_`, `queue_full_dropped_`, `alloc_failed_`). Worst case window state: about 20000 ids twice (set + vector) at up to `kMaxAgentIdLength` bytes each plus node overhead, plus the maps: about 20-22 MB per replica at the cap including `recent_`, freed at the window close (the closed window is moved out and its chunks built from it outside `mu_`).
  - Chunk building (`build_rows`) runs OUTSIDE `mu_` on a `ClosedWindow` moved out of it (`dropped_order_`, `dropped_by_source_` are moved, not copied).
  - `detail::reregistration_audit_budget()` and `detail::reregistration_log_budget()` -> two `DenialAuditBudget` (existing type: refusal rows; log lines), bounded by their own caps.
  - `detail::reregistration_audit_clock_skew_ms()`: a `std::atomic<int64_t>`, written only by unit tests, zero in production.
- **Callbacks and borrows.** `AgentIdentityHooks` (`std::shared_ptr<const ...>`) is set on both services before the gRPC servers start and cleared in `stop()`; its lambdas capture `this` (`ServerImpl`) and run on gRPC threads, safe under the same shutdown-before-destruct contract as the CSR signer (`stop()` drains the agent server before members are destroyed). The audit sink returned by `make_reregistration_audit_sink` captures by value (path, ids, source, store pointer) and is invoked synchronously; the store pointer outlives the call. `AgentServiceImpl::cert_proof_override_for_test_` (`std::function<bool(const std::string&)>`, `agent_service_impl.hpp`) is a stored callback with a test-only setter `override_cert_proof_for_test`: set before any `Register`, read on gRPC threads with no synchronisation, so it is safe only when set before the server starts serving (as the tests do); it is empty in production and pinned by `tests/test_reregistration_gate_wiring_lexical.py` check 6. `flush_reregistration_audit_summary` receives `audit_store_.get()` and `&metrics_`, uses them only for the duration of the call, and its sink's `on_write_failure` lambda captures a local `bool` by reference that does not outlive the call.
- **Allocation failure.** `UnprovenAuditBudget::admit` contains any exception (a throw inside the lock costs only that row: not admitted, so the caller counts it dropped); `enqueue_closed` is `noexcept` and, if building or queueing the chunks throws, counts the window (`alloc_failed_`, and every id not already queued or counted in `ids_truncated_`). Every allocation point of the covered paths (accumulation incl. the over-cap id, window close, enqueue, requeue_front, requeue_front_unconditional, take_pending, the flush success/failure/forced paths) is swept by `tests/unit/server/test_reregistration_audit_budget_alloc.cpp`; the sweep covers those paths, not every line. That executable replaces the global `operator new` and `operator new[]` (a `thread_local long g_countdown` armed around the code under test; the replacement allocates with `std::malloc` and relies on the default `operator delete` being `free`, which holds for libstdc++), so it is its own binary: Linux only, absent under a sanitizer. `drop_locked` performs every fallible allocation before a counter moves and undoes a partial insert; `admit()`'s catch counts the one id (`note_unrecorded`); `requeue_front` and `requeue_front_unconditional` are `noexcept` and count the chunk's ids and `alloc_failed` if they cannot allocate; `restore_counts` gives counts back when a metric publish throws. The budget class lives in `reregistration_audit_budget.hpp` (standard library only).
- **Threads.** None added. The summary flush is the new background pass `reregistration_audit.flush_summary` (`ReplicaSafe`, `background_jobs.hpp`), run by a NEW dedicated thread, `reregistration_flush_thread_` (own 5 s timer in 500 ms sleeps, `kReregistrationFlushIntervalMs`), so a slow audit store cannot delay the revocation sweep on `health_recompute_thread_`; per-iteration `try`/`catch`, a round stops starting writes after `kReregistrationFlushDeadlineMs` = 2000 ms (checked between rows only: one `AuditStore::log` can overrun it by its 4 s write timeout), skipped for one round after a failed round (a lambda-local `bool skip_next_round` of that thread), never leader-gated. The thread is joined in `stop()` next to `health_recompute_thread_` and BEFORE the forced flush and the store teardown; worst-case stop about 73 s against the shipped 210 s grace. Exactly one thread runs it; the member `std::thread` is the only new owner. The shutdown flush runs in `stop()` after the flush thread is joined, while `audit_store_` is alive, inside a `try`/`catch(...)`. Register and ProxyRegister threads never write a summary row.
- **Errors and exceptions.** `attested_leaf_proves` and `supersede_older_leaves` are called inside `try`/`catch(...)`: a throw from the witness callback is "no proof"; a throw from supersede is logged and counted (`yuzu_server_ca_supersede_failed_total`), and writes NO audit row. The signer call keeps its existing `try`/`catch`; a throw there is now also counted (`yuzu_register_reenrol_token_no_leaf_total{reason="signer_threw"}`) when a single-use token was consumed. `emit` swallows a throwing audit sink. The flush catches a throwing sink and treats it as a failed write.
- **Metrics (process-lifetime counters, labels from closed sets, all seeded at boot).** `yuzu_register_reregistration_total{path,outcome,mode}`, `..._audit_dropped_total{action}`, `..._audit_write_failures_total{reason}`, `..._audit_ids_truncated_total`, `..._audit_summary_dropped_total{reason=queue_full|write_failed|shutdown|alloc_failed}`, `yuzu_register_reenrol_token_refused_total{reason}`, `yuzu_register_reenrol_token_no_leaf_total{reason=no_csr|no_signer|signer_failed|signer_threw}`, `yuzu_server_ca_superseded_leaf_total`, `yuzu_server_ca_supersede_failed_total`, gauge `yuzu_server_agent_reregistration_proof_mode{mode}`.
- **Audit rows.** The aggregate chunk rows are written under the system principal `system:reregistration-audit` through `AuditStore::log` (a pooled synchronous write on the health thread, bounded by the 1 s deadline between rows). An enrolment audit row for a token re-enrolment on a wired but closed audit store now sets `enroll_audit_ok = false` (the `x-yuzu-audit-failed` trailer) in both handlers.
- **No** new fd, HANDLE, SOCKET, `FILE*`, sqlite object, OpenSSL object, allocated C string, mapped library, temp-file path, subprocess or shell string is acquired in production code. `agent_witnessed_leaf.hpp` calls the existing `pki::parse_certificate` and `pki::verify_chain` (RAII inside `x509_ca.cpp`). The `no_leaf_reason` local in both handlers is a `std::string_view` over `static constexpr` literals.
- **Tests (harness only).** `test_agent_register_mtls_proof.cpp` owns a `grpc::Server` (`unique_ptr`) on an ephemeral loopback port, Shutdown in `~Harness`; the PG-gated cases use template clones and the shared AuthDB fixture; the two-thread `revoke_older_agent_leaves` test joins both threads before reading results. The budget tests use a local `UnprovenAuditBudget` (no shared state) except the PG flush tests, which drain the process-wide budget's pending queue before and after; `simulate_flood` (gate test) drives the store-free flush core with a simulated clock. The alloc executable's `Ctx`/`Scenario` objects are heap-owned per allocation point and freed before the next.
