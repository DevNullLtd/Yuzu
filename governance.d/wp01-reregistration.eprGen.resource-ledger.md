# WP01 agent re-registration proof Resource Ledger (governance Gate 1)

Production-code ledger for `fix/wp01-reregistration`, kept here so the ownership analysis is retrievable with the change. Files: `server/core/src/agent_reregistration_gate.hpp`, `agent_reregistration_apply.hpp`, `agent_witnessed_leaf.hpp`, `agent_service_impl.{hpp,cpp}`, `gateway_service_impl.{hpp,cpp}`, `ca_store.{hpp,cpp}`, `auth_db.cpp`, `auth.cpp`, `server.cpp` (wiring, supersede, tick and shutdown flush), `main.cpp`.

## Resource Ledger (C++)
- **PGconn leases.** `PgPool::Lease` is move-only RAII. `CaStore::revoke_older_agent_leaves` moves its lease into `PgPool::with_txn_on` (acquired immediately before: a `false` return is "the held connection's transaction failed or rolled back", never "no connection"); `is_reenrolled_revoked`, `db_now`, `agent_leaf_state`, `live_agent_serials` and `AuthDB::refund_token_use` hold a lease for one statement and release it on return. `PgResult` is RAII in every path. No lease is held across a callback or a handler boundary.
- **Advisory lock.** `revoke_older_agent_leaves` takes `pg_advisory_xact_lock(hashtextextended('ca_agent_leaf:' || agent_id, 0))` as the FIRST statement of its transaction (ADR-0012): transaction-scoped, released by commit or rollback, never held past the call, never taken while another store's lock is held. Its UPDATE sets `status='revoked'` only (the `ca_issued_keep_revoked` trigger still forbids un-revoking or deleting).
- **Process-static state.** `UnprovenAuditBudget` (one function-local static, mutex-guarded; window state, per-source and per-id maps, recent-id set and deque, all bounded: at most 4096 tracked ids and sources per window, 8192 recent ids, summary capped at 200 ids and 10 sources), `DenialAuditBudget` x2 (refusal rows; log lines), and `reregistration_audit_clock_skew_ms` (a `std::atomic<int64_t>`, written only by unit tests, zero in production). Memory is bounded; there is no per-request allocation that outlives the call.
- **Callbacks and borrows.** `AgentIdentityHooks` (`std::shared_ptr<const ...>`) is set on both services before the gRPC servers start and cleared in `stop()`; its lambdas capture `this` (`ServerImpl`) and run on gRPC threads, safe under the same shutdown-before-destruct contract as the CSR signer (stop() drains the agent server before members are destroyed). `superseded_checker_` is nulled in `stop()` before `ca_store_` is reset. The audit sink returned by `make_reregistration_audit_sink` captures by value (path, ids, source, store pointer) and is invoked synchronously inside the handler; the store pointer outlives the call (the service is stopped before the store). The periodic tick and the shutdown flush call `flush_reregistration_audit_summary(audit_store_.get(), ...)`: the tick runs on the existing health-loop thread (no new thread), the shutdown flush runs in `stop()` while `audit_store_` is still alive.
- **Threads.** None added. The flush rides the existing health tick.
- **Errors.** `attested_leaf_proves` and `supersede_older_leaves` are called inside `try`/`catch(...)`: a throw from the witness callback is "no proof"; a throw from supersede is logged and counted (`yuzu_server_ca_supersede_failed_total`). The refund path (`refund_enrollment_token_use`) returns `expected`, counted.
- **No** new fd, HANDLE, SOCKET, `FILE*`, sqlite object, OpenSSL object, allocated C string, mapped library, temp-file path, subprocess or shell string is acquired in production code. `agent_witnessed_leaf.hpp` calls the existing `pki::parse_certificate` and `pki::verify_chain` (RAII inside `x509_ca.cpp`).
- **Tests (harness only).** `test_agent_register_mtls_proof.cpp` owns a `grpc::Server` (`unique_ptr`) on an ephemeral loopback port, Shutdown in `~Harness`; the PG-gated cases use template clones and the shared AuthDB fixture; the two-thread `revoke_older_agent_leaves` test joins both threads before reading results.
