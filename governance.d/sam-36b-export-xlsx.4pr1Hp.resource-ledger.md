# Resource Ledger: sam-36b-export-xlsx

Every owning boundary the C++ in `8221cf120..HEAD` (feat/sam-36b-export-xlsx) acquires: the XLSX writer (`software_export_xlsx.{hpp,cpp}`), the XLSX arm of `software_export_routes.cpp` (`serve_xlsx`, `build_xlsx`, `XlsxFile`, the directory preparation), the `Deps` fields and the wiring in `server.cpp`. The change adds one temporary file per XLSX export on the data volume, one disk budget, one process-wide mutex and one in-process library, and holds the HTTP worker, the stream lease and the file from admission to the last byte or the deadline.

## Bounds, stated once

- **Memory.** Constant per export: one row plus one slice. Not proportional to the result.
- **Temporary disk.** At most `kXlsxPeakDiskFactor` (3) x the export's accounted sheet bytes, and the sheet bytes are never past `--inventory-export-max-bytes` (1 GiB default): 3 GiB per export, 6 GiB at `--inventory-export-concurrency` 2. Enforced by accounting (no row is written past the limit, for any cell content) and by measurement (no grant when it could leave the volume under 1 GiB free). The library's intermediates may have no name, so a directory listing cannot measure them: accounted bytes and free space are the measures. The residual that is NOT bounded by this ledger: if a create inside an existing `export-tmp` fails (descriptor limit, permissions), the library tries `$TMPDIR`, `/tmp` and the working directory next (`tmpfileplus.c:282-293`) and the file lands on another volume; `open()` refuses a directory that does not exist, which closes the common case.
- **Time.** One 900 s deadline from admission covers the build and the delivery. The build checks it once per page of 1,000 rows (`read_step`), the delivery on every provider call, and a close in progress cannot be interrupted (seconds for a large sheet).
- **Worker.** One HTTP worker, one stream lease and the disk grant are held from admission to the last byte or the deadline, whichever is first; a client that disconnects during the build is not noticed until the build ends or hits a bound.
- **Sheet accounting.** `sheet_bytes()` is an upper bound: 88 bytes per non-empty cell, 64 per row, 64 KiB once, plus the text as the library escapes it. Measured 1.68 x the real sheet for a typical row shape (200,000 rows x 23 columns, a third of the cells empty), and pinned as an upper bound for adversarial rows by `test_software_export_xlsx.cpp` (ampersand, `<`, `>` and carriage-return cells, a 32,767-byte cell, leading and trailing white space, empty cells).

## Decision lines

- **No new flag.** `--inventory-export-max-rows` and `--inventory-export-max-bytes` still lower the XLSX limits; the sheet's own 1,048,575 data rows is a constant of the format. A lower XLSX-only limit, a different reserve or a separate flag are one-constant changes if wanted.
- **Cells are text.** Every cell is written through the library's string-cell call, never a formula, number or date, so no neutralising prefix is added (the CSV adds an apostrophe).
- **Failure is a status, not a cut transfer.** Everything before the first byte is a normal HTTP error; only a deadline or a shutdown during delivery stops short of the `Content-Length`.
- **Access-control table (routed concern: security-guardian).** No new route, permission or gate: the XLSX arm runs after the same `fleet_read_fn(req, res, "Inventory", "Read")` gate, scope, lease and version-range step as JSONL and CSV, and every page comes from the same scoped page reader, so a confined caller's workbook holds only in-scope rows. The resume anchor never leaves the process (`read_step` is the one page walker). The audit row is written once, after the build, with `stream=false`.
- **Third-party.** libxlsxwriter 1.2.4 (BSD-2-Clause; vendored files inside it: queue.h, tree.h, an MD5 implementation, and `tmpfileplus` under MPL-2.0, compiled in unmodified) and minizip 1.3.2 (Zlib licence), both recorded in `NOTICE`. The vcpkg port closure is `minizip` and `zlib` only.
