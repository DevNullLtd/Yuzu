# DEX per-version crash and hang join Resource Ledger (governance Gate 1)

Production-code ledger for the per-version failure join, kept here so the ownership analysis is retrievable with the change. Files: `server/core/src/dex_app_version_failures_owner.{hpp,cpp}` (new query owner), `server/core/src/dex_app_perf_model.cpp` and `dex_app_perf_pure.hpp` (pure join and serializer), `dex_perf_api.{hpp,cpp}` / `dex_perf_api_local.hpp` (the seam that holds the owner pointer), `dex_stats.hpp` (one defaulted parameter on the rate-ratio primitive), the REST and MCP handlers, the wiring in `server.cpp`, and the tests under `tests/unit/server/`.

## Resource Ledger (C++)
- New owner: one class, `DexAppVersionFailuresOwner`, the cross-schema query owner for the exposure rows and the crash and hang observations. It holds `pg::PgPool&` (borrowed, never owned) and an `int` retention; its copy operations are deleted (so no move is generated) and it has no destructor logic. Everything else in the change is a value type (`std::string`, `std::vector`, `std::optional`, structs of `int64_t` and doubles).
- No new file descriptor, handle, socket, `FILE*`, sqlite object, OpenSSL object, allocated C string, mapped library, temp-file path, subprocess, shell string, thread, lock or retained callback is acquired, owned or released. No `reinterpret_cast`, `const_cast`, raw `new`/`delete` or manual cleanup path exists in the new code.
- Lease and transaction: each `read()` takes exactly one bounded lease through `PgPool::with_txn_for(3 s, ...)`, which checks out a `PgPool::Lease` (RAII), opens a transaction guard declared after the lease (rollback first, then the connection returns to the pool) and runs the callback synchronously. The callback is passed by const reference and not stored. `SET LOCAL statement_timeout = '10s'` is transaction-scoped, so it cannot leak onto the pooled connection. A failed acquire, a failed statement or an uncommitted transaction returns `std::nullopt`; there is no early-return path that skips release. A request makes two sequential leases (the existing trend read, released before this one starts), never two held at once.
- Result handles: both statements return `pg::PgResult` (RAII `PGresult`). `PQgetvalue` pointers are read only while the `PgResult` is alive and are copied at once (`std::string` for the version, `strtoll` into `int64_t` for counts); no row holds a pointer into libpq memory. The error lambda `fail` captures `statement_failed` by reference and is invoked only inside `with_txn_for`, within the frame of `read()`, so the reference cannot dangle; `PQresultErrorField` on a null result is covered by the `unknown` fallback. The log carries the SQLSTATE only, never the caller-supplied application text.
- Borrowed data: `read()` takes `std::string_view app`, a `std::vector<std::string>` of versions and an ISO string view; the view and vector are used only before return. The version array is built into one owning string by `pg::to_text_array`, and the bind parameters are an owning `std::vector<std::optional<std::string>>`, so nothing outlives the caller's arguments. All values are bound parameters; none is interpolated into SQL.
- Ownership at the server: `ServerImpl::dex_app_version_failures_owner_` is a `std::unique_ptr` member, constructed in the guaranteed-state store block only after that store reports open, from `*pg_pool_` and the same observation retention as the store. It is declared after `guaranteed_state_store_` and after `pg_pool_`, so even implicit destruction runs the owner before the store and the pool. `make_local_dex_perf_api` receives `.get()` and keeps a non-owning pointer (a null owner degrades the read to a typed failure, never an empty success).
- Destruction order at shutdown: `stop()` stops the web server and runs the gRPC drains first, so no HTTP or MCP handler that could take a lease is still running; it then calls `dex_app_version_failures_owner_.reset()` immediately before `guaranteed_state_store_.reset()`, and `pg_pool_.reset()` runs later in the same function. No thread of this change survives into the reset, because the owner starts none and a read runs to completion on the calling handler thread.
- Static state: none added. Constants (`kAcquireTimeout`, `kStatementTimeout`, the SQL text) are `constexpr` literals.
- Integer and floating-point hazards: counts are `int64_t` from `COUNT(*)`/`COUNT(DISTINCT)` (non-negative); the join does no subtraction on them (a corrupt negative event count is passed to the rate primitive, which returns nothing and is counted as a statistic failure); `failure_window_days()` guards `retention_days_ > 0` before subtracting one, so there is no underflow, and the `std::min` call is parenthesised against the MSVC macro. The upper observation bound is a string from `dex_iso_at(end_day + 86400)`, so no integer overflow is possible for any plausible epoch.
- Tests (harness only): memory-only fixtures and ephemeral Postgres databases cloned from a template, one local `PgPool` per test case declared after its database; PG-gated cases skip without a DSN. No sleeps, no process spawns, no sockets and no threads added by the tests.
