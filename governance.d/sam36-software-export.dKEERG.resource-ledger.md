# Resource Ledger: sam36-software-export

Every owning boundary the C++ in `0e6a58722..HEAD` (feat/sam-36-export) acquires: the `SoftwareExportRoutes` route class and its per-request `Stream`, the pure `software_export_stream.hpp`, and the registration in `server.cpp`. The route is the first streamed file download that holds a lease across streamed I/O. No thread, fd, socket, `FILE*`, temp path, subprocess, mapped library or allocated C string is added; the provider has a catch-all and the releaser catches around the counter.

## Decision lines

- **Server-wide cap, no per-principal share.** The export cap is one counter in the one budget under one constant key (`stream_budget.hpp` key comment): one principal can hold every export slot. Stated in the manual and recorded here as the deliberate consequence of reusing the budget rather than adding a parallel limiter.
- **The 900 s deadline is the only bound on a sparse wide scope.** A confined caller whose scope is wider than `kScopePushdownMaxIds` makes the server read rows the scope excludes and filter them in process; the walk follows cursors to the end and the deadline ends it. An aborted transfer is the failure signal.
- **The roster map is bounded by the roster read itself.** The hostname map holds at most `kOfflineRosterRowCap` entries per stream and the budget admits at most 16 streams, so the worst case is fixed and display-only; it is not narrowed to the caller's scope (finding K5, not adopted).
- **Peer liveness is httplib's check, not the route's.** httplib's chunked loop checks the peer before every provider call, so a client that closed its connection frees its lease within one read step, including a step that wrote nothing. A connection lost without being closed (a crashed client, a dropped path) is noticed on a failed write or at the 900 s deadline, bounded by the cap (finding K2: the route consults no `is_writable` of its own).
- **A `denied` audit row per refused request.** Each request refused for the export cap or the full budget writes one `denied` row; it is bounded by the per-IP request limit (`--rate-limit`, default 100 per second), not by a route-local throttle (finding K3, not adopted).
- **The resume anchor never leaves the process.** On a wide scope it names the last row SCANNED, which may be a row the caller cannot see, so it lives only in `Stream::after` and is never formatted into a byte, header, log line, metric label or audit detail. Every store read is skip 0, so no OFFSET carries it either.
- **Access-control table (routed concern: security-guardian).** One new REST route, `GET /api/v1/inventory/software/export`, read-only, behind the sole gate `fleet_read_fn(req, res, "Inventory", "Read")` (ADR-0017), whose scope is passed to every store read. A named `agent_id` outside the caller's scope yields an empty export and no read. There is no MCP twin; the absence is recorded as a v1-keyed exception row in the API parity ledger.
