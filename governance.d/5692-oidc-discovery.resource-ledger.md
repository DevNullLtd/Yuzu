## Summary verdict

Production: no new `FILE*`, SOCKET, `sqlite3*`/`sqlite3_stmt*`, OpenSSL object, BCrypt handle, allocated C string, subprocess, temp path, mapped library or stored callback context. Round 2 added ONE
background thread per bounded GET on POSIX (the `RequestDeadlineWatchdog`, row P21) and round 3 gives it ONE reserved file descriptor (an `open` of `/dev/null` made before the client exists and turned into an alias of the socket with `dup2`), both owned by RAII members and released before `http_get_bounded` returns. The
owned things overall are: two `std::mutex` members (`discovery_mu_`, and the watchdog's own `mu_`) with a `std::condition_variable`, a `bool` in-flight flag and three plain value members, one
`std::atomic<int>` timeout, a stack-local `std::unique_ptr<httplib::Client>` per GET and per token POST (owns the socket and, for https, the SSL context), a stack-local watchdog per GET (owns one `std::thread`
and one reserved fd), one `std::unique_lock` local in `ensure_discovered` that is released and re-taken around the network call, a local RAII guard (`InFlightGuard`) that clears the in-flight flag on every
exit, by-value strings, `std::optional` and `std::expected` results, and file-local `std::string_view`s that borrow only from string literals or from a parameter that outlives them. Everything is
released by destructors. No `new`/`delete`/`malloc`/`free`/`release()`/`detach()`/`goto` was added in production. The only raw system calls added are `open`, `dup2`, `fcntl(F_SETFD)`, `shutdown(SHUT_RD)` and
`close` inside the watchdog class (row P21), each on the one descriptor that class owns, plus (round 4) one best-effort `shutdown(sock, SHUT_RDWR)` on httplib's raw socket in the unreachable `dup2`-failure branch (shut down, never closed or owned). The one explicit release elsewhere is `client.reset()` in two places (rows P4 and P20), on an RAII owner,
kept from the code it replaces. The removed `exchange_script` plumbing was dead (the old constructor copied the path into a member that nothing read, `cc73504a8:oidc_provider.cpp:1055`), so removing it
releases nothing and starts nothing; the Python script itself is still in the tree (row F5).

Tests: the `MockIdp` acceptor thread (joined in the destructor body) gains a chunked trickle writer, a discovery latch and a `GET /` route (rows T1, T2, T17); a raw TCP `TlsDripServer` acceptor thread
(row T13) is new in round 2. Test worker threads are `std::thread` owned by a scope-exit join guard (`ScopedThreads`, row T6) that sets an abort flag before joining; round 1's `std::jthread` is gone,
because Apple Clang 15 (the documented floor, `docs/build-guide.md`) does not provide it. No temp file, no env var, no fixed-port BIND was added; one fixed-port CONNECT target (`127.0.0.1:1`) is
used by two cases (F4). The new fd-count case reads `/proc/self/fd` (Linux only). Round 3 added three cases that `fork()`ed a child whose `RLIMIT_NOFILE` was lowered; round 4 REPLACED the fork with a re-exec (T19): the parent `posix_spawn`s the test binary itself with a hidden Catch case and `YUZU_TEST_OIDC_LOWFD_*` variables set in the CHILD's environment only, the helper resets the fatal signals to default first, lowers the limit (it applies to that process only), `alarm(8)` kills a hung fetch and the helper ends with `_exit`, never returning into Catch2. Round 3 also added one process-wide side effect (`signal(SIGPIPE, SIG_IGN)`, done once, in the drip fixture, comment at the site), and an `OwnedFd` RAII struct in the test TU (T13).
