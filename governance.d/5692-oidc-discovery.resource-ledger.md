## Summary verdict

Production: no new `FILE*`, SOCKET, `sqlite3*`/`sqlite3_stmt*`, OpenSSL object, BCrypt handle, allocated C string, subprocess, temp path, mapped library or stored callback context. Round 2 adds ONE
background thread and ONE duplicated file descriptor per bounded GET on POSIX (the `RequestDeadlineWatchdog`, row P21), both owned by RAII members and released before `http_get_bounded` returns. The
owned things overall are: two `std::mutex` members (`discovery_mu_`, and the watchdog's own `mu_`) with a `std::condition_variable`, a `bool` in-flight flag and three plain value members, one
`std::atomic<int>` timeout, a stack-local `std::unique_ptr<httplib::Client>` per GET and per token POST (owns the socket and, for https, the SSL context), a stack-local watchdog per GET (owns one `std::thread`
and one dup'd fd), one `std::unique_lock` local in `ensure_discovered` that is released and re-taken around the network call, a local RAII guard (`InFlightGuard`) that clears the in-flight flag on every
exit, by-value strings, `std::optional` and `std::expected` results, and file-local `std::string_view`s that borrow only from string literals or from a parameter that outlives them. Everything is
released by destructors. No `new`/`delete`/`malloc`/`free`/`release()`/`detach()`/`goto` was added in production. The only raw system calls added are `fcntl(F_DUPFD_CLOEXEC)`, `shutdown(SHUT_RD)` and
`close` inside the watchdog class (row P21), each on the one descriptor that class owns. The one explicit release elsewhere is `client.reset()` in two places (rows P4 and P20), on an RAII owner,
kept from the code it replaces. The removed `exchange_script` plumbing was dead (the old constructor copied the path into a member that nothing read, `cc73504a8:oidc_provider.cpp:1055`), so removing it
releases nothing and starts nothing; the Python script itself is still in the tree (row F5).

Tests: the `MockIdp` acceptor thread (joined in the destructor body) gains a chunked trickle writer, a discovery latch and a `GET /` route (rows T1, T2, T17); a raw TCP `TlsDripServer` acceptor thread
(row T13) is new in round 2. Test worker threads are `std::thread` owned by a scope-exit join guard (`ScopedThreads`, row T6) that sets an abort flag before joining; round 1's `std::jthread` is gone,
because Apple Clang 15 (the documented floor, `docs/build-guide.md`) does not provide it. No temp file, no env var, no fixed-port BIND was added; one fixed-port CONNECT target (`127.0.0.1:1`) is
used by two cases (F4). The new fd-count case reads `/proc/self/fd` (Linux only).

## Ownership notes

- Raw owners: none added in production beyond the watchdog's single `int` descriptor inside `OwnedFd` (P21). Borrowed raw pointers added: the `fields[]` array of `const std::string*` inside `parse_discovery_document` (P8), valid for that block only.

It captures the stack `watchdog` by reference; the client that stores it is destroyed BEFORE the watchdog (declaration order, plus the explicit `client.reset()`), and the callback only runs during `Get`, so it cannot outlive its capture.
