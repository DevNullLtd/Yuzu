## Summary verdict

Production: no new fd, `FILE*`, SOCKET, `sqlite3*`/`sqlite3_stmt*`, OpenSSL object, BCrypt handle, allocated C string, subprocess, temp path, mapped library, callback context or thread. The new owned
things are: one `std::mutex` (`discovery_mu_`) plus three plain value members it guards, one `std::atomic<int>` timeout, a stack-local `std::unique_ptr<httplib::Client>` per GET (owns the socket and, for https,
the SSL context), by-value strings and `std::expected` results, and two file-local `std::string_view`s that borrow only from string literals or from a parameter that outlives them. Everything is released by
destructors (`std::lock_guard`, `std::unique_ptr`, `std::string`, `std::optional`). No `new`/`delete`/`malloc`/`free`/`release()`/`detach()`/`goto` was added and no cast of any kind was added (grep over the
added lines of the five C++ files in the range, plus the two `*_for_test` additions). The one explicit release is `client.reset()` (row P4), on an RAII owner, kept from the code it replaces. The removed
`exchange_script` plumbing was dead (the old constructor copied the path into a member that nothing read, `cc73504a8:oidc_provider.cpp:1055`), so removing it releases nothing and starts nothing; the Python script
itself is still in the tree (row F5).

Tests: one new background-thread owner, the `MockIdp` acceptor thread, joined in the destructor body (unchanged shape; new handlers added). ONE bare `std::vector<std::thread>` is ADDED, in the single-flight test
(row T6): joined by hand, not by `yuzu::test::Workers`-style RAII. That is a finding (F1). No temp file, no env var, no fixed-path or fixed-port BIND was added; one fixed-port CONNECT target (`127.0.0.1:1`) is added (F4).

## Recorded, not fixed (found while reading; nothing was changed)

- **F1 (tests, policy-adjacent): a bare `std::vector<std::thread>` was ADDED** in the single-flight test (`test_oidc_provider.cpp:1501-1511`). It is joined by hand, so (a) a throw from `emplace_back` partway through the loop (bad_alloc, or `std::system_error` when thread creation fails) leaves the already started threads spinning at the barrier (:1505) forever and then destroys a joinable `std::thread`, which calls `std::terminate`; (b) the barrier waits for `kThreads` arrivals, so a failed creation also strands the others. `yuzu::test::Workers` (`tests/unit/server/test_principal_lock_gate.hpp:60`) is the existing owner for exactly this, but that header includes the libpq test helpers, so using it here needs either that include or a lighter shared extraction. The task brief says to treat any bare `std::thread` added as a finding; this is it.
- **F2 (production): IdP-controlled text is logged unsanitised.** `parse_discovery_document` embeds up to 200 bytes of the document's `issuer` string in the mismatch error (`oidc_provider.cpp:1164-1166`); `ensure_discovered` writes that error with `spdlog::error` (:1209-1210). A mismatching document is by definition not trusted, and the 200 bytes may contain CR, LF or other control bytes (CWE-117 shape). The login answer is unaffected (fixed token) and Test Connection `html_escape`s it; only the server log line is. A log-token filter like the one used for caller-supplied audit fields would close it.
- **F3 (production, minor): `split_http_url` treats `?` and `#` as part of the host** when no `/` follows (`oidc_provider.cpp:1052-1071`): `http://host?x` yields origin `http://host?x` and path `/`. It only matters for an endpoint or issuer the operator or a validated document supplied; `endpoint_acceptable` does not reject `?`/`#` right after the host.
- **F4 (tests): a fixed-port connect target.** `http://127.0.0.1:1` is used as an instantly-refused address (`test_oidc_provider.cpp:1455`, plus pre-existing :1031/:1040 and new `test_oidc_routes.cpp:341`). - **F5 (production/repo): `scripts/oidc_token_exchange.py` is still in the tree** and now nothing references it but its own text. The range removes the config plumbing but not the script (`git diff --stat` shows no `scripts/` change).
