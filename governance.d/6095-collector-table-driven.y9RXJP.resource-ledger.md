# Installed-software collector table-driven refactor — Resource Ledger (governance Gate 1)

The production-code ledger for the agent-side refactor of the installed-software collector (`agents/core/src/sync_source_installed_software.{cpp,hpp}`), the new header `agents/shared/inventory_status_row.hpp` and the two plugins that now call it, kept here so the ownership analysis is retrievable with the change.

## Resource Ledger (C++)
- No new or modified fd, HANDLE, SOCKET, `FILE*`, sqlite3 handle or statement, OpenSSL or BCrypt object, allocated C string, mapped library, temp-file path, subprocess, shell string, callback context or thread, in production or test code. No manual cleanup is added or changed.
- `yuzu::shared::StatusRow` (`agents/shared/inventory_status_row.hpp`): owner = the value itself. `level` is an `std::optional<StatusLevel>` (an enum, no resource) and `tokens` is an owning `std::string` copied from the fourth split token inside `parse_status_row`; no `string_view` or `span` is stored in or returned from it.
- `parse_status_row` / `is_status_line` take `std::span<const std::string_view>` and `std::string_view`: call-scoped borrows only. In `adapt_pkg_inventory` the token vector is a per-line local inside the `for_each_line` callback and views the caller's `const std::string& out`, which outlives the whole call; `reason` is a `std::string` filled by `std::move(row->tokens)` before the vector dies.
- `find_manager` returns `const ManagerEcosystem*` into `kManagerEcosystems`, a `constexpr` array with static storage duration in the translation unit's anonymous namespace: constant-initialised from string-literal views (no static-initialisation-order hazard), immutable, never freed, never stored past the statement that uses it, and null-checked before every dereference.
- `ConstrainedPolicy` is a scoped enum passed by value. Keeping a constrained answer's rows is the single opt-in (`policy != keep_rows_if_present_seen || seen == 0` fails the action), so an out-of-range value fails closed; the action table's `constrained` column defaults to `fail`.
- `kInventoryActions` and the manager table are `constexpr`/`const` aggregates of literals and function pointers: no mutable static or thread-local state, no lazy initialisation, no thread. The four exported adapters take `const std::string&` and the enum by value; they are in-process entry points of `agents/core`, not part of the plugin C ABI (`YuzuPluginDescriptor` is untouched).
- Exception paths: unchanged. The `msi_packages` `execute()` catch-all and the `pkg_inventory` `run_guarded` firewall only changed the qualification of `format_status_row`; the edit adds no throwing call outside the existing guards.
- Tests (harness only): no thread, process, socket, sleep or temp file. `capture_section` reads committed sample files (the translation unit's pre-existing idiom); the `static_cast<ConstrainedPolicy>(9)` case is defined behaviour for a scoped enum with a fixed underlying type.

## Independent ownership proof
Static proofs by security-guardian (Gate 2) and cpp-safety (Gate 3) at `8a49ea5b7`, re-checked on the fix delta at `438cb92a9` (Gate 8): no blocking finding. Dynamic: cpp-safety compiled the real collector with `-fsanitize=address,undefined -fno-sanitize-recover=undefined` and ran 400,000 random pipe-grammar documents (0 to 11 tokens, CRLF mixes, duplicate or mismatched status rows) through the four adapters with no report. unhappy-path ran a differential probe of the base collector against HEAD (94,680 and 214,680 adapter cells and 11,000 collector cycles over two seeds): 0 mismatches. Sanitizer coverage in CI: the nightly `sanitize-asan` job runs the agent suite, which contains `test_inventory_status_row.cpp` and the collector cases; no thread is added, so no TSan work is needed.
