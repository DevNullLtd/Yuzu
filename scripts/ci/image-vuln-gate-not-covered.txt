# Images NOT covered by OS package vulnerability scanning (WP15/S9).
#
# scripts/ci/image-vuln-gate.sh fails an image whose OS package scan finds no
# package at all: a scan that saw nothing is not a clean scan. An image listed
# here passes that check anyway, and the gate prints NOT COVERED with the reason
# for it on every run (and records it in the report). Listing an image is a
# reviewed decision that its OS packages ship UNSCANNED; it is not an acceptance
# of any vulnerability in them.
#
# Format, one image per line (validated by image-vuln-gate-checks.py; a
# malformed line refuses the whole list):
#   <image name>: approved_by=<login> approved_on=<YYYY-MM-DD> approval_ref=<#N|PR URL> expires=<YYYY-MM-DD> reason=<why>
# The name is the published repository name without the registry
# (yuzu-server-chisel), as release.yml passes it (`NAME=sha256:...`) and as
# pre-release.yml's tags end in it; it is matched EXACTLY (never a prefix or a
# substring). approved_by is the GitHub login of the person who accepted that
# the image ships unscanned, approval_ref the pull request in which they did,
# approved_on its date: a recorded reference the gate checks for format only
# (nothing verifies the pull request or the approver; the control is review of
# the change to this file; procedure: docs/ci-architecture.md "Recording an
# approval"). Until it is recorded, write `approved_on=-
# approval_ref=pending`: a pending listing is not honoured by the release gate
# (--release), so the image fails there as unscanned. expires is at most 92
# days out; an expired listing is not honoured anywhere, so the listing is
# re-reviewed rather than forgotten (the gate warns 21 days before). The reason
# is at least 20 characters.
# Remove a line as soon as the scanner sees the image's packages; the gate
# warns when a listed image does have OS packages.
#
# Why these four: they are assembled FROM scratch from Ubuntu package slices cut
# with Canonical's chisel. A chiselled root has no dpkg status database, and
# these images do not cut the base-files_chisel slice that would write a chisel
# manifest, so Trivy 0.70.0 detects Ubuntu 26.04 but reports "No OS package is
# detected" (0 packages, checked 2026-11-18 on the v0.15.0 server and gateway
# chisel images). What ships unscanned is each Dockerfile's SLICES list.
yuzu-server-chisel: approved_by=fjarvis approved_on=- approval_ref=pending expires=2027-02-15 reason=chiselled FROM scratch, no dpkg database or chisel manifest; ships unscanned Ubuntu 26.04 slices of libc6, libgcc-s1, libstdc++6, libssl3t64, libpq5 (and its krb5/ldap dependencies), zlib1g, openssl config, ca-certificates, netbase, busybox-static (deploy/docker/Dockerfile.server.chisel SLICES)
yuzu-gateway-chisel: approved_by=fjarvis approved_on=- approval_ref=pending expires=2027-02-15 reason=chiselled FROM scratch, no dpkg database or chisel manifest; ships unscanned Ubuntu 26.04 slices of libc6, libgcc-s1, libstdc++6, libncursesw6, libtinfo6, libssl3t64, zlib1g, openssl config, ca-certificates, netbase, busybox-static (deploy/docker/Dockerfile.gateway.chisel SLICES); the bundled Erlang/OTP runtime is not identified by Trivy either
yuzu-agent-chisel: approved_by=fjarvis approved_on=- approval_ref=pending expires=2027-02-15 reason=chiselled FROM scratch, no dpkg database or chisel manifest; ships unscanned Ubuntu 26.04 slices of libc6, libgcc-s1, libstdc++6, libssl3t64, libsqlite3-0, libsystemd0, libblkid1, zlib1g, openssl config, ca-certificates, netbase, busybox-static (deploy/docker/Dockerfile.agent.chisel SLICES)
yuzu-agent-bundle-chisel: approved_by=fjarvis approved_on=- approval_ref=pending expires=2027-02-15 reason=chiselled FROM scratch, no dpkg database or chisel manifest; ships unscanned Ubuntu 26.04 base-files, base-passwd and busybox-static slices plus the agent release archives it delivers (deploy/docker/Dockerfile.agent-bundle.chisel SLICES); the archives' own SBOMs are release assets
